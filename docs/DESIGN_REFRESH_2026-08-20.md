## 0. 판단 기준 — 무엇을 가져오고 무엇을 안 가져오나

샘플은 대부분 **B2C 문법**으로 그려져 있다. 우리는 ERP다. 그래서 두 가지를 분리해서 본다.

**가져오는 것 — 「형태 문법」**
- 층(層)을 만드는 방법: 모서리 단계, 면 대비, 테두리 세기
- 모양이 뜻을 나르는 방법: 알약 vs 사각, 반전 면 vs 틴트 면
- 표를 읽히게 하는 방법: 머리띠 반전, 강조 열 표식, 숫자 정렬

**안 가져오는 것 — 「B2C 감성」**
- 900 굵기, 24~32px 제목 → `FW` 최대 700 · `FS.page` 18 (DESIGN.md, [[b2b-dense-ui-principle]])
- 그라디언트 히어로·로고, backdrop-blur, hover 시 카드 뜨기, 펄스 테두리
- 이모지·장식 아이콘 (섹션 머리 1개만 허용 — `components/section-icons.tsx`)
- 큰 라운드(24px)를 전면 적용하는 것

**우리가 이미 맞게 하고 있는 것** (샘플과 방향이 같음 — 바꾸지 말 것)
- 뱃지 = 틴트 3종 세트(바탕/글자/테두리) — `--bdg-*-bg/-fg/-ac`
- 표 머리 반전 — `DetailTable headTone='invert'`
- 영업자 = 어두운 면으로 권한 구분 — `ProductAgentPanel` 남색 반전
- 최저가 행 강조 — `ProductPriceTable`

## 1. 지금 우리가 맹해 보이는 이유 (코드 실측)

| # | 무엇 | 근거 | 결과 |
|---|---|---|---|
| 1 | **모서리가 한 단계뿐** | `tokens.ts` `R = 4` 하나로 카드·표·뱃지·버튼 전부. `globals.css`에 `--radius-lg: 8px`·`--radius-pill: 999px`가 있는데 **쓰는 곳이 없다** | 층이 안 생겨 화면 전체가 종이 한 장처럼 평평 |
| 2 | **뱃지가 전부 같은 사각** | `badges.tsx` `borderRadius: R` 고정. `PILL_R`은 export만 되고 Badge에서 안 씀 | 상태(계약중·지연)와 분류(연료·차종)를 모양으로 못 가름 |
| 3 | **`--font-mono`가 mono가 아님** | `globals.css` `--font-mono: 'Pretendard Variable', Pretendard, …` — 고정폭 서체가 하나도 없음 | 표의 금액 열 숫자 폭이 흔들림 |
| 4 | 면 대비가 얕음 | `--bg-page #f6f7f9` vs `--bg-card #ffffff` + `--shadow-sm` 알파 0.035 | 카드가 «떠 보이지» 않음 |

→ **색 문제가 아니다.** 팔레트(네이비 `#1B2A4A` + 틴트 8종)는 이미 정리돼 있다. 형태 쪽이 단조롭다.

## 2. 트렌드 메모 (2026 B2B/SaaS)

- 모서리는 **3단으로 수렴** — 컨테이너 10~12 / 서피스 8 / 컨트롤 6. 24px 전면 라운드는 2022~23 소비자앱 잔재.
- **굵기 대신 대비** — 900 남발은 지난 유행. 550~650 + 색 대비로 위계.
- **그림자를 줄이고 «면 + 1px 테두리»로 층 구분.**
- **모양이 뜻을 나른다** — 알약=변하는 것(상태), 사각=안 변하는 것(분류).
- 숫자는 `font-variant-numeric: tabular-nums` 고정.
- **어두운 면으로 모드·권한을 가른다** — 우리 영업자 패널이 이미 이 방향.
- 밀도 우선(compact). B2B는 한 화면에 더 담는 쪽이 이긴다.

**두 샘플이 같이 말하는 것** — 둘 다 ①손님/영업자를 **면 또는 변의 색**으로 가르고 ②표 강조를 **머리 또는 행 안 칩**으로 표시하고 ③숫자를 mono로 세운다. 이 셋은 유행이 아니라 이 업종 화면의 공통 요구로 보인다.

### 샘플 ③ `drivedirect_pro.html` — DriveDirect PRO (2026-08-20 접수)

「공급사 정찰 재고 탐색 + 고객 제안」. **처음으로 목록 화면이 들어왔다** — 격자/표 두 뷰를 같은 데이터로 전환한다.

**목록 화면 — 가져올 것**

| 무엇 | 샘플③ | 우리 |
|---|---|---|
| 뷰 전환 | 격자 ↔ 표, 같은 데이터 | 우리도 격자(`ProductCard`)·행(`ProductRowCard`)이 이미 있음. **전환 규격이 없을 뿐** |
| 사진 위 뱃지 **자리가 뜻** | 좌상=공급사 · 우상=출고형태+재고수 · 좌하=사진 장수 | 우리는 CORE 뱃지 3개를 썸네일 우하에 몰아 둠. **자리로 종류를 가르는 규격**은 참고할 만함 |
| 카드 바닥 | 요금(큰 글씨) + 액션 버튼 한 줄, 위에 1px 구분선 | 우리와 비슷 |
| 카드 중간 「영업 핵심 포인트」 | 회색 박스에 보증금·출고일수·영업인포 1줄(truncate) | **영업자 정보를 목록 카드에도 얹는 발상** — 우리 혜택 뱃지와 역할이 겹침. 둘 중 하나로 정해야 함 |
| 표 뷰 열 | 공급사/ID · 차량정보(썸네일 64×44 + 3줄) · 신차가격 · 36/48/60 한 칸 · 보증금/분납 · 액션 | **기간 3개를 한 칸에 나열**하는 게 밀도가 좋다 |

**상세 화면 — 가져올 것**

1. **[영업자 Check] / [손님 Check] 두 색 박스** — 파랑=영업자, 앰버=손님. **색으로 두 축을 가름.** 우리가 「두 축으로 나눈다」고 한 것의 시각적 구현. 각 박스 안은 4칸 그리드 = 라벨(10px 회색) + 값(11px 굵게).
2. **기간을 표가 아니라 「선택 카드 목록」으로** — 카드마다 좌측 설명 + 우측 금액, 뱃지로 성격 표시(「인기 추천」·「최저 월 납부」), 선택된 것만 테두리 2px + 틴트. 사장님 「여기도 목록형으로 해야지」와 통한다. **우리 가격표의 대안 후보.**
3. 색상 표시에 **실제 색 동그라미**(외장/내장) — 우리 `색상` 행이 글자뿐이라 밋밋한 것의 해법.
4. 손님 화면 미리보기를 **폰 프레임 안**에 렌더 — 우리 `CustomerPreviewModal`의 대안.

**버릴 것**: `font-black`(900) 전면 · 그라디언트 뱃지(`luxury-gold-badge`·`badge-supplier`) · `rounded-3xl`(24) · hover 시 사진 확대 · backdrop-blur 카드 · 이모지 제목

**원자 대응**

| 샘플③ 칸 | 우리 원자 | 판정 |
|---|---|---|
| 목록 카드 뱃지 | **있다** — CORE 3(상태·상품유형·심사) + 혜택 5(분납·무보증·만21세·경력무관·무사고) | 우리가 더 많다. **자리·모양 규격만 없다** |
| 「재고 N대」 | 없음 (우리는 1행=1대) | 안 만든다 |
| 「출고 소요 3일」 | 없음 | 안 만든다 |
| 「동급 타사 대비 월 3.2만원 저렴」 | 없음 | 안 만든다 |
| 신차가격 | `차량가격` (영업자 이상만) | 손님 목록엔 안 나감 |
| 공급사명 | **관리자 전용** | 목록 카드 좌상 뱃지로 못 쓴다(영업사원에게 비공개) |
| 기간 3개 한 칸 | 반납형/인수형 × 기간 | 우리는 2갈래라 한 칸에 3개가 아니라 **2줄** 구조가 맞다 |

**세 샘플의 공통 결론** — 셋 다 ①손님/영업자를 색 또는 면으로 가르고 ②기간 선택을 «카드 목록 + 뱃지»로 풀고 ③금액을 큰 글씨 한 개만 세운다. 우리가 지금 못 하는 건 ②와 ③의 «앵커 하나» 규칙이다.
