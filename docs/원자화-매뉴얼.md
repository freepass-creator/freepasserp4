# 원자화 매뉴얼 — 「한 번만 잘 만들고, 다음엔 검수만」 (2026-09-04 확정)

> 사장님 2026-09-04 「원천이 어디인가 파악해서 한 번만 원자 잘 만들고, 대여료도 만들고, 다음엔 검수만.
> 차량번호 좌우 한 줄이 그거니까 안 달라지게. 그게 ERP·구글시트에 반영되고. 매뉴얼화 해서 안 움직이게.」

이 문서는 **안 움직이게 하는 매뉴얼**이다. 원천 매핑은 [원자-원천지도](원자-원천지도.md)에, 여기는 **어떻게 돌고·무엇을 지키고·어떻게 검증하나**를 박는다.

## 0. 한 장 요약

```
원자 = v4/products (차번 키) ──매시간 미러──▶ Firestore products
   │  ② 불변(한 번)         ③④⑤ 변동(매시간)
   ▼
ERP(파인더가 읽음) = 구글시트(make-sample 발행) = «같은 원자»
```
- **불변(②)**: 제조사·모델·세부모델·세부트림·원산지·배기량·색·연식·연료·차종구분·상품구분. 차종마스터로 검증해 **한 번** 박고 안 바꾼다.
- **변동(③④)**: 배차상태·주행거리·대여료·보증금. 매시간 공급사/정산원장을 따른다.
- **정책·계좌(⑤)**: 대인~자차·연령·1만+·전용계좌·공급사명. 준정적 — 확인되면 오버라이드로 박는다.

## 1. 매시간 파이프라인 (`scripts/hourly-sync.mts --apply`)

| 단계 | 하는 일 | 소유 도구 |
|---|---|---|
| ⓪ | 손오공 pull·정제(라이브 마스터 행 복사)·재고시트 | `sonokong/*` |
| ① ①′ | 정제시트 갱신 · 정제칸 채움(마스터 행) | `sync-mirror-all` · `fill-supplier-ai-columns` |
| ②③④⑤ | 차명중복·모델통일·입고일자·사진링크 | 각 스크립트 |
| ⑤′ | **정산원장 → 계약중/출고불가** 세움 | `mark-contract-in-listings` |
| ⑥ | 판매시트 4탭 발행(정제시트→판매). **`--force-shrink`** | `publish-origin-tab` |
| ⑦ | ERP 일일 동기(판매시트→v4/products) | `sheet/sync-daily` |
| ⑧⑨⑪ | 대조·상태갈림·요금검수(재는 자, 안 고침) | audit·check |
| ⑬½ | **정제시트·마스터 → 원자 치유**(불변 채움·색분리·트림피커·구분·주행) | `fix-atoms-from-refined-sheets` |
| ⑭ | v4/products → Firestore 미러(변동+불변 SPEC) | `mirror-to-firestore` |
| ⑮ | 원자 변경 검증(상태전이·요금변경 기록) | `detect-atom-changes` |
| ⑯ | **Firestore 원자 → 본시트 재발행**(집안 서식) | `make-sample-sheet-google --main` |

★**⑬½·⑯ 는 반드시 ⑭ 미러 앞/뒤 순서**다. ⑬½(원자 치유)→⑭(미러)→⑯(발행). 순서 바뀌면 낡은 원자가 실린다.
★**⑥ `--force-shrink` 이유**: ⑯ 이 본시트를 원자로 재발행하면서 ⑥ 의 shrink·「공급사 0대」 가드가 «표기 차이»로 오작동해 멈춘다(2026-09-04 실측 14:18·16:21). ⑯ 이 최종 발행자라 ⑥ 가드는 무의미 — 진짜 손실 보호는 ⑯(원자=정본)이 대신. 0대 전무 가드는 유지.

## 2. 불변을 «한 곳»에서만 박는다 — 치유 `fix-atoms-from-refined-sheets`

여러 코드가 제각각 불변을 박으면 어긋난다(2026-09-04 실측: 색이 주행칸에 박혀 write-once 로 굳음). **불변의 입구는 미러 snap + 이 치유 하나**다. ⑥⑦ 은 변동만.

치유가 하는 일(모두 «비었거나 명백히 틀린 것만», 상태 안 건드림):
1. **식별 오버라이드**(`vehicle-identity-overrides.json`) — 사람이 확인한 차종. 최우선.
2. **구분 5캐논** — 오플(RP023)→오플구독 · 재랜트/재렌트→중고렌트.
3. **정제시트 채움** — 제조사·모델·세부모델·세부트림·색을 정제칸(마스터 행 복사)에서. 비었을 때만.
4. **트림 피커** — 정제시트로도 못 채운 빈 트림을 **그 세부모델의 마스터 `trims[]`에서만** 원문과 정규화 대조해 뽑는다(비지니스↔비즈니스·Iconic↔아이코닉·Sport↔스포츠·Modern↔모던…). ★마스터에 없는 트림은 «지어내지 않고» 비운다 → 원문은 「차명(원문)」칸에 남는다.
5. **주행거리 갱신**(변동) — 정제시트 현재값과 다르면 갱신(비었을 때만 아님).
6. **외장/내장 분리** — 「A / B」 → 외장 A · 내장 B(손오공구독). 내장 비었을 때만.

## 3. 손대는 «칸» — 오버라이드 셋 (사장님이 알게 되는 대로 박는다)

| 파일 | 무엇 | 우선순위 |
|---|---|---|
| `public/data/vehicle-identity-overrides.json` | 차번→제조사·모델·세부모델·트림 (매처가 못 박은 차) | 불변 최우선 |
| `public/data/supplier-policy-overrides.json` | 공급사코드→정책칸(21세·23세·1만+…) 확인값 | 정책 최우선 |
| `public/data/supplier-policies.json` | 공급사코드→정책 학습본(구형 시트·supplier.xlsx) | 정책 기본 |

## 4. 표기 규격 (make-sample-sheet-google)

- **면책금**(대인·대물·자손·무보험·자차) = 「무한 / 30만원」·「1억원 / 30만원」 (단위 표기).
- **할증**(1만+·21세+·23세+) = 「대여료 X%」(바 정수·0.1) 또는 「정액 X만원」(「만」 붙은 것). 불가/협의/문의 그대로.
- **소비자가격** = 원단위 콤마(15,775,000).
- **옵션** = 「-」·「.」처럼 텍스트/영문/숫자 없으면 선택옵션 없음(빈칸).
- **계약중 행** = 가운데줄(strikethrough). 데이터는 안 지우고 상태값만 계약중.
- **탭 이름** = 「base 시각 · N대」. 아래 여유 20줄만.

## 5. 상태 규칙 (⑤′ `mark-contract-in-listings`)

- **정산원장에 차번 오르면(계약중·계약서·접수) → 계약중**(선점, 못 팜).
- **인도완료·계약완료 → 출고불가**(나감).
- **취소·환수 → 아무것도 안 함**(자동 해제 없음 — 「잘못 풀면 이미 나간 차 재판매」. 푸는 건 공급사 몫: 시트에 다시 올리면 정상 동기로 가용).
- **출고불가는 안 덮는다**(계약중보다 센 말).
- **원문 자체가 없는 차(검수상태=원문없음) → listable=false**(팔 수 없으니 내림). 매칭만 실패한 차(원문 있음)는 살린다.

## 6. 안 움직이게 — 검증 게이트

```
npm run check:atoms        # 원자 규격 검사(아래 항목). 어긋나면 exit 1.
```
검사 항목:
1. mileage 에 색상값(칸밀림) = 0
2. listable 인데 model/sub_model 빈 것 = 0 (원문없음은 listable=false 여야)
3. ext_color 에 「/」(미분리) = 0
4. product_type 가 5캐논 밖 = 0
5. listable 인데 원문없음 = 0

## 7. 드리프트 위험 (여기가 또 틀어지는 곳)

- ⚠ 불변을 ⑥⑦ 이나 새 코드가 «또» 박으면 어긋난다 — 입구는 치유+미러 하나.
- ⚠ ⑬½·⑯ 순서(미러 앞/뒤)를 바꾸면 낡은 원자가 실린다.
- ⚠ ⑥ `--force-shrink` 를 빼면 ⑯ 과 부딪혀 파이프라인이 멈춘다.
- ⚠ 트림 피커가 마스터 밖 트림을 지어내면 규격 붕괴 — 마스터 `trims[]` 안에서만.
- ⚠ 정책 갭: 이안카(RP031)·오토플러스(RP023) 정책은 supplier.xlsx 에 없다 → 별도 원천 필요.
