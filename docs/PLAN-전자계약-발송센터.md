# 설계 — 전자계약 발송센터 (2026-08-10)

사장님 설계서 v0.1 + 구두 지시 3건을 지금 코드 위에 얹기 위한 **구현 설계**다.
Claude 가 설계하고 Cursor 가 구현한다. 검증 기준은 이 문서가 아니라 «원래 요구사항»이다.

```
지시 1  전자계약을 별도로 만든다
지시 2  계약서관리를 갈아엎는다
지시 3  계약서관리 = 「계약서 생성」 + 「완료된 계약서 보관」 둘로
지시 4  지금까지 있는 건 잘 활용해서 모은다   ← 새로 짓지 않는다
```

---

## 1. 한 줄 요약

**엑셀을 없애지 않는다. 엑셀 뒤의 일곱 단계를 세 단계로 줄인다.**

```
지금   엑셀 작성 → 출력 → PDF → 전달 → 서명 → 회수 → 보관
목표   엑셀 작성 → 프리패스에 넣기 → 확인 → 보내기
```

전자계약은 ERP 의 부속이 아니라 **ERP 로 들어오는 입구**다.
렌터카사는 계약을 보내려고 접속하고, 그 결과로 고객·차량·계약·정산 데이터가 쌓인다.

---

## 2. 지금 있는 것 — 새로 만들지 마라

15 개 모듈이 이미 서 있다. 설계서의 절반은 **이미 구현돼 있다.**

| 설계서 요구 | 이미 있는 것 | 상태 |
|---|---|---|
| Contract Atom | `docs/CONTRACT_ATOMS.md`(107 항목) · `esign-field-map` · `esign-display-fields` | ✅ 그대로 씀 |
| 약관 버전관리 | `esign-agreement-text`(정본) · `esign-standard-terms` | ⚠ 버전 필드만 추가 |
| 중요 조문 강조 | `esign-agreement-emphasis` | ✅ |
| 동의 UX | `esign-consent-doc`(491줄) | ✅ |
| 진행 상태 | `esign-progress` | ✅ 상태 이름만 정렬 |
| 표준계약서 3벌 | `esign-templates` · `esign-template-profile` | ✅ |
| 착한거래 연동 | `chakhandeal-esign` · `/api/chakhandeal/contracts/send` | ✅ |
| 법적 요건 점검 | `esign-compliance` | ✅ |
| 못 채우는 원자 수집 | `esign-inputs` | ✅ |

**서명·본인확인·해시봉인은 착한거래(sign.freepasserp.com)가 한다.** fp4 는 연동만 한다.
이 경계를 흐리지 마라 — 서명 엔진을 fp4 에 다시 만드는 순간 두 벌이 된다.

### 새로 만들어야 하는 것

1. **Excel Adapter** — 설계서의 심장. 지금 아무것도 없다.
2. **발송센터 화면** — 지금 화면은 관리자형 3패널(데이터·착한거래·진행)이다.
3. **Contract Snapshot 봉인** — 지금은 `*_snapshot` 필드가 계약 레코드에 흩어져 있다.
4. **Revision** — 발송 후 변경을 새 회차로 만드는 축.

## 3. 화면 — 계약서관리를 갈아엎는다

### 지금 (`/esign`)

```
전자계약  ─ 목록 ─┬ 계약 데이터 (입력폼)
                 ├ 착한거래 데이터연동·링크
                 └ 착한거래 진행상황
```

계약을 **고르지 않으면** 아무것도 못 한다. 엑셀을 들고 온 사람이 설 자리가 없다.

### 바꿀 모습

```
/esign  전자계약 발송센터

  ┌ 무엇을 보낼 것인가 ─────────────────┐
  │ [＋ 엑셀 계약서 불러오기]  ← 주 동선  │
  │ [＋ 직접 계약 작성]                  │
  │ [ERP 계약 불러오기]                  │
  └────────────────────────────────┘

  발송대기 3   서명중 5   확인필요 2   완료 27
  ─────────────────────────────────
  김OO · 아반떼 · 손오공      월 600,000 · 48개월   [보내기]
  이OO · K5 · A렌터카        확인 필요 2건         [확인]
```

한 행에 여섯 값만 — **고객 · 차량 · 렌터카사 · 월대여료 · 기간 · 상태.**
지금의 3패널은 지우지 않는다. 행을 누르면 **상세보기**로 그대로 연다.

### 계약서관리 (지시 2·3)

지금 「계약서 관리」가 하는 일이 둘 섞여 있다. 갈라놓는다.

```
계약서 생성      양식 3벌 중 고르고 값 채워 계약서를 만든다 (지금 기능)
완료 계약서 보관  서명이 끝난 것만 모인다. 읽기 전용. 다시 못 고친다.
```

보관함에서 고칠 수 있으면 그건 보관이 아니다. **완료된 계약서는 열람·내려받기만.**
고쳐야 하면 §7 Revision 으로 새 회차를 만든다.

## 4. Excel Adapter — 새로 만드는 것 ①

### 원칙

```
엑셀 한 칸  →  Contract Atom 하나
```

**셀 주소는 Adapter 안에만 산다.** UI·API·도메인 어디에도 `GB14` 같은 글자가 나오면 안 된다.
공급사가 양식을 바꾸면 Adapter 한 파일만 고쳐야 한다.

### 구조

```
lib/domain/esign-excel/
  index.ts            양식 식별 → Adapter 선택 → 원자 추출 → 검증
  detect.ts           머리글·시트이름·앵커 셀로 templateId 판정
  types.ts            ExcelAdapter · DetectResult · ExtractResult
  adapters/
    sogong-personal-v1.ts
    sogong-business-v1.ts
```

```ts
export type ExcelAdapter = {
  templateId: string;          // 'SOGONG_PERSONAL_V1'
  supplierCode: string;        // 'RP012'
  contractKind: '렌트' | '구독';
  /** 이 파일이 이 양식인가 — 앵커 셀 몇 개로 판정한다. */
  detect(sheet: Sheet): number;        // 0~1 확신도
  /** 셀 → 원자. 여기서만 셀 주소를 안다. */
  extract(sheet: Sheet): Record<string, unknown>;
};
```

### 판정 실패는 실패가 아니다

지원하지 않는 양식이 오면 막다른 길로 끝내지 않는다.

```
지원하지 않는 계약서 형식입니다
  [렌터카사 선택] [계약형태 선택]  → 수동 매핑
  [직접 계약 작성]                → 값만 옮겨 적기
```

원본 엑셀은 **관리자 검토함**에 남긴다 — 다음 Adapter 의 재료다.

### ★블로커 — 손오공 엑셀 실물이 없다

리포에 계약서 엑셀이 한 장도 없다(`public/contract-template/` 은 HTML 서식뿐).
**Adapter 는 실물 없이는 한 줄도 못 쓴다.** 셀 주소를 지어낼 수 없다.

필요한 것: 손오공 개인 / 개인사업자 / 법인 각 1부. 값이 채워진 실제 계약서라야 한다
(빈 양식은 병합셀·행 밀림을 못 본다).

## 5. 검증 — 세 등급

엑셀에서 뽑은 값은 그대로 믿지 않는다.

| 등급 | 뜻 | 발송 |
|---|---|---|
| PASS | 값이 있고 형식이 맞다 | 가능 |
| WARNING | 값은 있으나 확인이 필요하다 (자동이체일 없음·추가운전자 미확정) | 가능, 배지로 알림 |
| BLOCK | 전자계약에 반드시 필요한 값이 없다 (고객명·연락처·공급사·월대여료·기간) | **불가** |

BLOCK 이 하나라도 있으면 「보내기」 버튼을 누를 수 없다. 회색으로 두지 말고
**무엇이 없는지 그 자리에 적는다** — 「연락처 없음」이라고.

판정은 `esign-compliance` 를 잇는다. 새 판정기를 또 만들면 답이 갈린다.

## 6. Contract Snapshot — 새로 만드는 것 ②

### 왜 필요한가

지금은 `car_number_snapshot` · `rent_month_snapshot` 처럼 **필드마다 흩어져** 있다.
발송 뒤 원본 계약이나 정책이 바뀌면 무엇을 보고 서명했는지 되짚을 수 없다.

### 구조

```
v4/esign_snapshots/{contractCode}/{revision}
  supplier · customer · vehicle
  rentTerms · driverTerms · insuranceTerms · maintenanceTerms
  specialTerms[]
  terms: { id, version, contentHash }      ← 약관을 «본문»이 아니라 «해시»로 박는다
  agreement: { confirmations[], viewedAt, agreedAt }
  signature: { signer, signedAt, signatureFile }
  audit: { createdAt, sentAt, openedAt, signedAt }
```

**발송 시점에 뜬다. 그 뒤로 자동으로 바뀌지 않는다.**
모바일 화면과 보관 PDF 는 같은 Snapshot 에서 각각 그린다 —
그래야 「화면에 본 것과 PDF 가 다르다」가 원천적으로 생기지 않는다.

약관은 본문을 통째로 복사하지 말고 `{id, version, contentHash}` 만 박는다.
본문은 버전별로 한 벌만 두고, 해시로 그때 그 본문임을 증명한다.

## 7. Revision — 새로 만드는 것 ③

발송한 계약은 고치지 않는다. **새 회차를 만든다.**

```
FP-202608-001-R1   보냄 → 고객 열람 → 조건 변경 필요
FP-202608-001-R2   새 Snapshot · 새 서명 토큰 · 이전 회차는 「대체됨」
```

이전 회차의 Snapshot·서명·감사기록은 남는다. 지우면 분쟁 때 댈 것이 없다.

## 8. 구현 순서

각 단계는 **그 단계까지만으로도 쓸 수 있어야** 한다. 반쯤 만든 채 다음으로 넘어가지 않는다.

| # | 무엇 | 왜 이 순서인가 | 실물 필요 |
|---|---|---|---|
| 1 | 발송센터 화면 골격 (상단 3버튼 · 상태 탭 · 6값 행) | 엑셀이 없어도 ERP 계약으로 바로 쓸 수 있다 | — |
| 2 | 계약서관리 분리 (생성 / 완료 보관) | 지시 2·3. 화면 정리가 먼저라야 뒤가 안 엉킨다 | — |
| 3 | Contract Snapshot 봉인 | Adapter 가 만들 결과를 담을 그릇 | — |
| 4 | Excel Adapter 뼈대 + 검증 3등급 | 그릇이 있어야 부을 수 있다 | — |
| 5 | 손오공 개인/개인사업자 Adapter | **엑셀 실물 필요** | ★ |
| 6 | 모바일 계약 확인 6 Step | 지금 `esign-consent-doc` 를 단계로 나눔 | — |
| 7 | 완료 PDF (Snapshot 기준) | 서명이 끝나야 만들 것이 생긴다 | — |
| 8 | Revision | 운영에서 «고쳐야 할 일»이 생긴 뒤에 필요해진다 | — |

2차 — 추가 공급사 Adapter · CMS 분리 · 차량 인수증 · 자동 재촉 · 대량 발송.

## 9. 손대면 안 되는 것

- **서명 엔진을 fp4 에 만들지 않는다.** 서명·본인확인·해시봉인은 착한거래 몫이다.
- **계약서 서식 원본은 프리패스다.** 착한거래가 사본을 가져갔다.
  갈리면 sim 이 거짓 초록불을 켠다 — `check:template-drift` 를 손대지 마라.
  계약서 «규격»은 `rental-contract.html`(140필드) 하나다. 새 규격을 만들지 마라.
- **PDF 를 원본으로 삼지 않는다.** Snapshot 이 원본이고 PDF 는 그것의 그림이다.
- **약관을 고치지 않는다.** 새 버전을 만든다. 체결된 계약은 그때 버전을 계속 본다.
- **A4 를 모바일에 축소하지 않는다.** 모바일은 모바일 UI 로 다시 짠다.
- **ERP 계약 등록을 전자계약의 선행조건으로 만들지 않는다.** 전자계약에서 바로 계약이 나야 한다.
- **엑셀 전체를 복제하지 않는다.** 직원이 «입력한» 원자만 뽑는다. 서식·수식·안내문은 버린다.
- 실계약과 시험 계약은 `is_test` 로 가른다(이미 있음). 시험이 실계약 목록에 새면 안 된다.

## 10. 지금 막힌 것

| 무엇 | 왜 막혔나 | 필요한 것 |
|---|---|---|
| 손오공 Excel Adapter | 실물 계약서가 리포에 없다 | 값이 채워진 엑셀 3부 |
| 약관 버전 | `esign-agreement-text` 에 버전 필드가 없다 | 현재 본문을 v1.0 으로 박고 시작 |
| Snapshot 저장 위치 | RTDB 규칙에 `v4/esign_snapshots` 가 없다 | 규칙 추가 후 콘솔 게시(사람이) |
| 서명 토큰 재사용 방지 | 착한거래 쪽 규칙 — fp4 에서 확인 불가 | 착한거래 리포에서 확인 |

## 11. 검사 (구현하며 같이 만든다)

```
sim-esign-excel-import   엑셀 3부 → 원자 → 검증등급. 값이 하나라도 어긋나면 실패
sim-esign-snapshot       발송 후 원본을 바꿔도 Snapshot 이 안 변하는가
sim-esign-revision       R1 → R2 후 R1 의 서명·감사기록이 남아 있는가
check:template-drift     두 리포 서식 동일 (이미 있음 — 끄지 마라)
```

엑셀 검사는 **실물 파일을 리포에 넣지 않는다.** 개인정보가 들어 있다.
값을 지운 «구조만 남긴» 샘플을 따로 만들어 검사에 쓴다.
