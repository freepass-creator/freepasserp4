# 설계 — 차종코드 파이프라인

기준일 2026-08-15 · 작성 Claude Code(설계) · 구현 Cursor · 검증 Codex
전제: 사장님이 「ERP4 차종마스터 원천대장」을 다지는 중이다.

---

## 0. 한 문장

**차번에 차종코드를 한 번 박고, 나머지는 전부 1:1로 당겨온다.**

> 사장님 2026-08-15 —
> 「차량번호랑 차종마스터 코드를 생성하는 게 관건이네. 나머지는 1/1로 댕겨오면 되는 거니까」
> 「새로운 차량번호 생겼을 때 니가 어떤 매물인지만 박아주면 되잖아 … 그럼 그 코드에
> 연동된 거를 나중에 이알피가 적용하면 되고」

지금 구조의 모든 오류는 **같은 판단을 반복해서** 생긴다. 발행할 때마다 차명을 다시
알아맞히고, 알아맞히는 한 언젠가 틀린다. 실제로 하루에 셋이 났다 —
배터리 용량이 배기량으로(77,400) · 파워트레인 44대 뒤집힘 · 세대 오판 27대.

판단을 **차번당 한 번**으로 줄이면 그 오류들이 생길 자리 자체가 없어진다.

## 1. 층 구조

```
[외부시트]   아이카 · 아이언(홈페이지) · 이안카 · 오플      ← 자체 규격을 쓰는 네 곳뿐이다
     │  ① 1차 정제 — 우리 규격으로 옮긴다(공급사마다 한 장)
     ↓
[제공시트]   「<공급사> 프리패스 재고」 — 공급사가 직접 채운다
     │       내부시트 공급사(14곳)는 여기서 시작한다. 이미 우리 규격이다
     │  ② 2차 모으기 — 공급사를 탭으로, 규격 하나로
     ↓
[정제시트]   「프리패스 차량정제」  ★차번 ↔ 차종코드가 여기 산다
     │       판단은 여기서만 한다. 나머지 칸은 코드에서 나온다
     ↓
[판매시트]   문서 **하나만** 당겨간다
     ↓
[ERP]        차량 레코드에 차종코드 한 칸. 조인해서 꺼내 쓴다
```

### 층마다 누가 만지나

| 층 | 만지는 사람 | 들어 있는 것 |
|---|---|---|
| 제공시트 | **공급사** | 상태 · 대여료 · 차명 원문 · 정책 |
| 정제시트 | **우리(나)** | 차종코드 + 코드에서 나온 차종 값 |
| 판매시트 | 아무도 (기계가 찍는다) | 영업자가 보는 표 |
| ERP | 앱 | 차종코드로 조인 |

**만지는 사람이 층마다 갈린다.** 그래서 서로 덮을 일이 없다. 이게 이 설계의 핵심이다.

## 2. 정본 규칙

### 2-1. 칸마다 누가 정본인가 — `columnOwner`

```
live  매번 공급사를 따라간다   상태·배차상태 · 기간 대여료 전부 · 단기/장기보증 · 주행거리
ours  우리가 정한다            차종코드 + 정제칸 11 · 정책코드
once  처음 한 번만 옮겨 온다    차명(트림)·연식·색·옵션·차량가격·최초등록일 …
```

공급사 시트에서 실제로 살아 움직이는 값은 **상태와 돈뿐**이다. 차종·색·연식은 그 차가
폐차될 때까지 안 바뀐다. 한 번 옮기면 우리 기록이고, 매번 다시 읽을 이유가 없다.
**다시 읽지 않으면 다시 틀리지도 않는다.**

⚠ 기간 대여료는 「기타기간①」처럼 제목을 바꿔 쓰므로 **이름에 「개월」이 들면 live**.

### 2-2. 차종은 코드가 정본

정제칸 12개 중 **맨 앞 「차종코드」만 사람이 정한다.** 나머지 11개는 그 코드가 가리키는
마스터 줄에서 나온 **표시값**이다. 값이 어긋나면 **코드가 이긴다** — 표시칸을 고치면
다음 채우기 때 덮인다. 고치려면 코드를 고쳐야 한다.

### 2-3. 코드는 영원하다

`docs/VEHICLE_MASTER_KEY_CONTRACT.md`(Codex 작성)가 보장한다.
코드를 지우지 않고 「제외」로 남기고, 순번을 재사용하지 않고, 뜻이 바뀌면 새 코드를 만든다.
`npm run audit:vehicle-trim-keys` 가 위반이면 실패한다.

**그래서 ERP가 차종코드를 저장해도 안전하다.** 이 계약이 깨지면 저장된 코드가 다른 차를
가리키므로, 계약 감사를 CI 에 걸어 두는 것이 ERP 연동의 전제조건이다.

## 4. 구현 항목

### A. 정제시트를 채우고 유지한다

- `build-refine-sheet.mts` — 이미 있다. 제공시트 → 정제시트(공급사=탭). **다시 돌려도
  안전해야 한다**(있는 코드·정제값을 가져온다).
- **[신규] 정책도 모은다.** 지금 정책은 제공시트마다 「정책」 탭에 있다. 정제시트에
  「정책」 탭 하나를 두고 `공급사 · 정책코드 · 정책명 · 43항목` 을 행으로 모은다.
  그래야 발행기가 진짜로 문서 하나만 읽는다.
- **[신규] 증분 갱신.** 통째로 다시 쓰지 말고 ①새 차번 추가 ②live 칸 갱신
  ③ours 칸은 안 건드림. 통째로 덮으면 사람이 박은 코드가 날아간다.

### B. 발행기 입력을 정제시트로 돌린다

- `publish-origin-tab.mts` 가 정제시트를 읽게 한다.
- ⚠ **한 번에 바꾸지 마라.** 두 경로를 나란히 돌려 `--dump` 로 전후를 견주고,
  **값이 사라진 칸 0 · 돈 어긋난 칸 0** 을 확인한 뒤 갈아탄다.
  (2026-08-14 에 이 대조로 파워트레인 44대 뒤집힘을 잡았다. 눈으로는 안 보였다.)

### C. 제공시트에서 정제칸을 걷어낸다 — **B 가 끝난 뒤에**

- 정제값이 두 곳에 있으면 반드시 갈린다. 정제시트가 정본이 되면 제공시트 정제칸은 폐지한다.
- 공급사가 보는 화면이 단순해지는 부수 효과가 있다(그들은 상태·대여료·정책만 채운다).
- ⚠ 걷어내기 전에 정제시트에 **그 값이 다 옮겨졌는지** 차번 단위로 대조한다.

### D. 새 차가 들어오는 길

```
매일  동기화 → 정제시트에 새 차번이 줄로 뜬다(코드 빈칸)
     → 「코드 없는 차 N대」가 보고된다
     → 내가 박는다 → 끝
```

- 지금 N = 283 (541 중 258 박힘). 초기 적재라 큰 것이고, 넘기면 하루 몇 대다.
- 보고 자리: 발행기 요약과 `audit-vehicle-spec`. **화면 밖에 두면 잊힌다.**

### E. ERP 연동

- 차량 레코드에 `vehicle_trim_key` 한 칸.
- 표시값은 저장하지 말고 **조인해서 꺼낸다.** 저장하면 마스터가 좋아져도 안 따라온다.
- 코드가 없는 차는 지금처럼 원문으로 두되 **「코드 없음」이 보이게** 한다.

## 8. 이행 순서

**순서를 바꾸면 값이 날아간다.**

```
① 마스터 다지기          ← 사장님. 없는 차종을 넣는다
② 코드 마저 박기          ← 나. 마스터가 열린 만큼
③ 정제시트에 정책 모으기   ← 구현
④ 정제시트 증분 갱신       ← 구현. 통째 덮기 금지
⑤ 발행기를 정제시트로      ← 구현. 두 경로 나란히 돌려 대조한 뒤 갈아탄다
⑥ 제공시트 정제칸 폐지     ← ⑤ 확인 뒤에만
⑦ ERP 에 차종코드         ← 계약 감사를 CI 에 건 뒤에
```

⚠ ①과 ②는 반복이다. 마스터가 좋아질 때마다 ②를 다시 돌리면 그만큼 채워진다.
