# 공급사 표준 재고 규격 — 우리 규격으로 뒤집기

2026-08-04 · Claude · 방향 제안 + 근거

지금은 **공급사 16곳의 시트 규격에 우리가 맞춘다.** 그걸 뒤집어 **우리 규격을 주고 채우게 한다.**

---

## 1. 왜 뒤집어야 하나 — 사고가 전부 여기서 났다

유입에서 터진 것들을 모아 보면 **하나도 빠짐없이 규격 불일치**다.

| 사고 | 원인 |
|---|---|
| 유입 2,193대 (실제 400대) | 배차중·이미 나간 차가 판매중으로 섞임 — 상태 열 의미가 공급사마다 다름 |
| 손오공·웰릭스 **0대** | 헤더가 3행에 있음. 1행을 헤더로 읽어 전부 무효 |
| 오토플러스 18대 (실제 107대) | 배너가 1행을 차지 |
| 아이카 1,875대 | 종합시트 24탭을 한 공급사로 읽음 |
| 빌린카 21/45대 | 재고가 3탭에 쪼개져 1탭만 읽힘 |
| 보증금 조작 | `"12개월 : 1개월치 / 24개월 : 2개월치"` 규칙 **문장**을 파싱해야 했음 |
| 상태 오판 | `차량상태`(물리 컨디션) vs `배차상태`(판매 가능) 구분 필요 |

이걸 막으려고 지금 코드가 이만큼이다 — 헤더 자동탐지, 공급사별 매핑 프로파일,
상태 열 우선순위, 배너 스킵, 탭 열거, 가격 열 이중 세트 파싱, 보증금 규칙 해석.
**규격을 우리가 쥐면 이 전부가 필요 없어진다.**

## 2. 진짜 장벽은 기술이 아니다 — 이중입력

공급사 시트는 우리를 위한 피드가 아니라 **그 회사의 내부 원장**이다.
「우리 양식에 또 채워 달라」고 하면 처음 한 달만 하고 만다. 그러면 재고가 늙고,
우리는 두 곳을 다 봐야 해서 지금보다 나빠진다.

**성립 조건은 하나다 — 추가가 아니라 «대체»가 되어야 한다.**

그래서 이 방향은 「양식을 배포한다」가 아니라 이렇게 가야 한다.

```
우리가 공급사별 「프리패스 재고 시트」를 만들어 준다   ← 우리 소유, 편집 권한만 공유
       ↑ 규격은 우리가 정의 → 읽기가 단순해진다
       ↓ 우리가 쓰기도 한다 → 미게시 사유·판매 결과가 같은 시트로 돌아온다
공급사는 시트 하나만 본다
```

**이건 `SHEET_WRITEBACK_PLAN.md` 의 인프라와 정확히 같은 것이다.**
「우리 소유 시트 + 공급사 공유 + 양방향」 — 회신 기능을 만들면 표준 규격이 따라온다.
따로 짓는 게 아니라 **순서만 다르다.**

공급사 입장의 유인도 거기서 나온다 — 「여기 채우면 왜 안 올라갔는지가 바로 보인다」.
지금은 전화해서 물어봐야 안다.

## 3. 규격 초안

현재 유입이 실제로 먹는 필드(`IMPORT_FIELDS`)에서 뽑았다. 없는 걸 새로 만들지 않았다.

### 필수 4 — 이게 없으면 상품이 안 된다

| 열 | 예 | 규칙 |
|---|---|---|
| `차량번호` | `125호6254` | 실번호판. 신차 미발급이면 **비워 둔다**(우리가 임시번호 부여) |
| `제조사` | `기아` | |
| `모델` | `K8` | |
| `상태` | `출고가능` | **`출고가능` / `출고불가` 둘뿐.** 사유는 메모에 |

> `상태`를 두 값으로 못 박는 게 핵심이다. 지금 「판매중·할인판매·가능·빈값·배차대기·보류·
> 대차·회수」가 뒤섞여 있고 그 해석이 사고의 절반이었다.

### 가격 — 여기가 제일 중요하다

| 열 | 예 |
|---|---|
| `보증금` | `1000000` |
| `12개월` `24개월` `36개월` `48개월` `60개월` | `710000` |

세 가지를 못 박는다.

1. **숫자만.** `71만`·`710,000원`·`71` 금지. 만원 단위 이중환산 사고의 근원이다.
2. **보증금은 숫자 한 칸.** 「1년 1개월치」 같은 규칙 문장 금지 — 계산해서 넣는다.
3. **인수형/반납형이 다르면 «행을 나눈다».** 열을 두 벌 만들지 않는다.
   지금 손오공·웰릭스가 `보증금|12~60개월|보증금|12~60개월` 구조라 파싱이 가장 복잡한 곳이다.
   같은 차 두 행 + `구분` 열이면 코드가 그냥 사라진다.

### 권장 — 있으면 매물 품질이 올라간다

`세부모델` `트림` `연식` `연료` `주행거리` `외장색` `내장색` `인승` `변속기` `배기량` `옵션` `메모` `사진링크`

### 시트 구조 규칙 4개

```
1. 헤더는 1행.            (3행 헤더·배너가 손오공·웰릭스·오토플러스를 0대로 만들었다)
2. 한 탭에 다 넣는다.     (빌린카 3탭 중 1탭만 읽혀 24대가 사라졌다)
3. 한 행 = 한 차 = 한 상품.
4. 한 시트 = 한 공급사.   (아이카 종합시트 24탭이 남의 재고를 아이카로 만들었다)
```

## 4. 전환 순서 — 강제하지 않는다

전면 전환은 실패한다. 재고를 매일 갱신하는 곳에서 시트는 곧 업무 도구다.

```
1단계  신규 공급사는 무조건 표준 시트     ← 온보딩이 즉시 끝난다(매핑 작업 0)
2단계  사고 잦은 곳부터 전환 제안         ← 아이카 종합시트·오토플러스 배너·손오공 이중 가격열
3단계  회신 기능이 붙으면 유인이 생긴다   ← 「표준 시트에 넣으면 미게시 사유가 돌아온다」
4단계  기존 매핑 코드는 그대로 둔다       ← 전환 안 하는 곳이 남는다. 지우지 않는다
```

**웹연동(아이언)과는 다른 축이다.** 웹연동은 시트를 아예 안 쓰는 곳,
표준 시트는 시트를 쓰되 규격이 제각각인 곳이다. 둘 다 필요하다.
