## 3. ★특히 의심할 것 (Claude 가 스스로 아는 위험)

**이걸 다 확인했다고 믿지 마라. Claude 가 «괜찮다고 판단한» 것들이고, 그 판단이 검증 대상이다.**

### A. 이름을 대량으로 바꿨다 — 되돌릴 수 있나
- 「AI 정제」 186줄은 **차종마스터·시트에 있던 이름을 전부 훑어** 만든 규칙이다.
  마스터에서 지운 차종이 이 사전 때문에 되살아나거나, 엉뚱한 이름이 겹쳐 덮이지 않나?
- 코드를 떼면 **세대가 겹치는 이름이 64가지**다(「그랜저 GN7」·「그랜저 IG」 → 둘 다 「그랜저」).
  Claude 는 「이름은 딱지이고 세대는 연식이 가른다」고 판단해 **그대로 합쳤다.**
  → 이 판단이 **검색·필터·중복판정·계약서·차종코드 매칭**을 깨지 않나? 특히:
  - `product-duplicate*` · `fold-duplicate-products` 가 이름으로 같은 차를 접지 않나?
  - `pickConfirmedMasterCode` 가 이름으로 마스터를 찾는데, 이름이 합쳐져 **후보가 둘**이 되지 않나?
  - 계약서·견적서가 `sub_model` 을 쓰는 곳이 있나?

### B. ERP 일괄 수정 4,390대 — 원본이 사라졌다
- `normalize-erp-submodel-codes.mts` 는 **백업을 안 남긴다.** 되돌리려면 시트에서 다시 동기해야 하는데
  `EXT_*`(옛 웹 등록분)은 시트에 없다. → **복구 불가 아닌가?** 몇 대가 그런가?

### C. 「차명」 → 「차명(원문)」 이름 변경
- 옛 이름 「차명」을 `SALES_RETIRED_COLUMNS` 에 넣었다. **다른 곳에서 「차명」 열을 읽던 코드**가 남아 있지 않나?
  (`sales-sheet-clean` · `sales-published-tabs` · `publish-sonogong-tab` · 손오공/오플 갈래 탭 · 미러 시트 매핑)
- `HEADER_ALIASES` 에 `'차명(원문)': 'supplier_vehicle_name'` 을 넣었는데,
  `autoMapHeaders` 는 **부분일치**도 한다(`aliasKeys.find((a) => norm(t).includes(norm(a)))`).
  「차명(원문)」이 **다른 시트에서 `차명`→`model` 로 잘못 잡히지** 않나? 반대로 「차명(세부모델+트림)」이
  「차명(원문)」으로 잘못 잡히지 않나? **21곳 공급사 시트 헤더 전부**에 대해 확인하라.

### D. 마스터 스냅 제거 — 정말 안 쓰였나
- `ironrentcar-source` 에서 `snapToMaster` 를 없애면 `product.sub_model` 이 안 채워진다.
  Claude 는 「미러 시트 왼쪽에만 실리므로 무해」라고 판단했다. → `app/api/inventory/ironrentcar/apply/route.ts` 가
  **ERP 에 직접 쓰지 않나?** 쓴다면 sub_model 이 빈 채로 들어가 기존 값을 지우지 않나?
  (`soft-merge` 가 빈 값을 무시한다는 가정이 이 경로에도 성립하나?)
- `catalog_id`·`_snap_confidence` 도 같이 사라졌다. 쓰는 곳이 정말 없나?

### E. 검사 자체가 거짓 초록 아닌가
- `check-sales-axes` 는 **선언과 코드**만 대조한다. 선언이 틀리면 둘 다 틀린 채로 초록이다.

  → 그 설명이 맞나, 아니면 **떨어진 걸 숨긴 것**인가? 실제로 08-22 대비 무엇이 줄었는지 확인하라.

### F. 자기참조 오염 — 정말 막혔나
- `build-vehicle-catalog --write-tab` 이 파생분을 「차종사전」 탭에 쓰고, 다음 실행에서 그걸 다시 읽는다.
  「출처=손추가」인 줄만 읽도록 막았다는데, **사람이 출처 칸을 비우고 줄을 더하면** 어떻게 되나?
  (실제로 212줄이 손추가로 둔갑한 사고가 한 번 났다)

### G. 사장님 요구와 어긋난 곳
- 「**필수입력은 차량번호야 모델명**」 — `entities` 에 `required: true` 를 달아 놓고 **저장 경로가 그걸 안 봐서
  실제로는 안 막히던 것**을 2026-08-23 에 고쳤다(`useInventoryEditorLifecycle.save` 가 선언을 강제).
  → **그 수정 자체를 검증하라**: `required` 가 달린 필드가 지금 몇 개인가(차량번호·모델명 둘뿐인가)?
    OCR·엑셀·시트 유입으로 만들어지는 상품이 이 게이트에 걸려 **저장이 막히지 않나**?
