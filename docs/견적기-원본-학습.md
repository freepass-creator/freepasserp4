## 3. 무엇이 어느 기둥에 있나 — ★가장 자주 틀리는 것

### 손오공 견적 (`App.vue`)

**좌 `.vside`(400)** — 차 고르기와 그 차의 «사실»이 전부 여기 박혀 있다. **모달이 아니다.**
1. 상품 — 세그 3층(`seg-t1/t2/t3`)
2. (신차) 제조사 → 모델 → 트림 · 신용등급 ※**중고 차량정보에도 신용등급이 있다**(`App.vue:589`)
3. (구독) **매물 링크 불러오기** — 엔카·케이카·오토플러스·오토핸즈·헤이딜러
4. **차종 검색**(`.srch`) — 결과가 그 자리에 목록으로 뜬다
5. **캐스케이드**(`.cascade`) — 제조사 → 모델 → 세부모델 (훑어서 고르는 길)
6. **차량 정보** — 차를 고르기 전엔 잠겨 있다(`.vinfo-lock` 「차종을 먼저 선택하면 **금액 입력**이 열립니다」)
   → 연식 · 차량가격 · 주행거리 · 배기량 · 연료 · 사고 이력

**우 `.main`** — 조건과 결과.
1. `.mhead` 차종명 + 차량가
2. **`.condbar`** — 손님 · 담당자 · 담당연락처 / **수수료 · 보증금 · 선납**
   ★조건은 좌 사이드바가 **아니라 여기** 있다
3. `.qsec` 「기본 견적」 → `.qcols`(기간 열, `repeat(4,1fr)`, 열 사이 `border-left`)
4. `.qsec.send` 「손님 발송용 견적」 — 발송할 약정만 체크

**모달로 띄우는 것** — 견적 바구니(`.cart-panel`) · 견적서 미리보기(`.qm`) · 공지(`.nt`) · 확보 차량 조회.

★규칙은 「**일반 차량 입력은 좌 기둥 인라인**」이다. 「모달은 결과물에만」은 **너무 넓게 적은 것**이었다
  (2026-09-07 코덱스 지적) — 웰릭스 «표준 견적» 모달(`StandardPriceTable.vue`) 안에서는
  제조사·모델을 고르고 트림 카드를 **다중 선택**한다. 그건 «한 대 견적»이 아니라 «여러 대 가격표»라
  성격이 다르다. 우리 `CarPicker` 가 인라인이어야 하는 근거는 그대로다.

|---|---|---|
| 왼쪽 | 신차 카탈로그 — 제조사→모델→세부모델→트림, 옵션·색상·탁송·선팅·용품·보험 | **중고** — 상품(중고/신차·렌트/구독·반납/인수) · 신용 · 차종 · **시세·연식·주행·배기량·매입할인** · 연도별 잔가 |
| 오른쪽 | 계약 접수 + 채팅 | **원가·손익**(기간 탭 + 매출→감가·이자·직접비·손바뀜→매출총이익→수수료→영업이익) |

그 밖은 원본을 **고치지 않는다.**

### ㉡ CSS 는 원본을 «한 글자도 안 고치고» 가둔 것

`components/estimate/welrix.css` = 원본 `<style>` 넷 + 두 SFC 의 `<style scoped>` 를
**선택자 앞에 `.wx-root` 만 붙여** 옮긴 것이다(`body`·`html`·`:root` → `.wx-root` · `*` → `.wx-root *`).

- 생성기 = `scripts/extract-welrix-css.py`. **손으로 고치지 마라** — 원본이 바뀌면 다시 돌린다.
- 왜 가두나 — 견적은 ERP «안»의 페이지다. 원본의 전역 리셋(`*`·`body`·`select`)이 그대로 풀리면
  **ERP 전체가 웰릭스 톤으로 물든다.** 검사가 「전역 리셋이 샜는지」를 본다.
- 우리 사정으로 덮는 것은 파일 맨 아래 **「프리패스 덧칠」**에만 적는다(생성기 안에 있다):
  ㉠ 높이 = `calc(100vh - var(--topbar-h))` — ERP 상단바 밑에 서니까
  ㉡ **웰릭스 CI 레드(#e1141e) → 프리패스 남색(#1B2A4A)** — 남의 간판을 달 수 없다(노브랜드 규칙)
  ㉢ 피커가 쓰는 토큰 넷(`--surface`·`--surface-2`·`--on`·`--accent-line`) — 웰릭스 토큰표에 없다
  ㉣ 중고 입력칸(`.vfields`) — 원본은 신차라 DB 가 다 채워 **입력칸이 아예 없었다**
  ㉤ 손익 줄(`.pnl-row`) — 원본 셋째 칸에는 없던 것
  ㉥ **폰(≤1024)** — 원본은 폰을 `mobile.html` 로 보내 버려 이 폭에서 기둥 셋이 제자리를 못 잡는다
     (칸마다 `height:100%+overflow:auto` 라 뒤 칸이 통째로 잘린다 · 2026-09-07 실측).
     우리는 폰에서도 같은 페이지를 쓰므로 세로로 이어 붙이고 총액 띠를 ERP 하단 홈바 위로 올린다.

### ㉢ 옵션·색상은 «왼쪽 별도 칸»이다 (2026-09-08)

> 사장님 「그리고 **신차는 옵션이 나오는데**」 → 「**1번으로**」
> (①옵션·색상을 원본처럼 왼쪽 별도 칸으로 / ②차종 칸 안에 두기 / ③조합규칙부터 — 중 ①)

원본 왼쪽 차례 = 차종 캐스케이드 → **`#sec-options`(선택 옵션)** → **`#sec-color`(색상)** → 부대.
그 전에는 옵션이 **차 고르기 시트 «안»**에 있었다. 밖으로 꺼내 같은 자리에 세웠다.

- 시트는 **트림까지만** 묻는다(`CarPicker optionsOutside`). ⚠ 두 군데서 고르면 어느 값이 이겼는지 모른다.
- 그래서 시트가 돌려주는 `price` 는 «옵션 뺀 트림값»이고, **옵션 합산은 화면이 한다**(`listPrice`).
- 트림이 바뀌면 고른 옵션·색을 **비운다** — 안 비우면 딴 차 옵션값이 남아 차량가가 조용히 틀어진다.
- 옵션 줄 짜임은 원본 `OptionsList.vue` 그대로(`.option-row` · `.o-info` · `.o-price`).

⚠⚠ **색상은 값에 영향이 없다.** 원본은 제조사 색상표(유료색·투톤 +50만)를 들고 있어 차량가에 더하지만,
  **우리 신차마스터에는 색상별 가격이 없다.** 없는 값을 지어내느니 「고른 것을 적어만 둔다」로 뒀다
  (견적서 표기용). 색 이름·색칩은 **색상마스터**(`lib/domain/color-master`) 규격색 12색에서 당긴다 —
  화면이 색을 지어내지 않는다(로컬 색맵 금지). 색상 가격이 생기면 그때 값에 얹는다.

⚠⚠ **옵션 조합규칙은 아직 «글»이라 못 막는다.** 원본은 「선행 필수」·「배타 그룹」·「이미 포함」을
  기계가 잠근다. 우리 `rules` 는 제조사 가격표에서 뽑은 **문장**이라 화면이 보여만 준다.
  ⇒ **지금은 고를 수 없는 조합도 골리고, 그 값으로 견적이 나온다.** 원본을 따라가려면 여기가 다음 일감이다.

### ㉣ 왼쪽은 «라벨 + 한 줄» 이다 — 카드로 쌓지 않는다 (2026-09-08)

> 사장님 「차량 선택하는 거는 **저렇게 굵을 필요 없고**」 · 「**버튼만** 만들어 주면 되고」
> 「차량 고르는 거는 **딱딱 누르는 거에 연동**이 되어야지」

원본 웰릭스 왼쪽은 **전부 한 줄짜리 컨트롤(32px)** 이다. 카드도, 검색 판도 없다.

```
제조사 ▾   모델 ▾   세부/연료 ▾   트림 ▾        ← 위를 바꾸면 아래가 비워진다
```

- 차종은 `features/estimate/VehicleCascade.tsx` — 원본 `VehicleCascade.vue` 를 옮긴 것이다.
  칸 이름(`#sec-manufacturer`·`#sec-model`·`#sec-variant`·`#sec-trim`)은 **원본 것 그대로** 써야 한다 —
  웰릭스 CSS 가 그 이름에 「라벨 96 + 한 줄」 짜임을 걸어 두었다.
- 상품·채널·만기·신용도 같은 줄이다(카드 아홉 → 한 줄 넷).
- 트림까지 고르면 **그 자리에서** 반영한다. 「확인」 단추를 두지 않는다(원본과 같다).

⚠⚠ **9/7 규격이 뒤집혔다.** 그날은 「웹은 차 고르기 판을 좌 기둥에 통째로 펼친다」였다.
  펼쳐 보니 검색칸·제조사 칩·목록이 왼쪽을 다 먹어, 정작 조건 칸들이 저 아래로 밀렸다.
  ★그렇다고 9/7 「왜 패널이 새로 뜨니」와 부딪히는 게 아니다 — 그건 «왼쪽에서 다 고르고 나서 또»
    뜬 것을 두고 하신 말이고, 지금은 **왼쪽에서 고르고 끝난다.** 뜨는 판이 없다.
  검색(`CarPicker`)은 **폰 하단 「검색」 탭**에만 남는다 — 이름을 알 때 한 번에 가는 길이다.

### ㉤ 머리는 «두 화면이 같은 것»을 쓴다 (2026-09-08)

> 사장님 「원가설정에는 왜 **밑줄**이 가져 있지?」 · 「**견적내기 / 원가설정** 이거 잘 정렬해 주고」

- **원가 화면도 같은 머리 띠**(`.global-topbar`)를 쓴다 — `app/estimate/cost/page.tsx` 가
  `.wx-root.cost` 로 감싸고, 그 안에서만 제 몸통(`est-root cost` · 설정 34칸 4단)을 쓴다.
  ★「동일하게」는 **머리·색·글꼴·토글**이다. 몸통까지 400/52/20 으로 밀면 설정 칸이 안 들어간다.

### ㉥ 고르는 일에는 모달을 안 쓴다

원본 둘 다 좌 400 에 차종검색·캐스케이드·차량정보가 **박혀** 있다.

⇒ 웹은 `CarPicker inline`(좌 기둥 안), 폰은 시트. 「차종 고르기」 버튼은 **폰에서만** 선다.

  성격이 다르다(2026-09-07 코덱스 지적으로 범위를 좁혔다).

### ㉦ 1년 ~ 5년은 «줄»이고, 원가는 그 줄 «안»에 있다 (2026-09-08)

> 사장님 「차량 선택하고 **우측에서 1년부터 5년까지 설계**되게끔 해주고
> 각 기간별로 **수익이나 원가 볼 수 있게끔 그 라인에 표현**해주면 돼. **우측에 따로 놓지 말고**」

```
[✓] 4년  670,000원/월   보증금 10%   선납 0%   만기인수 1,539만   매출 2,923만   원가 2,657만   영업이익 266만 9.1%
     └ 누르면 그 자리에서 : 감가 · 이자 · 직접운영비 · 손바뀜 · 매출총이익 · 수수료 · 영업이익
```

- **기둥은 둘**이다 — 좌 400(차량 선택) : 우 나머지(조건 + 다섯 줄). 셋째 칸을 두지 않는다.
- 보증금·선납은 **줄마다** 잡는다(그게 「설계」다). 위 조건 칸은 다섯 줄을 **한꺼번에** 바꾸는 손잡이다.
- 체크한 줄만 손님 견적서로 나간다(원본 「견적서에 포함」).
- 원가 칸은 **총원가**(매출원가 + 판관비)다 — 그래야 줄에서 「매출 − 원가 = 영업이익」이 눈으로 맞는다.
  ⚠ 매출원가만 넣으면 수수료가 빠져 뺄셈이 안 맞는다(2026-09-08 정지 그림에서 잡았다).
- 한 줄에서 **단위를 섞지 않는다** — 월 대여료만 「원」, 나머지 금액은 「만원」.

⚠⚠ **이 절이 앞의 셋을 대신한다.** 2026-09-07 까지는 「기본 견적(고정 3장)」 · 「손님 발송용(자유 3열)」 ·
  「오른쪽 손익(기간 탭)」 셋이 따로 있었다. 같은 숫자를 세 군데서 세니 어디를 봐야 하는지가 흐려졌고,
  무엇보다 **다섯 해를 나란히 견줄 수가 없었다**(4년이 왜 이 값인지 보려고 탭을 옮겨 다녀야 했다).

### ㉩ «임시 공개» — 로그인 없이 열려 있다 (2026-09-08)
