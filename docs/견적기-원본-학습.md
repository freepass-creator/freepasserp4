★★**손오공 `src/style.css` 머리말이 이렇게 시작한다** —

## 3. 무엇이 어느 기둥에 있나 — ★가장 자주 틀리는 것

### 손오공 견적 (`App.vue`)

**좌 `.vside`(400)** — 차 고르기와 그 차의 «사실»이 전부 여기 박혀 있다. **모달이 아니다.**
1. 상품 — 세그 3층(`seg-t1/t2/t3`)
2. (신차) 제조사 → 모델 → 트림 · 신용등급 ※**중고 차량정보에도 신용등급이 있다**(`App.vue:589`)
3. (구독) **매물 링크 불러오기** — 엔카·케이카·오토플러스·오토핸즈·헤이딜러
4. **차종 검색**(`.srch`) — 결과가 그 자리에 목록으로 뜬다
5. **캐스케이드**(`.cascade`) — 제조사 → 모델 → 세부모델 (훑어서 고르는 길)
6. **차량 정보** — 차를 고르기 전엔 잠겨 있다(`.vinfo-lock` 「차종을 먼저 선택하면 **금액 입력**이 열립니다」)
   → 연식 · 차량가격 · 주행거리 · 배기량 · 연료 · 사고 이력

**우 `.main`** — 조건과 결과.
1. `.mhead` 차종명 + 차량가
2. **`.condbar`** — 손님 · 담당자 · 담당연락처 / **수수료 · 보증금 · 선납**
   ★조건은 좌 사이드바가 **아니라 여기** 있다
3. `.qsec` 「기본 견적」 → `.qcols`(기간 열, `repeat(4,1fr)`, 열 사이 `border-left`)
4. `.qsec.send` 「손님 발송용 견적」 — 발송할 약정만 체크

**모달로 띄우는 것** — 견적 바구니(`.cart-panel`) · 견적서 미리보기(`.qm`) · 공지(`.nt`) · 확보 차량 조회.

★규칙은 「**일반 차량 입력은 좌 기둥 인라인**」이다. 「모달은 결과물에만」은 **너무 넓게 적은 것**이었다
  (2026-09-07 코덱스 지적) — 웰릭스 «표준 견적» 모달(`StandardPriceTable.vue`) 안에서는
  제조사·모델을 고르고 트림 카드를 **다중 선택**한다. 그건 «한 대 견적»이 아니라 «여러 대 가격표»라
  성격이 다르다. 우리 `CarPicker` 가 인라인이어야 하는 근거는 그대로다.

### ㉠ 기둥은 «1 : 1 : 1 : 1» — 공통규격이 원본보다 먼저다

```
정본  components/WorkPage.tsx  — 목록 `flex:1 1 0` · 패널 `flex:${paneRatio} 1 0` · 기본 ratio 1
      (defaultPaneRatio = panes.length === 1 ? 3 : 1)

견적  c1 차량(+인라인 피커) │ c2 조건·잔가·원가기준 │ c3 손익표 **(두 칸)**
원가  c1 지금 보는 조합    │ c2 Ⅰ 직접비      │ c3 Ⅱ 판관비·Ⅲ 영업외 │ c4 Ⅳ 이익과 잔가
```

⚠ 원본은 손오공 `400px 1fr` · 웰릭스 `400px 52fr 20fr`(단순 견적 모드는 `28fr 72fr`)이지만
  **칸의 «넓이»는 우리 공통규격을 쓴다.** 원본에서 배우는 것은 «무엇이 어느 칸에 있나»다.
  안 그러면 화면마다 기둥 폭이 달라져 「같은 건물인데 문짝이 다른」 꼴이 된다.

- 기둥마다 **제 안에서 스크롤**(`overflow-y:auto`)하고 오른쪽에 선을 긋되 **마지막 기둥만 선이 없다**
  (`WorkPage` 의 `i === panes.length - 1` 과 같은 규칙).
- 접힘 **1000px** — 원본 손오공과 같은 자리(`App.vue:1021`).
- ★**칸 수(4)는 규격이고 «비율»은 줄 수 있다.** `WorkPage` 도 `paneRatio`·`width` 로 패널마다 몫을
  달리 준다 — 4등분만 강제하지 않는다. 견적의 **손익표는 두 칸**을 쓴다.
  ⚠ 왜 — 표가 요구하는 최소폭이 **760px**(항목 150 + 기간 112×5 + 간격 10×5)인데
    한 칸은 1600 화면에서 400 이라 **항목명과 기간 한둘만** 보였다(2026-09-07 코덱스 실측 388px).
    그리고 표를 오른쪽으로 밀면 항목명이 사라진다 — 비교가 되질 않는다.

### ㉡ 폰은 «목업 그대로»다 — 웹 분기는 CSS 로만

감싸개 `.col` 의 기본값이 **`display:contents`** 라 폰에서는 «없는 셈»이다.
마크업은 폰·웹이 같고, 넓은 화면에서만 기둥이 된다.
⚠ 마크업으로 폰을 가르지 않는다. 목업이 «폰 화면의» 정본이다.
⚠ 예외 하나 — **손익표**만 `useIsMobile()` 로 마크업이 갈린다(표는 폰에서 여섯 열이라 못 읽는다).
  색이 아니라 «짜임»이라 첫 그림이 한 번 바뀌어도 번쩍이지 않는다.

### ㉢ 고르는 일에는 모달을 안 쓴다

원본 둘 다 좌 400 에 차종검색·캐스케이드·차량정보가 **박혀** 있다.
모달은 «견적 바구니 · 견적서 미리보기 · 공지» 같은 **결과물**에만 쓴다.
⇒ 웹은 `CarPicker inline`(좌 기둥 안), 폰은 시트. 「차종 고르기」 버튼은 **폰에서만** 선다.
⚠ 웰릭스 «표준 견적» 모달 안에서는 차를 고른다 — 그건 «한 대 견적»이 아니라 «여러 대 가격표»라
  성격이 다르다(2026-09-07 코덱스 지적으로 범위를 좁혔다).

### ㉣ 기간 1~5년은 «행 = 항목 · 열 = 기간»

기간마다 카드를 세우면 「매출·감가·이자·수수료…」 라벨이 **다섯 번 반복**된다.
행으로 세워야 다섯 해가 같은 줄에서 견줘진다.
⚠ 원본 `.qcols` 는 열마다 반복하지만 원본은 기간4×항목3 이고 **우리는 기간5×항목12** 다.
⚠ 숫자는 **줄바꿈하지 않는다**(`white-space:nowrap` · 칸 최소폭 112).
★★**다 들어가는 폭에서만 편다** — 화면 1,600 미만이면 폰과 같은 **아코디언**을 쓴다.
  반쪽만 보이는 표는 안 편 것만 못하다. 기준은 «화면 폭»이 아니라 «표가 들어갈 가용폭»이다.

### ㉤ 컨트롤 치수 — 웹은 목업, 폰은 공통규격

`.est-root` 의 CSS 변수 한 곳(`--r` · `--ctrl-*` · `--seg1~3` · `--chip-h`)이 쥔다.
웹은 목업 치수 그대로(28/32/30), **폰만** 공통규격(sm36·md40·lg48 · 입력 **16px** — iOS 확대 방지).
⚠ 손롤 컨트롤은 **태그가 하나 늘면 규칙이 못 따라온다** — `.modesw a,button` 이 활성 `<span>` 을
  못 잡아 글자가 칸 밖으로 넘쳤다(2026-09-07). 지금은 `.modesw > *` 로 잡는다.
