# 교차 검증판 — 2026-08-21

사장님 2026-08-21 「커서, 클로드, 코덱스가 교차 검증할거야」.

**오늘 두 번 다 «만든 사람이 검증»해서 늦게 잡혔다.** 그래서 규칙을 셋만 둔다.

1. **찾은 사람은 자기 건을 검증하지 않는다.** 한 건에 **다른 둘 중 최소 하나**가 붙는다.
2. **검증은 원본을 연다.** 시트·라이브 데이터·Actions 로그를 직접 본다.
   **다른 AI의 도구 출력을 다시 인용하는 것은 검증이 아니다** — 그게 오늘 사고의 뿌리다.
3. **판정은 셋뿐** — `맞음` · `틀림` · `못정함`. 애매하면 `못정함`이다.
   갈리면 **고치지 말고 남긴다.** 결정은 사장님이 한다.

## 어떻게 적나

자기 파일에만 적는다. **남의 파일을 고치지 않는다**(세 도구가 한 파일을 같이 만지면 서로 덮는다).

```
docs/crosscheck/클로드.md
docs/crosscheck/커서.md
docs/crosscheck/코덱스.md
```

한 줄 = 한 판정. 형식은 파이프 셋.

```
F3 | 맞음 | 시트 「차종마스터」 탭에서 팰리세이드 LX3 줄을 직접 열어 차종구분 SUV 확인
F8 | 틀림 | 안내 탭 「제조사(정제)에는 공급사 표기」 — 르노·KGM 이 맞는 값이다
F4 | 못정함 | 시트에 하이브리드 줄이 없는 건 맞으나, 세부모델 이름이 어긋난 것인지 구분 못 함
```

확인:

```bash
npx tsx scripts/check-crosscheck.mts
```

이 도구가 **자기 건을 자기가 검증했는지**, **아직 아무도 안 본 건이 있는지**, **판정이 갈리는지**를 센다.

## 무엇을 어떻게 확인하나

숫자를 다시 세라는 게 아니다. **원본을 열어 «정말 그런가»를 본다.**

| # | 이렇게 확인한다 |
|---|---|
| F1·F2 | Actions 로그를 직접 연다. main 의 그 파일을 `git show origin/main:<경로>` 로 열어 정말 옛 코드인지 본다 |
| F3 | 시트 「차종마스터」 탭에서 그 세부모델 줄을 **눈으로** 본다. 차종크기·차종구분 칸이 정말 그 값인가 |
| F4 | 그 37대의 세부모델을 시트에서 찾는다. **하이브리드 줄이 없는 것인가, 이름이 어긋난 것인가** |
| F5 | 「차종분류」 칸이 어디서 채워지는지 역추적한다. 규격채택 탭인가, 다른 곳인가 |
| F6 | 시트에서 그 29대를 열어 정말 빈 칸인가 |
| F7 | 시트 428종 · JSON 1,813종을 각각 세어 본다. 249와 59가 나오는가 |
| F8 | 안내 탭을 직접 읽는다. 클로드가 철회한 게 맞는가, 아니면 철회가 틀렸는가 |
