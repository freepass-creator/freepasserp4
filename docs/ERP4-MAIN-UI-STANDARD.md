# ERP4 MAIN · Product Browse UI Standard

최종: 2026-09-19  
상태: **CURRENT / ERP4 공개 메인 정본**

## 1. 제품 정의

**freepasserp.com의 ERP4 메인은 로그인 시스템이 아니라 상품 조회·검색 화면이다.**

- `freepasserp.com/` → 주소를 유지한 채 상품 목록(`/shop`)을 보여준다.
- 미들웨어가 없는 로컬·미리보기 fallback도 `/shop`으로 간다.
- 공개 메인에는 로그인, 업무 화면 이동, 내부 구글시트, 관리자 도구의 진입 링크를 두지 않는다.
- `/finder` 등 과거 ERP4 업무 화면은 기존 링크 호환·보관 목적의 **레거시 경로**일 뿐 메인 IA가 아니다.
- **`freepasserp.com` 및 화이트라벨 상품 호스트에서는 `/login` 화면 자체를 노출하지 않는다.** 직접 접근·옛 북마크도 `/` 상품 메인으로 보낸다.
- 상품 상세 `/q/[code]`, 채널 주소, 공유 링크는 기존 호환성을 유지한다.

## 2. 화면의 역할

ERP4 MAIN의 일은 세 가지뿐이다.

`찾기 → 비교 → 상세 확인`

목록에서 계약·정산·관리 업무를 섞지 않는다. 공개 화면은 상품을 빠르게 찾고 조건을 좁히고 상세를 확인하는 데 집중한다.

## 3. UI/UX 공통 원칙

freepass-admin의 최신 Product Experience Principles와 같은 철학을 쓰되, 내부 콕핏의 작은 치수를 그대로 복사하지 않는다.

- 콘텐츠 우선. 장식·대형 고정 chrome보다 상품·검색·필터가 먼저다.
- 검색어·필터·정렬·목록 스크롤을 가능한 한 보존한다.
- 같은 상품/조건 데이터와 쿼리 규칙을 웹·모바일이 공유한다.
- 모바일은 PC 축소판이 아니라 한 화면 한 목적의 흐름으로 만든다.
- 모바일 터치 대상은 최소 44px 수준을 유지한다.
- 색은 의미가 있을 때만 사용하고, 배지·칩·그림자를 남발하지 않는다.
- ERP4 MAIN 기본 팔레트는 **네이비 `#1B2A4A`(주색) + ERP BI 블루 `#5B9FD4`(보조 반응색)**다. 초록·빨강 등은 상태 의미색으로만 쓴다.
- 로딩·빈 결과·오류·갱신 상태를 실제 UI 상태로 다룬다.
- 숫자·금액·차량명·상태의 위계를 화면 전체에서 일관되게 유지한다.
- 검색 결과는 새 설명 배지를 추가하기보다 **이미 보이는 일치 값**을 옅게 강조해 결과 이유를 설명한다.
- 반복적으로 스스로 움직이는 장식보다 hover/focus/press 같은 **사용자 행동에 대한 반응**을 우선한다.

## 4. ERP4 MAIN 전용 치수

공개 상품 탐색은 내부 ERP보다 손가락·시선 이동이 크므로 `SHOP` 토큰을 정본으로 유지한다.

- 상단바 제목: **목록 → 상세에서 동일 규격 유지**. 웹 18 / 모바일 18, 동일 굵기·자간·줄높이 · 동반표기 12
- 기본 컨트롤: 웹 44 / 모바일 **44**
- 최소 터치 영역: 모바일 44
- 빠른조건 칩: 웹 26 / 모바일 32 (보이는 높이; 실제 누름 영역은 더 넓게)
- 아이콘 버튼: 웹 36 / 모바일 40
- 여백: 4 / 8 / 12 / 16 / 24 / 32 / 48
- 모서리: 표시 8 / 컨트롤 10 / 카드 12
- 목록 최대폭: 1280
- 상세 최대폭: 1120
- 웹 목록: 좌측 조건 260 + 상품 **중간폭 3열 / 1280px 이상 4열**
- 모바일 목록: 상품 1열 + 머리의 검색/상세조건 + 조건 시트
- 모바일 카드: 세로 간격 **24**, 차량명 15 / 대여료 18 / 보조정보 13 / 캡션 12
- 모바일 검색 입력은 iOS 자동확대 방지를 위해 16 유지

관리자 UI의 30~38px 콕핏 치수로 축소하지 않는다. **공통화 대상은 철학·위계·토큰 체계와 동작 규칙이지 모든 픽셀 값이 아니다.**

## 5. 현재 유지할 패턴

다음은 이미 ERP4 MAIN 표준에 맞으므로 재설계하지 않는다.

- 웹: 검색 + 좌측 필터 + **3→4열 반응형 상품 목록**
- 모바일: 상단 검색/조건 진입 + 가로 빠른조건 + 1열 카드
- URL 기반 검색/필터 조건
- 목록 스크롤/노출 개수 복원
- 카드 전체 클릭/탭
- 웹·모바일 동일 상품/필터 도메인 로직
- 상세 4:3 사진, 웹 1120 읽기 폭
- 웹 상세의 `목록으로 ↔ 공유` sticky 실행줄 가운데에 `대여료 · 차량정보 · 보험 · 이용조건` 인페이지 길잡이를 둔다. 내용은 숨기지 않고 같은 긴 페이지 안에서 이동만 한다.
- 내부 업무 원가·마진을 공개 상품 화면에 섞지 않는 구조

## 6. 다음 UI 감사 항목

코드 기준으로 다음은 **시각 검수 후 조정 후보**다.

1. 상단 chrome 높이: 현재 웹 72 / 모바일 56. 공개 메인에서 상품보다 무겁게 보이는지 확인한다.
2. 웹 표준라벨의 날짜·시각·날씨: 상품 탐색에 불필요한 chrome이면 제거한다.
3. 360 / 390 / 412px: 검색·필터·칩·금액 줄바꿈, 고정독, safe-area를 실측한다.
4. 1280 / 1440px: 260px 필터 + **4열 카드**의 가독성·줄바꿈·첫 화면 상품 노출량을 실측한다.
5. 상세: sticky header·인페이지 길잡이·사진·대여료표·하단독이 서로 가리지 않는지 확인한다.
6. focus-visible, 키보드 탐색, reduced-motion, 로딩/빈/오류 상태를 전수 점검한다.

## 7. 금지

- ERP4 루트에서 `/login`으로 보내기
- ERP4 MAIN/화이트라벨 상품 호스트에서 `/login` UI를 노출하기
- 공개 푸터/헤더에 로그인·업무화면·내부 시트 링크 추가
- 웹/모바일 상호 영향 확인 없이 한쪽만 임의 수정
- 페이지 한 곳에서 새 높이·색·radius를 임의로 만들기
- 내부 admin 치수를 공개 상품 화면에 기계적으로 복사
- 과거 “로그인 현관 / 영업자홈피가 보조 화면” 정의를 현재 규칙처럼 복구
- 목록 카드에 사진 넘김·썸네일 탐색 UI 추가 — 2026-09-19 결정으로 **제외**
