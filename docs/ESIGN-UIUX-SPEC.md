# 전자계약 손님 화면 — UI·UX 규격

> 손님이 보는 화면(`/sign/[token]`)의 **생김새 정본**입니다.
> 기능은 코덱스, **생김새는 이 문서**입니다(사장님 2026-08-29 「전자계약은 코덱스랑 기능만 잡고, 너는 UI/UX만 규격화」).
> 코드와 어긋나면 **코드가 아니라 여기를 먼저 고칩니다.**

확인 명령 — `npx tsx scripts/check-esign-uiux.mts`

---

## 0. 왜 ERP 와 다른 얼굴인가

이 화면은 **손님이** 주민등록번호·운전면허번호·주소·얼굴 사진·서명을 내는 자리입니다.
ERP 업무화면과 같은 얼굴이면 손님은 «남의 회사 관리자 화면»에 개인정보를 넣는 셈이 됩니다.

> 사장님 2026-08-21 「착한거래를 하나 더 만든다고 생각하고 가는 거야 · 숨소리까지」
> 사장님 2026-08-29 「착한거래와 동일하게 해야지 · 착한거래 한쪽으로 맞춰, 그쪽에 디자인 고도화를 할 거야」

그래서 **착한거래 규격을 그대로** 쓰고, **색만** 프리패스 토큰에 얹습니다.
착한거래 저장소로 파일을 옮겨도 그대로 서도록 만들어 뒀습니다.

| | 어디 |
|---|---|
| 규격(CSS) | `components/sign/sign.css` — 모든 선택자가 `.sign-root` 안에 갇혀 있다 |
| 원자(TSX) | `components/sign/atoms.tsx` — ERP 토큰을 **import 하지 않는다** |
| 착한거래 정본 | `chakhandeal/docs/UIUX-SSOT.md` (S01–S30) + `app/globals.css` |

## 1. 그릇 — 이 순서를 바꾸지 않는다

```
<main className="sign-root sign-page">
  <div className="sign-frame">
    <div className="c-head compact">   남색 띠 · CI 체크 · freepass | 전자계약 <현재단계> · N/M
    <nav className="steps has-labels"> 진행 막대
    <section className="c-body">       눈썹 → 제목 → 설명 → 내용
    <div className="c-footer wiz">     [이전] [다음]
```

**⚠ 중간에 다른 `div` 를 끼우지 않습니다.** `.c-body` 의 `flex:1` 이 끊겨 몸통이 안 스크롤됩니다.
(실제로 `.c-shell` 이라는 없는 클래스를 끼워 몸통이 죽은 적이 있습니다 — 2026-08-29)

**⚠ `.c-body` 안을 `display:flex` 로 만들지 않습니다.** flex 자식은 기본으로 줄어들어(`flex-shrink:1`)
내용이 길면 판이 찌그러집니다(실측: 첫 판이 346×**2**px).

## 3. 깨면 안 되는 것

1. **제목은 «이름»이 아니라 «문장»이다.**
   「계약 확인」이 아니라 **「고객님, 아래 계약이 맞습니까?」**.
   하단 버튼과 짝을 이룬다 — 「맞습니까?」 ↔ 「맞습니다. 계속하기」
   (사장님 2026-08-21 「누구님 계약이 맞습니까? 이렇게 시작을 해야할 거 아냐」)

2. **파란 안내 박스를 잇달아 쌓지 않는다.** 규격은 셋뿐이다.
   ```
   막혔다·되돌아왔다   Message variant="warning"   지금 못 넘어가는 이유
   끝났다·됐다         Message variant="success"   상태가 바뀐 순간
   그냥 설명           SignFootnote (※)            그 밖 전부
   ```
   한때 파란 info 박스가 **12개** 있었다. 전부 중요하면 아무것도 안 읽힌다.

3. **판 머리는 남색 띠 + 흰 글씨.** 띠 안에 밝은 칩을 얹지 않는다 — 머리에 주인공이 둘 생긴다.

4. **체크는 CI 좌표 하나.** `M128 264 l80 80 L384 168` · 라운드 18.75% · 획 52/512.
   정본은 `public/icon.svg`. **고칠 일이 생기면 둘을 같이 고친다.**
   머리 위에서는 **흰 네모 + 남색 체크**(대비 14.1:1 — CI 원본 13.9:1 과 같은 세기).
   스카이 네모 + 흰 체크는 1.8:1 이라 체크가 뭉갠다.

5. **입력칸은 라벨 위·글자 16px.** 16px 은 iOS 가 포커스 때 화면을 확대하지 않는 최소값이다.

6. **한 화면에 한 가지만 시킨다.** 정보 입력·신분증 촬영·얼굴 촬영은 각각 다른 화면이다.
   한 화면에 몰면 폰에서 스크롤이 길어지고 어디까지 했는지 모른다.

7. **고르는 줄은 누르면 곧 다음.** 고르고 나서 [다음]을 또 누르게 하면 결정이 두 번 생긴다.

8. **촬영 화면의 하단 버튼은 «안 찍었으면 카메라를 연다».** 토스트로 막으면 헛걸음이다.

9. **한 동의 = 한 판.** 고지(무엇을·왜·얼마나·거부하면)와 그 체크는 같은 판에 있어야 한다.
   갈라 놓으면 「위 표랑 아래 표가 뭐지」가 된다(사장님 2026-08-28).

10. **색·크기 상수를 `atoms.tsx` 에 두지 않는다.** 전부 `sign.css` 의 `.sign-root` 가 한 번만 얹는다.
    (생 hex 를 두면 `check-tokens` 가 잡는다 — 실제로 13곳 잡혔다)

## 4. ERP 원자 전환 — 끝났습니다 (2026-08-29)

**남은 ERP 원자 0개.** 임시 클래스 `erp-bridge` 는 TSX·CSS 양쪽에서 떼어 냈습니다.
`check-esign-uiux` 가 매번 개수를 세므로, 다시 섞이면 그 자리에서 잡힙니다.

다만 별칭(`SignPanel as WorkTable` 등)은 **«옮기는 중»이라는 표시**로 아직 남아 있습니다.
호출부 100여 곳을 한꺼번에 고치지 않으려고 둔 것이니, **새로 쓸 때는 본이름**을 씁니다.

## 5. 코덱스와의 경계

| | 누구 | 무엇 |
|---|---|---|
| **기능** | 코덱스 | 단계 구성·검증·저장·제출·봉인·PDF. 값이 오가는 길 |
| **생김새** | Claude | 이 문서의 그릇·원자·규칙. 무엇이 어떻게 보이는가 |

**부딪히는 자리 하나** — 새 단계를 만들면 둘 다 손이 갑니다.
- 코덱스: 서버 `PROGRESS_KEYS` 에 키를 넣는다 (`sim-esign-progress-keys` 가 잡는다)
- Claude: 그 화면의 눈썹·제목·설명·버튼 글을 정한다

기능 쪽 정본은 `docs/ESIGN-MANUAL.md` 입니다.
