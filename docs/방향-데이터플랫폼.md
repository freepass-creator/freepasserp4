# 방향 — 모빌리티 데이터 플랫폼 (네 AI 공통 닻)

> 사장님 2026-09-05 「궁극적으로 하려는 건 프리패스보다 «모빌리티»다. 원천 데이터를 확보해서,
> 날것 아닌 «모아진» 데이터가 한 줄 한 줄 실시간으로 어떻게 되고 있고 연동이 어떻게 되는지 파악하고,
> 그걸로 폐쇄형 ERP·B2C·외부 영업채널을 만든다. 물이 나오는 «샘»을 관리하는 거지. 오염 안 된
> 데이터베이스 모아놓은 거. 방향만 제시할게 — 결정·옷(디자인)은 너희끼리 알아서.」

**이 문서는 «무엇을 하느냐」가 아니라 «무엇이 본질이냐」다.** 네 AI(클로드·코덱스·커서·제미나이)가 각자 다르게
해석해 갈라지지 않도록, 방향을 한 장에 박는다. 구현·디자인은 이 방향 «안에서» 각자 정한다.

## 1. 진짜 물건은 화면이 아니라 «데이터»다

프리패스(저신용 렌터카 마켓)는 이 데이터로 만든 **첫 번째 쓰임**일 뿐이다. 진짜 자산은:

```
원천에서 확보한 · 오염 안 된 · 모아진(정제된) 원자 데이터
  +  그 한 줄 한 줄이 «지금 어디서 왔고 · 무슨 상태고 · 연동이 어떻게 흐르는지» 실시간으로 보는 능력
```

날것(raw)이 아니다. 공급사가 제각각 적은 걸 **차번을 키로 한 번 정제·원자화**해 «믿을 수 있는 한 줄」로 만든 것.

## 2. 하나의 «샘», 여러 «옷»

```
공급사 원천(시트·홈페이지·API·ERP — 제각각)
        │  직접 읽어 코드가 정제·원자화 (정제시트·중간 없이)
        ▼
   ★ 샘 = 원자 데이터베이스 (Firestore products · 차번=키 · 구조적 유일)     ← 물이 나오는 곳
        │
        ├── 구글시트로 뿌린다
        ├── 폐쇄형 ERP (우리·공급사·영업자)
        ├── B2C (손님 카탈로그)
        └── 외부 영업채널용 (화이트라벨 — 그 회사 이름으로)
```

- **샘은 하나다.** 모든 «옷」은 같은 샘을 읽는다 → 숫자·상태가 갈라질 수 없다.
- **옷은 껍데기다.** ERP든 B2C든 채널이든 «껍데기만 갈아» 찍는다. 새 옷을 만들 때 데이터를 새로 세지 않는다.
- **디자인은 옷의 문제다 — 본질 아님.** 방향(무엇이 자산·원천·껍데기냐)만 지키면 옷은 각자 정해도 된다.

## 3. 네 AI가 지킬 «변하지 않는 것» 다섯

1. **원천이 정본이다.** 값은 원천에서 온다. 샘·화면·시트가 값을 지어내거나 서로 덮지 않는다.
2. **한 줄 = 한 차, 차번이 영구 키.** 정체(제조사·모델·세부모델·트림)는 «한 번» 마스터와 맞춰 박고 지킨다(재해석 금지 — 세대강등 사고의 원인). 다음부턴 변동(상태·주행·요금)만 따라간다.
3. **한 줄 한 줄이 실시간으로 보여야 한다.** 어디서 왔나(정밀타격: source·tab·row) · 지금 상태 · 언제 갱신 · 연동 성패. 이게 플랫폼의 심장(샘 `/spring` · 관제탑 `/hub`).
4. **샘은 읽기·지키는 곳이다.** 사람이 샘에서 값을 손으로 고치지 않는다 — 고칠 게 있으면 원천/오버라이드에서.
5. **디자인·화면은 갈아끼우는 것.** 옷 때문에 데이터 층을 흔들지 않는다. 반대로 데이터가 튼튼하면 옷은 얼마든지.

## 4. 지금까지 실현된 것 (이 방향의 «증거»)

- **직접수집**: 원천(시트·홈피·손오공API 21개사) → 코드가 정제·원자화 → Firestore. 정제시트·RTDB 없이.
  (`scripts/ingest-supplier-to-firestore.mts` · `ingest-all-suppliers.mts` · `direct-ingest-hourly.yml`)
- **차번 pin(유효보존)** + 수입차 세대 판별(섀시코드·최초등록 — 「N세대」 숫자는 시장 관례가 달라 안 씀).
- **변동 폴링**: 상태·주행·요금만 매시간 delta. 불변 불가침.
- **샘 `/spring`**: 원자 DB 그 자체를 실시간으로(차 한 대=한 줄). **관제탑 `/hub`**: 파이프라인이 도는가.
- **컷오버**: 옛 미러가 직접수집 공급사에서 손 뗌 → 샘이 단일 원천.
- 첫 «옷» 두 벌이 이미 이 샘을 읽는다: ERP 파인더 · 화이트라벨 손님 카탈로그.

세부 파이프라인은 [데이터-수집-전도](데이터-수집-전도.md) · [원자-원천지도](원자-원천지도.md), 화면 배치는 [건물도면](건물도면.md).

## 5. 결정 방식 (사장님 2026-09-05)

**사장님은 «방향」만 준다. 구현·디자인·옷의 결정은 네 AI가 알아서 합의한다.**
합의가 갈릴 땐 이 문서 §3(변하지 않는 것 다섯)로 되돌아온다 — 그게 갈라짐을 막는 닻이다.
