# 영업자 홈페이지(유니오토모빌) 운영 점검 — Codex → Claude

점검 시각: 2026-09-06 KST · 범위: `https://freepasserp.com/uniauto`, 공개 목록·상세 API, 영업자 귀속(`a=U0060`)

## 판정

**기능 정합성은 표본 PASS. 속도는 캐시 적중 시 양호하지만, 캐시 미스 상세가 1~7초대로 흔들려 구조 개선 필요.**

운영 배포·데이터 변경은 하지 않았다. 이 문서는 수정 요청이 아니라 Claude의 설계·우선순위 검토용이다.

## 실제 운영 측정

| 대상 | 결과 | 비고 |
|---|---:|---|
| `/shop` HTML | 200 · 0.36초 | 껍데기 자체는 빠름 |
| `/uniauto` HTML | 200 · 0.32초 | 영업자 홈페이지 전용 경로 정상 |
| `/api/catalog/feed` 첫 측정 | 200 · 4.65초 · 1,738,856B | 콜드/원본 조회로 추정 |
| `/api/catalog/feed?a=U0060` 첫 측정 | 200 · 1.90초 · 1,738,941B | 담당자 조회 포함 |
| 같은 목록 API 캐시 적중 | 0.23~0.56초 | `X-Vercel-Cache: HIT` 확인 |
| `/api/catalog/quote` 첫 표본 | 6.79초 | 캐시 미스 상세 |
| 상세 추가 4개 캐시 미스 표본 | 1.22~1.39초 | 상품별 편차 존재 |
| 같은 상세 캐시 적중 | 0.07초 | `X-Vercel-Cache: HIT` 확인 |

목록 응답은 JSON 원문 1.74MB(압축 시 약 189KB)다. 첫 화면은 카드 60개만 그리지만, 클라이언트는 721대 전체를 한 번에 받는다.

## 정합성 실측

`/api/catalog/feed?a=U0060` 기준:

- 목록 721대, 응답 `count`와 실제 배열 길이 일치.
- 상품키 중복 0건.
- 유효 기간별 가격이 없는 매물 0건.
- 관리자 전용 `vehicle_price` 공개 노출 0건.
- `U0060`은 담당자 김영재·전화번호로 정상 해석.
- 임의 담당자 코드는 담당자만 `null`이고 목록 721대는 유지. 현재 설계는 **영업자별 재고 분리**가 아니라 **전체 재고 + 담당자 귀속**이다.
- 목록 첫 상품과 상세 5개 표본에서 차명·기간별 대여료·보증금이 모두 일치했고, 상세에서도 담당자 귀속이 유지됐다.

## 속도 병목의 근거

### 1. 목록은 전량·상세 정책을 내려보냄

`app/api/catalog/feed/route.ts`는 매 요청마다 상품 전체와 정책 전체를 읽어, 721대 각각에 `_policy`를 붙여 보낸다.

응답 용량 구성:

| 필드군 | 원문 크기 |
|---|---:|
| `_policy` | 약 600KB |
| `photo_link` | 약 307KB |
| `image_urls` | 약 221KB |
| `price` | 약 204KB |

목록 카드에 필요한 것은 요약 정책 신호(무심사/분납/연령 등)와 첫 사진뿐인데, 상세용 정책·복수 사진까지 전량 전달된다.

또한 `ShopView`가 `fetch('/api/catalog/feed', { cache: 'no-store' })`를 사용한다. API는 CDN `s-maxage=120, stale-while-revalidate=600`를 선언하지만, 클라이언트 no-store와 영업자 코드별 쿼리 캐시가 함께 있어 실제 첫 방문의 일관된 속도 보장은 약하다.

### 2. 상세는 상품 전체를 읽고 토큰을 선형 탐색

`lib/server/guest-quote.ts`의 `loadGuestQuote()`는 짧은 공유 토큰을 풀기 위해 `v4/products` 전체를 읽고 모든 매물을 순회한다. 이후 정책, 담당자가 있으면 사용자 전체도 추가로 읽는다. 따라서 신규 캐시·신규 서버에서 상세 API가 1~7초대로 흔들린다.

## Codex 권고 (아직 반영하지 않음)

1. **목록/상세 응답 분리**: 목록 API는 카드가 쓰는 요약 필드·최저가·첫 사진·혜택 신호만 제공하고, 상세 정책과 전체 사진·전체 기간표는 quote API에 둔다. 목표는 목록 원문을 1.74MB에서 수백 KB 이하로 낮추는 것이다.
2. **상세 토큰 인덱스**: 발행/이관 때 결정론적 `shareToken`을 공개 조회용 필드로 저장하고 인덱스 조회한다. 기존 링크는 현재의 전체 탐색 폴백을 임시로 유지한다. 토큰 충돌 점검도 발행 게이트로 둔다.
3. **담당자 귀속 응답 분리 검토**: 재고 데이터는 공통이므로 목록 본문 캐시를 `a`와 분리하고, 담당자 이름·전화만 별도 작은 응답으로 합치면 영업자별 캐시 중복을 줄일 수 있다.
4. 사진은 목록에 `image_url` 하나만 제공하고, 나머지 갤러리·원본 링크는 상세에서만 제공하는지 검토한다. 목록 `photo_link`가 필요한 현재 해석 경로와 충돌하지 않도록 사진 캐시 규격을 먼저 대조해야 한다.

## Claude에게 요청하는 판정

- 위 네 항목의 우선순위와 안전한 단계적 전환 순서.
- `shareToken` 저장·조회 인덱스가 기존 공유 링크·Firestore 이관 규칙과 충돌하지 않는지.
- 목록 요약 정책 신호의 최소 필드가 손님 UI 요구(심사 조건·우대 조건)와 정확히 맞는지.
- 캐시 최대 2분 + stale 10분이 출고/가격 갱신의 허용 범위인지. 허용 범위가 아니면 CDN 캐시를 짧게 두고 서버 메모리/Firestore 조회 최적화로 전환할지.

## 제한

- 브라우저 자동화 표면이 현재 세션에 없어 실제 Chrome waterfall/LCP·모바일 렌더링은 못 쟀다.
- 721개 상세 전수 대조는 하지 않았다. 위 정합성은 목록 전수 집계 + 상세 5개 표본이다.
