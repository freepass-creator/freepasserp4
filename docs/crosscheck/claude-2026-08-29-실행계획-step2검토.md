# Claude 독립검토 (실행계획 step 2) — 새 규칙 ↔ 원문보존·동결·검수대기 정합

역할: 실행계획 step 2 — 새 규칙이 원문 보존·마스터 동결·검수대기 안전장치와 모순 없는지. 판정 = 맞음/틀림/못정함.

## 판정

| 항목 | 판정 | 근거 |
|---|---|---|
| 규칙 ↔ **원문 보존** | 맞음 | 정제칸만 쓰고 원문 안 건드림. F01 직접 쓰기 금지(재발행). |
| 규칙 ↔ **마스터 동결** | 맞음 | F03 기존 행 변경·삭제 금지, 추가만 3-AI. G80 DH→G80은 동결 «전» 사장님 지시 반영이라 예외 아님. |
| 규칙 ↔ **검수대기 안전** | 맞음 | F03 없음·세대 안 갈림·제원 충돌 → 빈칸/검수대기, 추정 금지. 원문 그대로 발행. |
| 감사기 입력 = **원문(기존 세부모델 아님)** | 맞음·★반례 | 계획 안전계약 #1 옳다. **단 내 라운드4 측정(`tmp/f01-yield.mts`)은 `filled.세부모델`(결과)을 snap 입력으로 썼다 → 위반.** step 4에서 원문 `차명(원문)`·연식·제원에서만 후보 생성으로 고쳐야. 내 120 매칭은 그 기준 재측정 대상. |
| 자동후보 5조건 | 맞음 | 원문 직접 도출·F03 존재·연식 교차·제원 충돌 없음·후보 유일 — 모두 「추정 금지」와 정합. |

## ★반례 1건 (step 4에서 닫아야)

- 라운드4 감사기가 «후보 생성」의 시작을 F03 대조된 `세부모델`(결과)에서 했는지, 원문 `차명(원문)`에서 했는지 확인 필요. **결과에서 시작하면 원문에 없는 토큰(하류 오염)이 근거로 새어든다.** 반드시 원문 차명·연식·제원만 입력.

## 못정함 (내 범위 밖, 유지)

- F03 전체가 엔카와 완전 동일한지 = 엔카 iNav 전수대조 없음 → 못정함(오픈 후 백로그).
- G80 RG3 = 엔카 표기 확인 대기(엔카 iNav).

## 정리

**규칙·계획은 원문보존·동결·검수대기와 모순 없음 = 맞음.** 유일한 실질 반례 = «감사기 입력을 원문으로»(step 4). 그거만 지키면 진행 가능. 마스터 동결·추가 3-AI 게이트는 정합.
