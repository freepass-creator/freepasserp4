## 확인된 안전성 및 남은 결함

1. 표본 원문→F03 매칭 자체는 F03형으로의 정상화가 확인됐다.
   - `현대_아이오닉_아이오닉5…` → `아이오닉5`
   - `G80 RG3…` → `G80 RG3` (FL 제거)
   - `싼타페 MX5…` → `싼타페 MX5`
   - `더 뉴 카니발…`(2020) → `더 뉴 카니발 YP`
   이들은 원문·연식·F03 생산기간을 직접 다시 대조해 반례가 아니었다.
2. 그러나 `--apply` 실행의 **사후 재읽기 검증이 코드에 없다.** 스냅샷은 `apply:true`를 먼저 기록할 뿐 실제 Google Sheets 값이 반영됐는지 재조회하지 않는다. 현재 234셀 잔존으로 보아, 쓰기 실패 또는 이후 덮어쓰기를 구별할 수 없다.
3. 자동후보 632은 정제 완료가 아니다. 521행이 검수대기이며, 이 중 135행은 연식↔F03 생산기간 밖, 345행은 원문 후보가 F03 확정 집합 밖이다. 이 행들을 F01·천이·ERP로 확정 발행하면 안 된다.

## 사장님 확정 순서(2026-08-29) 대조

확정 순서: **① 원문에서 모델 추출 → ② 연식 확인 → ③ 그 모델의 F03 생산기간과 겹치는 후보만 원문 대조하여 세부모델 확정 → ④ 확정 세부모델 하위 트림 풀에서만 세부트림 확정(없으면 `기본형`)**. 게이트는 `세부모델∈F03`, `연식↔생산기간`, `세부트림∈그 세부모델 풀` 세 가지다. 영·한 표기 동치는 모델 추출 단계에서만 허용한다(`RAV4=라브4`, `E-클래스=E클래스`).

현재 코드에서 수정해야 할 두 지점:

1. `audit-refine-vs-master.mts`의 `const model = attached.모델 || filledModel`은 모델 추출 실패 시 **기존 정제 `모델`을 재사용**한다. 이는 ①의 원문 기준을 깨므로, 원문에서 모델을 못 뽑으면 자동후보가 아니라 `검수대기`여야 한다.
2. `apply-refine-r5-auto.mts`는 현재 모델·세부모델만 쓴다. ④의 트림 게이트를 통과한 `attached.세부트림` 또는 해당 세부모델 트림 풀이 반영 대상/재검증 대상에 포함되지 않는다. 확정 세부모델의 하위 트림을 다시 계산하고, 일치하는 한 개만 쓰며, 풀에 트림이 없을 때만 `기본형`을 써야 한다. 그 외는 검수대기다.

## Codex 독립 재실행 — Cursor 작업 중간 스냅샷 (2026-08-29)

Cursor가 변경 중인 최신 코드로 같은 원문·F03 읽기 전용 감사를 다시 실행했다. 이 수치는 이전 절의 실행 스냅샷과 달라, 두 결과를 섞어 완료 판단하지 않는다.

- 전체 1,153대 중 **자동후보 933대(80.9%)**, **검수대기 220대(19.1%)**, 읽기 실패 0.
- 자동후보 933대 모두 원문 차명에서 모델·세부모델·세부트림 후보가 생성됐고, F03 확정원자와 연식·생산기간 게이트를 통과했다.
- 기존 정제값과 달라 실제로 반영할 축이 있는 차량은 **255대**: 세부모델 14대, 세부트림 245대(중복 포함), 모델 0대다.
- 보류 220대는 생산기간 불겹침 96대, 원문으로 동률 세부모델을 못 가름 121대, 연식 없음 2대, 모델 없음 1대다.

따라서 이 규칙으로는 약 81%를 자동처리할 수 있다. 다만 트림 245대의 실제 쓰기와 사후 재읽기가 아직 통과하지 않았으므로, F01·천이·ERP로의 발행은 여전히 보류한다.

## 기아 개발코드 예외 규칙 — 사장님 확정 (2026-08-29)

- 기아 개발코드는 **엔카에 복수 세대명이 있을 때에만** `세대명 → 개발코드`로 대응한다. 예: `K5 (3세대)` → `K5 DL3`.
- 단일세대 모델은 엔카 세대명이 없으므로 개발코드를 만들지 않는다. 예: `K8`은 `K8` 그대로다.
- F03에 이미 있는 단일세대 코드 표기(예: `K8 GL3`)는 같은 차종의 허용 오차다. F03 원자를 고치거나 검수대기로 빼지 않으며, F03 타겟과 정상 매칭한다.
- 매칭 타겟은 항상 F03 확정원자다. “기아이므로”라는 이유만으로 F03에 없는 개발코드를 생성·치환하지 않는다.

### 현재 코드 점검

`lib/domain/submodel-normalize-f03.ts`의 `KIA_GEN`에 `K8: { 1: 'GL3' }`가 있어 원문 `K8 1세대`를 기계적으로 `GL3`로 만든다. 이 항목은 위 규칙과 맞지 않으므로 Cursor가 제거 또는 F03 후보 존재·엔카 복수세대 확인 조건으로 제한해야 한다. Codex는 차종마스터 코드 수정 권한이 없으므로 코드 수정은 하지 않았다.
