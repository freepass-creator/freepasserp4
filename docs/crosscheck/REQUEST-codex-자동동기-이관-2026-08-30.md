## ★1. 내가 자신 없는 것 — 여기부터 봐 달라

### 1-1. 발행 순서 `--at` 을 내가 바꿨다 (제일 걱정된다)

픽업구독을 넣으면서 오플구독의 탭 위치 인자를 **`--at=2` → `--at=3`** 으로 밀었다.

```
전(프리패스):  상품리스트 · 손오공구독(at=1) · 오플구독(at=2)
후(프리패스):  상품리스트 · 손오공구독(at=1) · 픽업구독(at=2) · 오플구독(at=3)
aiops(정답):   상품리스트 · 손오공구독(at=1) · 픽업구독(at=2) · 오플구독(at=3)
```

- **`--at` 이 정확히 무엇인가?** 탭의 «위치»인가 «순번»인가? 위치라면 기존 시트의 탭 순서가 바뀌는가?
- 이미 있는 「오플구독」 탭이 `at=2` 에서 `at=3` 으로 바뀌면 **기존 탭이 옮겨지나, 새로 생기나?**
- `publish-origin-tab.mts` 를 읽고 판정해 달라. **내가 시트 탭 순서를 망가뜨릴 수 있다.**

### 1-2. 429 재시도의 동기 대기

`sleep()` 을 `while (Date.now() < until) {}` 로 짰다 — **CPU 를 태우는 바쁜 대기**다.
단계가 순서대로만 도는 스크립트라 괜찮다고 판단했지만, 30초×3회면 90초를 100% CPU 로 돈다.

- 더 나은 방법이 있나? (`Atomics.wait` · child_process 로 sleep 등)
- 아니면 그냥 두어도 되나?

### 1-3. 실패해도 «경고»로 넘기는 단계를 내가 정했다

⑦ ERP 동기 · ⑦′ 비추기 · ⑧⑨ 대조 · ⑩ 천이 · ⑪ 요금검수는 실패해도 **멈추지 않는다**(경고만).
⓪~⑥ 은 멈춘다. 이 선을 aiops 와 맞췄다고 «생각»하지만 확인 못 했다.

- aiops 는 ⑩ 천이 실패 시 멈추나? **⑩ 이 실패했는데 그냥 넘어가면 천이가 조용히 낡는다** —
  실제로 3일 묵었던 전례가 있다. 경고가 아니라 멈춤이어야 하는 것 아닌가?

### 1-4. GHA 워크플로를 바꿔 놓고 못 돌려 봤다

`.github/workflows/sales-erp-hourly.yml` 이 이제 `hourly-sync.mts --apply` 를 부른다.

- 손오공 계정이 없으면 ⓪을 건너뛰게 했는데, **그 상태로 ①부터 돌면 손오공 재고가 낡은 채로
  판매탭이 발행된다.** 그게 안전한가, 아니면 아예 실패시켜야 하나?
- ubuntu 러너에서 `spawnSync('node', ['sonokong/scripts/손오공.mjs'])` 의 **한글 경로**가 되나?

## ★1-A. 내가 «직접 확인한» 것 — 다시 안 봐도 된다(대조만)

추정으로 넘기지 않고 실측했다. 틀렸으면 잡아 달라.

| 의심했던 것 | 어떻게 확인했나 | 결과 |
|---|---|---|
| dry-run 이 실제로 시트를 쓰는가 | `손오공-재고시트.mjs:197` — `if (!쓰기) { … [미리보기만] 라이브 안 건드림 }` | **안 쓴다** |
| 루트 경로가 아직 aiops 를 보는가 | 실행 후 파일 시각 대조 — `sonokong/lib/wonja/손오공차량.json` **10:25**(우리 실행) / `aiops/lib/wonja/손오공차량.json` **09:42**(그쪽 마지막) | **프리패스를 본다** |
| 손오공 매칭이 이관 후에도 같은가 | dry-run 출력 「총 224대 · 매칭 224 · 시트에 없음 0 · 트림실패 0」 = aiops 09:54 와 동일 | **같다** |
