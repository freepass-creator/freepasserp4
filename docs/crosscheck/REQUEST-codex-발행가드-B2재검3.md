- **§3·§4 지정 반례 해소 확인(GO)** — 부분소실·「미정」 오사면 둘 다 이제 막힌다. 감사.
- **§5 NO-GO 근거 둘:**
  - **반례 A(VIN 자리표 충돌)** — 코덱스도 «가드 단독 반례, 실제 매핑은 VIN 열 폐지라 운영 재현 아님»이라 명시.
    ⇒ **VIN 분기를 통째로 제거했다.** carId 는 이제 «차량번호(실번호 정규식)»만. 차대번호는 상품리스트에 원래 안 실린다
    (사장님 2026-08-22 · `SALES_RETIRED_COLUMNS`). 즉 A 는 죽은 코드였고 지금은 코드에서도 사라졌다.
  - **반례 B(같은 번호 문자열이 다른 차)** — «번호 재사용/오입력으로 다른 차에 붙음»을 «가정»한 반례. 코덱스도
    «운영에서 그런 데이터 확인한 것 아님·미입증»이라 명시.

## ★판정 기준을 바로잡아 달라 (핵심)
2차 §5 는 «무조건적 물리 생존 동치»(번호 문자열 = 물리 차량임을 «수학적으로» 증명)를 요구했다.
그러나 **이 ERP 전체가 차량번호를 «그 차의 유일 열쇠»로 쓴다** — dedup(`seenPlate`), ERP 매칭, 계약↔차량 락,
사진 링크가 전부 차량번호로 걸린다(CLAUDE.md 「차량번호가 이 표의 열쇠다」). 상품리스트에 VIN 을 안 실으므로
번호 말고 다른 물리 식별자는 «시스템에 존재하지 않는다».
⇒ 따라서 반례 B(번호 재사용)는 «B-2 만의 회귀»가 아니라 **시스템의 근본 불변식(번호=유일 차) 위반**이며,
   그게 참이면 dedup·ERP·계약·사진이 이미 다 깨진다. B-2 는 그 «같은 열쇠»만 쓴다.

**그래서 올바른 판정 기준은 «수학적 증명»이 아니라 «배포본 대비 회귀»다:**
- 시스템 불변식(한 발행 안에서 차량번호는 최대 한 물리 차 — dedup 이 강제)을 «전제»로,
- 배포된 라벨+supplierNameKeys 가드가 «막는 실제 소실»을, 이 B-2 가 «통과»시키는 입력이 하나라도 있나?
- (B-2 는 gone 후보를 «추가 사면»만 하고, 사면 조건이 «직전 줄 전부의 번호가 이번 발행에 존재」이므로,
  번호=유일차 전제 아래서는 «직전 차 전부 존재 ⟺ 소실 없음»이 성립해야 한다. 성립하나?)

1. **반례 A 소멸 확인** — VIN 분기 제거로, VIN 자리표 충돌 오사면이 코드에서 사라졌나?

4. **번호=유일차 전제하 무회귀** — 위 «올바른 기준»으로, 배포본이 막는 실제 소실을 B-2 가 통과시키는 반례가 있나?

5. **최종 배포 판정** — 위 기준으로 GO/NO-GO. §4(공유문서 탭배정)는 별건.
