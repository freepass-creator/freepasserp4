# 오더 — Firestore 플립 선행: 컬렉션 경로 `transaction()` 여섯 자리 (2026-09-09)

> 근거: `CLAUDE.md` 「데이터·엔진」 · 개발센터 DC-014 · Codex 2026-09-09 실행 재현

## 무엇을 (한 문장)

**Firestore 심이 못 받는 «컬렉션·루트 경로 `transaction()`» 여섯 자리를 문서 단위로 바꾼다.**

## 왜 지금인가

운영은 아직 `NEXT_PUBLIC_DATA_BACKEND=rtdb` 다(2026-09-09 배포 번들에서 확정).
대표 결정은 「Firestore 로 간다」인데, **지금 플립하면 이 여섯이 터진다.**
심은 문서 경로 아닌 `transaction()` 을 거부한다 — `docRef()` 가 null 이라 던진다
(`firestore-ref-shim` `parse()`: 맨 앞 `v4` 를 떼고 **두 조각 이상**이어야 문서).

★**Codex 가 심을 실제로 실행해 재현했다**(추론 아님):
```
transaction 은 문서 경로여야 함: v4
transaction 은 문서 경로여야 함: v4/products
```

## 어떻게

- 각 자리를 **문서 단위 트랜잭션**으로 쪼개거나, 트랜잭션이 필요 없으면 다른 잠금으로 바꾼다.
- `ref('v4').transaction(...)` 처럼 **루트를 통째로 잠그는** 것은 RTDB 에서도 비싼 짓이다 —
  Firestore 로 옮기는 김에 «무엇을 지키려는 잠금인지»를 먼저 적고 그 범위만 잠근다.
- ⚠ **원자가 없으면 만들지 말고 멈추고 보고한다.**
- ⚠ 잘 돌던 동작·순서는 건드리지 않는다. 버그를 봐도 **고치지 말고 보고**한다.
- ⚠ **플립(`=firestore`)은 이 오더에 «없다».** 여섯이 0 이 된 뒤 대표님이 정한다.

## 보고

- 여섯 자리를 «각각» 무엇으로 바꿨는지(무엇을 지키는 잠금이었는지 포함)
- 바꾼 뒤 **실제로 돌려 본 것**(어느 경로를 어떤 입력으로 태웠는지). 「빌드 통과」는 실행 증거가 아니다.
- 못 바꾼 자리가 있으면 **왜**인지. 미실행·미확인을 통과로 적지 않는다.
