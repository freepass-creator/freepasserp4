## 1. 판단 기준 — 무엇을 좋게 볼 것인가

계약서는 «예쁜 화면»이 아니라 **「읽고 서명해도 되겠다」는 신뢰**를 만드는 문서다. 그래서 판단 기준이 다르다.

1. **격(格)** — 관공서 양식처럼 딱딱하지도, 앱 랜딩처럼 가볍지도 않게. 은행 여신 서류의 톤.
2. **돈이 먼저 보일 것** — 월 대여료·보증금·기간·위약금. 손님이 실제로 확인하는 건 이 넷이다.
3. **빈칸이 부끄럽지 않을 것** — 서명 전에는 손님 정보가 비어 있다. 비어 있어도 «미완성 서류»로 보이면 안 된다.
4. **인쇄가 정본** — 화면에서 예뻐도 A4로 접히면 끝이다. 모든 결정은 인쇄 결과로 판정한다.
5. **B2B 밀도** — 큰 글씨·큰 여백으로 도망가지 않는다([[b2b-dense-ui-principle]] · `DESIGN.md`).

## 2. 지금 문제 — 실측 근거

렌더해서 확인한 것(샘플 계약 `FPS-SAMPLE-01`, 문서 높이 11,465px · 9페이지 · 섹션 10개).

### A. A4 계약서

| # | 무엇 | 근거 | 왜 문제인가 |
|---|---|---|---|
| A1 | **표지 1페이지가 거의 백지** | 제목 블록과 당사자 박스 사이 약 600px 공백 | 인쇄 첫 장이 텅 빔. 「대충 만든 문서」 인상이 첫 페이지에서 결정된다 |
| A2 | **10개 섹션이 전부 같은 리듬** | 라벨(회색 셀)–값(흰 셀) 2열 표가 처음부터 끝까지 동일 | 월 대여료 420,000원과 「내장 색상」이 **같은 무게**로 보인다. 위계 없음 |
| A3 | **빈칸이 그대로 노출** | 주민등록번호·운전면허번호·주소·차대번호·연식·연료·외장/내장 색상·선택 옵션 등 | 서명 전 미리보기에서 빈 줄이 10개 넘게 이어짐 → 미완성 서류로 읽힘 |
| A4 | **섹션 경계가 약함** | 섹션 번호 배지(01~10)만 다르고 위아래 여백은 같음 | 9페이지를 넘길 때 「어디까지 봤는지」가 안 잡힘 |
| A5 | **금액 자릿수 정렬이 표에만 걸려 있음** | A4 템플릿의 `font-variant-numeric:tabular-nums` 는 `.kv .v.one-line` 과 약관 `.t-sub` **두 곳뿐**(실측). 표지 요지·본문 금액 셀엔 없음 | 세로로 쌓인 금액의 자릿수가 어긋나 보인다 |
| A6 | **모서리가 한 단계** | `--radius:4px` 하나로 카드·표·배지 전부 | 층이 안 생김(상세화면과 같은 병) |

### B. 손님 서명 화면 (12단계)

| # | 무엇 | 근거 | 왜 문제인가 |
|---|---|---|---|
| B1 | **어디까지 왔는지만 알고 무엇이 남았는지 모름** | 얇은 진행바 + 「3 / 12」 숫자 | 12단계는 길다. 남은 게 무엇인지 모르면 중간에 닫는다 |
| B2 | **헤더가 매 장 같은 문구** | 「프리패스 · 전자계약」 고정 | 화면이 바뀐 느낌이 안 남 |
| B3 | **입력 화면이 세로로 길다** | 3/12 본인확인 = 라벨+입력 7개 세로 나열 + 업로드 2개 | 폰에서 스크롤이 길고, 필수(*) 표시가 작아 무엇이 필수인지 흐림 |
| B4 | **조건 화면의 긴 문단** | 10/12 정비·기타 — 4~5줄 문단이 카드 안에 그대로 | 읽지 않고 「확인했습니다」를 누르게 만든다(법적으로도 나쁘다) |
| B5 | **A4와 다른 문법** | 화면은 카드+라운드, A4는 표+각진 선 | 같은 계약이 두 얼굴 |

## 3. A4 계약서 설계

### 3-1. 페이지 골격 (인쇄 기준)

```
[1p] 표지          ─ 제목 · 계약 요지 4칸 · 당사자 2칸 · 체결 문구
[2p] 01 계약자 · 02 대여 차량
[3p] 03 대여 조건  ← 돈이 모이는 장. 여기가 문서의 심장
[4p] 04 보험 · 05 정비
[5p] 06 결제 · 07 특약
[6p] 08 추가 운전자 · 09 연대보증인(해당 시)
[7p~] 10 동의·확인 · 약관
```

**표지 — A1 해결.** 지금의 600px 공백을 **「계약 요지 4칸」**으로 채운다. 새 정보가 아니라 본문에 이미 있는 값을 끌어올리는 것이다.

```
┌───────────────────────────────────────────────┐
│ [샘플] 프리패스테스트렌터카        계약서 번호 FPS-… │  ← 머리띠(현행 유지)
├───────────────────────────────────────────────┤
│ LONG-TERM VEHICLE RENTAL AGREEMENT             │  ← 키커(현행 유지)
│ 자동차 장기대여 계약서                            │  ← 대제목(현행 유지)
│                                                │
│ ┌──────────┬──────────┬──────────┬──────────┐ │  ★신설: 계약 요지 4칸
│ │ 월 대여료  │  보증금   │  대여기간  │ 차량      │ │
│ │ 420,000원 │ 840,000원 │  36개월   │ 00가0001  │ │
│ └──────────┴──────────┴──────────┴──────────┘ │
│                                                │
│ 본 자동차 임대차 계약은 아래 당사자 간 체결됩니다      │
│ ┌────────────────────┬────────────────────┐   │  ← 당사자 2칸(현행 유지)
│ │ 임대인 (회사)        │ 임차인 (고객)        │   │
│ └────────────────────┴────────────────────┘   │
│ 본 계약은 …서명·기명날인… 효력이 발생합니다          │
└───────────────────────────────────────────────┘
```

- 요지 4칸: 값 `20px/700`, 라벨 `10px/500 --mute`, 셀 배경 `--tint`, 테두리 `--line`.
- **금액은 표지에서 딱 한 번만 크게 쓴다.** 본문 03 대여 조건에서는 본문 크기로 돌아간다(같은 값을 두 번 크게 쓰면 어느 쪽이 정본인지 흐려진다).
- 표지 아래 여백은 남겨도 된다 — 요지가 채워지면 「비어서 허전한」 것이 아니라 「여백이 있는」 것이 된다.

### 3-2. 섹션 리듬 — A2·A4 해결

세 종류의 표를 **의미로 구분**한다. 지금은 한 종류다.

| 종류 | 쓰는 곳 | 형태 |
|---|---|---|
| **핵심표** | 03 대여 조건의 돈 4줄(월 대여료·보증금·기간·인도일) | 라벨 셀 `--accent-bg`, 값 `600` 굵기, 행 높이 +2px |
| **일반표** | 나머지 라벨–값 전부 | 현행 유지(`--tint` 라벨 셀) |
| **문단블록** | 연체·시동제어, 초과주행 안내 등 서술 | 표에서 빼고 들여쓴 문단 + 좌측 3px `--accent` 세로선 |

섹션 사이 간격을 **위 24px / 아래 12px 비대칭**으로. 지금은 위아래가 같아 섹션이 «붙어» 보인다. 섹션 제목 줄에 `--line` 1px 밑줄을 넣어 머리를 고정한다.

### 3-3. 빈칸 처리 — A3 해결 (가장 중요)

**규칙: 빈칸은 «비워두지» 말고 «왜 비었는지» 적는다.**

| 상황 | 지금 | 바꿀 것 |
|---|---|---|
| 손님이 링크에서 채울 값(주민번호·면허번호·주소) | 빈 셀 | `고객 작성` — `--faint` 10px, 옅은 점선 밑줄 |
| 해당 없는 값(연대보증인·추가 운전자) | 빈 셀 | 섹션 통째로 **숨김**(이미 `data-contract-option` 있음 — 활용) |
| 정보가 없는 차량 값(차대번호·연식·색상) | 빈 셀 | `—` 한 글자 |

이 셋만 지켜도 서명 전 미리보기의 「미완성」 인상이 사라진다.

### 3-4. 타이포·색 규격 (A5·A6)

| 요소 | 값 |
|---|---|
| 본문 | 10.5pt / 400 / `--ink` |
| 라벨 | 9.5pt / 500 / `--mute` |
| 섹션 제목 | 12pt / 700 / `--ink` |
| 표지 대제목 | 24pt / 700 |
| 표지 요지 값 | 20px / 700 |
| 금액·번호 | `font-variant-numeric: tabular-nums` **적용 범위를 넓힌다**(A5). ⚠ `--font-mono` 를 실제 고정폭 서체로 바꾸지 말 것 — 한글 서체와 섞여 계약서 톤이 깨진다. ERP도 «Pretendard + tabular-nums» 로 이미 결론이 나 있다(`app/globals.css` 주석) |
| 모서리 | 표·카드 `--radius:4px` 유지 / **요지 4칸·당사자 박스만 8px**(층 1단계 추가) |
| 강조색 | `--accent:#1f3b63` 유지. **면(面)으로만 쓰고 글자색으로 남발하지 않는다** |

**색은 늘리지 않는다.** 지금 팔레트(`--accent`/`--tint`/`--ink`/`--mute`/`--line`)로 충분하다. 새 색을 넣으면 계약서가 광고물처럼 보인다.

## 4. 손님 서명 화면 설계

### 4-1. 12단계를 3묶음으로 — B1 해결

12개를 평평하게 세지 말고 **묶음 3개**로 보여준다. 숫자는 그대로 두되 위에 묶음을 얹는다.

```
① 확인      ② 작성          ③ 동의·서명
 계약 확인    본인확인          계약조건 확인 ×N
 수집 동의    추가 운전자        약관
             추가서류          서명
```

- 상단: `① 확인 —— ② 작성 —— ③ 동의·서명` 3점 스텝퍼(현재 묶음만 진한 면, 나머지 옅은 선).
- 그 아래 얇은 진행바 + 「3 / 12」 유지.
- **효과**: 「아직 9개 남았네」가 아니라 「지금 작성 단계, 다음은 동의만」으로 읽힌다.

### 4-2. 화면 골격 통일

모든 단계가 **같은 4층**을 쓴다. 지금은 단계마다 조금씩 다르다.

```
┌─────────────────────────────┐
│ 머리띠: 묶음 스텝퍼 · N/12      │  고정(sticky)
│ 제목(단계 이름)                │
│ 진행바                         │
├─────────────────────────────┤
│ 안내 한 줄 (무엇을 왜 하는지)     │  ← 모든 단계에 반드시 1줄
│                              │
│ 본문 (입력 / 조건표 / 문단)      │  스크롤
│                              │
├─────────────────────────────┤
│ [← 이전]  [        다음      ] │  고정(sticky) · 다음이 3배 폭
└─────────────────────────────┘
```

- 「이전」은 **테두리만**, 「다음」은 **채운 면**. 지금은 둘 다 눈에 띈다.
- 「다음」 버튼 글은 **그 단계에서 하는 일**로(현행 「정비·기타 조건을 확인했습니다」 방식이 옳다 — 전 단계에 적용).

### 4-3. 입력 단계 — B3 해결

- **필수 표시**를 `*`에서 **라벨 옆 「필수」 태그**(9px, `--danger` 틴트 면)로.
- 관련 입력을 **묶음 카드**로 자른다: 「계약자 정보」 / 「비상 연락처」 / 「본인확인 자료」 — 지금도 제목은 있으나 카드 경계가 없다.
- 업로드 칸은 **찍은 뒤 미리보기 썸네일**이 그 자리에 남게(현재 점선 박스만).
- 입력 폰트 16px 유지(iOS 줌 방지 — 이미 규격).

### 4-4. 조건 확인 단계 — B4 해결

긴 문단을 **「한 줄 요지 + 접힘 상세」**로 바꾼다.

```
정비상품        미제공
엔진오일        연 1회 비용 지원          [자세히 ▾]
                └ (펼치면 원문 그대로)
```

- 요지 한 줄은 **정책 값 그대로**(가공 금지 — 법적 문구다). 원문은 접힘 안에 **전문 그대로** 둔다.
- 「아래까지 모두 확인하면 다음으로」 규칙은 유지하되, **접힘을 펼쳐야 확인으로 치지 않는다**(현행 스크롤 도달 기준 유지 — 바꾸지 말 것).

### 4-5. A4와 문법 맞추기 — B5 해결

- 손님 화면의 라벨–값 카드를 **A4의 일반표와 같은 비율**로(라벨 좌 40% / 값 우 60%, 라벨 `--mute`).
- 색·모서리·굵기를 A4 규격표(3-4)와 **같은 값**으로 맞춘다.
- 서명 화면의 계약 요지는 **A4 표지의 요지 4칸과 같은 구성**으로.

## 6. 수용 기준 — Codex 검증용 체크리스트
