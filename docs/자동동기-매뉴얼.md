## 0. ★★내 몫은 어디까지인가 — 이걸 먼저 읽는다

> 사장님 2026-09-01 「우리가 지금 **차종마스터 신규 구글시트**를 쓰잖아. 근데 **이 ERP에는 그거하고
>  상관이 없는 게**, 정제시트를 그대로 불러온 상품리스트를 끌고 오는 거잖아.
>  그러니까 **넌 차종마스터 신경 쓸 일이 없어.**」

```
   [차종마스터 신규 시트]              ← ★내 몫 아니다. 딴 사람이 채운다
            │ (정제칸을 채우는 데 쓰인다)
            ▼
   원본 → 정제시트 → ★[정제칸] ──→ 판매 4탭(상품리스트…) ──→ ERP
                        └──────── 여기서부터가 내 몫 ────────┘
                        «있는 그대로 나른다»
```

**내 몫 = 정제시트의 정제칸을 «그대로» 판매 4탭으로 옮기고, 그 상품리스트를 «그대로» ERP 로 옮기는 것.**

- ERP 는 **차종마스터를 안 본다.** 정제시트를 불러온 **상품리스트만** 본다.
- 그러므로 나는 **차종마스터를 채우지도, 고치지도, 쫓아다니지도 않는다.**
- 정제칸이 비어 있으면 **비운 채로 나른다.** 채워 넣지 않는다 —
  「없다」가 아니라 「모른다」이고, 채우는 것은 차종마스터 담당의 일이다.

### 그래서 «내 건강 지표»가 아닌 것

| 숫자 | 무엇의 지표인가 |
|---|---|
| 손오공 정제 매칭율(예: 141/215 = 66%) | **차종마스터 담당의 지표.** 마스터에 행이 몇 개 있느냐일 뿐이다 |
| 트림·세부모델이 빈 차 N대 | 위와 같다 |

★2026-09-01 에 나는 이 매칭율이 100% → 66% 로 내려간 것을 보고 **「고장났다, 되돌리자」**고 했다.
  그건 사장님이 시키신 규칙대로(마스터에 없으면 비운다) 동작한 것이었다 — **오독이었다.**
  그리고 그 74대를 쫓다가 «로컬 사본 vs 라이브 시트»를 헷갈려 또 틀린 표를 만들었다.
  **애초에 내가 볼 자리가 아니었다.**

### «내 건강 지표»인 것 — 이것만 본다

| 물음 | 어디서 보나 |
|---|---|
| 매시간 도는가 · 끝까지 갔는가 | 상태로그 `ok` · 실패 단계 |
| 정제칸이 판매 4탭에 **그대로** 갔는가 | ⑧ 시트↔ERP 대조 — 누락·초과 |
| 상품리스트가 ERP 에 **그대로** 갔는가 | ⑦ ERP 동기 반영 수 · ⑧ 핵심값 불일치 |
| 요금이 새지 않았는가 | ⑪ 요금검수(판매엔 있는데 ERP 요금 0) |
| 상태가 중간에 갈리지 않았는가 | ⑨ 상태 갈림 |

**「이름이 다 찼나」가 아니라 「있는 그대로 옮겨졌나」가 내 지표다.**

## 1. 왜 이 구조인가 — 세 가지 원칙

**① 원본은 못 만진다.** 공급사 제공시트·자체시트·홈페이지·손오공 API 는 남의 것이다.
우리는 **정제시트로 가져오기만** 한다. 원문 칸은 그대로 두고 정제칸만 채운다(2중 보관).

**② 정제칸이 방화벽이다.** `원문 → [정제칸] → ERP`. 사이에 버퍼가 있어 틀린 값이 ERP 로 안 샌다.
마스터에 없으면 **비운다** — 「없다」가 아니라 「모른다」다.
그리고 **비운 것을 내가 채우지 않는다**(§0). 비운 채로 나르는 것이 이 방화벽의 뜻이다.

**③ 실패는 «멈춤»과 «경고» 둘로 갈린다. 다만 어느 쪽이든 «성공으로 적지 않는다».**

- **멈춤(⓪~⑥)** — 여기서 실패하면 그 자리에서 끝낸다. 낡은 값을 발행하지 않기 위해서다.
- **경고(⑦~⑪)** — 발행은 이미 끝났으므로 계속 가되, **상태로그 `ok:false` + 종료코드 1 + 메일**.
  ★한때 ⑦~⑪ 이 실패해도 `ok:true` 로 적고 정상 종료했다 — 그러면 천이가 조용히 낡아도
  아무도 모른다(실제로 3일 묵은 적이 있다). 코덱스 2026-08-30 지적으로 고쳤다.

멈추든 경고든 **메일이 간다**(대표·강지수·박태윤). 2026-08-20 에 네 시간 멈췄는데 아무도 몰랐던 적이 있다 —
자동은 「멈췄다는 사실이 사람에게 닿을 때」 완성된다.

## 4. 지금 켜는 법 (로컬)

```bat
scripts\hourly-sync.cmd        (이미 있다 — --apply 로 부른다)
```

작업 스케줄러에 **매시간** 등록한다:

```powershell
$a = New-ScheduledTaskAction -Execute 'C:\dev\freepasserp4\scripts\hourly-sync.cmd'
$t = New-ScheduledTaskTrigger -Once -At (Get-Date).Date `
       -RepetitionInterval (New-TimeSpan -Hours 1)
Register-ScheduledTask -TaskName '프리패스-자동동기' -Action $a -Trigger $t -RunLevel Highest
```

**★켜기 전에 반드시 aiops 작업을 먼저 끈다.**

```powershell
Disable-ScheduledTask -TaskName '손오공-시간동기화'      # aiops 것
```

**둘 다 켜져 있으면 같은 시트를 두 곳이 쓴다.** 이게 이 작업의 유일한 위험 구간이다.

⚠ **끄기는 «다음 회차»만 막는다 — 도는 중인 것은 안 멈춘다.**
2026-08-30 전환 때 껐더니 상태가 `Running` 이었다(13:42 회차가 아직 돌고 있었다).
그대로 시작했으면 두 곳이 같은 시트를 썼다. **끈 뒤 `State` 가 `Running` 이 아닌지 확인하고 시작한다.**

```powershell
(Get-ScheduledTask -TaskName '손오공-시간동기화').State    # Running 이면 끝날 때까지 기다린다
```

### 등록 (2026-08-30 실제로 쓴 명령)

`-RunLevel Highest` 는 관리자 권한이 필요해 실패한다. aiops 작업과 같은 주체로 맞춘다.

```powershell
$a = New-ScheduledTaskAction -Execute 'C:\devreepasserp4\scripts\hourly-sync.cmd'
$t = New-ScheduledTaskTrigger -Once -At (Get-Date).Date -RepetitionInterval (New-TimeSpan -Hours 1)
$s = New-ScheduledTaskSettingsSet -MultipleInstances IgnoreNew -ExecutionTimeLimit (New-TimeSpan -Hours 2)
$p = New-ScheduledTaskPrincipal -UserId 'admin' -LogonType Interactive -RunLevel Limited
Register-ScheduledTask -TaskName '프리패스-자동동기' -Action $a -Trigger $t -Settings $s -Principal $p -Force
```

### 되돌리기 (문제가 생기면)

```powershell
Disable-ScheduledTask -TaskName '프리패스-자동동기'
Enable-ScheduledTask  -TaskName '손오공-시간동기화'
```

aiops 쪽은 **지우지 않고 꺼 두기만** 한다 — 되돌릴 자리가 있어야 한다.

워크플로는 이미 있다 — `.github/workflows/sales-erp-hourly.yml` 이 같은 `hourly-sync.mts` 를 부른다.
**단 그 파일이 `main` 에 있어야 크론이 돈다**(GitHub 크론은 기본 브랜치에서만 돈다).
2026-08-28 에 「천이가 3일 묵어 있던」 원인이 정확히 이것이다.

옮기기 전에 셋을 갖춰야 한다.

1. **시크릿** — `GOOGLE_SA_JSON`(있는지 확인) + 손오공 계정(`SONOKONG_ACCOUNT_JSON` 신설 필요)
2. **시간대** — 지금 cron 은 `0 0-9 * * 1-5` = **평일 KST 09~18시만**. 로컬은 24시간이므로 넓혀야 한다
3. **로컬을 끈다** — 로컬과 GHA 가 동시에 돌면 또 겹친다

⚠ 손오공 계정이 없는데 `--apply` 로 돌면 **큰 소리로 멈춘다**(코덱스 2026-08-30 지적).
⓪ 을 건너뛴 채 손오공구독·픽업구독을 다시 발행하면 «낡은 재고»가 새 발행처럼 찍히기 때문이다.
정말 손오공 없이 돌려야 하면 `--손오공없이` 를 명시한다 — 그때는 **손오공 탭 셋을 발행하지 않는다**.
