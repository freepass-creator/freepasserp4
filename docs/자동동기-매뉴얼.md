# 자동동기 매뉴얼 — 프리패스가 스스로 도는 법

> 사장님 2026-08-30 「**프리패스는 AIOps 를 쓰지 않아. 프리패스 자체적으로 자동으로 하게 만들 거야.**」
> 「내 PC는 계속 켜 놓을 거니까 **일단 로컬에서 자동으로**, 그게 문제가 없을 때 **깃허브로 옮기는** 게 맞을 거 같다.」

규격 정본은 `C:/dev/aiops/docs/연동지도.md` 입니다. 이 문서는 **그 지도를 프리패스가 어떻게 돌리는가**입니다.

```
한 줄:  원본 4곳(못 만짐) → 정제시트 → 정제칸 채움 → 판매 4탭 → 천이 → ERP
한 파일: scripts/hourly-sync.mts        ← 오케스트레이터는 이것 하나뿐이다
한 명령: npx tsx scripts/hourly-sync.mts --apply
```

---

## 1. 왜 이 구조인가 — 세 가지 원칙

**① 원본은 못 만진다.** 공급사 제공시트·자체시트·홈페이지·손오공 API 는 남의 것이다.
우리는 **정제시트로 가져오기만** 한다. 원문 칸은 그대로 두고 정제칸만 채운다(2중 보관).

**② 정제칸이 방화벽이다.** `원문 → [정제칸] → ERP`. 사이에 버퍼가 있어 틀린 값이 ERP 로 안 샌다.
마스터에 없으면 **비운다** — 「없다」가 아니라 「모른다」다.

**③ 실패는 «멈춤»과 «경고» 둘로 갈린다. 다만 어느 쪽이든 «성공으로 적지 않는다».**

- **멈춤(⓪~⑥)** — 여기서 실패하면 그 자리에서 끝낸다. 낡은 값을 발행하지 않기 위해서다.
- **경고(⑦~⑪)** — 발행은 이미 끝났으므로 계속 가되, **상태로그 `ok:false` + 종료코드 1 + 메일**.
  ★한때 ⑦~⑪ 이 실패해도 `ok:true` 로 적고 정상 종료했다 — 그러면 천이가 조용히 낡아도
  아무도 모른다(실제로 3일 묵은 적이 있다). 코덱스 2026-08-30 지적으로 고쳤다.

멈추든 경고든 **메일이 간다**(대표·강지수·박태윤). 2026-08-20 에 네 시간 멈췄는데 아무도 몰랐던 적이 있다 —
자동은 「멈췄다는 사실이 사람에게 닿을 때」 완성된다.

## 2. 차례 — 21단계

| | 단계 | 무엇 | 실패하면 |
|---|---|---|---|
| ⓪ | 손오공 pull → 정제 → 재고시트 | 손오공 API 에서 차를 받아 차종마스터로 매칭하고 재고시트에 넣는다 | 멈춤 |
| ① | 정제시트 갱신 | 미러 4곳(아이카·오토플러스·이안카·아이언) 원본 → 정제시트 원문칸 | 멈춤 |
| ①′ | **정제칸 채움** | 제조사·모델·원산지를 차종마스터로 매칭 | 멈춤 |
| ② ③ | 차명 정리 · 모델명 통일 | 「쏘나타 쏘나타 DN8」→「쏘나타 DN8」 · 벤츠 E200→E-클래스 | 멈춤 |
| ④ ⑤ | 입고일자 · 차번 사진링크 | 처음 올라온 날 · 차량번호 셀에 사진 링크 | 멈춤 |
| ⑥ | **판매 4탭 발행** | 상품리스트 · 손오공구독 · 픽업구독 · 오플구독 (+각 요금블록) | 멈춤 |
| ⑦ | ERP 일일 동기 | 판매시트 → ERP(RTDB products) | 경고* |
| ⑦′ | 사진·이름·부재 비추기 | 일일 동기가 안 옮기는 것들. 시트에 없으면 ERP 도 비운다 | 경고 |
| ⑧ ⑨ | 시트↔ERP 대조 · 상태 갈림 신호 | 어긋남을 «기록만» 한다. 자동으로 안 고친다 | 경고 |
| ⑩ | 천이 카드시트 | **손오공 정제칸 + 대여료만** 받아 최저가 카드로 | 경고 |
| ⑪ | 요금 검수 | 「판매엔 있는데 ERP 요금 0」인 차 수 | 경고 |

\* **경고 = 「계속 가되 실패로 기록」**이다. 상태로그 `ok:false` · 종료코드 1 · 메일 발송.
「그냥 넘어감」이 아니다.

**★①′ 를 빠뜨리면 안 된다.** 미러만 하고 정제칸을 안 채우면 원산지가 비고 →
보증금 계산이 막히고 → **요금이 통째로 사라진다**(2026-08-28 오플에서 실제로 났다).

## 3. 어디에 무엇이 남나

| 파일 | 무엇 | 누가 읽나 |
|---|---|---|
| `tmp/hourly-sync-log.txt` | 한 줄 = 한 번의 실행 (요약) | 사람 |

| `tmp/자동동기-상태.json` | `ok`·`단계[]`·`커버리지{}`·`경고[]` | **코덱스**(검증) |

`tmp/` 는 git 이 무시한다 — **기록은 이 PC 안에만 있다.** GitHub 로 옮기면 로그도 밖으로 나간다.

## 4. 지금 켜는 법 (로컬)

```bat
scripts\hourly-sync.cmd        (이미 있다 — --apply 로 부른다)
```

작업 스케줄러에 **매시간** 등록한다:

```powershell
$a = New-ScheduledTaskAction -Execute 'C:\dev\freepasserp4\scripts\hourly-sync.cmd'
$t = New-ScheduledTaskTrigger -Once -At (Get-Date).Date `
       -RepetitionInterval (New-TimeSpan -Hours 1)
Register-ScheduledTask -TaskName '프리패스-자동동기' -Action $a -Trigger $t -RunLevel Highest
```

**★켜기 전에 반드시 aiops 작업을 먼저 끈다.**

```powershell
Disable-ScheduledTask -TaskName '손오공-시간동기화'      # aiops 것
```

**둘 다 켜져 있으면 같은 시트를 두 곳이 쓴다.** 이게 이 작업의 유일한 위험 구간이다.

### 되돌리기 (문제가 생기면)

```powershell
Disable-ScheduledTask -TaskName '프리패스-자동동기'
Enable-ScheduledTask  -TaskName '손오공-시간동기화'
```

aiops 쪽은 **지우지 않고 꺼 두기만** 한다 — 되돌릴 자리가 있어야 한다.

## 5. 나중에 GitHub 로 옮길 때

워크플로는 이미 있다 — `.github/workflows/sales-erp-hourly.yml` 이 같은 `hourly-sync.mts` 를 부른다.
**단 그 파일이 `main` 에 있어야 크론이 돈다**(GitHub 크론은 기본 브랜치에서만 돈다).
2026-08-28 에 「천이가 3일 묵어 있던」 원인이 정확히 이것이다.

옮기기 전에 셋을 갖춰야 한다.

1. **시크릿** — `GOOGLE_SA_JSON`(있는지 확인) + 손오공 계정(`SONOKONG_ACCOUNT_JSON` 신설 필요)
2. **시간대** — 지금 cron 은 `0 0-9 * * 1-5` = **평일 KST 09~18시만**. 로컬은 24시간이므로 넓혀야 한다
3. **로컬을 끈다** — 로컬과 GHA 가 동시에 돌면 또 겹친다

⚠ 손오공 계정이 없는데 `--apply` 로 돌면 **큰 소리로 멈춘다**(코덱스 2026-08-30 지적).
⓪ 을 건너뛴 채 손오공구독·픽업구독을 다시 발행하면 «낡은 재고»가 새 발행처럼 찍히기 때문이다.
정말 손오공 없이 돌려야 하면 `--손오공없이` 를 명시한다 — 그때는 **손오공 탭 셋을 발행하지 않는다**.
