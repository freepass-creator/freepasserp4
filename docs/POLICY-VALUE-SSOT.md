# 정책값 SSOT 규정

시행 기준: `firestore-policy-record-v1`

## 정본

- 정책의 **값**(보험·운전자·주행·정비·면책·요금)은 ERP5 Firestore `policy/{documentId}` 원자만 정본이다.
- 상품의 `policy_code`는 정책값이 아닌 **연결키**다. 상품에 남아 있는 `_policy`는 이전 발행의 파생본이며, 화면·계약·수출·가격 계산의 근거가 될 수 없다.
- 정책 원자의 문서 ID와 `policy_code`는 모두 같은 원장을 가리키는 식별자다. `_S1`/`_S01`, `_P1`/`_P01` 보정은 연결 해석에만 쓴다.

## 값 생성과 수정

- `POLICY_DEFAULTS`는 새 정책 작성 때만 쓰는 **버전 있는 초안 템플릿**이다. 실제 적용이면 해당 값을 Firestore 정책 원자에 명시적으로 저장하고 `policy_default_pack`에 팩 버전을 남긴다.
- `POLICY_PREFILL`은 시트 입력 편의를 위한 표시 템플릿이다. 값 원장이 아니며 `POLICY_DEFAULTS`와 별도 유지하지 않는다. 두 표의 필드·값 패리티 검사를 통과하기 전에는 팩을 바꾸지 않는다.
- 읽는 곳에서 `applyPolicyDefaults`로 빈 필드를 채우지 않는다. 빈 값, 미연결 코드, 중복/모호 연결은 `HOLD`다.

## 소비 규칙

| 소비처 | 허용 연결 | 값 처리 |
| --- | --- | --- |
| 화이트라벨·상품찾기·내보내기 | 명시 코드 또는 공급사 안에서 유일한 자동 연결 | Firestore 원장 저장값 그대로, 공개 허용필드만 노출 |
| 계약·전자서명 | 계약/상품의 명시 코드만 | Firestore 원장 저장값을 봉인. 미연결·고아·빈 정책은 발행 HOLD |
| 정책 편집 화면 | 원장 원문 | 초안 템플릿 적용은 사용자의 명시 저장 전까지 값이 아님 |

## 공통 해석기와 완료 조건

- 코드의 유일한 연결 해석기는 `lib/domain/policy-resolution.ts`의 `createPolicyResolver`와 `resolveExplicitContractPolicy`다.
- 공개·계약·내부 상품찾기·수출은 이 결과의 정책키·정책코드·상태를 함께 사용한다.
- 배포 전에는 정책코드↔Firestore 문서 매핑, 제품 연결 상태, 팩-시트 패리티, 공개/계약 동일값 스냅샷을 실데이터로 재검증한다.
