# 오더 양식 — 「시킨 것만 하게」 만드는 법

> 사장님 2026-08-30 「커서한테 오더를 내리니까 **지가 맘대로만 막 하더라구.** 이거 어떻게 안 그러게 할 수 있나?」

## 왜 글로는 안 되나

오더에 「이 오더 범위 밖으로 움직이지 마라」라고 **이미 적고 있었습니다**
(`오더-cursor-정제칸-확정원자-2026-08-29.md` §4). 그런데도 나갔습니다.
`.cursorrules` 73줄에도 「임의 개선 금지」가 있습니다. 그래도 나갑니다.

**글은 지킴을 강제하지 못합니다.** 커서는 「일을 끝냈다」를 목표로 움직이므로,
가는 길에 눈에 띄는 걸 같이 고치는 게 그 목표에 «도움»이 됩니다. 막으려면 **잴 수 있어야** 합니다.

그래서 오더에 **기계가 읽는 두 칸**을 붙입니다.

| 칸 | 무엇을 막나 |
|---|---|
| `<!-- 오더:범위 -->` | **손대도 되는 파일 목록.** 그 밖의 파일이 바뀌면 즉시 빨간불 → 곁다리 리팩터·임의 개선이 여기서 걸립니다 |
| `<!-- 오더:완료 -->` | **내려가야 할 숫자.** 목표에 못 미치면 빨간불. 동시에 «오더에 없는 층이 나빠졌는지»도 같이 잽니다 |

## 쓰는 순서 (셋뿐입니다)

```bash
# 1. 오더를 넘기기 «전» — 지금 상태에 도장을 찍는다
npx tsx scripts/check-order.mts docs/crosscheck/오더-cursor-….md --start

# 2. 커서에게 오더 문서를 넘긴다

# 3. 끝났다고 하면 — 이걸로 받는다
npx tsx scripts/check-order.mts docs/crosscheck/오더-cursor-….md
```

**★1번을 꼭 먼저 합니다.** 이 저장소는 늘 작업 중이라 워킹트리가 이미 지저분합니다(오늘도 40여 개).
도장이 없으면 «커서가 건드린 것»과 «원래 지저분하던 것»을 못 가릅니다.

받을 때 가드가 잡는 것 셋:
1. **오더 범위 밖 파일을 건드렸나** — 파일 이름을 그대로 찍어 줍니다. 되돌리려면 그 파일만 `git checkout --`
2. **시킨 숫자가 내려갔나** — 목표 미달이면 어디가 몇 개 남았는지
3. **딴 층이 나빠졌나** — 고치다가 저쪽에 raw·높이를 새로 만든 경우 (「오더 밖」으로 표시)

통과하면 이어서 `npm run check:building` · `npm run check:ui` · `npx tsc --noEmit`.

## 오더 본문 양식

아래를 복사해 씁니다. **두 마커 구간은 형식을 지켜야** 가드가 읽습니다.

````markdown

> 근거: docs/건물도면.md §4 <몇 번>

## 무엇을 (한 문장)

<한 문장. 두 문장이 되면 오더를 쪼갠다.>

- 원자가 없으면 **만들지 말고 멈추고 보고**한다.
- 잘 돌던 동작·문구·순서는 건드리지 않는다. 버그를 봐도 **고치지 말고 보고**한다.
````

## 오더를 쪼개는 기준

가드가 있어도 **큰 오더는 여전히 샙니다.** 커서가 오래 헤맬수록 곁길이 생깁니다.

- **한 오더 = 한 파일 또는 한 묶음.** 「로그인 화면」은 되고 「로비 전체」는 안 됩니다.
- **완료조건이 3줄을 넘으면** 쪼갭니다.
- **설계 판단이 필요하면 오더를 내지 않습니다.** 판단부터 받고 오더를 냅니다
  (예: 「로그인 화면이 ERP 얼굴이어야 하는가」는 커서가 정할 일이 아닙니다).

## 커서가 자꾸 나가는 자리 (실측)

| 나가는 짓 | 오더에 미리 박을 문장 |
|---|---|
| 눈에 띈 버그를 같이 고침 | 「버그를 봐도 고치지 말고 보고한다」 |
| 공용 원자를 «개선» | 「`components/ui/**` 는 이 오더에서 **읽기만** 한다」(범위에서 빼면 가드가 잡습니다) |
| 없는 원자를 새로 만듦 | 「원자가 없으면 만들지 말고 멈춘다」 |
| 문서·주석을 정리 | 「문서는 이 오더의 대상이 아니다」(범위에서 뺍니다) |
| 잘 되던 문구·순서를 바꿈 | 「문구·순서·기본값은 그대로 둔다」 |
