# 코덱스 전달 — 엑셀 임포트 실물 검증 (2026-08-11)

`lib/domain/esign-excel` 를 **실제 계약서 파일로** 돌린 결과다.
`sim-esign-excel-import` 는 통과하지만, 그 검사는 코덱스가 자기 코드에 맞춰 쓴 것이라
«실물이 읽히는가»는 따로 재야 했다.

돌린 파일 — 카톡 받은 실물 5부(손오공 개인·손오공 법인·아이언·스타스카이·빌린카).
**실물은 리포에 넣지 않는다.** 고객 성명·주민번호가 들어 있다.

---

## 결론

**셀 매핑은 맞다. 그런데 지금 상태로는 한 건도 발송까지 못 간다.**

```
손오공 개인    ✓ 값이 정확히 뽑힌다   그러나 계약기간이 비어 BLOCK
스타스카이     ✓ 같은 양식이라 덤으로 읽힌다   〃
손오공 법인    ✗ detect 가 못 집는다 (parse 코드는 이미 있는데 문이 안 열렸다)
아이언        ✗ 미지원 — 이건 정상이다
빌린카        ★ 손오공으로 «오인식» 되고 전 칸이 빈다
```

잘한 것 — **주민등록번호·면허번호를 명시적으로 제외**하고 그 사실을
`skippedSensitiveFields` 로 알린다. 조용히 버리면 나중에 「왜 없지」가 된다.

---

## 1. 계약기간이 비어 발송이 막힌다 ★가장 급함

세 건 모두 `contractMonths` 가 빈 채로 나온다.
계약기간은 **BLOCK 5개 중 하나**라 이대로면 어떤 계약서도 못 보낸다.

실물 확인 결과 — 개인 양식의 대여기간은 **`GB17`** 이다.

```
A62  「대여기간」   Q62  「48」        ← 인쇄면
FZ17 「대여기간」   GB17 「48」        ← 입력면(어댑터가 보는 쪽)
                  GB18 「33500」     ← 현재 주행거리
                  GB19 「2」
```

그런데 지금 어댑터는 개인일 때 `GB17` 을 **보증금 분납 여부**로 읽고 있다.

```ts
// lib/domain/esign-excel/adapters/sonogong.ts
depositInstallment: text(sheet, corporate ? 'GB17' : 'GB15'),   // 개인 GB15
rentAmount:        numberText(cell(sheet, corporate ? 'GB18' : 'GB16')),
// contractMonths 를 채우는 자리가 없다 → 개인은 GB17
```

라벨 열(`FZ*`)과 값 열(`GB*`)이 **같은 행에서 짝**이므로,
셀 주소를 세는 대신 **라벨로 찾아 그 행의 값을 읽는 방식**이 안전하다.
`FZ17='대여기간'` → 같은 행 `GB17`. 양식이 한 줄 밀려도 따라간다.

---

## 2. 다른 회사 계약서를 손오공으로 오인식한다

```
빌린카 → sonogong-rent-v1 · 개인
   customerName=  customerPhone=  carNumber=  rentAmount=
   경고: 연락처 확인 · 대여기간 확인 · 차량번호 비어 있음
```

`detect` 가 라벨만 본다.

```ts
text(sheet, 'FZ10') === '차량번호' && text(sheet, 'FZ16') === '대여료' && text(sheet, 'FZ17') === '대여기간'
```

빌린카도 우연히 같은 자리에 같은 말이 있어 걸린다.

지금은 BLOCK 이 막아 주지만, **직원은 「인식됐다」고 믿고 빈 화면을 본다.**
「지원하지 않는 양식」이 훨씬 낫다 — 그러면 직접 작성으로 가는데,
지금은 무엇이 잘못됐는지 모른 채 빈칸만 본다.

**고치는 방향** — `detect` 가 «값이 실제로 읽히는지»까지 본다.
라벨이 맞아도 고객명·차량번호·대여료가 **모두** 비면 그건 내 양식이 아니다.
확신도를 0~1 로 돌려 가장 높은 어댑터를 고르는 방식도 좋다(설계서 §4).

---

## 3. 손오공 법인이 안 읽힌다

`parse` 에는 `corporate` 분기가 이미 있다(`GB7`·`GB16`·`GB18`).
그런데 `detect` 가 개인 양식 기준이라 법인 파일이 걸러진다. **문만 안 열린 상태다.**

실물 법인 양식의 같은 자리:

```
FZ3  「법인명」        ← 개인은 「성명」
FZ10 「색상」          ← 개인은 「차량번호」   ★라벨이 한 칸씩 밀렸다
FZ16 「보증금」        ← 개인은 「대여료」
FZ17 「보증급 분납 여부」 ← 개인은 「대여기간」
GB3  「주식회사 …렌터카…」
```

라벨 자리가 통째로 밀려 있으므로 **개인/법인을 각각 detect** 해야 한다.
`FZ3 === '법인명'` 이 법인의 가장 또렷한 표식이다.

---

## 4. 확인한 것 (되돌리지 마라)

- 손오공 개인에서 값이 정확히 나온다 — 성명·연락처·차량·차번·대여료·보증금
- 주민등록번호·면허번호 제외 + `skippedSensitiveFields` 로 고지
- 스타스카이가 같은 양식이라 그대로 읽힌다 — 양식이 같으면 회사가 늘어도 어댑터는 하나다
- 아이언이 「지원하지 않는 양식」으로 떨어지는 것은 **정상**이다(어댑터가 없다)
