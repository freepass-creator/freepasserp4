# ① 유입은 맞게 되고 있다

`scripts/scan-supplier-sheets.mts` 를 **v3∪v4 병합 기준**으로 다시 돌린 결과.

```
시트 연결 공급사 16곳 · 앱(v3∪v4) 살아있는 매물 425대
시트 판매가능 525대 · 앱에 없음 166대
```

`scan-supplier-sheets.mts` 는 `v4/products` **만** 본다. v3 에 사는 차를 「없음」으로 세서
같은 측정이 406대로 나온다. 실제 격차는 **166대**다. 스크립트의 결함이 아니라 용도 차이지만,
숫자를 인용할 때 반드시 구분해야 한다.

공급사별로는 15곳이 0~7대 차이로 사실상 일치한다.

```
PT-0023 에스에이 1 · RP006 아이언 0 · RP008 리더스 0 · RP010 KH 0 · RP012 손오공 1
RP013 웰릭스 7 · RP015 경진렌트카 0 · RP017 센트로 0 · RP018 스타 2 · RP020 우리캐피탈 0
RP021 빌린카 0 · RP022 퍼시픽 0 · RP023 오토플러스 7 · RP030 제이앤제이 0
RP004 아이카 154   ← 전체 격차의 93%
```

## RP004 는 «아이카의 시트»가 아니라 «종합시트»다

탭 이름을 Sheets API 로 열거해 확정했다(24탭).

```
종합 · 샘플 · 에코렌트카 · 퍼시픽 · 리더스렌트카 · 아이카 ← 지금 읽는 탭 · KH · 아이언 ·
연카 · 스타 · 제이앤제이렌트카 · 렌트존 · 에스에이렌터카 · 손오공 · 스위치 · 웰릭스 ·
경진렌트카 · 경진카 · 센트로 · 에이스 · 우리캐피탈렌터카 · 빌린카 · 엘씨렌트 · 빌린카구독
```

**탭 하나가 공급사 하나다.** 따라서 `sheet_tab = "250079782"`(아이카 탭)만 읽는 현재 설정이 **맞다.**
24탭을 다 읽으면 남의 재고가 아이카 것으로 들어간다 — 공급사 귀속이 깨지고,
같은 차가 자기 시트로도 들어와 **트윈이 대량 생성된다**(`DOUBLE_SALE_GUARD_2026-08-04.md` 의 그 트윈).

즉 154대는 «놓친 재고»가 아니라 «다른 공급사 탭»이다. 유입 로직은 정상이다.

## 남은 판단 — 자기 시트가 없는 공급사

종합시트에만 탭이 있고 `sheet_url` 이 등록되지 않은 이름이 몇 개 있다.

```
연카 · 렌트존 · 스위치 · 에이스 · 엘씨렌트 · 빌린카구독 · 에코렌트카
```

이들은 v3 이관분으로만 앱에 남아 있어 **시트 갱신이 반영되지 않는다**(재고가 늙는다).
엘씨렌트는 파트너로는 존재한다(`PT-0026`) — 트윈 감사에서 `엘씨렌트_182하4240` 로 잡혔던 그 이름이다.

**이건 코드 문제가 아니라 «이 공급사를 계속 운영하는가» 판단이다.** 두 갈래뿐이다.

1. **운영 중** → `partner.sheet_url` 에 종합시트 URL + `sheet_tab` 에 해당 gid 를 넣는다.
   같은 스프레드시트를 여러 파트너가 탭만 달리 가리키는 구조라 코드 변경이 필요 없다.
2. **운영 안 함** → 그대로 둔다. 재고가 안 늙는 게 아니라, 애초에 팔지 않는 차다.

※ 위 이름 목록은 문자열 대조라 표기 흔들림(`리더스렌트카`/`리더스렌터카`, `아이언`/`아이언렌트카`)이
   섞여 있을 수 있다. 확정은 파트너 코드로 해야 한다.

# ② 구글시트에 쓰기 — 지금은 못 한다

## 현재 경로는 «인증 없는 공개 읽기»다

```
읽기: https://docs.google.com/spreadsheets/d/{id}/export?format=csv&gid={gid}
      (sheet-url.ts:26 — 링크 공개 시트라 자격증명이 아예 필요 없다)
```

이 경로에는 **쓰기가 없다.** CSV export 는 단방향이다.

## 쓰려면 네 가지가 필요하다 — 그중 둘이 지금 없다

| 필요 | 현재 | 비고 |
|---|---|---|
| Sheets API 활성화 | **꺼져 있음** | 방금 확인: 프로젝트 `172664197996` 에서 `has not been used ... or it is disabled` |
| 쓰기 자격증명 | **없음** | Drive 백업용 OAuth(`GOOGLE_DRIVE_*`)는 있으나 스코프가 Drive 다. `spreadsheets` 재동의 필요 |
| 시트 편집 권한 | **없음(추정)** | 시트 주인은 공급사다. «링크 공개 읽기»와 «편집 허용»은 완전히 다른 권한이다 |
| 서버 실행 자리 | **있음** | `app/api/sheet` 옆에 라우트 추가. 브라우저에서 직접 호출 불가(비밀키 노출) |

## 「온라인에서 작동」의 답 — 서버 라우트로 하면 된다

로컬 스크립트가 아니라 배포된 앱에서 돌아야 한다는 요건은 **충족 가능하다.**
이미 `app/api/sheet`(읽기 프록시)와 `app/api/drive-backup`(OAuth 토큰 교환)이 서버에서 도는
같은 패턴이 있다. 쓰기도 동일하게 Route Handler 로 만든다.

```
브라우저 «시트에 반영» 버튼
   → POST /api/sheet/write        (서버에서만 자격증명 사용)
   → OAuth 액세스토큰 발급 (drive-backup.ts:62 getDriveAccessToken 재사용 가능)
   → sheets.googleapis.com/v4/spreadsheets/{id}/values/{range}:update
```

비밀키는 서버 환경변수(Vercel)에만 두고 클라이언트로 내려보내지 않는다.

## 설계 권고 — 공급사 시트 원본에 직접 쓰지 말 것

기술적으로 가능해져도 **남의 운영 시트 셀을 우리가 덮는 것**은 다른 문제다.

- 공급사가 수식·필터·서식을 걸어 둔 칸을 값으로 덮으면 복구가 어렵다.
- 행 순서가 바뀌면 우리가 기억한 행 번호가 다른 차를 가리킨다. 번호판으로 찾아 쓰더라도
  같은 번호판이 여러 행에 있는 시트가 실제로 있다(트윈의 근원).
- 사고가 나면 우리 잘못이 아니어도 우리 탓이 된다.

안전한 순서로:

```
1단계  전용 탭에 쓴다 — 공급사 시트에 「프리패스현황」 탭을 새로 만들고 거기에만 쓴다.
       공급사 원본 탭은 손대지 않는다. 편집 권한은 필요하지만 파괴 범위가 격리된다.
2단계  우리 소유 시트에 쓰고 공급사에 공유한다. 권한도 우리 것, 사고도 우리 안에서 끝난다.
3단계  (원한다면) 원본 탭 특정 열만 — 번호판 정합 + 변경 전 스냅샷 백업 + 감사로그가 전제.
```

**2단계를 기본으로 권한다.** 편집 권한을 16곳에서 받아내는 협상이 없고, 사고 반경이 우리 안이다.
공급사가 「우리 시트에서 보고 싶다」고 하면 그때 1단계로 올린다.

## 무엇을 쓸 것인가부터 정해야 한다

쓰기 자체보다 이게 먼저다. 후보 —

- **판매 결과 회신**: 계약완료된 차를 시트에 «출고완료»로 표시 → 공급사가 수기로 지우는 일이 준다.
- **미게시 사유 회신**: 가격이 없어 게시 못 한 차(`sheet-import.ts` 의 `noPriceCount`)를 알려 준다.
  지금은 우리만 알고 공급사는 왜 안 올라가는지 모른다. **이게 실효가 가장 크다.**
- **트윈 경고**: 같은 번호판이 두 공급사에 있다는 사실을 양쪽에 알린다.

## 판정

**오픈 차단 아님.** 읽기는 정상 작동 중이고, 쓰기는 오픈에 필요한 기능이 아니다.
착수하려면 순서는 ① 무엇을 쓸지 확정 → ② Sheets API 활성화 + OAuth 스코프 재동의
→ ③ 우리 소유 시트로 2단계 구현 → ④ 공급사 협의 후 필요 시 1단계.
