# 원자가 뻗어나가는 지도 (SSOT) — 주는 쪽이 어디로, 어떻게, 막힘없이

> 사장님 2026-09-06 「견적기·카탈로그·영업자 정책 홈피·구글시트·관리자 — 그쪽으로 나가는 것도 막힘없게끔 준비.」

원자(재고·정책·공급사·신차마스터·차종마스터·조합지도)가 «어느 소비처»로 «어느 피드»를 타고 나가는지, 각 «상태»가
막힘없나. 새 소비처를 붙일 때·기존 피드를 손댈 때 **먼저 이 지도를 본다.** 막히면 여기에 원인을 적는다.

## 원자 소스 (주는 쪽 정본)
| 원자 | 저장 | 뜻 |
|---|---|---|
| 재고(products) | Firestore `products` | 실매물(중고 재고). 손님·영업자·시트·관리자·중고견적 다 이걸 봄 |
| 정책(policy) | Firestore `policy` | 보험·계약·운전·기타 정책. 손님 상세·영업자 홈피 |
| 공급사(partner)·사용자(user) | Firestore `partner`·`user` | 화이트라벨·인증 |
| 신차마스터(new_car_trim) | Firestore `new_car_trim` | 제조사 크롤 신차 트림·가격·옵션 |
| 조합지도(config) | `data/new-car/*-config.json` | 배타·종속·패키지·min~max(BTO↔가격표 교차검증) |
| 차종마스터 | `public/data/vehicle-master.json` | 신차/중고 식별(`market_class`·`newcar_priced`) |

## 손님 카탈로그 = 영업자 홈피 «같은 것» — 연락처만 공유자에 따라 갈린다 (사장님 2026-09-06)
손님 카탈로그(1·2)와 영업자 홈피는 **같은 화면**이다. 손님한테 우리(프리패스) 이름은 «어디에도 안 뜬다»(노브랜드). 차이는 **연락처 하나**:
- **로그인한 영업자가 손님한테 공유**(`?a={영업 user_code}`) → 손님에게 **그 영업자 번호**가 뜬다.
- **공유자 없음**(회사 공개 홈페이지·맨 주소) → **회사 대표번호**(`Whitelabel.tel`, 예 유니오토모빌 1800-6454).
- 구현 = `components/WhitelabelFrame.tsx:63` `phone = agentPhone || wl.tel` (담당자 → 대표번호 순 폴백). ★2026-09-05 이 폴백이 깨져 사고 → 그래서 규격으로 박음. 새로 손대면 이 순서 지킬 것.

## 막힘없게 — 규칙
- **공개 피드(1·2·6·7) = 인증 없이·화이트리스트만·CORS·장애 no-store.** 손님/견적기 오리진이 크로스오리진으로 땡김. 민감정보(고객·계약·공급사 명단)는 서버가 걸러 «공표가·식별»만 내보낸다.
- **읽기 정본 = Firestore**(재고·정책·신차). 배포 Firestore 인증이 풀리면 손님 카탈로그 폴백이 걷히고 정상화(코드 그대로). ⇒ **지금 유일한 실막힘 = 배포 Firestore 키**(1·2), 코덱스 라인.
- **화면이 데이터를 가리지 않는다**(CLAUDE.md): 카탈로그는 상태와 무관하게 제원·요금·정책을 다 보여준다. 대수는 판매시트 정본, 화면이 시트를 다시 읽지 않는다.
- 새 소비처를 붙이면 이 표에 한 줄 등록하고, 그 피드가 «공개면 화이트리스트·인증이면 게이트»를 지키는지 확인한다.
