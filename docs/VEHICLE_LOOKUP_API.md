# 차량번호로 제원을 «확정»할 수 있나 — 조사 결과 (2026-08-07)

## 왜 조사했나

시트 텍스트를 해석해서 차종을 붙이는 방식은 한계가 분명하다. 실측(2026-08-07):

- 유입 487대 중 **검수대기 47대** — 대부분 «모델을 잘못 잠근» 경우다
  (글에는 「벤츠 E-클래스 W213 E250 아방가르드」인데 「기아 EV6」로 붙는 식)
- 트림·인승·구동은 **시트에 열이 아예 없는** 공급사가 많다

차량번호만으로 등록원부 기준 제원을 받아올 수 있다면, 시트 텍스트를 추측할 필요가 없어진다.

## 결론 먼저

| | 답 |
|---|---|
| 차번으로 제조사·차명·연식·배기량·연료·인승을 확정할 수 있나 | **가능하다** (아래 API) |
| **트림**(인스퍼레이션·프레스티지…)도 오나 | **아니다.** 등록원부 법정 기재사항에 트림·등급이 없다 |
| 동의 없이 되나 | 사업용차량(=렌터카)은 **미동의 항목 API가 따로 있다** |

즉 API 는 «모델을 잘못 잠그는» 문제를 없애 준다. 트림은 여전히 시트 글에서 뽑아야 한다.
우리 검수 47대의 큰 덩어리가 전자이므로 도입 가치는 크다.

## 후보 ①  국토교통부 자동차종합정보 API (첨부형)

- 공공데이터포털 `15071233`
- 제공: 기본정보 32건 · **제원 70건** · 정비이력 16건 · 성능점검 56건
- 입력: **자동차등록번호 + 소유주명**
- 조건: **소유주의 제3자 정보제공 동의** 필요
- 요금: 무료 또는 항목에 따라 유료(**호출 건당 최대 90원**)
- 신청: 개발단계 자동승인 / 운영단계 심의승인

**우리 적합성** — 렌터카 소유자는 공급사(법인)다. 우리는 그 공급사와 계약 관계이므로
«공급사 명의의 제3자 제공 동의»를 한 번 받으면 그 회사 차량 전체를 조회할 수 있다.
공급사 온보딩 서류에 동의 조항을 넣는 방식이 현실적이다.

## 후보 ②  국토교통부 사업용차량 이력정보 API

- 공공데이터포털 `15126856` · 운영기관 한국교통안전공단
- **소유주 미동의 항목**을 API 로 제공 — 렌터카는 사업용차량이므로 해당
- 제공: 차량 기본정보 · 검사이력 · 정비이력 · 성능점검 · 의무보험 · 체납 · 압류/저당
- 유료. 운영계정 심의 후 **별도 유료 서비스 신청**(`kotsa.or.kr/tscardata/pub`)
- 개발계정은 샘플 데이터만 나온다

**미확인** — 여기 «기본정보»에 제원(차명·배기량·연료·인승)이 어디까지 포함되는지.
문서가 열리지 않아 확인 못 했다. 한국교통안전공단 자동차정보처(054-459-7492)에 확인 필요.

## 민간 대안

데이터허브(`dataapi.co.kr`) · 하이픈 · 에이픽 등이 «자동차등록원부 조회» API 를 판다.
대체로 **차량번호 + 소유자명**을 요구한다(원천이 같은 공적 데이터이므로 당연하다).
공공 API 로 직접 가는 것과 비교해 얻는 건 편의성이지 데이터 범위가 아니다.

## 권고

1. **후보 ②의 응답 필드부터 확인한다**(전화 문의). 제원이 오면 동의 없이 끝난다.
2. 안 되면 **후보 ①** — 공급사 온보딩에 제3자 제공 동의를 넣는다.
   건당 최대 90원이면 500대 기준 4.5만원/회, 신규·변경분만 조회하면 훨씬 적다.
3. 어느 쪽이든 **트림은 API 로 안 온다.** 시트 글 파싱은 계속 필요하다 —
   다만 모델·세대가 확정된 상태에서 트림만 찾으면 되므로 난이도가 크게 낮아진다.

## 도입 시 설계 메모

- 조회 결과는 **원본 그대로 보관**하고(`_gov_vehicle`), 우리 필드에는 매핑해서 넣는다.
  나중에 규칙이 바뀌어도 재해석할 수 있어야 한다.
- 시트 값과 API 값이 **다를 때 API 를 이긴 것으로 본다**. 단 «다르다»는 사실을 기록해
  공급사 시트 오류를 알려줄 수 있게 한다(우리가 조용히 덮으면 시트는 계속 틀린 채로 남는다).
- 호출은 **신규 차번·변경분만**. 전량 재조회는 비용·트래픽 모두 낭비다.
