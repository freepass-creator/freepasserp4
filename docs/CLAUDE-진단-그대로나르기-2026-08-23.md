## ③ 「모델 Y」▶「모델Y」 — **원인 찾음. 공백을 지운 게 아니라 «다른 칸»을 실었다.**

오더 문서는 「발행기가 공백을 지운다 · 원인 미확정」으로 남겨 두고 네 곳을 후보로 적었다.
**넷 다 아니다.** 실제 길은 이렇다.

```
이안카 원본 「테슬라 모델Y」
   └─ 미러(splitMakerModel) ─▶ 정제시트 «모델명» 칸 = 「모델Y」   ← 원문 표기 그대로, 공백 없음
   └─ 정제칸 채우기        ─▶ 정제시트 «모델» 칸   = 「모델 Y」   ← 우리 정본

발행기 SALES_MAPPING: ['모델', ['모델명', '모델']]   ← «모델명»이 먼저
   └─ cell() = 값이 든 «첫» 칸 ─▶ 판매시트 「모델」 = 「모델Y」
```

- **후보에서 지운 것** — `sales-sheet-clean` 은 「모델」 열을 아예 안 건드린다(`cleanCell` 에 그 열 규칙이 없다).
  `code-vs-name.MODEL_ALIAS` 는 **읽기 전용 판정표**라 값을 쓰지 않는다.
  `vehicle-trim-operational-policy` 의 `'테슬라|모델 Y|모델 Y'` 도 쓰는 자리가 아니다.
  발행기 안의 `replace(/\s+/g,'')`(`norm`)은 **차량번호·VIN·헤더 이름**에만 쓴다.
- **왜 테슬라만 걸렸나** — 다른 차는 「모델명」과 정제칸 「모델」의 글자가 어차피 같다.
  모델 이름에 공백이 있으면서 원본이 붙여 쓴 차가 테슬라 모델 Y뿐이었다(10대 전부 이안카).
- **왜 이게 «잘못»인가** — 축 레지스트리가 이 축을 `fromRefined: true`(정제칸 이름 = 「모델」)로 **선언**한다.
  선언은 정제칸인데 발행기는 정제칸이 아닌 칸을 먼저 쓰고 있었다. 선언과 코드가 갈려 있었다.

**고친 곳** — `lib/domain/sales-sheet-mapping.ts`

```diff
- ['모델', ['모델명', '모델']],
+ ['모델', ['모델', '모델명']],
```

- 정제칸이 비면 예전처럼 「모델명」으로 떨어진다(`cell` 은 «값이 든 첫 칸»). **채움률은 안 떨어진다.**
- 「AI 인계」 @매핑 표를 다시 발행할 필요 **없다** — `parsePublishedSalesMapping` 이
  「제조사·모델·차명(원문)·옵션(원문)」 네 칸만은 **코드의 `SALES_ALIAS` 로 덮는다.** 다음 발행부터 바로 먹는다.
- ⚠ 이 바꿈은 **모든 공급사에 걸린다.** 정제칸 「모델」과 「모델명」이 다른 차가 이안카 10대 말고 더 있으면
  그 차들의 판매시트 「모델」도 정제칸 쪽으로 바뀐다 — 그게 원칙이지만 **발행 뒤 `audit:passthrough` 로 세어 보고 넘어간다.**

## ② 옵션 콤마 뒤 공백 143건 — **(가) 그대로 나르기로 고쳤다**

사장님 원칙(「옮기는 길에서 값을 가공하지 마라」)에 맞는 쪽이 (가)라 그쪽으로 갔다. 되돌리기는 한 글자다.

**고친 곳** — `lib/domain/product.ts`

```diff
- return parseProductOptions(cleaned).join(', ');
+ return parseProductOptions(cleaned).join(',');
```

- **구분자 통일은 그대로 둔다** — `·` `;` `|` 개행 → `,` 는 표기 가공이 아니라 «구분자를 하나로»다(오더 문서 지시대로).
- **화면은 안 깨진다** — 이 파일이 스스로 선언한 SSOT 가 「표시·칩·검색·상세는 전부 `parseProductOptions`」이고,
  그 파서가 조각마다 `trim()` 한다. 저장 글자에 공백이 없어도 칩은 그대로 선다.
- `normalizeProductOptionsText` 를 부르는 자리는 **`sheet-import.ts:907` 한 곳뿐**이다(유입 경로).
  「옵션(원문)」(`supplier_options`)은 애초에 이 함수를 안 탄다 — 원문 2중 보관은 그대로다.
- ⚠ **이미 ERP 에 굳어 있는 143건은 안 바뀐다.** 다음 유입에서 그 줄을 다시 읽어야 덮인다.
  발행·동기 뒤에도 남으면 그건 «시트에 값이 없어 유입이 그 칸을 건너뛴 차»다.

## ① 「더 뉴 기아 레이 TAM」 13건 — **오더 문서가 지목한 곳이 틀렸다**

오더 문서: 「고칠 곳: **차종마스터 시트**의 세부모델명」.
**차종마스터는 두 층인데, 깨끗한 쪽을 지목했다.** 실제로 열어 본 결과:

| 자리 | 「레이」 세부모델명 | 판정 |
|---|---|---|
| `public/data/vehicle-master.json` (이름 사전 1,816종) | **「더 뉴 레이 TAM」** | ✓ 이미 깨끗하다 |
| `public/data/vehicle-trim-master.json` (트림 원장 2,086행 · 2026-08-15 캡처) | **「더 뉴 기아 레이 TAM」 13행** | ⛔ **여기가 원인** |
| `data/vehicle-trim-key-registry.json` (mf- 키 책) | 같은 글자 13곳 | ⛔ 같이 고쳐야 |
| `data/product-vehicle-review-decisions.json` | 같은 글자 12곳(+메모 2곳) | ⛔ 같이 고쳐야 |

**왜 깨끗한 쪽이 안 이기나** — `fill-supplier-ai-columns` 의 정본 계산이
`preferMasterNames = (vehicle-trim-key-registry.schemaVersion >= 3)` 로 도는데 **지금 값이 3**이다.
그래서 `normalizedNameForKey` 가 **트림 원장(artifact) 이름을 1순위**로 쓴다 —
이름 사전(`vehicle-master.json`)이 아니라 **트림 원장의 `sub_model` 이 정제칸에 박힌다.**

```
vehicle-trim-master.json 「더 뉴 기아 레이 TAM」
  ─▶ 정제칸 세부모델 ─▶ 판매시트 세부모델 ─▶ ERP sub_model
  ─▶ 화면이 「기아」 중복을 떼어 「더 뉴 레이 TAM」  ← audit 가 잡은 13건
```

**규칙 위반이기도 하다** — `vehicle-master-lock.SUBMODEL_NAME_RULE = 'model+gen_code'`.
세부모델명은 「모델 + 개발코드」다. 제조사 말이 들어갈 자리가 없다(제조사는 별도 열이 든다).
전수 훑었더니 **트림 원장 2,086행 중 제조사 말이 세부모델에 섞인 것은 이 13행뿐**이다
(「폴스타 2」·「마쯔다 3」 같은 것은 제조사가 곧 모델 이름이라 정상).

### 커서에게 (차종마스터·코드 쓰기는 커서 단독)

1. `public/data/vehicle-trim-master.json` — `sub_model` 「더 뉴 기아 레이 TAM」 13행 → **「더 뉴 레이 TAM」**
   (`title`·`master_id` 등 같은 글자를 쓰는 칸을 함께 본다)
2. `data/vehicle-trim-key-registry.json` 13곳 · `data/product-vehicle-review-decisions.json` 12곳 같은 글자
3. `npx tsx scripts/check-vehicle-master-lock.mts` · `npx tsx scripts/verify-master-pass.mts`
4. `fill-supplier-ai-columns --include-mirror --apply` → 3탭 재발행 → ERP 동기 → `npm run audit:passthrough`
5. ⚠ **화면 코드(`vehicle-name.removeKnownPhrases`)는 지우지 않는다.** 다른 공급사 원문에도 걸리는 안전장치다.

### ★사장님 판단이 필요한 한 가지

트림 원장은 **원천대장 「차종마스터」 탭(A:AE)에서 뜬 캡처**다(`source.spreadsheet_id` 가 그 문서를 가리킨다).
그런데 `vehicle-master-lock` 은 **그 탭을 «읽기만»** 으로 잠가 두었다(누구도 쓰지 않는다).
그래서 json 만 고치면 **원장을 다시 뜨는 순간 13건이 되돌아온다.** 둘 중 하나를 정해 주셔야 한다.

- **(가)** 사장님이 원장 「차종마스터」 탭의 그 13행을 고치고, 커서는 json 을 다시 뜬다 — 되돌아오지 않는다.
- **(나)** 커서가 json 만 고치고, 원장을 다시 뜰 때 이 이름을 되살리지 않도록 **덮개 규칙**을 둔다
  (`ai-refine-guard` 처럼 «무시 목록»을 한 줄 두는 방식). 원장과 json 이 갈리는 값이 하나 생긴다.

**클로드 의견: (가).** 「값이 틀렸으면 시트를 고친다」가 이번 주 내내 지킨 원칙이고,
(나)는 «옮기는 길에 덮개를 끼우는 것»이라 08-23 오전에 낸 사고와 성격이 같다.
