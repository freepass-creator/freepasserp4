## 1. 두 축

| | 실적 | 청구 |
|---|---|---|
| 언제로 세나 | **접수일** | **청구월** |
| 무엇을 세나 | 계약이 들어온 것 전부 | 그중 이번 달에 돈 받을 것 |
| 상태 | 계약중·완료·환수·취소 다 있음 | 관문을 통과한 것만 |
| 안 통과한 것 | — | **미청구 실적으로 계속 보관·관리** |

「미청구실적은 계속 보관관리되는거고」 — 사라지지 않는다. 다음 달 후보로 남는다.

## 2. 청구 관문 — **인도일 하나뿐이다**

사장님 2026-08-25 「분납중이지만 청구는 들어갈거야 · 청구서는 다른거고」.

```
인도일이 있다   →  청구한다.  끝
```

**분납은 관문이 아니다.** 분납 중이어도 인도가 됐으면 청구가 나간다 —
보증금 분납이지 수수료 분납이 아니기 때문이다. 우리 수수료는 인도 시점에 확정된다.

⇒ 그래서 **오플이 「2회분납이어도 당월청구」** 인 것이 예외가 아니라 **원칙**이다.
  앞서 이 문서에 「인도일 + 분납 조건」이라 적었는데 **그건 틀렸다.** 관문은 인도일 하나다.

**분납은 청구 뒤에 굴러간다.** 만료까지 환수가 없으면 끝이고, 뿌러지면 환수 줄을 세운다(2′장).

**청구서(계산서)는 또 다른 것이다.** 청구가 «장부에 적는 일»이라면 계산서는 «세금계산서를 끊는 일»이고,
6단계 흐름의 5번이다. 청구 줄이 섰다고 계산서가 나간 것은 아니다.
## 2′. ★청구는 안 바뀐다. 분납은 계속 산다

사장님 2026-08-25 「청구는 변동없는거고 분납은 계속 살아있는거고
기 청구한거로 일단 완료될 때까지 관리하는거지」.

```
청구   한 번 찍히면 **확정**. 청구월·청구금액을 나중에 고치지 않는다
       5단계에서 계산서가 이미 나갔다 — 줄을 고치면 계산서와 장부가 어긋난다

분납   청구된 뒤에도 **계속 굴러간다.** 2회차·3회차가 들어올 때까지 따라간다
       청구 줄을 건드리지 않고 **분납 관리 탭에서** 회차를 채운다

환수   분납이 뿌러지면 청구 줄을 고치는 게 아니라 **환수 줄을 새로 세운다**
       원래 청구월을 적어 두고, 환수금액을 그 달 정산에서 뺀다
```

**왜 고치지 않고 새 줄을 세우나** — 이미 나간 계산서·이미 준 돈을 되돌리는 일이라
«얼마를 청구했다가 얼마를 돌려받았다»가 둘 다 남아야 한다. 청구 줄을 덮으면
그 달 실적이 소급해서 바뀌고, 지난달 마감이 흔들린다.

★**환수도 청구 시트에 들어간다**(사장님 2026-08-25 「같은번호가 환수가 터지면 청구시트 하나에 들어가는거야」).
환수를 딴 탭으로 빼지 않는다 — 빼면 «그 차에 얼마 청구했다가 얼마 돌려받았나»가 두 곳으로 갈린다.
**같은 차번이 청구 시트에 여러 줄** 있는 것이 정상이다.

```
청구 시트(장부)
  청구월  차량번호     구분   금액        사유            원청구월
  2026-08 161하1266   청구   972,000
  2026-09 161하1266   환수  −972,000    2회차 미입금     2026-08
```

⇒ **청구 시트는 «장부»**다. 지우거나 덮지 않고 **줄을 더한다.**
⇒ 그 달 청구액 = 그 달 줄의 **합**이다(환수가 음수로 깎는다).
⇒ **분납 관리는 «살아 있는 트랙»**이다. 뿌러지면 청구 시트에 환수 줄을 만든다.

## 3. 여섯 단계 — 업무동선 그대로

```
1. 실적기반 청구        기계가 «이번 달 청구 후보»를 뽑는다
2. 영업자 확인          영업채널별로 «이거 청구하면 되죠?» → ㅇㅋ
3. 공급사 검수·승인      렌트사가 «수금됐나»를 본다
4. 영업자 재확인         갈린 건을 다시 맞춘다
5. 계산서 발행·공급사 청구
6. 영업자 지급
```

**크로스체크가 핵심이다.** 「영업자가 4건 청구 말했는데 공급사는 아직 수금 안 됐다고 3건 인정이면
3건만 청구되는 거지 · 영업채널에 3건만 청구할 수 있다고 하고」

```
영업자 주장 4  ─┐
                ├─→  겹치는 3건만 청구.  갈린 1건은 다음 달 후보로 남는다
공급사 인정 3  ─┘
```

「당사자들이 ㅇㅋ 한 건이니까」 — 나중에 다투지 않는다. 그게 이 왕복의 값이다.

**단계마다 «누가·언제·몇 건»이 남아야 한다.** 안 남기면 크로스체크가 말싸움이 된다.

## 4. 시트 구조 — 셋이다

★**당월 입력하는 칸과 청구 탭은 다른 것이다**(사장님 2026-08-25).
입력하는 손과 판단하는 눈이 달라서, 한 표에 두면 둘 다 불편해진다.

```
① 실적 입력        계약이 들어오면 여기. 접수일 기준으로 계속 쌓는다
                   ▸ 팀장이 넣는 곳. 넣는 칸만 앞에
                   ▸ 지우지 않는다. 미청구도 계속 남는다

② 청구 시트(장부)   ①에서 관문을 통과한 것 + **환수 줄**
                   ▸ 같은 차번이 여러 줄일 수 있다(청구 → 환수)
                   ▸ 한 번 찍힌 줄은 안 고친다. 되돌릴 땐 줄을 더한다
                   ▸ 영업채널별로 묶여 보인다(영업자에게 그대로 보여 줄 표)
                   ▸ 단계 1~6 · 영업자확인 · 공급사승인 칸

③ 분납 관리        분납 건만. 회차 · 약정일 · 입금일 · 최종완료
                   ▸ 청구된 뒤에도 계속 굴러간다
                   ▸ 뿌러지면 ②에 환수 줄을 만든다
```

**②는 ①에서 뽑아 만든다.** 값을 손으로 옮기지 않는다 — 옮기면 두 곳이 갈린다.
