## 0. ★★차종마스터 = 동결 (하드룰, 사장님 2026-08-29)

**차종마스터(F03 「차종마스터」 탭)의 «기존 항목」은 변경 불가다. 어떤 AI도 못 고친다.**

- 기존 행의 원산지·제조사·모델·세부모델·세부트림·생산기간을 **수정·삭제 금지**(Claude·Cursor·Codex·Gemini 전부).
- **추가만 가능** — 그것도 **3-AI 검토 합의 후에만**(§5). F03에 실재 형태가 있으면 추가가 아니라 §3 정제(파서) 매핑.
- 예외 없음. 규칙 변경이 필요하면 **사장님 직접 지시**로만(예: 2026-08-29 `G80 DH→G80`은 사장님 지시로 반영, 이후 동결).
- 이유: 마스터가 원자(차량번호별 신원)의 «기준»이다. 기준이 흔들리면 확정된 원자가 다 흔들린다.

## 0-1. AI 검토 의견 칸 (동결과 양립)

차종마스터 시트에 **«AI검토/의견» 칸**을 데이터 7열 «오른쪽»에 둔다. 이건 **데이터가 아니라 리뷰 메타**라 동결(§0)을 안 어긴다(기존 7열 값 불변).

- **용도 ①(추가)**: F03에 없는 새 세부모델 추가 제안건에 각 AI가 의견 기록 → 3-AI 합의면 Cursor가 추가.
- **용도 ②(의심 플래그)**: 기존 항목 중 «엔카 대조 필요/의심»을 표시(고치는 게 아니라 표시만 — 사장님/엔카 판정 대기).
- 칸 구성(권장): `제안세부모델 · Claude의견 · Cursor의견 · Codex의견 · Gemini의견 · 합의 · 근거 · 시각`. AI는 «자기 열»에만 씀.
- ★의견 칸을 채운다고 데이터 7열이 바뀌는 것 아님. 추가/수정 반영은 별도 게이트(3-AI 합의 + Cursor 쓰기 + 백업).

## 2. 명명 기준 (딱 이것뿐 — 2026-08-29 갈아엎음)

> 기준값은 이 두 줄이 전부다. 나머지는 다 여기서 나온다.

**① 기준 = 엔카와 «완전 동일».** 엔카 세부모델 표기를 그대로 쓴다.
**② 예외 = 하나뿐 — 기아는 «엔카에 세대명이 있으면」 그걸 개발명(개발코드)으로 따라 쓴다.** 예: 엔카 `K5 3세대` → `K5 DL3`.
- ★**엔카에 세대명이 «없으면»(=최초/유일 세대) 코드도 없다.** 무조건 붙이는 게 아님. 예: **K8은 한 세대뿐 → 엔카 「더 뉴 K8」·「K8」 → 코드 없이.**
- ★★**«허용 가능한 오류」 같은 건 없다.** 엔카와 다른 건 전부 오류라 고친다. **유일한 «엔카와 다름」 허용 = 이 세대명→개발명 변환 하나뿐**(엔카 `K5 3세대`→`K5 DL3`). 그 외는 엔카 완전 동일. 예: F03의 `K8 GL3`는 오류 → **`K8`·`더 뉴 K8`로 수정 완료(2026-08-29)**.
- ★**왜 기아만 다르게?** 나머지가 엔카와 완전 동일이라 «그대로 베낀 것처럼」 보일 수 있어, **기아만 세대명→개발명으로 «의도적으로 다르게」** 둔 것. 그러니 기아 개발코드(K5 DL3 등)를 «오류」로 착각해 «엔카 세대명으로 되돌리지」 마라 — 그건 의도된 차이다. (단 K8처럼 «세대가 하나라 엔카에 세대명이 없는」 경우는 바꿀 게 없어 코드도 없음)

- 그 외 규칙 없음. FL 안 씀·괄호 안 씀·`G80` 표기 등은 **«엔카 그대로»에 이미 포함**(별도 규칙 아님).
- 세부트림 없으면 「기본형」(이건 명명이 아니라 정제 표기 — §3).

**③ 연료는 세부모델에 «안 넣는다» — fuel_type 축으로 뺀다 (사장님 2026-09-05 개정).**
> 「가솔린·디젤·하이브리드는 제조사가 나누긴 하지만, 전기까지 온 마당에 연료로 필터하는 세상이다. 깔끔하게.」
- 엔카는 「그랜저 하이브리드」처럼 연료로 세부모델을 나누지만, **우리는 세부모델에서 연료어(하이브리드/HEV/PHEV)를 뺀다** — 「아반떼 하이브리드」 → 세부모델 `아반떼` + `fuel_type=하이브리드`.
  - ★이것이 **§2①「엔카 완전 동일」의 두 번째 «의도된 예외»**다(첫째=기아 세대명→개발코드). 그래서 「아반떼」가 엔카 「아반떼 하이브리드」와 달라도 오류가 아니다 — 되돌리지 마라.
  - **예외 — 전기전용 모델명은 그대로 둔다**: `EV6`·`아이오닉5/6/9`·`쏘울 EV`·`캐스퍼 일렉트릭` 등 «전기가 곧 정체」인 이름. 이건 연료변형이 아니라 모델명이다.
- 마스터의 기존 「X 하이브리드」 세부모델은 **`retired:true`로 «비활성»**(삭제 아님 · `scripts/retire-hybrid-master-models.mts`). 비우기 전에 **고유 트림을 base로 병합**하고, base가 없으면 개명해 트림째 승격 — 트림 손실 0. `buildMasterIndex`가 retired를 건너뛴다.
- 원자는 이미 이렇게 되어 있다(하이브리드 168대가 base명+fuel_type). 이 규칙은 그 상태를 «명문화 + 마스터 청소»한 것.
- ★**판정은 「엔카에 있으면 맞다」뿐.** 내 논리·직관으로 문제 삼지 않는다.
  - 예: `더 뉴 기아 레이`는 **엔카가 쓰는 이름 → 맞음.** 「제조사가 세부모델에 들었다」처럼 내 규칙으로 «문제」라고 하면 안 된다(2026-08-29 교훈).

## 3. 정제 흐름 (원문 → 정제칸)

재료 = **원본시트(원문)** + **제공시트(공급사 입력칸)**. → 정제칸 채움 → 상품시트(F01) 재발행.

- **세부모델 정규화 — ★F03가 심판(arbiter)**: 원문/입력 세부모델에서 후보를 여러 개 만든다(원본 · FL 제거 · 제조사 누출 제거 · dev코드 제거 · **올 뉴류 제거**도 후보에 포함). → **F03 세부모델 집합에 실재하는 형태를 채택.** 여러 후보가 F03에 있으면 **연식/생산기간**으로 하나로.
  - ★「올 뉴」류는 «강제로 벗기지 않는다» — 하지만 **F03가 non-올뉴 형태를 쓰면**(예: F03에 `싼타페 MX5`만 있고 `디 올 뉴 싼타페` 없음) **연식이 그 세대면 그 형태로 매칭**한다. 즉 벗길지 말지는 F03+연식이 정한다(오매칭은 연식이 막음).
  - 예: `디 올 뉴 싼타페 MX5`(연식 2023+) → F03 `싼타페 MX5` · `올 뉴 K7 YG` → F03에 `올 뉴 K7`이 있으면 그대로.
  - F03에 어느 형태도 없으면 **빈칸/검수대기**(추정 금지). F03가 dev코드를 쓰면 유지(싼타페 MX5·K5 DL3).
- ★★**하드 게이트 (완전 원천 차단, 사장님 2026-08-29)**: 정제칸·F01 발행 «세부모델」은 **반드시 F03 세부모델 집합에 실재해야 한다.** 발행 직전 «F03 멤버십 검사»를 최종 게이트로 둔다 — **F03에 없는 형태(`디 올 뉴 싼타페 MX5` 등)는 발행 거부** → F03형(`싼타페 MX5`)으로 매핑되거나 검수대기. 코드·별칭·원문 어디서 비-F03 형태를 만들어도 이 게이트가 막는다. 「차종 매칭 무조건 F03 시트 기준」의 강제점.
- **세대 확정**: 여러 F03 후보면 **연식/최초등록 ↔ F03 생산기간**으로 교차검증해 하나로. 안 갈리면 검수대기.
- **제원(연료·배기량·구동)**: 원문에서 발라내되 「제원마스터」 허용값으로. 없으면 공급사 입력칸 활용. 그래도 없으면 빈칸.
- **세부트림 없으면 「기본형」.**

## 3-1. 세부모델·세부트림 찾는 법 (해상도 순서 — 사장님 2026-08-29)

★**제일 심플한 로직(사장님 확정)**: ①모델 추출(오류없이 금방) → ②연식 본다 → ③**생산기간 겹치는 것만** 원문 대조(영/한 감안) → **= 세부모델 확정(80%+는 ①②로).** → **그 세부모델 «하위에서만» 세부트림.**

**순서:**
1. **모델** — ★**«원문 줄」에서 찾는다**(정제 결과 열 재사용 금지 — 원문이 근거). 차명을 훑으면 금방. 예: `싼타페` · `E클래스` · `쏘나타`. (영/한 감안: `E-클래스`=`E클래스`)
2. **연식** — ★**그 «원문 줄 어딘가」에 있다**(연식/최초등록/연도 토큰). 거기서 뽑는다.
3. **세부모델(세대)**:
   - **① 1차(80%+): 모델 + 연식 → F03에서 «그 모델」의 세대들 중 «연식이 생산기간에 «딱 하나」에 드는」 세부모델.** 예: 싼타페 + 2024 → `싼타페 MX5`(2023~현재). **연식이 한 세대에만 들면 그대로 자동 확정.**
   - **② 2차로 «한번 더」 보는 건 딱 둘뿐**:
     - (a) **연식이 어느 생산기간에도 안 듦**(no match) — 원문/데이터 이상.
     - (b) **연식이 여러 세대 생산기간에 겹침**(전환기, 예: 세대 교체 연도) — 어느 세대인지 애매.
     - 이 둘일 때만 **원문을 대조**한다 — ★**영문/한글 표기 감안**(`RAV4`=`라브4` · `E-클래스`=`E클래스` · 산타페=싼타페).
     - ★★**원문의 «세대 표현」을 F03 세대에 매핑**(개발코드가 원문에 없어도 됨 — 이게 검수 대부분을 가림):
       - **「N세대」 → 그 모델의 «생산시작 순 N번째 세대».** 예: 「E클래스 6세대」 → `W214`(6번째).
       - **「디 올뉴 / 올 뉴 / 신형」 = «최신(마지막) 세대».** 예: 「디 올뉴 그랜저」 → `GN7` · 「신형 K5」 → `DL3`.
       - **「더 뉴」 = 그 세대의 페이스리프트**(같은 dev코드, 더 뉴 접두). 예: 「더 뉴 스포티지」 → `NQ5`.
       - + **연식으로 교차확정**(그 세대 생산기간에 연식이 드는지). 원문 세대표현과 연식이 어긋나면 검수대기.
       - 원문에 개발코드가 직접 있으면(`DN8`·`MX5`) 그걸로 바로.
   - **③ 2차로도 안 갈리거나 F03에 없으면 → 검수대기**(추정 금지). 나머지(1차에서 한 세대 확정)는 손 안 댐.
4. **세부트림 — ★«확정된 세부모델의 «하위에서만»» 찾는다**(다른 세부모델 트림 안 섞음). 원문 차명의 트림 토큰(`프레스티지`·`익스클루시브`·`E200 아방가르드`) → **F03 «그 세부모델의 트림 풀」과 대조 → 실재하는 트림만** 채택. 원문에 없거나 풀에 없으면 → **「기본형」**.

**게이트(필수·코드로 박음):**
- **세부모델 ∈ F03**(비-F03 형태 금지 — 디올뉴 싼타페 등).
- **연식 ↔ F03 생산기간 일치**(세대 오매칭 차단 — W213/W214).
- **트림 ∈ F03 그 세부모델 트림 풀**(없으면 기본형).

→ **이 순서로 «약 99%」가 여기서 가려진다**: 80%+는 모델+연식(①②)만으로, 나머지는 «생산기간 겹치는 것만» 원문 대조(영/한 감안). **연식 없음·원문도 애매한 ~1%만 검수대기.** 게이트 셋이 오매칭·비-F03를 구조적으로 막는다.

## 4. 원자 확정 (차량번호 = 스파인)

**신원은 한 번 확정하면 영원, 변동은 상태·대여료뿐.**

```
차량번호별 원자(영원·잠금): 원산지·제조사·모델·세부모델·세부트림·배기량·연료·구동·인승·색상·배터리
                          ← 엔진이 원문+F03+연식으로 도출
변동(라이브, 매시간): 차량상태 · 대여료 (· 주행거리)
```

- **자동후보** = F03 실재 형태 + 연식 세대 확정 + 제원 충돌 없음 → **원자 확정**(신원 잠금).
  - ★**원천 = `자동확정(F03+연식)`** (사람확정 아님 — Codex NO-GO 회피, 정직한 이력). 근거·시각 기록.
- **검수대기** = F03에 없음 · 세대 안 갈림 · 원문 부족 · 제원 충돌 → **확정 안 함, 원문 그대로**(안전). 사람 나중.
- **신규차** → 엔진 도출 → 자동후보면 그 자리서 원자 확정(1회) → **다음부터 신원 재도출 안 함**(잠금).
