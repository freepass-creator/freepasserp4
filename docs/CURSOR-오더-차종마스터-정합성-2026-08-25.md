## Codex 시트·매뉴얼 검수 — 2026-08-26 (읽기 전용)

검수 대상은 Google 작업 시트 `차종마스터 신규`(`1oMB9eoNnQFxUyRK4CSxYh_hKrtCf7s_79xLs-GYwXCE`)의

### 합격한 구조 검사

- 차종마스터 1,102행: 원산지·제조사·모델·세부모델·세부트림 필수값 누락 0건.
- 완전 중복과 공백/대시/대소문자를 무시한 중복 0건, 괄호 표기 0건, 앞뒤·연속 공백 0건.
- 기아 세부모델의 `N세대` 잔존 0건. `모델 모델 개발코드` 같은 이중 모델명도 0건.
- 제원마스터 114행: 빈값·중복 0건. 허용 축은 연료·배기량(cc)·구동방식 세 가지로만 구성됨.
- 전기차배터리마스터 49행: 동일 제조사·모델·세부모델·kWh 중복 0건, 차종마스터에 없는 세부모델 참조 0건.

### 수정 전 반드시 해소할 규격 오류 — **차단**

`docs/차종마스터-엔카작업시트-매뉴얼.md`는 "세부모델 개수 = 엔카 iNav와 1:1" 및
"기아만 N세대→개발코드"라고 한다. 그러나 `안내` 탭의 세부모델 설명은
"개수 1:1 강제 아님 · FL분할(엔카 미분리) · G80→G80 DH"라고 적혀 있다.

이는 사용자가 확정한 **엔카 모델·세부모델·세부트림 표기 그대로, 기아만 개발코드 예외**와 양립하지 않는다.
`안내` 탭 문구를 최신 규칙으로 고치고, FL 분할·G80 DH 같은 비기아 별도 가공 행이 있는지 엔카 원문과 재대조하기 전에는
“엔카 1:1 검수 합격”으로 표시하지 않는다.

### 보류 항목 (근거 확인 필요, 자동 수정 금지)

- 배터리 12행은 kWh·근거가 모두 비어 있다(아이오닉 일렉트릭 2, 쏘울 EV 2, KG모빌리티 3,
  조에·트위지 2, 볼트 계열 3). 매뉴얼은 공식 제원이 없으면 kWh 공란을 허용하므로 오류로 단정하지 않는다.
  다만 공란 사유/근거도 없으므로 `공식 미확인`으로 명시하거나 공식 근거를 채운 뒤 확정한다.
- 세부트림 18행에 연료·배기량·구동으로 보이는 글자가 포함된다. 현재 매뉴얼은 이런 제원 글자를 트림에서 빼라고 하지만,
  사용자의 최신 "엔카 세부트림 동일" 원칙과 충돌할 수 있다. 각 행이 실제 엔카 트림 원문인지부터 확인하고,
  원문이면 보존·원문이 아니면 정리한다. 추측으로 삭제하지 않는다.
- 이 작업 시트에는 엔카 원문 행/스냅샷/조회일이 같이 남아 있지 않다. 따라서 구조 검사는 통과했어도
  1,102행 전체가 엔카와 1:1이라는 사실은 아직 재현 가능하게 증명되지 않는다. 차종별 엔카 조회 기준(조회일·대상·원문명)을
  작업 이력에 남긴 뒤에만 이 항목을 합격 처리한다.

## 절대 규칙

- 차종마스터·mf- 키 쓰기는 Cursor만 한다.
- 이름·제원 정본은 `public/data/vehicle-master.json`, 영구 트림키 정본은 `data/vehicle-trim-key-registry.json` 및 라이브 원장이다.
- 기존 `mf-` 키를 삭제·재사용·의미 변경하지 않는다. 오기 때문에 실제 차량 의미가 달라진다면 기존 행은 `제외`로 보존하고 새 키를 만든다.
- 정제칸은 마스터 값을 그대로 옮긴다. 판매시트·ERP·공급사 원문 칸에서 역으로 고치지 않는다.
- 모델/세부모델/세부트림/연료/배기량/구동/인승을 추측하지 않는다. 후보 복수나 근거 부족이면 빈칸/보류다.

## 작업 순서

1. `docs/상품리스트-연동.md`, `lib/domain/vehicle-master-playbook.ts`, `docs/VEHICLE_MASTER_KEY_CONTRACT.md`를 다시 읽는다.
2. 마스터 보강 후보별 공식 근거와 차량번호 원문을 확인한다. 기존 키 의미 변경이 필요한 후보는 즉시 보류한다.
3. 마스터 변경 후 아래를 모두 통과시킨다.

```powershell
npm.cmd run audit:vehicle-trim-keys
npm.cmd run check:vehicle-trim-master
npx.cmd tsx scripts/sim-grandeur-2026-contract.mts
npx.cmd tsx scripts/check-vehicle-master-lock.mts
```

4. 먼저 dry-run을 다시 실행한다.

```powershell
npx.cmd tsx scripts/fill-supplier-ai-columns.mts --include-mirror
```

5. 실제 정제시트 반영은 대상·셀 수·덮어쓰기 목록을 사용자에게 직전 보고하고 승인받은 뒤에만 `--apply` 한다. 반영 후 같은 dry-run과 `npm.cmd run audit:axes`로 재조회한다.

## 주의

- `연카`는 정제칸이 없다는 최초 감사 결과와 달리, 2026-08-25 직전 dry-run에서 이미 `재고` 탭에 모든 정제칸이 있는 것으로 확인됐다. 열 추가 작업은 하지 말고, 먼저 현행 헤더를 재조회한다.
- `audit-refine-vs-master.mts`는 엔카 시트를 이름 사전으로 보는 구형 감사이므로, 현행 매뉴얼 정본 판정에 단독 사용하지 않는다. `fill-supplier-ai-columns` dry-run과 영구키 계약을 기준으로 삼는다.
- 이 메모 작성 이후 시트가 바뀔 수 있으므로, 적용 직전에 라이브 원장·대상 정제시트를 재조회한다.

## 추가 독립 검토 (2026-08-25)

## 최종 방향 전환 — 시트 우선, 엔카 명칭 우선 (2026-08-25 사용자 확정)

이 절은 위의 이전 메모와 충돌할 경우 **항상 우선**한다.

- `public/data/vehicle-master.json`은 더 이상 차종명 정본·보정 사전·정제시트 입력으로 쓰지 않는다. 기존 파일을 기준으로
  `fill-supplier-ai-columns`를 다시 실행하거나, 시트 이름을 덮어쓰면 안 된다.
- 작업 순서는 **엔카 기준 차종마스터 시트 정리 → 정제시트 정제칸 반영 → 시트 확정본을 코드 산출물로 생성**이다.
  코드 JSON은 시트의 결과물이며, 시트보다 앞선 정본이 아니다.
- 모델·세부모델·세부트림은 엔카 표기와 개수까지 1:1로 동일하게 쓴다. 임의 축약·확장·별칭 치환·우리식 이름 만들기는 금지한다.
- 유일한 명칭 예외는 **둘뿐**이다. 정본 표: `docs/차종마스터-엔카작업시트-매뉴얼.md` 「예외 — 이 둘만」. ① 기아 `N세대`→개발코드 ② 우리 시트만 `G80 DH`. FL 분할은 예외가 아니다.
- 엔카 행키(M/SM/T)는 이름을 대체하는 값이 아니라, 확정된 엔카 이름과의 1:1 대응·추적용이다. ERP 차종코드는 이 작업에서 건드리지 않는다.

### Cursor 실행 전 확인할 결함/보완점

1. `scripts/fill-supplier-ai-columns.mts`는 우리 로컬 `vehicle-master.json`을 채움 사전으로 쓰는 기존 흐름이다.
   이번 방향에는 사용 금지다. 기존에 실행된 결과가 있다면, 적용 범위와 변경 셀을 먼저 엔카 차종마스터와 대조해
   잘못된 명칭만 되돌림 후보로 목록화한다. 추측으로 일괄 되돌리지 않는다.
2. `scripts/stamp-encar-codes-on-supplier.mts`는 현행 주석대로 M/SM/T 행키만 찍고 모델·세부모델·세부트림 글자는 쓰지 않는다.
   따라서 이 스크립트만으로는 이번 요구사항을 충족하지 못한다. 엔카의 세 개 명칭을 그대로 반영하되,
   기아 `N세대 → 개발코드`와 우리 시트 `G80 DH` 두 예외만 적용하는 별도 dry-run/적용 경로가 필요하다.
3. `scripts/audit-refine-vs-master.mts`는 엔카 시트를 읽지만 `세부트림` 동등성을 검사하지 않는다.
   모델·세부모델·세부트림 세 축 모두에 대해 `엔카값 / 현 마스터값 / 현 정제칸값 / 판정근거`를 출력하도록
   **쓰기 없는 감사부터** 보완한다. 기아 예외는 감사 출력에서 원본 엔카명과 변환 후 표기를 함께 남긴다.
4. 동명이인·복수 후보·엔카에 없는 값은 빈칸/보류로 남긴다. `vehicle-master.json`, 원문 차명, 코드 토큰으로
   정답을 추측해 자동 채우지 않는다. 확정 근거가 있는 행만 차종마스터 시트에 반영한다.

### 권장 실행 순서

1. 엔카 차종마스터와 현 차종마스터 시트를 재조회하여 세 축 불일치·누락·중복을 **dry-run 목록**으로 만든다.
2. 목록을 사용자에게 보고하고 승인받은 범위만 Cursor가 차종마스터 시트에 수정한다.
3. 확정된 차종마스터를 기준으로 공급사 정제시트에 반영한다. 대상·셀 수·덮어쓰기 목록은 적용 직전에 다시 제시한다.
4. 수정 후 시트 재조회로 엔카 1:1 일치(기아 예외 포함)와 행키 연결을 검증한다.
5. 그때의 확정 시트만 코드 산출물로 생성하고, 코드가 시트와 같은지 재검증한다.

### 1. 회귀 테스트와 표준 생성기의 파워트레인 표기가 갈림 — **먼저 판정 필요**

- `npm run audit:vehicle-trim-keys`: PASS (2,086행, 영구키 계약 위반 0).
- `npm run check:vehicle-trim-master`: PASS (라이브 시트와 산출물 드리프트 0).
- 그러나 `npx tsx scripts/sim-grandeur-2026-contract.mts`: FAIL.
- 원인: 표준 생성기 출력은 `FWD/AWD`이고, 이 시뮬레이션은 예전 `2WD/4WD`를 기대한다.
  - 실제: `가솔린 2.5 FWD`, `가솔린 3.5 AWD`, `하이브리드 1.6T FWD`
  - 테스트 기대: `가솔린 2.5 2WD`, `가솔린 3.5 4WD`, `하이브리드 1.6T 2WD`

의견: 마스터 행이나 영구키를 다시 바꾸지 말고, `lib/domain/vehicle-powertrain-label.ts`의 현재 파생 규칙과
운영 매뉴얼(파워트레인은 차명 축에서 폐지)을 먼저 정본으로 확정해야 한다. 그 뒤 회귀 시뮬레이션의 기대값을
현재 정본 표기로 고칠지, 파생 라벨 규칙을 되돌릴지 한쪽만 선택한다. 둘을 섞어 두면 매번 재생성 때 산출물이 달라진다.

### 2. 이름 사전(`vehicle-master.json`)은 모순은 없지만, 활성 재고 기준 보강이 필요함

`npx tsx scripts/audit-vehicle-master-identifiers.mts` 결과:

- 최근 10년 생산 가능 세부모델 1,032개, 명백한 모순 0건.
- 다만 월 생산기간 1,032건, 개발코드 700건, variant 182건, 정확 배기량 1,996건,
  구동 1,354건, 인승 1,570건, 트림 39건이 비어 보강 대기다.

의견: 전 차종을 한 번에 추정 보강하지 말고, 위 전수 dry-run에서 나온 **실제 재고 55개 세부모델 없음·91개 트림 없음**부터
공식 근거로 우선 보강한다. `기타`·수출형·미판매 차종은 활성 재고에 등장하기 전까지 보류한다.

### 3. 감사 도구의 정본 혼선

`scripts/audit-refine-vs-master.mts`는 엔카 「차종마스터 신규」 시트를 이름·제원 사전으로 읽는다.
현재 운영 매뉴얼은 이름 사전을 `public/data/vehicle-master.json`으로 정한다. 이 감사는 구형 비교 참고용으로만 두고,
수정 대상 판정·자동 적용 게이트에는 사용하지 않는다. 필요하면 이름을 `audit-refine-vs-encar-reference`처럼 바꾸거나
출력에 "현행 정본 판정용 아님"을 명확히 표시한다(사용자 승인 후).
