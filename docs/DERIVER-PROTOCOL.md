# 판별기 프로토콜 — 각 AI가 «자동으로» 자기 표를 내는 방법

> 사장님(2026-08-29): 「커서랑 코덱스가 그걸 **자동으로** 할 수 있게. 각자한테 자동으로 할 방법이 있을 거야.」
> 상위 설계 = `CONSENSUS-CONFIRM-MANUAL.md` · `PLAN-jeongje-confirm-2026-08-29.md` v2. Codex NO-GO 반영.

## 0. 핵심 발상 — «살아있는 AI»가 아니라 «AI가 짠 판별기»

매시간 4개 AI를 살려서 돌리는 건 비싸고 흔들린다. 대신:

```
각 AI가 «자기만의 판별기(deriver)»를 «한 번» 짠다 (서로 다른 알고리즘·데이터경로)
  → 그 판별기 4개가 «매시간 저절로» 돈다 → 같은 차종코드를 3+ 개가 내면 = «3+ AI 합의» = 확정
살아있는 AI는 «합의 안 된 차(검수대기)»에만 부른다 (2단계).
```

이게 «자동»의 진짜 뜻이다. 4개 독립 구현이 같은 답 → N-버전 교차검증(강한 신호). 하나라도 다르면 자연히 검수대기로 빠진다.

## 1. 판별기 계약 (4개 공통)

각 판별기 = 순수 함수. **입력은 원문뿐, 남의 표를 못 본다**(독립 보장).

```
입력:  { 차번, 원문차명, 원문연료, 원문배기량, 원문구동, 원문인승, 공급사명 }   ← 오직 원문
출력:  { 차종코드 | null, 근거:"원문의 무엇을 보고", confidence }
규칙:  · 원문에 근거 없으면 null(빈칸). 지어내면 안 됨 → 합의 깨져 검수대기로 감(그게 정상)
       · 남의 열/집계 결과 읽기 금지. 읽으면 «독립»이 죽어 교차검증 무의미
       · 자기 열에만 쓴다. 집계열(합의수·확정코드·검증상태)은 안 건드림
```

써지는 곳 = 상품마스터 「AI합의」 탭, 자기 코드열 하나. (탭 스키마 = CONSENSUS-CONFIRM-MANUAL §2)

## 2. 4개 판별기 — «서로 다른 경로»라야 의미 있다

| AI | 판별기 파일 | 독립 경로(달라야 함) |
|---|---|---|
| **Claude** | `scripts/derive-claude.mts` | `snapToMaster`(엔카/프리패스 별칭사전) → 코드 |
| **Cursor** | `scripts/derive-cursor.mts` | `vehicle-master-playbook` 규칙 직접 매칭(트림 정규식) → 코드 |
| **Codex** | `scripts/derive-codex.mts` | 독립 파서(제조사·모델·트림 토큰화, 적대적: 애매하면 null) → 코드 |
| **Gemini** | `scripts/derive-gemini.mts` | 마스터 역인덱스 최장일치 → 코드 |

★4개가 «같은 로직 복붙»이면 교차검증이 아니다. **일부러 다른 방식**으로 짜라 — 그래야 한쪽 버그를 다른 쪽이 안 따라간다.

## 3. 자동 실행 — 시간잡에 끼운다

집계기(=`confirm-lock.mts` 개편판, Cursor 소유)가 매시간 순서대로:

```
③‴ 판별  : 4개 판별기 실행 → 각자 「AI합의」 탭 자기 열에 코드+근거 write (원문만 입력)
③⁗ 집계  : 차번마다 «같은 코드» 표수 → 3+ = 확정후보 · <3 = 검수대기
③⁵ 감사  : 「기존 확정」 전부를 감사기로 재검사 — 코드함의 제원 ↔ 원문 제원, 역검증
            모순 발견 → 자동 철회(확정→'오류격리'·원천='자동철회'·백업) → 재도출 큐   ← 교정(CONSENSUS §8)
③⁶ 확정  : 확정후보(신규 + 재도출 통과분)를 상품마스터 「검증상태=확정·차종코드·원천='AI합의 N/4'·확정시각」 으로 이관
            ★쓰기 = Cursor 규칙 · 대상행 백업 · 실행ID · 실행 후 재읽기 검증 (Codex NO-GO)
```

- **교정은 검토와 다르다** — ③⁵ 감사가 «틀린 확정을 자동 철회»한다(검토만 X). 철회=락 해제라 안전, 재확정은 ③⁶ 게이트 통과라야. 상세 = CONSENSUS-CONFIRM-MANUAL §8.
- 같은 차번 N회 철회 → 자동 재도출 멈추고 사람 에스컬레이션(마스터 의심).
- 선행(Codex #4): F01 4탭·68열 매뉴얼 드리프트(`npm run check:sync`) 통과 전엔 ③⁶ 금지.
- 읽기 실패한 판별기가 하나라도 있으면 그 실행은 실패 → ③⁶ 안 함(운영매뉴얼 §4).

## 4. Cursor — 자동으로 할 일 (2가지)

1. **판별기 저작+유지**: `scripts/derive-cursor.mts` 를 짠다(§2 경로). 마스터/플레이북 바뀌면 갱신. 한 번 짜두면 매시간 저절로 돈다.
2. **확정·철회 쓰기(mf-코드=커서 전용)**: ③⁶ 확정 + ③⁵ 감사의 «자동 철회(격리)» 를 구현·소유. **반드시** — 대상행 백업 → write → 재읽기 대조 → 실행ID·시각 로그. 원천은 확정='AI합의 N/4'·철회='자동철회'(사람확정 아님).
3. **감사기 구현**: `scripts/audit-confirmed.mts` — 확정값의 «코드 함의 제원 ↔ 원문 제원» 모순·역검증(CONSENSUS §8). Claude 설계, Cursor 구현. 모순 → 철회 트리거.
   - `.cursorrules` 에 이 프로토콜 경로를 박아, Cursor 세션이 열릴 때마다 «먼저 읽는다».

## 5. Codex — 자동으로 할 일 (2가지)

1. **판별기 저작(적대적)**: `scripts/derive-codex.mts` — 독립 파서. **애매하면 null**(다른 셋과 일부러 안 맞춤). 이게 «반대표» 역할이라 오합의를 깬다.
2. **검증만, 쓰기 없음**: 집계 후 A(오매칭0)·B(구멍)·C(중복0·차번집합정합) 전수검증 → `docs/crosscheck/` 에 판정 append. **Codex는 확정을 못 쓴다**(NO-GO 재발 방지). 코드 수정도 커서.
   - 자동 트리거: `codex exec --cd C:\dev\freepasserp4 "docs/DERIVER-PROTOCOL.md·CONSENSUS-CONFIRM-MANUAL.md 읽고, 최신 「AI합의」 집계 A/B/C 검증해서 crosscheck에 append"` 를 시간잡 뒤에 건다.

## 6. 2단계 — 합의 안 된 차(검수대기)

<3 합의로 남은 차(예: 싼타페 후보2)만:
- 사람이 「AI합의」 탭에서 4표를 나란히 보고 고른다(원천='사람확정'), 또는
- 살아있는 AI 한 번(커서 컴포저/codex exec)에게 «이 차만» 원문 재검토 시킨다.
- 명백한 다수는 손 안 감. 애매한 소수만 사람/라이브.
