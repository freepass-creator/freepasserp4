# 수정이력 — 공급사 시트

> 기계가 공급사 시트 구조를 바꿀 때마다 여기에 쌓는다. 새 것이 위.

## 2026. 8. 21. 17시 44분 · 비공개 필드 연동 수정안 미적용

17:38 수정안은 공개·비공개 노드를 한 transaction으로 묶는 방식이었다. 독립 검토에서 **시트가 비공개 원가·VIN 필드를 새로 쓸 수 있는 경로**와 `v4` 전체 transaction의 과도한 경합 위험이 확인되어, 코드 변경을 되돌리고 운영 데이터에는 적용하지 않았다.

다음 조치 — 시트는 계속 비공개 필드를 쓰지 못하게 유지한다. 별도 설계에서 “공개 재고 반영”과 “기존 비공개 값 보존”을 분리하고, Firebase 에뮬레이터로 원자성·경합·고아 private 레코드 회귀검증을 통과한 경우에만 배포한다.

## 2026. 8. 21. 17시 38분 · 상품마스터 → ERP 비공개 필드 동기화 차단 해소

원인 — 동기화가 기존 상품의 원가·수수료 등 비공개 필드를 다시 읽은 뒤, 공개 재고 변경과 함께 처리하지 못하고 **즉시 실패**했다. 이로 인해 빌린카(RP021_100신0001)·RP004(RP004_109호5628)·RP031(RP031_133호5391) 3건이 전체 자동연동을 막았다.

수정 — `lib/server/sheet-daily-sync.ts`에서 공개 상품과 비공개 상품을 `v4` 한 번의 CAS transaction으로 함께 반영하도록 변경했다. 비공개 값은 공개 `products` 노드에 쓰지 않으며, 기존 값은 보존한다.

검증 예정 — 타입검사와 상품마스터 시뮬레이션 후, 배포본에서 상품마스터 → ERP를 한 번 실행하고 481건·실패 0곳을 재확인한다. 되돌림은 이 커밋을 revert하면 된다.

## 2026. 8. 22. · ERP 신규 상품 생성의 private 필드 차단 오류 보정

증상: 상품시트 신규 행에 원가·VIN·계좌·수수료가 함께 들어오면, 신규 생성 경로만 공개 필드 정제를 거치지 않아 ERP 자동연동 전체가 중단됐다.

조치: 신규 생성도 기존 수정·삭제복구와 동일하게 `vehicle_price`·`vin`·`account_number`·가격의 `fee`·`commission`·`fee_memo`를 제거한 공개 데이터만 계획에 넣도록 변경했다. 수수료만 있던 가격 기간은 빈 객체로 남기지 않는다.

보안 경계: 상품시트의 private 값은 `products_private`에 쓰지 않으며, 서버 반영 경계의 private 쓰기 거부도 유지한다. 로컬 시뮬레이션으로 신규 private 필드 제거와 공개 대여료 보존을 확인했고, 실제 ERP·시트 반영은 별도 실행 전이다.
