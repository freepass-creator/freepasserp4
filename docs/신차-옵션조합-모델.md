# 신차 옵션 조합 모델 (배타그룹 · 최대구성) — 설계 스펙 v0

> 사장님 2026-09-06: 「이 차량에서 «최대 선택 가능한 옵션»이 뭐고 «배타그룹»이 뭔지 명확히 정의 못 하면 안 된다.
> 코덱스와 상의해 명확하게 만들어라.」

지금 파서는 제조사 「필수 선택 사양」을 전부 «필수»로 뭉개, 「GV80 쿠페 3.5 풀옵션 얼마」에 답을 못 한다.
제조사 PDF 는 조합 규칙을 «명시»한다(제네시스 G80: “엔진/구동/외장컬러 각 1개씩 선택, 기본/스포츠 중 1개 분류에서
휠·내장 선택”). 이 구조를 그대로 데이터로 세운다.

## 1. 용어 정의
- **배타그룹(exclusive group)** = «택1» 그룹. 그 안의 옵션 중 반드시 하나만 고른다. 예: 엔진(2.5T/3.5T), 구동(2WD/AWD),
  외장컬러, 휠&타이어, 내장디자인, 그리고 상위 «분류»(기본/스포츠). 각 옵션은 `addPrice`(기본=0, 나머지는 추가금).
- **자유선택(free option)** = 「선택 사양」. 원하는 만큼 추가. 각 `price`. 서로 `requires`(종속)·`excludes`(배타) 규칙 가능.
- **분류(variant class)** = 최상위 배타그룹(제네시스 기본/스포츠). 분류를 고르면 그 아래 배타그룹 후보가 달라진다(중첩 배타).
- **기본구성(base config)** = 각 배타그룹에서 [기본사양]을 고른 최저가 구성. `basePrice` = 그 가격.
- **최대구성(풀옵션)** = 각 배타그룹에서 «가장 비싼 유효 옵션» + 유효한 자유선택 전부. = 이 차의 «완전 최고 금액».

## 2. 데이터 스키마 (new_car_trim 또는 new_car_config)
```
{
  maker, model, sub_model, fuel,
  basePrice,                       // 기본구성 가격(모든 배타그룹 [기본사양])
  exclusiveGroups: [               // 배타 — 각 택1
    { group: '분류',     pick:1, options:[{name:'기본', addPrice:0}, {name:'스포츠', addPrice:… , onlyWith?}] },
    { group: '엔진',     pick:1, options:[{name:'가솔린 2.5 터보', addPrice:0}, {name:'가솔린 3.5 터보', addPrice:6600000}] },
    { group: '구동',     pick:1, options:[{name:'2WD(후륜)', addPrice:0}, {name:'AWD', addPrice:2800000}] },
    { group: '외장컬러', pick:1, options:[{name:'글로시', addPrice:0}, {name:'매트', addPrice:700000}] },
    { group: '휠타이어', pick:1, options:[…], onlyWithClass:'기본'|'스포츠', onlyWithEngine? },
    { group: '내장디자인', pick:1, options:[…] }
  ],
  freeOptions: [ { name, price, requires?:[…], excludes?:[…], onlyWithClass? } ],  // 선택 사양
  rules: [ 원문 조합 규칙 문자열 … ]              // 감사·표시용 원문
}
```
- **중첩 배타**: 휠타이어·내장디자인은 «분류(기본/스포츠)»와 «엔진»에 종속(onlyWithClass/onlyWithEngine). 그래서 유효 조합만 센다.

## 3. 최대구성(풀옵션) 계산 규칙
```
maxConfig(veh):
  # 분류를 포함한 배타그룹을 조합해 «유효하면서 가장 비싼» 경로를 찾는다(단순 그룹별 max 합산이 아니라,
  # onlyWith 제약 때문에 분류 선택이 하위 그룹 후보를 바꾼다 → 분류별로 계산해 큰 쪽).
  for cls in 분류.options:
     price = basePrice + cls.addPrice
     for g in 배타그룹(cls 에서 유효한 것):  price += max(g.options[유효].addPrice)
     price += Σ freeOptions(유효, 종속·배타 반영).price
     후보.push(price)
  return max(후보)     # = 완전 최고 금액
```
- 「기본사양」 여러 개가 같은 그룹에 있으면(파서 노이즈) 배타그룹 하나로 «접어» 중복 합산 금지.
- 구동(2WD/AWD)은 배타 — 둘 다 더하면 틀림(현 파서 버그: 선택에 「2WD 전용/AWD 전용」이 섞여 둘 다 합산).

## 4. 파싱 (제조사 PDF → 이 모델)
- **필수 선택 사양** 구역: 「엔진」「구동 타입」「외장 컬러」「휠 & 타이어」「내장 디자인」 헤더로 배타그룹 경계.
  각 헤더 아래 「옵션명 … [가격]/[기본사양]」이 그 그룹의 택1 후보.
- **분류(기본/스포츠)**: 「기본」「스포츠」 대분류 헤더로 중첩. 스포츠 아래 휠·내장은 onlyWithClass='스포츠'.
- **선택 사양** 구역: 자유선택. 「※ … 선택 시 … 적용/불가」는 requires/excludes 로 정규화.
- ★현·기아와 다름: 현대·기아는 트림계층(모던/프레스티지) → 트림별 옵션. 제네시스·수입 고급은 «기본+배타조합».
  모델별로 «트림형/조합형»을 구분해 스키마를 쓴다.

## 5. 코덱스에 확인받을 것
- 이 배타/자유/분류 3층 모델이 제네시스 PDF 구조를 «빠짐없이» 담는가(엔진·구동·컬러·휠·내장·분류·선택).
- 최대구성 계산이 onlyWith 제약을 옳게 반영하는가(단순 그룹 max 합산의 함정).
- 현대·기아 트림형과 제네시스 조합형을 «한 스키마»로 통합할지, «모델 타입」으로 가를지.
- GV80 쿠페처럼 «바디»가 또 하나의 배타축인 경우(쿠페 vs SUV) 분류 축을 어떻게 둘지.
