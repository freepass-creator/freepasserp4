## 0. 사장님 결정(2026-08-19)

- 회원가입은 **직접**(관리자는 연결·승인만) · 파트너사는 **우리가 생성** · 유형 = **공급사(렌트사) / 영업채널**.
- 파트너사관리는 **계약정책과 수수료정책을 입력하는 곳**이다 — 다른 화면으로 튀지 않는다.

## 1. 지금 화면 실측 — 왜 대충 느낌인가

현재 4패널 = 목록 | 기본정보 | 계약·정책 | 소속·운영 (`app/members/page.tsx:1064-1068`).

| # | 증상 | 실체 |
|---|---|---|
| 1 | 정책을 «입력»할 수 없다 | 「계약·정책」 패널은 상태 요약(전자계약 사용·회사정보 완성 배지·출고가능 차량 N·정책 N개)이고, 「정책 추가」는 `/policy?new=1&provider=…` 로 **화면을 떠난다**(`:873`). 등록한 정책은 칩 버튼으로만 보이고 누르면 또 `/policy` 로 간다(`:884`) |
| 2 | 수수료가 연동 설정에 묻혔다 | 「소속·운영」 패널에 공급사 수수료율이 구글시트 URL·gid·헤더행·어댑터·보증금규칙 사이에 끼어 있다(`:906-912`, `operationFields :690`) — 돈 규칙과 데이터 파이프 설정이 한 묶음 |
| 3 | 계약 관련 값이 두 패널에 갈렸다 | 계약서 회사정보(대표자·대표번호·주소·대여사업등록번호·입금계좌)는 기본정보에, 「프리패스 전자계약 사용」은 계약·정책에 |
| 4 | 관리 도구가 패널 안에 섞였다 | 소속 회원 칩(`:898`) · 시트 매핑 초기화(`:1048`) · 민감정보 분리·개인채널 백필(`:995-1013`, 빈 상태에 노출) |
| 5 | 묶음 기준이 «일»이 아니라 «필드 순서» | `entities.ts` partner 필드 순서대로 basic/access/operation 에 나눠 담았다(`:685-691`) |
| 6 | 영업채널이면 패널이 비어 있다 | 「계약서와 계약정책은 공급사에서만 관리합니다」 한 줄(`:978`) — 영업채널에게 이 패널이 무엇을 해 주는지 없음 |

시트 연동 입력은 이미 **재고관리 › 시트 연동**(`components/SheetSync.tsx` 「매핑·URL 저장」이 partner `sheet_url` 등에 씀)에도 있다 — 파트너사관리와 **이중 입력**.

## 2. 설계표 — 공급사 기준

패널 이름 = `WorkPage` panes title. 모바일은 같은 4패널을 목록→상세 전환으로(규격 §4).

| 패널 | 묻는 질문 | 내용(위→아래) | 여기서 입력 |
|---|---|---|---|
| **목록** | 어느 회사인가 | 검색 · 유형 칩(전체/공급사/영업채널) · 「신규 파트너사」(관리자만). 행 = 상호(별칭) · 유형 배지 · 공급사: `정책 N · 수수료 X% · 전자계약 사용/미사용` · 영업채널: `소속 N명` | 생성 |
| **기본정보** | 이 회사는 누구인가 | ① 회사: 상호 · 별칭 · 유형 · 사업자등록번호 · 담당/연락처 ② **계약서 회사정보**(공급사만): 대표자 · 대표번호 · 사업장 주소 · 자동차대여사업 등록번호 · 입금계좌(은행·계좌·예금주) — 완성/미완성 N 배지 ③ 연결 현황(읽기): 소속 회원 N명(칩 → 회원관리 해당 회원) · 출고가능 차량 N대 · 재고 시트 연결됨/미연결 · 최근 동기화(입력은 재고관리 › 시트 연동) | ①② |
| **계약정책** | 이 회사 계약서엔 어떤 조건이 실리나 | 상단: **프리패스 전자계약 사용/미사용**. 그 아래 **이 회사의 정책 목록**(정책명 · 정책유형 · `발송가능 / 보완 N` 배지) + 「정책 추가」. 정책을 고르면 **같은 패널 안에서** 편집 — 섹션은 `/policy` 와 동일(정책 기본정보 → 심사 기준 → 운전자 자격 → 운행 조건 → 납부 조건 → 운전자 범위 → 포함 서비스·정산 → 보험 4(대인·대물 / 운전자·무보험차 / 자차 / 보험·사고 지원) → 주행·승계 → 해지·연체 → 반환·보관·회수 → 연장·인수·장치). 「계약회사」 칸은 이 회사로 고정. 읽기 → 수정 → 저장 규칙 = 정책관리와 동일 | 정책 전체 |
| **수수료정책** | 이 회사와 돈을 어떻게 나누나 | ① 공급사 수수료율(R1 공급사→프리패스, 0~1, 미설정이면 「기본 10%」 배지) ② 환수 조건(현재 정책 필드 `commission_clawback_condition` — §7-1) ③ 예시 계산: 월대여료 1,000,000원 기준 수수료 N원(정산 엔진 함수 재사용, 새 계산식 금지) ④ 변경 이력(언제·누가) | ①② |

- 패널 이름·순서·의미는 웹·모바일 동일(규격). 패널 안에 임의 KPI 줄 금지.
- 목록 행은 한 칸 한 원자(상호 / 유형 / 정책 N / 수수료 / 전자계약) — 텍스트 이어붙이기 금지.
- 「정책 추가」·정책 편집은 **정책관리(/policy) 페이지의 섹션·필드·검증을 그대로 쓰는 공용 컴포넌트**로 만든다(`PolicyForm` 추출). 편집기가 두 벌이면 한쪽이 낡는다.

## 3. 영업채널 유형일 때

| 패널 | 내용 |
|---|---|
| 기본정보 | ① 회사 · 연락처 ③ 소속 영업자 N명(칩) — ② 계약서 회사정보 없음 |
| 계약정책 | 「영업채널은 계약정책이 없습니다. 계약서 조건은 공급사(렌트사) 정책을 따릅니다」 한 줄 + 이 채널 소속 영업자가 최근 만든 계약의 공급사 분포(읽기, 있으면) — 패널 이름은 바꾸지 않는다(규격: 패널 의미 고정) |
| 수수료정책 | 채널 기본 영업지급율(R2 기본값 — **신규 필드, §7-2**). 지금은 회원별 `agent_payout_rate` 뿐이라 채널 단위 값이 없다 |

## 4. 등록한 정책은 어디에 보이나 (사장님 질문 답)

```
정본 위치   파트너사관리 › (그 공급사) › 계약정책 패널의 목록      ← 정책은 «공급사의 것»
횡단 조회   정책관리(/policy) 전체 목록  관리자=전사 · 공급사=자기 것   (같은 레코드·같은 편집기)
쓰이는 곳   재고관리(상품에 정책 연결 Select) · 계약서관리(회사 고르면 그 회사 정책만) · 손님 링크(정책값이 계약서에 실림)
```

## 6. 구현 순서 (Cursor)

1. `PolicyForm` 추출 — `/policy` 의 섹션·필드·검증·저장(provider 고정 규칙 `app/policy/page.tsx:279-333`)을 컴포넌트로. `/policy` 가 먼저 이 컴포넌트를 쓰게 바꾸고 회귀 확인(sim-policy-*).
2. `app/members/page.tsx` 파트너 탭 panes = `basic | policy | fee` 로 재배치(§2). 회원 탭 panes 는 손대지 않는다.
3. 목록 행 메타(정책 N · 수수료 · 전자계약) — 한 칸 한 원자.
4. 시트 필드 제거 → 재고관리 › 시트 연동에서 같은 값이 입력·저장되는지 확인 후 제거. 도구 2종 이동.
5. 검증: 정책 저장 시 `provider_company_code` 가 선택 회사로 고정되는가 · 영업채널 회사에서 정책 추가 불가 · 회원 탭 회귀 · 모바일 390 목록→상세 4패널 전환.

## 7. 결정 필요(사장님)

1. **환수 조건**을 정책별(현재)에서 회사별(수수료정책 패널)로 올릴지 — 손오공처럼 회사 단위 규칙이면 회사별이 맞고, 상품유형별로 다르면 정책별 유지.
2. **영업채널 기본 지급율** 필드 신설 여부(회원별 지급율의 기본값으로 쓰고, 회원 값이 있으면 회원 값 우선).
3. 시트 연동 입력을 파트너사관리에서 **완전히** 뺄지(재고관리 일원화) — 내 안: 뺀다.
4. 계약서 회사정보를 기본정보(내 안)에 둘지 계약정책 상단에 둘지.
