# 관리자 응대 페이지 (`/desk`) — 설계

2026-08-07 사장님 지시. 「관리자가 여러 영업자·여러 차 문의를 편하게 받을 별도 페이지」.

관련: `docs/ROLE_NAVIGATION.md`(역할별 동선) · `features/chat/room-filter.ts`(현 목록 규칙)

---

## 1. 왜 `/chat` 이 아니라 새 페이지인가

같은 방을 다루지만 **문법이 다르다.**

| | `/chat` 계약문의 | `/desk` 응대 |
|---|---|---|
| 무엇의 목록인가 | 내 대화 | **내가 처리해야 할 일** |
| 정렬의 뜻 | 최근에 온 것 | **오래 기다린 것** |
| 다 본 상태 | 읽었다 | **큐가 비었다** |
| 주인 | 영업자·공급사 | 관리자(운영자) |

관리자에게 필요한 건 대화함이 아니라 **대기함**이다. 같은 화면에 모드를 붙이면
«읽음 위주»와 «처리 위주»가 한 목록에서 싸운다.

**공급사는 시트로 관리한다(앱에 안 들어온다).** 그래서 계약 5단계의 «공급 몫»은
실제로 운영자가 처리한다 — 관리자의 큐는 곧 **공급 몫 대기열**이다.

## 2. 만들지 않는 것 — 부품은 전부 재사용

새로 만드는 것은 **큐 하나뿐**이다. 두 벌로 갈라지면 곧 어긋난다.

| 자리 | 재사용 |
|---|---|
| 3열 껍데기 | `components/WorkPage` |
| 대화 | `components/ChatThread` |
| 계약 | `components/ContractPanel` (`stepView="focus"`) |
| 파일 | `components/RoomFiles` |
| 안읽음 | `lib/domain/messaging` (`roomsWithUnread`·`unreadFor`) |
| 행 원자 | `features/chat/ChatRoomList` |
| **큐 판정** | **신규 `features/desk/queue.ts`** |

## 3. 큐 판정 — 이 페이지의 전부

`deskQueue(rooms, contracts, role)` = **순수 함수**. 방마다 계약을 찾아 다음 미완 체크를 본다.

| 상태 | 판정 | 행에 뜨는 «다음 할 일» |
|---|---|---|
| 계약 없음 + 마지막 말이 영업자 | **내 차례** | `첫 응답` |
| 다음 미완 체크 `actor === 'provider'` | **내 차례** | 출고응답 / 서류확인 / 입금확인 / 약정발송 / 출고완료 |
| 다음 미완 체크 `actor === 'agent'` | 영업자 대기 | `영업자 대기` |
| 계약 완료·취소 | 종료 | — |

**안읽음은 별도 축이다.** 내 차례가 아니어도 «말이 왔다»는 따로 뜬다.
(안읽음 = 말 걸었나 / 내 차례 = 일이 걸렸나. 섞으면 둘 다 못 쓴다.)

**정렬 = 오래 기다린 순** (마지막 영업자 발화 시각 오름차순).
최신순으로 두면 오래된 건이 영원히 목록 아래에 깔린다 — 응대의 정의에 어긋난다.

## 4. 화면

```
 내 차례 7 | 미확인 3 | 전체 24          ← 세그먼트(칩 아님, 큐 전환)
┌──────────────────┬────────────────┬──────────────┐
│ 김대리 · 123가4567 │                │ 계약 진행     │
│ 서류확인 · 2시간   │     대화       ├──────────────┤
│ "등록증 보냈습니다"│   (ChatThread) │ 파일 3       │
├──────────────────┤                ├──────────────┤
│ 박과장 · 45나6789  │                │ 매물 요약     │
│ 첫 응답 · 20분     │                │              │
└──────────────────┴────────────────┴──────────────┘
```

행 한 줄에 판단 재료를 다 넣는다 — **영업자 · 차번+차명 · 다음 할 일 · 기다린 시간 · 마지막 말 · 안읽음.**
관리자의 1순위 축은 «누가»(영업자)다. 매물이 아니다.

## 5. 진입

- 관리자 하단 탭의 `/chat` 자리를 `/desk` 로 바꾼다(`lib/tabbar.tsx` `appTabsFor`).
  관리자에게 정본은 응대다. `/chat` 은 URL로 남긴다(삭제하지 않는다).
- 뱃지 = **내 차례 수**(안읽음 아님). `lib/domain/menu-badges.ts` 에 `/desk` 키 추가.

## 6. v1에서 하지 않는 것 — 이유와 함께

- **담당 잡기(claim)**: 안읽음이 «편» 단위라 A가 읽으면 B에게도 사라진다. 관리자가 여럿이면
  중복 응대가 생긴다. 다만 지금 인원(1~2명)에선 과잉이라 안 만든다. 늘면 방에 `handled_by`.
- **목록에서 바로 승인 버튼**: 오클릭 하나가 계약 단계를 넘긴다. 승인은 계약 칸에서.
- **브라우저 알림**: 폴링 5초 + `fp:unread` 로 충분. 알림은 권한·소음 문제가 따로 붙는다.

## 7. 데이터

**새 필드 0 · 보안규칙 변경 0.** 전부 기존 `rooms`·`contracts` 에서 파생한다.
계약은 Map 1회(`contract_code`·`product_code` 색인) → 방당 O(1).

## 8. 완료 판정

- 관리자로 로그인 → `/desk` → 「내 차례」에 뜬 건을 처리하면 그 방이 큐에서 빠진다.
- 영업자가 새 문의 → 5초 안에 「내 차례」 +1, 탭 뱃지 +1.
- 영업자·공급사 계정에는 `/desk` 가 보이지 않는다(탭·직접 URL 모두 차단).
- `npx tsc --noEmit` 0 · `npm run check:tokens` 통과 · 큐 판정 단위 시험(계약 없음/공급 대기/영업 대기/완료).
