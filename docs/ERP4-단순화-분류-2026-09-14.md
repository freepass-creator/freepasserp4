# ERP4 단순화 분류표

기준: 2026-09-14, `feat/spring-atom-monitor` 작업 트리.  
목적: ERP4를 버리지 않고 **화이트라벨 공개 카탈로그만** ERP5 Firestore 소비자로 단순화한다.
내부 ERP·계약·정산·직원 로그인 전환은 현재 범위 밖이다. 이 문서는 **삭제 지시가 아니다**.
각 항목은 실제 소비자·외부 URL·운영 이력을 다시 확인한 뒤 별도 변경으로 진행한다.

## 원칙

- 정본·계약·정산·시트 원본·원자·감사 이력은 삭제하지 않는다.
- RTDB는 되살리거나 fallback으로 남기지 않는다. Firestore 대사가 부족한 경로는 `HOLD`다.
- URL을 없애기 전에 새 단일 화면으로 redirect/사용자 흐름 검증을 한다.
- 자동화는 삭제 전에 실제 스케줄러·GitHub Actions·Vercel Cron의 실행 대상을 확인한다.

## 1. 현재 범위 유지 — 화이트라벨 공개 카탈로그

| 영역 | 유지 대상 | 근거 |
|---|---|---|
| 화이트라벨 목록 | `/shop`, `/uniauto` | 브랜드별 공개 판매 목록이다. `/uniauto`는 도메인 연결 전 임시 bridge다. |
| 화이트라벨 상세 | `/q/[code]`, `/api/catalog/quote` | 이미 발행된 공유 링크와 카카오 미리보기의 공개 상세 경로다. |
| 공개 카탈로그 API | `/api/catalog/feed`, `/api/catalog/quote` | ERP5 READY 영수증 통과 뒤에만 ERP5 reader를 선택한다. |
| 브랜드 정본 | `lib/whitelabel.ts`, `WhitelabelFrame`, `components/shop/*` | 브랜드 표기와 공개 화면을 분리하는 최소 껍데기다. |

## 2. 이후 검토 — 기능을 버리지 않고 입구를 하나로

| 현재 중복 | 목표 | 선행 조건 |
|---|---|---|
| `/finder`와 `/erp5` 상품찾기 | `/finder`를 단일 상품탐색 화면으로, `/erp5`는 호환 redirect 또는 ERP5 업무 셸로 축소 | ERP5 Firestore 상품 소비자·로그인 경계가 실제 동작하고 상세/비교/공유 URL이 보존돼야 한다. |
| `/dev`, `/diag`, `/data-check`, `/audit`, `/spring`, `/connectors`, `/hub` | 관리자 전용 **운영센터** 한 곳으로 통합 | 각 화면의 점검·쓰기 동작을 읽기/실행권한으로 구분하고, 기존 deep link를 redirect로 보존한다. |
| `/contract`, `/esign`, `/erp5/esign`, `/erp5/contracts` | 계약/전자서명 업무 셸 하나 + 외부 서명/검증 URL 유지 | 계약 단계·권한·발송/취소 원자성을 실제 Firestore에서 재현한다. |
| 외부 견적 iframe `/sonogong`, `/welrix`와 `/estimate` | ERP4 내부 메뉴에는 “견적 도구” 한 입구만 두고 외부 앱은 링크/새 창으로 분리 | 각 서비스의 소유자·사용량·외부 URL 유지 필요성을 확인한다. |
| `/catalog`과 `/shop` | 공개 상점은 `/shop`을 정본으로 하고 `/catalog`은 호환 redirect로 축소 | 설정·공유 발행원이 `/shop`으로 바뀌고 기존 공개 링크를 재확인한다. |
| `/settlement/intake`과 `/settlement/board` | `board`를 정산 기본 진입점으로, `intake`는 명시적 접수 모드/딥링크로 축소 | 두 화면의 권한·월마감·원장 반영 동작이 동일하게 검증돼야 한다. |

## 3. 현재 범위 밖 보관/향후 후보 — 지금 삭제 금지

| 후보 | 현재 근거 | 안전한 처리 |
|---|---|---|
| ERP3/RTDB client·admin·shim·adapter | `lib/firebase/client.ts`, `lib/server/firebase-admin.ts`, `lib/server/firestore-ref-shim.ts` 등 | ERP5 소비자가 실제로 대체된 뒤 파일별 import 0·빌드·핵심 화면 검증 후 제거한다. 지금은 전환 HOLD다. |
| 숨은 RTDB 진단 화면 `/diag` | 메뉴 진입이 없고 `firebase/database`·`getRtdb`를 직접 연다 | 먼저 운영 URL/메뉴에서 격리한다. RTDB 의존 제거 전 파일 자체 삭제는 금지다. |
| 임시 공개 bridge `/uniauto` | `/shop`의 `ShopView`를 재사용하는 임시 주소다 | 실제 도메인 연결과 기존 URL 사용량 확인 뒤 redirect 또는 제거한다. |
| 외부 iframe 래퍼 `/sonogong`, `/welrix` | 자체 ERP 데이터가 아니라 외부 견적기를 감싼다 | `/estimate` 기능 대조 후 종료 안내/redirect만 남긴다. 외부 도메인을 차단하지 않는다. |
| 숨은 QA/개발 경로 `/dev`, `/m`, `/settlement/*/preview` | 운영 메뉴가 아닌 개발·미리보기 성격이다 | 운영 메뉴에서 분리하고 권한/노출 정책을 먼저 확인한다. 정산 preview는 금융 이력과 분리해 보존한다. |
| RTDB 전용 자동화 | `scripts/hourly-sync.cmd`는 스스로 ERP3 자동동기 중지라고 기록. RTDB URL을 주입하는 Actions도 존재한다. | 실제 Windows 작업 스케줄러와 GitHub Actions 실행 이력을 확인하고, ERP5 발행 체인으로 옮긴 뒤 workflow를 archive/삭제한다. |
| 깨진/옛 Actions | 현재 workflow가 없는 스크립트들을 참조하는 경우가 있다. | 실행 이력과 기본 브랜치를 대조해 먼저 비활성화하거나 ERP5 체인으로 교체한다. 실패한 workflow를 조용히 삭제하지 않는다. |
| 과거 감사·이관 스크립트 | `scripts/`가 786개, npm 명령이 145개다. 과거 이관·복구는 실행 시 데이터에 영향을 줄 수 있다. | `scripts/legacy/`로 git 보관하고 `README`에 목적·마지막 실행·대체 명령을 남긴 뒤 package/workflow 참조를 제거한다. |
| `tmp/` 스냅샷·수동 도구 | 로컬 생성물에는 이관 스냅샷·복구 증적이 섞여 있다. | 보존기간과 해시를 정해 archive한 뒤에만 개별 삭제한다. 광역 삭제 금지. |

## 4. 지금 하지 않을 것

- 계약·정산·차량·정책·감사 데이터 삭제
- ERP5 대사 전 Vercel Firebase 환경변수 전환 또는 배포
- 내부 ERP·계약·정산·직원 로그인 데이터 경로 변경
- RTDB 재활성화/폴백 복구
- “참조가 적다”는 이유만으로 외부 영업 URL이나 GitHub Actions 삭제

## 5. 권장 실행 순서

1. ERP5 원자 담당이 상품 71건 및 공개 카탈로그 필요 컬렉션의 대사 PASS를 영수증으로 남긴다.
2. ERP4 화이트라벨에서 목록·상세·담당자 귀속·사진·정책을 ERP5 Firestore 데이터로 실제 검증한다.
3. 사용자 승인 뒤 화이트라벨 전용 환경변수와 서비스계정을 설정하고 배포한다.
4. 내부 ERP 전환·운영센터·RTDB migration debt 정리는 별도 범위와 검증으로 진행한다.

## 검토 근거

- 실제 데스크톱 메뉴 SSOT는 `components/TopBar.tsx`의 `GROUPS`, 모바일 진입은 `lib/tabbar.tsx`다.
- `/erp5`는 이 메뉴에 노출되지 않은 병행 워크스페이스다. 전환 준비용으로 보관하며,
  `EsignSendCenter`를 같이 쓰는 `/erp5/esign`과 `/esign`부터 하나로 합치는 것이 안전하다.
- 이 분류는 코드의 라우트·import·내부 링크를 기준으로 했다. 외부 공유 URL 사용량과 실제 화면 이용량은
  아직 확인하지 않았으므로, 후보의 redirect/삭제 전에는 운영 로그와 사용자 흐름을 다시 확인한다.
