# 2026-09-16 — 손오공·오토플러스 판매탭 라우팅 결정

## 판매시트 탭 원칙

1. **손오공은 별도 탭을 유지한다.**
   - 기본 판매탭과 섞지 않는다.
   - 현재 코드의 `손오공구독` 갈래를 유지한다.

2. **오토플러스는 별도 탭을 유지한다.**
   - 기본 판매탭과 섞지 않는다.
   - 현재 코드의 `오플구독` 갈래를 유지한다.

3. **손오공 중고렌트는 새 탭을 만들지 않는다.**
   - 손오공 중고렌트 재고는 `손오공구독` 내부의 **반납형 갈래**에 합류시킨다.
   - 즉 `손오공중고렌트` 같은 신규 판매탭을 추가하지 않는다.
   - 판매/ERP 쪽에서는 손오공 반납형 상품군으로 취급한다.

4. **인수형은 기존 손오공 인수형 갈래를 유지한다.**
   - 중고렌트를 이유로 인수형 구조를 변경하지 않는다.

## 현재 코드와의 관계

현재 `lib/domain/sales-published-tabs.ts`는 다음 판매탭을 선언한다.

- `상품리스트`
- `손오공구독`
- `픽업구독`
- `오플구독`

그리고 `손오공구독` 안에는 이미 `N개월 반납형`과 `N개월 인수형` 요금 블록이 존재한다.
따라서 이번 결정은 새로운 탭 구조를 만드는 것이 아니라, **손오공 ERP/API에서 확인되는 중고렌트 재고를 기존 `손오공구독` 반납형으로 라우팅**하는 규칙을 추가하는 것이다.

## 구현 시 주의

- 손오공 ERP/API의 **중고렌트 버킷 식별자/필드명은 코드·실데이터로 확인한 뒤 연결한다. 추측하지 않는다.**
- 버킷을 찾았다고 새 판매탭을 만들지 않는다.
- 원천은 계속 `RP012` 손오공 ERP API이며, 판매탭 라우팅은 원천 SSOT와 별개의 projection/presentation 규칙이다.
- 오토플러스 `RP023` 원천은 계속 RebornCar이며, 별도 `오플구독` 탭 유지 원칙과 혼동하지 않는다.
