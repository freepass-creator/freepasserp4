## 1. 목록

- **얼룩무늬(지브라) 안 쓴다.** 행 경계는 하단선(hairline) 하나로 충분하다.
  - `app/globals.css` — `.fp-card-row:nth-child(even)` 규칙은 **주석 상태로 둔다**
  - ⚠ 인라인 `background` 를 행에 칠하지 않는다. 인라인은 클래스를 이겨서, 나중에 무엇을 켜도 안 먹는다
- **검색창 주변은 흰 바탕.** 회색 금지.
  - `.fp-page-toolbar`(모바일) 와 `.fp-finder-toolbar`(웹) **둘 다** `--bg-card`
  - 두 줄은 같은 자리다. 한쪽만 고치면 반드시 되돌아온다

## 2. 카드 (목록 카드 · 상품 간단보기 — 둘이 같은 규격)

```
┌────────────────────────────────┐
│ 사진                  [출고가능][중고렌트] │ ← 뱃지 = 상태·상품구분. 사진 우하
├────────────────────────────────┤
│ 아반떼 CN7 인스퍼레이션            │ ← 이름 = 정제 세부모델 + 세부트림
│ 12가3456 · 2024년                │
│ 월 52만원  보증금 100만  [12~48개월] │
│ 📄무심사  🪙분납가능  👤만21세      │ ← 우대조건 줄. **심사조건이 맨 앞**
└────────────────────────────────┘
```

- **이름** = 정제칸(세부모델 + 세부트림). 공급사 원문을 이름으로 쓰지 않는다
- **차량번호 옆 원자 차례** = 연식 · 주행거리 · 연료 · 배기량(전기는 배터리용량) · 구동방식
  - 사장님 2026-08-28 「차량번호 옆으로 연식 주행거리 연료 배기량 … 배터리용량이나 구동방식
    순서대로 · **있는 거라도**」
  - **있는 것만.** 빈 칸은 구분자째 뺀다 — `-` 를 찍으면 그 폭 때문에 앞의 주행거리가 잘린다
  - 차례는 `specAtoms` 한 곳에서만 정한다. 예전엔 세 갈래가 각자 적어 연료가 목록에서만 빠졌다
- **모바일 목록에는 출고상태·상품구분을 세우지 않는다** (사장님 2026-08-28 「모바일에서
  출고가능 중고구독은 목록에서는 빼자고 했어 · 상세에만 넣고」). 좁은 줄에 붙으면 차명이 밀린다.
  웹 목록 행은 폭이 있어 그대로 세운다 — 같은 컴포넌트라도 자리가 다르다
- **상품구분 「픽업구독」은 「중고구독」이 아니다** (사장님 2026-08-28). 손오공 T카 재고에서 오는
  별개 갈래고 판매시트도 탭을 따로 낸다. 데이터는 338대가 「픽업구독」으로 잘 들어와 있었는데
  캐논(`PRODUCT_TYPES`)에 없어 화면에서만 「중고구독」으로 바뀌어 보였다
- **차량 신호(출고상태 · 상품구분) = 아이콘 + 글자.** 상자(박스 뱃지) 안 쓴다
  - 사장님 2026-08-28 「박스 뱃지 쓰지 말고 아이콘 텍스트 형태의 뱃지를 쓰자 · 우리도 기존에
    썼었지 · **모든 곳에서** 그렇게 하자」
  - 위는 상자, 아래(우대조건)는 아이콘+글자면 같은 성질의 값이 한 카드에서 두 문법으로 선다
  - 색은 **아이콘에만**, 글자는 먹색 — 우대조건 줄과 같은 규칙
  - 아이콘은 «값»이 아니라 «갈래»를 가리킨다. 출고상태만 상태에 따라 갈린다
    (살 수 있나 ○ / 기다려야 하나 ⏱ / 안 되나 ⊘)
  - 코드: `SignalMarks` — 렌더러는 우대조건과 **같은 `MetaIcon`** 을 쓴다(두 벌 만들면 또 갈린다)
  - 사진 위 한 덩어리 유리바는 그대로 — 그건 낱개 상자가 아니라 사진 위 가독을 위한 그릇이다
- **우대조건 줄** = **아이콘 + 글자**(상자 아님). 사장님 2026-08-20 「우대조건은 아이콘+텍스트지」
  - **맨 앞이 심사조건**(무심사·소득확인·신용조회) — 사장님 2026-08-28
  - 목록을 훑는 사람이 제일 먼저 거르는 값이 「살 수 있는 손님인가」다
  - **심사도 다른 우대조건과 똑같이 색 든 아이콘 + 글자.** 혼자 흑백으로 세우지 않는다
    (사장님 2026-08-28 「심사조건도 동일하게 해야지 · 아이콘 텍스트 구조로」 — 한 번 먹색으로
    따로 세웠다가 되돌렸다. 한 줄에 서는 값인데 혼자 다르면 «다른 종류»로 읽힌다)
  - 색은 이미 있는 `CREDIT_TONE`(무심사 초록 · 그 밖 amber)을 쓴다. 새로 정하지 않는다
  - 코드: `benefitSignals(p, { withCredit: true })` · 부르는 곳은 목록 행 2곳 + 간단보기 1곳

## 3. 상세

- **읽는 차례는 그대로** — 사진 → 차량스펙 → 대여료조건 → 보험조건 → 계약조건 → 기타사항
  - 사장님 2026-08-28 「순서는 큰 이슈 없어」 「**영업자도 사진부터 봐야지**」
  - 한 번 「영업자는 가격부터 본다」며 사진을 아래로 내리자고 했다가 바로잡혔다
- **같은 값을 두 번 찍지 않는다**
  - 「차명」 줄 없앰 — 맨 위 제목이 이미 정제 세부모델+세부트림을 든다
  - 「상품」 줄 없앰 — `RP014_188호3065` 는 공급사코드+차량번호라 「차량번호」와 겹친다
  - 정책코드는 관리자만
- **대여료표는 반납형 · 인수형을 갈라 세운다** (사장님 2026-08-28 「반납형 기본하고 인수형 정보가
  있으면 구분해서 써주기로 했잖아 · 구분되게」)
  - 기간 오름차순으로 섞으면 36개월 반납형 바로 밑에 36개월 인수형이 붙어, 조건 칸 넉 자를
    못 보면 «같은 상품의 다른 줄»로 읽힌다. 손오공 구독은 403대 중 386대가 인수형을 든다
  - **탭으로 감추지 않는다** — 영업자는 둘을 나란히 놓고 손님에게 고르게 한다
  - 인수형이 없는 차는 갈래 줄도 안 세운다
  - 갈래 판정은 `PricePlan.acquisition` **플래그**로. 조건 글자(「만기인수」)로 판정하지 않는다
  - **인수형에 위계를 한 단 더 준다**(사장님 2026-08-28 「인수형을 좀 더 위계를 줘서 구분을」):
    반납형 = 면 없이 회색 글자(기본이라 조용해도 된다) / 인수형 = 연회색 면 + 먹색 굵은 글자 +
    위쪽 진한 구분선. **새 색은 안 들인다** — 판매시트는 인수형을 보라로 칠하지만 그건 시트 규격이고,
    화면 색은 네이비 하나다(`DESIGN_COLOR_LADDER.md`). 위계는 무채의 세기와 굵기로만 준다
- **빈 값은 「미입력」** — 줄을 감추지 않는다. 안 채워진 것과 해당 없는 것은 다르다
- **없는 것은 지어내지 않는다** — 정책이 안 붙은 매물에 프리패스 표준을 채우지 않는다
  (자세한 내력은 `PRODUCT_DETAIL_SPEC.md`)

## 고칠 때 지킬 것

1. **화면을 못 보면 짐작하지 말고 여쭌다.** 스크린샷 한 장이 다섯 번의 헛수정보다 빠르다
2. **같은 값이 웹·모바일 두 줄로 나뉘어 있으면 둘을 같이 본다** (`.fp-page-toolbar` / `.fp-finder-toolbar`)
3. **차례·규격은 상수 한 곳에서만 정한다.** 부르는 쪽이 각자 적으면 한 곳만 고쳐지고 나머지가 남는다
4. **바꾸면 이 문서를 같이 고친다** — 그리고 `npm run check:design` 을 통과시킨다.
   검사를 지나가려고 검사를 지우지 않는다. 지울 만한 이유가 있으면 그건 사장님께 여쭐 일이다.
