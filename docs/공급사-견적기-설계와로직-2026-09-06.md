## 3. 원가 모델 (견적이 결정되는 곳)
### 공식
```
대여료(월, VAT포함) = 원가소계 ÷ 개월 × (1 + 마진) × (1 + VAT)
```
### 원가소계
차량감가(=차량가−잔존가, 최대원가) + 금융이자(대출90%·금리6.5%) + 취득세(렌트4/구독7%) + 공채 + **등록비 15만** + 자동차세(영업용) + 보험·자차충당(1.2%/년, 렌트) + 정비·GPS·주차 + 영업수당 + **손바뀜**.

### 마진 = 등급 공통 (직접비 기준)
- 신용으로 가격을 달리 매기지 않는다. 등급차는 **손바뀜(원가)**로만.
- **판관비(일반관리·간접비)는 원가에 안 넣는다** — 렌트사 몫. 손익엔 참고로만.

### 잔가 = 국산 표준 + 차종델타
- 국산 표준곡선(4년 **58%** 앵커): 1년85·2년75·3년66·**4년58**·5년51…
- 차종델타(±%p): 아반떼·그랜저 **+2**(→60) · 쏘나타 0 · 카니발 +5 · 대형 −6 · 제네시스 −4 · EV −8 · 수입 −8.
- 시세 흐름 바뀌면 **표준곡선 하나만** 조정 → 전 차종 반영.
- **연식**: 시세대비 잔존율 = 표준곡선의 (연식+약정)/(연식). 연식 필수.
- **주행거리**: **시세엔 페널티 안 붙임**(시세가 이미 반영), **잔가율엔 붙임**(미래 하락). §8-④.

### 손바뀜 (신용등급 = 마진 아니라 원가)
- 유지율: 정상 **97%** · 중신용 **75%** · 저신용 **30%**. 횟수 ≈ 1/유지율−1 (0 / 0.33 / 2.33회).
- 회당 **≈ 200~250만** = 상품화 50 + **왕복탁송 50** + 영업수수료(대여료×48×**3%**) + 휴차 1개월.
- 저신용은 **연체 즉시 회수(선물조건)** → 대손 ≈0, 안 넣음.

## 8. 설계 결정 (붙이기 전 확인·근거)
① **마진 등급 공통(10%)** — 목업의 「수익률=신용등급별」 표기는 폐기. 손바뀜을 원가에 넣은 이유가 마진 공통이라, 등급별 마진을 또 얹으면 이중부과. (손바뀜만으로 저신용 이미 +23%)
② **판관비 = 대여료 산정 제외, 손익 참고만.** 가격은 직접비 기준, 손익은 완전원가 — 두 축 분리. 원가설정의 「간접비 배분율」 칸은 「손익 참고」로 이름 변경(안 그러면 언젠가 채워져 대여료 8% 뜀).
③ **대손 칸 = 기본 0 + 경고.** 손바뀜과 겹침(휴차·재상품화·재영업수수료). 켤 땐 겹치는 것 빼기.
④ **주행 = 시세엔 X · 잔가율엔 O.** 두 문장을 한 줄로 못 박아야 다음 사람이 하나를 안 지운다.
⑤ **★견적 엔진은 하나.** welrix·sonogong·이 견적기 = 셋. erp4에서 `SETTLEMENT_STATES`·`AGENT_COL_GAP` 이 같은 이름 다른 값으로 갈렸던 사고처럼, **로직이 갈리면 손님에게 나가는 금액이 갈린다.** 잔가 리스트 새로 만들면 차종/중고/신차마스터 위 4번째 정본 생김. 편입 전 통합 방침 확정.
⑥ **위험한 값을 기본값에 두지 않는다.** 마진 1% 폴백처럼, 비면 사고 나는 값이 default면 안 됨.

## ★9. 노하우 · 함정 (구현 시 삽질 포인트 — 여기서 다 겪음)

1. **배포 URL이 둘로 갈린다** (§0-1). erp 임베드는 `sonogong-estimator.vercel.app`, 개편은 `freepass-estimator.vercel.app`. **화면이 "안 바뀐다"의 90%는 이것 아니면 캐시.** 먼저 「내가 보는 URL == 내가 배포한 URL」인지부터 확인.
2. **캐시**: HTML을 `Cache-Control: no-store` 로. 폰은 must-revalidate 를 무시하기도 한다. **테스트는 한 번도 안 연 새 경로**(예: `/calc`)로 — 그 URL은 캐시가 있을 수 없다. 홈화면 아이콘·즐겨찾기는 옛 걸 붙든다.
3. **12개월(1년) 상품**: 엔진 `RESIDUAL_TABLE`·`residualRates` 가 24/36/48/60 만 있어 12개월이 **NaN** 난다. 고침 둘 — ① `residualRates` 에 12 를 채운다(usedResidPct), ② `resolveResidualRate` 가 표에 없는 term 에서 `row[group]` 로 크래시하니 `row` null 가드.
4. **연식 이중반영**: 표준+델타 잔가는 usedResidPct 로 **연식이 이미 반영**됨. 그런데 `resolveResidualRate` 가 연식차감을 또 한다 → 1년식이 신차보다 잔가 높은 **역전**. `residualAgeBaked` 플래그로 연식차감을 끈다(주행·사고는 유지 여부 §8-④대로).
5. **주행 방향 함정**: "주행 많으면 잔가↓→감가↑→대여료↑"로 짜면 **거꾸로**다(대표: 주행 많은 차는 싸야지). 시세가 이미 반영하므로 **시세엔 페널티 X**, 미래하락은 **잔가율에만**. §8-④.
6. **마진 1% 폴백**: `DEFAULT_CONFIG.marginRate` 가 1%면 견적 수익이 사실상 0. 게다가 **RTDB에 저장된 값이 코드 기본값을 덮는다**(shallow merge) — 코드만 고치면 안 바뀐다. **[원가]탭에서 저장(RTDB 기록)** 해야 반영. 위험값을 기본값에 두지 말 것(§8-⑥).
7. **RTDB shallow merge**: `loadConfig = {...DEFAULT_CONFIG, ...snap}`. `setting` 객체가 통째로 교체되어, DEFAULT에 새 필드(예 regFee) 넣어도 저장본에 없으면 0. **관리자 한 번 재저장**이 필요.
8. **견적 엔진 하나**(§8-⑤): 잔가/원가 정본을 새로 만들면 마스터가 넷 된다. 갈리면 손님 금액이 갈린다.
