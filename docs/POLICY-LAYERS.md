# 정책 세 층 — 상품 · 영업 · 계약

2026-08-09 사장님 확정. 코드 SSOT 는 `lib/domain/policy-tier.ts`.

공급사 배포·동의 절차는 [`SUPPLIER_POLICY_AGREEMENT_MANUAL.md`](./SUPPLIER_POLICY_AGREEMENT_MANUAL.md)를 따른다.

---

## 왜 나누나

공급사마다 우리에게 맡기는 범위가 다르다.

```
상품만 공급하는 곳     매물·견적만 우리를 통하고 계약서는 자기가 쓴다
계약까지 맡기는 곳     계약서를 우리가 쓴다 → 해지·연체·위약금·보관료·통지기한까지
                      우리 정책이 들고 있어야 계약서가 완성된다
```

한 덩어리로 두면 양쪽 다 틀어진다.
상품만 맡긴 곳에 해지 조건을 채우라 하면 못 채우고,
계약까지 맡긴 곳인데 비워 두면 **빈칸 계약서가 나가거나 약관 조문이 공중에 뜬다.**

**전자계약은 「계약」 층까지 채운 공급사에만 나간다.**

---

## 층별로 무엇이 사는가

### 층 1 · 상품 (15항목)

매물·견적에 필요한 것. **상품만 공급하는 업체는 여기까지.**

```
약정 주행거리 · 1만km 추가 · 기본 운전자 연령 · 면허 경력요건
보험 포함 여부 · 정비 상품 · 운전자 범위(개인/사업자)
대인·대물·자손·무보험·자차 보상 · 자차 자기부담률 · 긴급출동
```

### 층 2 · 영업 (14항목)

영업사원이 상담에서 쓰는 **가격표**. 여기 있는 값은 «결정을 위한 계산 입력»이다.
**결정이 끝나면 요율은 소임을 다하고 결과만 계약서로 넘어간다.**

```
1만km 상향 10만원   →  월 대여료 750,000원          계약서에는 결과만
연령 하향 5.5만원    →  운전자 연령 만 21세 이상      계약서에는 결과만
```

요율을 계약서에 그대로 실으면 손님은 **「이걸 따로 더 내나」**로 읽는다.
사실상 이 층이 정하는 것은 **대여료와 운전 연령** 둘이다.

| 무엇을 결정하나 | 항목 |
|---|---|
| 월 대여료 | 1만km 상향 요금 · 연령 하향 요금 · 추가운전자 요금 · 탁송비 |
| 운전자 연령 | 연령 하향 가능 범위 · 연령 상한 · (하향 요금) |
| 등록 가능 인원 | 추가운전자 허용 수 |
| 납부 방식 | 보증금 분납 가능 회차 · 보증카드 · 결제방식 |
| **계약 승인 여부** ⚠ | 심사기준 · 신용등급 — **손님에게 절대 안 나간다** |
| (결정 아님) | 대여지역 · 수수료 환수조건 ⚠ |

`salesLevers(policy)` 로 「이 값이 무엇을 결정하는가」와 함께 뽑는다.

### 층 3 · 계약 (17항목)

**전자계약을 우리가 쓰는 공급사만** 채운다.
목록은 임의로 정한 것이 아니라 **약관이 계약서를 참조하는 자리**다 —
비면 그 조문이 아무것도 정하지 못한다.

| 묶음 | 항목 | 약관 |
|---|---|---|
| **돈** | 초과 주행요금(1km당) | 제15조 |
| | 지연손해금율 | 제3조 |
| | 보증금 반환기한(일) | 제4조 |
| | 물품 보관기간(일) · 보관료 | 제13조 |
| **제재** | 시동제어 연체일수 | 제11조 |
| | 자동해지 연체일수 | 제11조 |
| | 1년 이내 사고 누적(N회) | 제11조 |
| | 청구 기준(잔여료/위약금) | 제11·14조 |
| **만기** | 연장 사전통지기한(일) | 제2조 |
| | 인수 사전통지기한(일) | 제17조 |
| **실명** | 보험사 · 연락처 | 제9조 |
| | 지정 정비점 | 제7·9조 |
| | 자차 처리 제외 | 제9조 |
| | 대차 정책 | 제7조 |
| | GPS 장착 | 제10조 |

## 노출 딱지 — 이게 없어서 사고가 났다

항목마다 **어디까지 나가는가**를 못박는다.

| 딱지 | 뜻 |
|---|---|
| `internal` | 내부 전용 — 손님에게 **절대** 안 나간다 |
| `sales` | 영업 상담용 — 말로 전하되 계약서에는 안 실린다 |
| `quote` | 견적서에 나간다 |
| `contract` | 계약서·손님 서명화면에 실린다 |

**2026-08-09 실제로 새고 있었다** — 손님 서명화면에 「심사기준 : 중신용 이상」이 떴다.
우리가 그 사람을 어떻게 평가했는지를 본인에게 보여준 것이다.
같은 화면에 「대여지역 : 전국」·「보증금 3회 분납 **가능**」·「만 21세까지 하향 **가능**」도 있었다 —
전부 영업 단계의 말이지 확정된 계약 내용이 아니다.

화면·계약서를 만들 때 `isCustomerFacing(key)` 로 거른다.

## 상품상세 「자세히보기」 — ⚠ 아직 닫혀 있다

방향은 이렇다. **계약 정책을 채운 공급사는 상품을 고르는 자리에서 이미** 패널티·위약금·해지
조건을 보여준다. 계약서를 열어야 알 수 있던 것을 앞당겨 보이는 것이라,
**채운 업체가 더 투명한 상품**이 된다.

**다만 지금은 열지 않는다(2026-08-09 사장님 판단).**
정책이 다 채워지지 않은 공급사가 대부분이라, 반쯤 찬 조건이 먼저 나가면
「이 업체는 조건이 부실하다」로 읽힌다. 채울 시간을 준 뒤 켠다.

```ts
export const CONTRACT_TERMS_DETAIL_OPEN = false;   // ← 켤 때 이것만 true
contractTermsForDetail(policy, { viewer })
```

| 보는 사람 | 지금 | 열었을 때 |
|---|---|---|
| 영업자 `agent` | 안 보임 | **보임** |
| 관리자 `admin` | 안 보임 | **보임** |
| 공급사 `provider` | 안 보임 | 안 보임 — 자기 정책은 정책관리에서 본다 |
| 손님 `customer` | 안 보임 | 안 보임 — 별도 판단 필요 |

**먼저 영업자에게만 연다.** 손님에게 바로 열면 정책이 덜 찬 공급사가 손해를 본다.
호출부는 손대지 않고 플래그 하나만 바꾸면 된다.

```
[주행]      초과 주행요금(1km당)   200원 / 1km              (제15조)
[연체·정산]  지연손해금율          연 12%                    (제3조)
            보증금 반환기한        7일 이내                  (제4조)
            청구 기준             잔여 대여료                (제11·14조)
[제재]      시동제어 연체일수       3일 연체 시                (제11조)
            자동해지 연체일수       10일 연체 시               (제11조)
            1년 이내 사고 누적      3회 (과실 50% 이상)        (제11조)
[만기]      연장 사전통지기한       30일 전까지                (제2조)
            인수 사전통지기한       30일 전까지                (제17조)
[반환·보관]  물품 보관기간·보관료    30일 · 일 10,000원         (제13조)
[사고·정비]  보험사·연락처          DB손해보험 1588-0100       (제9조)
            지정 정비점 · 자차 처리 제외 · 대차 정책
[차량관리]   GPS 장착              장착                      (제10조)
```

상품만 공급하는 업체는 **빈 배열**이 나오고 「계약서는 공급사가 직접 작성」으로 안내한다.
내부 전용(심사기준·신용등급·수수료 환수)은 `exposure` 로 걸러져 **절대 섞이지 않는다.**
값이 빈 항목은 내보내지 않는다 — 「—」로 채우면 «조건이 없다»로 읽힌다.

미리 보려면 `npx tsx scripts/preview-policy-detail.mts`.

## 발행 게이트

```ts
const { ok, layer, missing, reason } = canIssueContract(policy);
```

- 계약 층이 아니면 → **「이 공급사는 상품만 공급합니다」** 로 막는다
- 계약 층인데 필수가 비면 → **비어 있는 항목을 세어 막는다**

빈칸 계약서를 손님에게 보내는 것보다 발행이 안 되는 편이 낫다 —
**서명이 끝나면 그 빈칸은 봉인되어 고치지 못한다.**

---

## 항목을 늘릴 때

계약 층에 넣으려면 **근거 약관 조항을 반드시 적는다.**
조항을 못 적는 항목은 애초에 계약서에 실릴 값이 아니다.

거꾸로도 본다 — 약관이 「계약서에 정한 ○○」이라고 써 놓았는데
정책에 그 값이 없으면, 그 조문은 분쟁에서 못 쓴다.

```
npx tsx scripts/check-consent-leak.mts      정책 누출·영업 표현·잘못된 라벨
npx tsx scripts/check-article-badges.mts    배지가 실제 조문을 가리키나 · 묶음 간 중복
```

## 화면 — 정책관리 5패널

```
목록 | 기본·심사 | 계약조건 | 보험 | 전자계약
```

「전자계약」 패널이 층 3이다(`app/policy/page.tsx` 의 `G_ESIGN`).
패널 상단 안내가 **지금 이 정책으로 계약서를 보낼 수 있는지**를 그 자리에서 말한다.

```
상품 층      「상품만 공급하는 정책입니다 — 계약서는 공급사가 직접 작성합니다」
계약 층·빈칸  「전자계약 발송 불가 — N개 항목이 비어 있습니다: …」
계약 층·완비  「전자계약 발송 가능 — 아래 값이 계약서와 약관에 그대로 실립니다」
```

**필드 그룹에 안 넣으면 보험 패널이 흡수한다**(미지정 필드 흡수 규칙). 항목을 늘릴 때
`G_ESIGN` 과 `grouped` 양쪽에 넣어야 한다.

2026-08-09 기준 정책 엔티티에 **44항목 전부 칸이 있다**(`check-policy-layers.mts` 로 확인).
그전에는 아래가 코드·서식에 박혀 있어 공급사마다 다르게 둘 수 없었다.

```
engine_control_overdue_days   시동제어 연체일수    서식에 「3일」 박힘
auto_terminate_overdue_days   자동해지 연체일수    서식에 「10일」 박힘
renewal_notice_days           연장 사전통지기한    칸 자체가 없었음
buyout_notice_days            인수 사전통지기한    칸 자체가 없었음
```

**서식 고정문구는 아직 남아 있다** — 정책값이 그 자리를 대체하도록 잇는 것이 다음 일이다.
