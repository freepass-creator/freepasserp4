## 규칙 — Claude · Codex · Cursor · 사람 공통

1. **프리패스 시트·원장을 쓰는 예약은 GitHub Actions(이 저장소 main) 한 곳에만 둔다.**
   PC 작업 스케줄러 · Codex 자동화 · Claude 예약 작업 · Vercel cron 에 «새로» 만들지 않는다(읽기 전용 점검도 여기 먼저 적는다).
2. **운영 판매시트 F01 · 하허호 F86 에 쓰는 것은 아래 표에서 「운영 쓰기 허용」인 워크플로뿐이다.**
   발행기가 스스로 막는다 — `lib/server/production-sheet-write-gate.ts`(`GITHUB_WORKFLOW` 허용 목록).
   로컬·다른 AI 는 미리보기 사본만 쓴다(F86 `--시트=<사본 id>` · F01 `SAMPLE_SHEET_ID`).
   긴급 수동 발행은 **사장님 허락을 받고** `FREEPASS_MANUAL_PUBLISH_APPROVED="YYYY-MM-DD 사유"` 로 연다.
3. **발행 엔진은 하나** — 통합 워크플로가 `ref:` 로 고정한 커밋. 다른 가지 코드로 운영에 쓰지 않는다.
4. **예약을 더하거나·끄거나·cron 을 바꾸면 이 표를 «같은 커밋»에서 고친다.**
   `npm run check:schedules` 가 표와 `.github/workflows/*.yml` cron · `vercel.json` crons 를 맞대 어긋나면 exit 1(CI).
5. **GitHub 에서 켜고 끄는 것(disable/enable)은 파일에 안 남는다** — 바꾼 사람이 아래 「상태」 칸과 날짜를 고친다.

### 2026-09-19 안전 자동화 흐름

```text
09:05~18:05  settlement-intake-sync
              계약접수 시트 → 정산원장 접수
                    ↓
09:17~19:17  ERP5 SSOT 원천 최신화
```

`contract-status`·`sales-erp-hourly`·`mirror-sync`는 자동 writer가 아니다. 운영 쓰기 책임은 위 두 자동화와 canonical ERP5 engine에만 둔다.

**하허호 F86 지키기**(사장님 2026-09-16 「하허호 시트는 제일 중요하게」) — 통합 워크플로 한 회차에서 스냅샷만 제대로 떴으면
F01 이 실패해도 F86 은 **백업**(`backup-f86` · 최근 48개) → **발행** → **F86 감사·신선도 120분**(`audit-f86-vs-atom`, 첫 관문) 까지 간다.
되돌리기 = `restore-f86-from-backup --from=<백업 id> --apply`(사장님 허락 플래그). 장치가 빠지면 `check:schedules` 가 막는다.

스케줄 없이 손으로만 도는 워크플로(버튼): `ci.yml` · `firestore-sample.yml` · `publish-erp5-ssot.yml` · `sheet-sync.yml` ·
