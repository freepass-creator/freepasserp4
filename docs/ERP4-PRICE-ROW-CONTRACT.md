# ERP4 MAIN · 가격행 정합성 계약

최종: 2026-09-19  
상태: **CURRENT / Stability Lock 보조 정본**

## 원칙

ERP4 MAIN에서 **계약기간 · 월 대여료 · 보증금은 반드시 같은 `price[term]` 행을 본다.**

차량 한 대에 여러 기간의 가격이 있어도 서로 다른 기간의 값을 조합해서 존재하지 않는 조건을 만들지 않는다.

예:

| 기간 | 월 대여료 | 보증금 |
|---:|---:|---:|
| 12개월 | 550,000원 | 0원 |
| 36개월 | 450,000원 | 2,000,000원 |

이 차량에서:

- `12개월 + 월 50~60만원 + 보증금 없음` → **통과**
- `36개월 + 월 50만원 이하 + 보증금 200만원` → **통과**
- `12개월 + 보증금 200만원` → **불통과**
- `12개월 + 월 50만원 이하` → **불통과**

마지막 두 조건은 차량 안에 각각의 값이 존재하더라도 **같은 가격행에 존재하지 않기 때문**이다.

## 적용 범위

같은 행 규칙은 다음 모두에 적용한다.

- 목록 필터 통과 여부
- 기간·월대여료·보증금 facet 건수
- 카드에 표시하는 기간·월대여료·보증금
- 월 대여료 정렬
- 보증금 낮은순 정렬
- 여러 기간을 OR 선택했을 때의 대표 가격행

## 카드 대표가격

가격조건이 하나라도 활성화되어 있으면 카드 대표가격은 그 조건을 같은 행에서 모두 만족하는 후보 중 **월 대여료가 가장 낮은 실제 행**을 사용한다.

가격조건이 없을 때만 전체 가격행 중 기존 대표가격 규칙을 사용한다.

## UI 동기화

목록 계산은 `liveQuery`(deferred state)로 수행한다. 따라서 카드의 `displayPrice`도 반드시 **같은 `liveQuery.sel`**에서 계산한다.

즉 칩은 즉시 반응하고 목록은 transition으로 뒤따라오더라도, **목록과 카드 가격은 같은 상태 버전**을 사용한다.

## 회귀 검사

`npm run check:deposit` 안에서 다음 두 검사를 함께 실행한다.

1. 기존 보증금 규칙 → 실제 금액 계산 검사
2. `sim-shop-deposit-term.mts` — 기간/대여료/보증금 동일 가격행 계약

그리고 `npm run check:erp4-main`은 이 동일행 엔진과 회귀 테스트가 연결되어 있는지 상위 구조를 검사한다.

## 금지

- `term`, `rent`, `dep`를 각각 독립 `priceList(...).some()`으로 최종 필터링하기
- 기간을 선택한 상태에서 카드가 전체 기간 최저가를 다시 표시하기
- 보증금 정렬이 선택 기간 밖의 보증금을 사용하기
- facet 건수가 다른 기간의 가격행을 섞기
- 목록은 `liveQuery`, 카드 가격은 즉시 `query`를 써서 한 프레임 동안 서로 다른 조건을 표시하기
