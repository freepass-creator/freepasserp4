# 공급사 데이터 연동 매뉴얼

기준일 2026-08-15. 운영자가 보는 정본은 `ERP4 차종마스터 원천대장`의 다음 두 탭이다.

- `공급사 데이터 매뉴얼`: 공급사별 정본, 우선순위, 제외 규칙, 누락 현황
- `공급사 열 매핑`: 실제 원본 탭·헤더 행·차량번호/상태/차명/옵션/대여료/보증금/정책 열

## 공통 원칙

- 공급사 데이터는 규칙 엔진이 매일 차종을 다시 판단하지 않는다. AI가 신규 차량번호를 최초 1회만
  차종마스터와 매칭하고 관리자가 확정한다.
- 확정 뒤 `차종코드·차종마스터 적용값·옵션·공급사 입력 차명`은 잠근다. 공급사 문구가 바뀌어도 자동 재매칭하지 않는다.
- 시스템은 같은 차량번호의 `차량상태·정책코드·기간별 대여료·보증금`만 이전 상품마스터 값과 비교한다.
  변경된 원자만 반영 후보로 만들고, 신규 차량번호만 AI 매칭 대기열로 보낸다.
- 차량상태는 판매 가능 여부를 위한 별도 재고 값이며 차종 재매칭을 유발하지 않는다.
- 상품마스터 앞쪽에는 `공급사 입력 차명 → 차종마스터 적용값 → 검증상태 → 검수사유`만 표시한다.
- 공급사 입력 차명은 각 원본의 제조사·차종·모델·트림과 차종 판별에 필요한 연료·배기량·
  연식/최초등록·구동·인승을 합친다. 옵션은 별도 열에 둔다.
- 차량번호가 있는 원본 행은 빈칸을 제외한 모든 셀을 헤더명과 함께 `공급사 원문보존`에 저장한다.
  공급사마다 열 위치가 달라도 행번호가 아니라 차량번호로 결합하며 가격·보험·메모도 버리지 않는다.
- 2026-08-15 전수 재조회 결과 현재 원본 576대는 위 규칙의 차량번호 자기참조 증빙을 576/576건 갖췄다.
  원본부재 과거 이력 11대는 신규 원문을 지어내지 않고 기존 이력으로 유지한다.
- 주행거리·색상·보험·계좌·가격은 원문보존에서만 확인하고, 연료·배기량·연식/최초등록처럼
  차종 판별에 필요한 값만 앞쪽 비교칸에도 함께 표시한다.
- 차량번호는 한 줄만 허용한다. 중복 탭에 같은 차량이 있으면 공급사별 우선순위 규칙을 따른다.
- 보증금·정책코드는 상품마스터의 운영 값으로 갱신하되 차종 재매칭과는 항상 분리한다.

## 예외 공급사

- 아이카: 정본은 `아이카 프리패스 재고`의 `재고`·`정책`. 차명은 `차명(세부모델+트림)`을 사용한다. 과거 `공급사연동` 탭의 구주소는 정본으로 쓰지 않는다.
- 오토플러스: `판매차량리스트`가 우선이고 프로모션 탭은 보조다. 숨김 행은 제외한다. 차명은 `차종 + 모델명`. 연 2만km가 기본이며 12개월만 3만km 예외다.
- 이안카: `이안카 재렌트`가 `이안카`보다 우선한다. 차명은 `차종분류 + 세부모델 + 트림`. 입고일자 칸에 상태 문구가 들어온 행은 날짜로 저장하지 않는다.
- 손오공 렌트: `렌트 상품 현황`. 차명은 `차종 + 모델명(트림)`. 공급사가 준 기간별 보증금과 12·24·36·48개월 가격을 그대로 쓴다.
- 손오공 구독: `구독 상품 현황`. 반납형은 표준 가격블록, 인수형 36·48·60개월은 후행 가격블록에 저장한다. 보증금은 월대여료 × 약정연수다.
- 아이언: Google Sheet가 아니라 `ironrentcar.com`이 정본이다. 신차·중고 목록과 상세를 모두 읽고 판매완료는 제외한다. 상세 수집 하나라도 실패하면 전체 반영을 중단한다.

`공급사 데이터 매뉴얼` 탭에서 관리한다.

## 원본 열 매핑 정본

Google Sheet의 `공급사 열 매핑` 탭은 공급사 단위가 아니라 **실제로 읽는 탭·페이지 단위**로 한 줄씩 관리한다.
따라서 오토플러스, 이안카, 손오공, 웰릭스처럼 서로 다른 구조가 한 파일에 섞인 경우도 별도 행으로 확인할 수 있다.

각 행은 다음 위치를 반드시 기록한다.

1. 정본 파일 또는 홈페이지와 실제 탭·페이지
2. 헤더 행
3. 차량번호와 상태 열
4. 최초 AI 매칭에 넣을 공급사 차명 조합과 옵션 열
5. 기간별 대여료와 보증금 열
6. 정책·사진·주행거리 등 보조정보 열
7. 중복 탭 우선순위와 제외 규칙
8. 최초 1회 AI 매칭 입력과 이후 대여료 변경감지 범위

### 공통 A:AG 규격

빌린카, 우리캐피탈, 에스에이, 스타, 리더스는 아래 공통 규격을 사용한다. 빌린카는
`빌린카·엘씨렌트·빌린카구독` 세 탭을 같은 규격으로 읽는다. 렌트존도 같은 열 규격이지만 1행이 비어 있어
2행을 헤더로 고정한다.

- A 상태, B 차량번호, C 차종, D 모델명(트림), E 옵션
- F:J 색상·유종·최초등록·주행거리, K 구분
- L 단기보증, M 1개월, N 6개월, O 12개월
- P 장기보증, Q 24개월, R 36개월, S 48개월, T 60개월
- U 소비자가격, V:AG 주행·분납·연령·보험·계좌·비고
- AH가 있는 공급사는 `보증금 조율 조건`까지 읽되 대여료 변경감지에는 넣지 않는다.

### 우리 제공 `재고·정책` 규격

KH, 경진카, 경진렌트카, 퍼시픽, 연카, 스위치플랜, 에코렌트카는 우리가 제공한 템플릿을 쓴다.

- A 차량번호, C 상태, E 제조사, F 차명(세부모델+트림), K 옵션
- O 단기보증, P 1개월, Q 12개월, R 장기보증, S:V 24·36·48·60개월, W:Y 기타기간
- Z 정책코드, AA 최초등록, AB 사진, AC:AN AI 확정값
- 제이앤제이는 W를 6개월 가격으로 쓴다. 센트로는 정제 열이 앞에 있어 상태 I, 차명 K, 옵션 P, 가격 U:AA로 이동한 변형 규격이다.

연카는 시트 주소·헤더·기본 정책을 확정했지만 현재 입력 차량이 0대라 신규행 발생 전까지 `입력대기`로 유지한다.
에코렌트카는 원본 URL·공급사코드와 상품마스터 5대 이관을 확인했다. 렉스턴 1대는 세대를 확정할 수 없어 미매칭으로 유지한다.
스위치플랜은 사용자 계정과 운영 서비스계정 모두 `재고` 탭 읽기가 타임아웃되어 현재 원본을 검증할 수 없다. 상품마스터의
8대는 전부 출고불가·가격 미제공 이력으로만 보존하고, 원본 재조회가 성공하기 전에는 상태·가격 자동갱신 대상으로 쓰지 않는다.

열 문자가 바뀌거나 새 탭이 생기면 ERP 코드를 먼저 고치지 않는다. 원본 헤더를 다시 실측하고 `공급사 열 매핑`을
갱신한 뒤, 같은 변경에서 파서·시뮬레이션을 함께 수정한다.

## 공급사 한 곳씩 완료하는 절차

5. 정본 차량마다 기간별 `대여료 + 해당 보증금`을 한 쌍으로 비교한다. 원본 대여료가 빈 기간은 두 칸을 함께 비운다.
6. 최초 확정한 차종코드·적용 차명·옵션은 가격 검수 과정에서 덮어쓰지 않는다.
