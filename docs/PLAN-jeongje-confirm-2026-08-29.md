# PLAN — 정제 «채움» vs «확정» 정합 (2026-08-29)

> 설계: Claude Code. 구현: Cursor(★mf-코드 쓰기=커서). 검증: Codex(독립 전수검증+완료).
> 검증 기준 = **사용자 원래 요구사항**(§1), 이 설계문서 아님. 위험영역(상품마스터 write)은 Claude 게이트 + 사용자 승인.

## 1. 사용자 원래 요구사항 (가공 없이)

- 「공급사 원문을 가지고 **차종마스터를 활용해서 정제시트를 채운다.** 원문에 정보 충분한데 왜 못 채우냐.」
- 「싼타페 프레스티지인데(영어 Prestige) 세부트림 못 찾았다 — 이런 것도 잘 봐야 한다.」
- 「한번 들어온 차는 **한번만 정제칸 입력해두면 바뀔 일이 없어야** 한다 = **확정값 박으면.**」
- 「**시트를 확인했으면 맞다고 판단되면 ERP에 반영**하는 게 왜 안 되냐.」

## 2. 제약 (운영매뉴얼 `상품리스트-ERP-정합-운영매뉴얼.md` + 협업검토안)

- ★**정제칸 값 «추정·치환» 금지**(운영매뉴얼 §3). 「없다」가 아니라 「모른다」 — 모르면 비운다.
- **차종코드 「절대 안 틀린다」** — 후보 여럿/없으면 안 박는다.
- **F01 차번 중복 0**, 임의 «중복 제거» 금지. ERP 총수는 참고값, 정합 기준은 «F01 차번집합 ↔ ERP 같은 차번집합».
- **상품마스터 확정행 = AI_LOCKED** — 공급사시트가 못 덮음, sync 가 보존.
- **mf-코드 쓰기 = Cursor만.** 상품마스터 write 는 위험영역 → Claude 게이트 + 사용자 승인.

## 3. 현재 흐름 조사 (실측)

- **fill**(`scripts/fill-supplier-ai-columns.mts`): snap → 정제칸. 원래 `ok`(confidence==='high')만 채움. Claude가 `softOk`(=high|medium)로 완화(커밋 `ba3b2bd`·`d497677`) → 이름칸·제원칸. ⚠**이게 «추정으로 채움»이라 운영매뉴얼 §3 정신에 걸린다.**
- **확정 메커니즘 이미 존재**: 상품마스터(`DEFAULT_PRODUCT_MASTER_SHEET_ID`·`상품마스터_구버전`) 검증상태=확정 → fill 이 PM_CODE 를 스냅보다 먼저 써 «재추정 안 함»(fill 134~138행). 주석: 「차량번호별 최초 1회만 매칭, 확정 코드는 매일 다시 추정 안 함」.
- **confirm-lock dry-run**(Claude 조사용, `scripts/confirm-lock.mts`): 정제칸 → `pickConfirmedMasterCode` → **유일코드=확정가능 / 후보여럿=애매**. 실측 마음카 3대 = 2 확정가능(투싼·그랜저) · 1 애매(싼타페 후보2).

## 4. 대안·트레이드오프

| 안 | 내용 | 매뉴얼 부합 | 위험 |
|---|---|---|---|
| A | medium 완화 «그대로» | ✗ 추정 금지 위반 | 오매칭이 ERP·계약서까지 |
| B | medium 완화 롤백 + 확정(코드)만 | ○ | 채움 줄어 «구멍» 다시 |
| **C(권장)** | medium 을 «안전한 것»만(값이 후보 세대들에서 동일) + 확정(코드) 도입 | ○ | 커서↔코덱스 루프로 안전선 검증 |

## 5. 권장안 + 이유

**C** — 원래 요구(「원문 있으면 채운다」)와 매뉴얼(「추정 금지」)을 둘 다 만족:
1. **확정(코드 박기)** 이 근본 — 정제칸이 «유일 코드»로 떨어지면 상품마스터에 확정 박아 «한번 박으면 안 흔들림».
2. **medium 완화는 «안전 medium»만** — snap 이 준 트림·모델이 «후보 세대들에서 동일」할 때만 채움(세대만 애매·값은 확실). «모델 자체가 후보 여럿»이면 안 채움(추정 금지).
3. 「시트 확인 → ERP」 = 확정 액션이 담당(확정=시트 정제칸을 코드로 굳혀 ERP에 잠금 반영).

## 6. 구현 순서 (Cursor)

1. **`confirm-lock.mts --apply`** — 확정가능 차(유일코드)를 상품마스터에 append/갱신: `차량번호·공급사명·공급사입력차명·차종마스터적용값·차종코드·검증상태='확정'·원천='사람확정'·최종갱신`. 이미 확정이면 skip. ★Sheets JWT `subject:'pyh@teamjpk.com'` 필수. 애매 차는 **안 박고 큐로**.
2. **fill `softOk` 좁히기** — «안전 medium»만(§5-2). Codex 반례가 나온 축만 되돌린다.
3. **확정 큐/뷰** — 애매(후보 여럿) 차를 사람이 고르는 목록(상품마스터 검증상태=검수필요 활용). 사람이 고르면 confirm-lock 이 그 코드로 확정.

## 7. 영향 파일

- `scripts/confirm-lock.mts`(--apply 구현) · `scripts/fill-supplier-ai-columns.mts`(softOk 좁힘) · 상품마스터 시트(확정행 write) · `sync-product-master-live.mts`(확정행 보존 확인).

## 8. 테스트

- confirm-lock dry-run: 마음카 2 확정가능·1 애매 (✅ 통과).
- --apply 후: 상품마스터에 확정행 → 다음 fill 이 그 코드 씀(audit-jeongje 로 «채운 칸 안 줄고 안 바뀜» 확인) → ERP에 그 값 유지.
- Codex 전수검증: **오매칭 0**(A) · 채울 수 있는 구멍(B) · F01 차번 중복 0·F01↔ERP 차번집합 정합(C, 운영매뉴얼 §2·§4).

## 9. 완료 조건

- 확정가능 차 = 상품마스터에 확정으로 박히고, 매시간 fill 이 «다시 추정 안 함».
- 애매 차 = 사람 큐로(자동 확정 안 함).
- **Codex «OK»** — 오매칭 0 + 운영매뉴얼 부합. (그때까지 Claude가 마스터·조율.)

## 10. 가정·미확정 — ★사용자 결정 필요

# PLAN v2 — «확정 = 다수 AI 합의» (2026-08-29, Codex NO-GO 교정 후)

> 사장님: 「4개 AI가 ㅇㅋ하면 확정. 공급사 원문으로 **최소 3개**가 ㅇㅋ하면 그걸로 확정.」
> Codex NO-GO(#1 자동≠사람확정·#2 추정) 를 **«단일 계산」이 아니라 «다수 독립 합의»** 로 푼다.

## 확정의 정의 (새 기준)

**차량번호별 정체성 = «원산지·제조사·모델·세부모델·세부트림 + 제원(배기량·연료·구동·인승·색상)»** 을
**4개 AI(Claude·Cursor·Codex·Gemini)가 «각자 독립」으로 공급사 원문에서 도출** → 집계:

```
3+ 일치(전 필드) →  확정   원천='AI합의 N/4' · 근거=각 AI 도출값+원문+시각  ← 정직한 이력(사람확정 아님)
<3 일치 / 불일치 →  검수대기  → 사람이 본다
```

- ★**원천은 «AI합의»** — 사람확정 아니다(Codex #1). 자동 계산 하나면 «자동후보」, 3+ 합의여야 «확정».
- ★**추정 방지(Codex #2)**: 3개가 «독립으로 같은 값」이면 추정이 아니라 교차검증. 원문에 근거 없으면 합의 안 되고 검수대기로 빠진다.
- ★**필드 전부 일치**여야 확정. 하나라도 갈리면(예: 세대 TM vs 더뉴TM) 검수대기.

## 연동 정합도 같은 방식

**대수·차번집합·핵심값 대조(운영매뉴얼 §2·§4)** 를 4개 AI가 «각자 독립 검수» → 3+ 합의 시 «문제 없음» 확정.
한 AI라도 읽기 실패면 그 실행은 실패(다음 단계 쓰기 막음).

## 흐름 (Codex 수정요청대로)

```
공급사 원문 → 4 AI 각자 독립 도출(쓰기 없음) → 합의 집계
  3+ → 확정값+근거+확정자(AI합의N/4)+시각 기록 → F01 4탭 재발행 → 천이·ERP → 전 필드 재대조
  <3 → 검수대기(원문 근거 첨부) → 사람
```

## 역할 (협업검토안)

- **Claude**: 이 설계 + 합의 집계 규칙 + 위험 게이트. 내 도출값 1표 제출.
- **Cursor**: 확정 쓰기(mf-코드=커서) — 사람/합의 승인 + 대상행 백업 + 재읽기 검증. confirm-lock 을 «합의 집계기»로(자동쓰기 제거).
- **Codex·Gemini**: 각자 독립 도출 1표씩 + 전수검증.

## 선행 (Codex #4)

- **F01 4탭·68열 매뉴얼 드리프트 먼저 닫기** (`npm run check:sync` 통과). 그 전엔 확정 쓰기 금지.

## 완료조건 (Codex #5)

F01↔천이↔ERP 전 필드(차번집합·배차상태·사진·기간별 대여료·차종4축·원문차명·옵션·정책코드·계약상태) 재대조 **모두 통과** + AI 3+ 합의 + 대상행 백업·재읽기.

# PLAN v3 — «마스터 먼저, 그 다음 per-car» (2026-08-29, Codex 2차 NO-GO 반영)

> Codex 2차(`crosscheck/codex-2026-08-29-구조검토.md`) NO-GO: 판별기 4개가 «같은 차종마스터»를 봐서 3/4가 «독립 3표」가 아니다(상관 실패). 1·2·3·5·6·7 구멍, 4 실측 필요.
> 사장님: 「**차종마스터부터 모든 AI 확정받고 가자.**」 → 독립성을 «마스터 자체 검증」에서 확보한다.

## 순서 (뒤집힘)

```
[0] 차종마스터 확정 — 마스터 «밖» 독립 근거로 각 항목(코드↔별칭↔제원(배기량·연료·구동·인승)·원산지) 검증
    · 독립 근거원: OEM 공식제원 · 엔카 식별값 · 공급사 상세제원 · 사람 검수 (마스터 자신을 근거로 쓰지 않는다)
    · 다수 «독립 소스» 합의 → 마스터 항목에 «신뢰(trusted)+버전» 도장. 이게 진짜 교차검증.
[1] per-car 매칭 — 신뢰된 마스터에 원문 매칭 (그제야 원문↔마스터 감사가 «진짜 확인»)
[2] 마스터 교정 전파 — 마스터 변경 → 관련 확정 «재검증대기»로만 (자동 덮어쓰기 금지)
```

## Codex 5개 조건 (구현 전 닫는다)

1. **상관 그룹 = 1표.** 같은 마스터 계열 파서(snap·playbook·토큰화·역인덱스)는 묶어 «1근거». 확정하려면 «다른 상관그룹 3개 근거 일치» — 최소 하나는 마스터-독립(공급사 상세제원/OEM/엔카/사람). 독립 근거 부족 → 검수대기.
2. **감사 3값 = PASS / FAIL / 미검사.** 원문 제원 비면 «미검사»(≠통과). 미검사는 자동 확정 불가.
3. **「AI합의」 탭에 감사 메타 추가**: `evidenceHash(원문 스냅샷)` · `masterVersion` · 판별기별 `version·실행시각·근거필드` · `철회횟수·격리사유`.
4. **재확정 불변키**: `evidenceHash+masterVersion+deriverVersion` 동일하면 재확정 금지(진동 차단). N회 도달 → 즉시 사람 큐.
5. **health gate + 수확량 드라이런**: 판별기별 입력수·성공수·null율·오류율·실행시각·버전 기록. 기준 벗어나면 확정 쓰기 차단. 매시간 자동 켜기 «전에» «같은 non-null 3+/4 도달율·검수대기율»을 드라이런으로 수치화.
6. **완료조건 배선**: 단일 실행ID로 F01 4탭·천이·ERP를 읽어 차번·상태·사진·대여료까지 대조 green일 때만 «완료». 부분·읽기 실패 = 실행 실패 → 다음 쓰기 차단 + 이미 쓴 ERP 보정/롤백.

## 이미 처리 (Codex 조건 5-말미)
