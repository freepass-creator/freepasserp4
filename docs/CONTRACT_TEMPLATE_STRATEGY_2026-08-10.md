# 계약서 템플릿 운영 기준 (2026-08-10 최종 정정)

## 프리패스 표준계약서는 3벌

1. `표준 렌트계약서`
2. `표준 구독계약서 · 보험포함`
3. `표준 구독계약서 · 보험별도`

` 인수 / 반납 `은 계약서를 더 나누는 기준이 아니다. 위 3벌 모두에서 관리자가 확정하는 만기 선택입니다. 따라서 관리자가 확정할 수 있는 조합은 6개이지만 표준계약서 파일은 3벌입니다.

## 확정·서명 흐름

1. 플랫폼 관리자가 계약 내용을 검토합니다.
2. 관리자가 표준계약서 3벌 중 하나를 선택합니다.
3. 관리자가 인수/반납을 선택해 계약을 확정합니다.
4. 정책관리의 보험 조건과 선택한 계약서가 다르면 발행을 막습니다.
5. 고객은 계약서 종류나 인수/반납을 고르지 않습니다. 관리자가 확정한 계약서 종류·만기선택·보험조건·대여조건을 확인하고 동의·서명합니다.

## 업체별 커스텀

- 커스텀판은 공급사별로 따로 관리하되, 반드시 `3벌 중 어느 표준계약서를 상속했는지`를 명시합니다.
- 예를 들어 A업체의 렌트계약서만 커스텀했다면, A업체의 구독 보험포함/별도는 각각 프리패스 표준판을 그대로 쓹니다.
- 커스텀판의 `baseVersion`이 해당 표준계약서의 현재 `version`과 다르면 발행하지 않습니다.
- 커스텀 JSON이 깨졌거나 필수값이 비면 표준판으로 조용히 대체하지 않고 전자계약 연동을 준비 중으로 닫습니다.

## 서버 설정

| 용도 | 환경변수 |
|---|---|
| 표준 렌트계약서 외부 ID | `CHAKHANDEAL_RENT_TEMPLATE_ID` |
| 표준 구독계약서·보험포함 외부 ID | `CHAKHANDEAL_SUBSCRIPTION_INSURANCE_INCLUDED_TEMPLATE_ID` |
| 표준 구독계약서·보험별도 외부 ID | `CHAKHANDEAL_SUBSCRIPTION_INSURANCE_SEPARATE_TEMPLATE_ID` |
| 업체별·기준서식별 커스텀 장부 | `CHAKHANDEAL_PROVIDER_TEMPLATES_JSON` |

세 표준 ID 중 하나라도 비면 실제 연동은 준비 중으로 닫습니다. 브라우저는 위 외부 ID를 보내지 않고 프리패스 내부 기준서식 ID만 보냅니다.

## 발행 스냅샷

계약에 아래를 서로 다른 값으로 남깁니다.

- 실제 착한거래 외부 템플릿 ID
- 표준/업체별 커스텀 여부와 적용판
- 3벌 중 선택한 표준계약서 ID와 기준판
- 인수/반납 선택
- 보험포함/보험별도

## 실발행 전 게이트

- 현재 3벌 모두 `sample-v1` / 샘플로 잠겨 있습니다.

- Preview에서 3벌 × 인수/반납 6조합을 발행하고 PDF·확인화면·서명완료를 확인해야 합니다.
