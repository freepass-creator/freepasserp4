## 공통 규격과 존재 이유

| 요소 | 통일 규격 | 존재 이유 / 제거 기준 |
|---|---|---|
| 기본 버튼 | `Btn`, 웹 32px·모바일 36px, 위험 동작만 danger | 실행 결과가 있는 행동. 단순 설명·상태 표시는 버튼으로 만들지 않는다. |

## 이번 통일·수정

1. `WorkPage`와 일반 `Page`의 데스크톱 검색·정렬·필터를 `WebListTools` 하나로 통합했다.
   - FAQ 검색이 데스크톱에서 사라지던 누락을 해결했다.
   - 감사 페이지의 별도 데스크톱 검색·영역 필터를 제거해 이중 구현을 없앴다.
2. `FilterGroup`의 숨김 placeholder 건수 `1`이 접근성 트리에 읽히지 않게 했고, 펼침 상태와 버튼 type을 명시했다.
3. `Select`와 `Input`의 좌우 패딩을 `ctrlPadX`로 통일했다.
4. 오류·404의 손제작 행동을 `Btn`으로 교체하고, FAQ·설정·엑셀 필터·스켈레톤의 radius/높이/아이콘을 토큰으로 수렴했다.
5. `check:ui`를 추가했다. 업무 코드의 새 raw 컨트롤과 숫자 radius를 차단하며, 숨김 파일 입력·채팅 textarea·루트 오류·로그인·프로모션 섬만 이유와 개수를 고정해 허용한다.

## 목록 의미 검증 결과

- 차량명은 제조사·모델·트림을 복원하되 제조사를 중복하지 않는다. 차번을 차량명으로 위장하지 않고 결손은 `차량명 미확인`으로 명시한다.
- 공급사·영업자·채널은 실제 표시명을 우선하고 코드·UID를 사람 이름으로 위장하지 않는다.
- 문의의 기본 `문의` 뱃지는 제거했다. 미확인·진행·완료·취소는 좌측 아이콘과 필요한 명시 뱃지로 구분한다.
- 계약 단계 뱃지와 필터는 문의→서류→입금→약정→출고→완료→취소의 같은 축을 쓴다. 누락·지원외·부결·철회는 `확인 필요` 계열 경고로 보낸다.
- 구분점은 두 개 이상의 실제 값 사이에만 생성한다. 빈 공급사 앞 또는 행 시작·끝의 점은 만들지 않는다.
- 역할별 상대방 표시는 영업자=공급사, 공급사=담당자, 관리계열=업무에 필요한 양쪽으로 검증했다.

## 의도된 예외

- `global-error`: 앱 셸과 CSS 자체가 실패해도 살아야 하므로 공용 UI import 없이 독립 렌더한다.
- `login`: 앱 셸 이전의 인증·필수동의 네이티브 폼이다. 내부 업무 페이지 규격과 분리하되 자체 필드 규격은 일관되게 유지한다.
- 채팅 textarea: 일반 input 사용 시 모바일 브라우저의 비밀번호·카드·주소 자동완성 UI가 끼어드는 문제를 막고 줄바꿈을 지원한다. 높이·폰트·radius는 공통 토큰을 쓴다.
- 숨김 file input: OS 파일 선택기를 열기 위한 비가시 네이티브 연결점이다. 화면에 보이는 실행 버튼은 공용 `Btn`/`IconBtn`을 쓴다.
- `/m` 프로모션 미리보기와 전자서명 지면은 업무 목록이 아니며, 전화기 목업·서명/PDF 물리 지면 규격 때문에 별도 섬으로 유지한다.
