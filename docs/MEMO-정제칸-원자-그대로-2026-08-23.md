# 메모 — 「정제칸 원자를 다 가져오고, 조합은 ERP 에서」 (2026-08-23)

> **받는 사람**: 코덱스 · 커서 · 다음 세션의 AI.
> **한 줄**: 옮기는 길에서 **값을 가공하지 마라.** 정제칸 원자를 그대로 나르고, 붙이는 일은 ERP·화면에서 한다.

---

## 0. 사장님 원문 (이게 기준이다)

- 「**니가 빼면 안 되고 있는 걸 그대로 갖고 오는 거잖아 · 그렇게 로직을 짜야 해**」
- 「**니가 수정하는 게 아니라 정제시트가 잘못되어 있으면 거기를 수정하든가 커서한테 오더를 주든가 해야 함**」
- 「**그냥 정제시트 말고 상품리스트를 가지고 오면 되는 거야 너는**」 · 「그거를 코덱스랑 각 시트 만지는 애들이랑 둬야지」
- 「**차량정보에 대한 걸 정제칸에 있는 걸 다 갖고 오는 거지... 그걸 조합해서 ERP 를 하면 되고**」
- 「차종마스터는 계속 늘려 갈 거야 — **네가 판단하지 말고 구글시트를 반영하는 것일 뿐**」

---

## 1. 경계 — 누가 어디를 만지나

```
 렌터카사 원본 ─▶ 공급사 정제시트 ─▶ 상품리스트(판매시트) ─▶ ERP ─▶ 화면
                 └─ 커서·코덱스 ──┘  └────── 여기부터 옮기기만 ──────┘
                    사장님이 챙김            (조합은 여기서)
```

| 자리 | 누가 | 규칙 |
|---|---|---|
| 정제칸 · 차종마스터 | 커서·코덱스 / 사장님 | **값이 틀리면 여기를 고친다** |
| 상품리스트 → ERP → 화면 | 옮기는 코드 | **글자를 그대로 나른다.** 붙이는 것만 여기서 |

---

## 2. ★ 이번에 낸 사고 — 되풀이하지 마라

2026-08-23 오전, 개발코드(MX5·GN7)가 손님 화면에 보인다는 지적을 받고 **옮기는 길에서 깎았다.**
「AI 정제」에 `@세부모델` 186줄을 넣고 `fill-supplier-ai-columns --apply` 를 세 번 돌려 **정제칸을 덮었다.**

무엇이 잘못이었나 — **고쳐야 할 곳은 마스터·정제시트였다.** 이름이 마음에 안 들면 그 시트를 고치면 되고,
옮기는 코드는 글자를 그대로 나르기만 하면 된다. 그래야 시트와 화면이 갈릴 수가 없다.

같은 날 오후에 되돌렸다:
- `fill-supplier-ai-columns` 의 마스터·스냅·정본 세 경로에서 치환 제거 → 마스터 글자 그대로
- `build-vehicle-catalog` 에서 치환 제거
- `lib/domain/ai-refine-guard` — 「AI 정제」에 코드를 깎는 줄이 다시 들어와도 **무시**한다
- `add-submodel-code-strip-rules` · `normalize-erp-submodel-codes` 는 **폐기(거부)**

---

## 3. ★ 또 하나 — 화면이 ERP 를 덮고 있었다

`vehicle-name.partsOfRecord` 가 `_review_identity`(코드 없는 차의 옛 사람 결정)로 **ERP 값을 덮었다.**
그래서 정제칸을 고쳐도 화면이 안 바뀌었다(실측 39대):

```
ERP·시트 「싼타페 MX5」        ▶ 화면 「디 올 뉴 싼타페 MX5」
ERP·시트 「쏘나타 디 엣지」     ▶ 화면 「쏘나타 DN8 디 엣지」
ERP·시트 「GV80 JX1 FL」      ▶ 화면 「GV80 부분변경 JX1」
```

**ERP 가 이기고, ERP 가 빈 축만 옛 결정으로 메우도록** 뒤집었다(39 → 13건).

## 4. 지금 정제칸 22칸이 어디까지 가나 (실측 2026-08-23)

**ERP 까지 오는 14칸** — 원산지 · 제조사(정제) · 모델 · 세부모델 · 세부트림 · 배기량(정제) ·
배터리용량(정제) · 연료(정제) · 구동방식 · 인승 · 선택옵션 · 외장색상 · 내장색상 · 차종분류

**안 오는 8칸**

| 칸 | 성격 | 어떻게 볼 것인가 |
|---|---|---|
| 모델행키 · 세부모델행키 · 세부트림행키 | 엔카 매칭용 내부 키 | 차량정보가 아니다. 안 날라도 된다 |
| 차명(정제) | **조합값** (모델+세부모델+세부트림) | **안 나르는 게 맞다** — 사장님 「조합해서 ERP 를 하면 되고」. 화면이 세부모델+세부트림으로 만든다 |
| 차종크기(중형) · 차종구분(SUV) | **원자** | 지금은 합본 「차종분류」(중형 SUV)만 나른다. 정보 손실은 없지만 **원자 단위로는 안 온다** — 나눠 쓸 일이 생기면 이 둘을 세워야 한다 |
| 차종코드 · 차종분류코드 | 코드(식별자) | 화면에 쓸 값은 아니지만 **차를 특정하는 열쇠**다. 필요해지면 축으로 세운다 |

> ⚠ 이름이 헷갈리는 자리 — 정제칸 「차종구분」은 `SUV`(차체형태)이고,
> 판매시트 열 「차종구분」은 정제칸 **「차종분류」**(중형 SUV)에서 온다. 같은 이름, 다른 값이다.

## 5. 검사 — 「그대로 가나」를 잰다

```bash
npm run audit:passthrough        # 정제칸 ▶ 판매시트 ▶ ERP ▶ 화면 글자 대조
npm run audit:passthrough -- --gate
```

채움률 검사(`audit:axes`)는 «값이 있나»만 본다. **값이 있는데 도중에 바뀌는 것**은 이 검사가 잡는다.

### 지금 남아 있는 «바뀜» 3갈래 (사장님 판단 대기)

| 구간 | 무엇 | 건수 | 원인 |
|---|---|---|---|
| 정제칸▶판매시트 | 「모델 Y」▶「모델Y」 | 10 | 발행기가 공백을 지운다 |
| 판매시트▶ERP | 옵션 「A,B,C」▶「A, B, C」 | 143 | 유입이 콤마 뒤에 공백을 넣는다 |
| ERP▶화면 | 「더 뉴 **기아** 레이 TAM」▶「더 뉴 레이 TAM」 | 13 | **마스터 이름에 제조사가 들어 있다.** 안 떼면 「기아 · 더 뉴 기아 레이」로 두 번 나온다 |

**세 번째는 시트를 고치면 없어진다** — 마스터 세부모델명에서 「기아」를 빼면 화면 가공이 필요 없다.
앞의 둘은 표기 정규화라 그대로 둘지 결정이 필요하다.

## 6. 하지 말 것 · 할 것

**하지 마라**
- 정제시트·차종마스터 **값**을 코드로 고치기
- `fill-supplier-ai-columns --apply` 를 옮기는 쪽에서 돌리기
- 옮기는 코드(발행기·유입·표시)에 치환·정규화·«보기 좋게» 끼워 넣기
- 「AI 정제」에 개발코드를 깎는 줄 넣기 (`ai-refine-guard` 가 막지만 애초에 넣지 마라)

**해라**
- 상품리스트를 읽어 ERP·재고관리·화면에 **그대로** 반영
- 조합(차명 = 세부모델+세부트림)은 **ERP·화면에서**
- 값이 이상하면 **어디가 원인인지 짚어서 보고** — 고치는 건 시트 담당이 한다
- 축을 세울 때는 `lib/domain/sales-axis-registry` 에 한 줄 선언 → `npm run check:axes` 가 여섯 곳을 대조한다
