# 인계 — 정제칸 검증 · 차종구분 (2026-08-21)

받는 사람: **커서**(구현) · **코덱스**(독립검증). 쓴 사람: 클로드 코드.

사장님이 정제시트 정제칸에 **「차종마스터 신규」를 다 채워 넣었다.** 481대를 전수 대조했다.
**채운 값은 거의 정확하다** — 차급이 어긋난 건 481대 중 **5대뿐**이다.
아래는 남은 것과, **내가 잘못해서 한 번 잘못 보고한 것**이다.

---

## 0. 사전이 두 층이다 — 여기서 내가 두 번 틀렸다

「차종마스터 신규」 시트(`1oMB9eo…`) **「안내」 탭이 스스로 적고 있다**:

> · 「범위 — **엔카 중고차만. 신차는 나중에 따로 뽑는다.** 프리패스 ERP 원장 「차종마스터」(mf-…)는 보지 않는다. **이 시트가 차명·제원 사전이다.**」
> · 「차종마스터 — **이 시트가 정본.** 연식·연료·배기량·구동·**차종크기·차종구분은 이 시트 칸.**」
> · 「제조사 표기 — 이 시트(엔카) = 르노코리아 · KG모빌리티. **공급사 칸 = 르노 · KGM. 제조사(정제)에는 공급사 표기를 넣는다.**」

**실측으로 갈라진다:**

| | 세부모델 수 | 481대 중 이름이 붙는 수 | 무엇의 정본인가 |
|---|---|---|---|
| 「차종마스터 신규」 시트 | **428종** | 203대 | **차종크기·차종구분·연료·배기량·구동·엔카 행키(M/SM/T/U)** |
| `public/data/vehicle-master.json` | **1,813종** | 394대 | **이름 커버리지**(신차·수입 포함) |

시트는 「엔카 중고차만」이라 **우리가 파는 차의 절반이 안 잡힌다.**
둘 중 하나만 정본이라고 쓰면 안 된다 — **이름은 JSON, 차급·제원은 시트**다.

**내가 틀린 자리 두 곳:**

- 1차 감사에서 `audit-vehicle-refine` 이 **옛 원장 탭**을 읽는 줄 모르고 결과를 옮겼다 → 「마스터에 없다」 16건 중 **7건이 헛발**.
- 2차 감사에서 시트 「안내」를 안 보고 JSON 으로만 견주며 제조사를 시트 표기로 맞추라 했다 →
  **「제조사 어긋남 55건」은 없는 문제였다.** 「르노 · KGM」이 안내대로 **맞는 값**이다(`canonMakerDisplay`).

> **도구를 돌리기 전에 그 도구가 무엇을 정본으로 읽는지 먼저 연다.**

## 1. 해야 할 일

기본 dry-run → 사람 승인 → `--apply`. 되돌릴 값은 `tmp/*.json`.

### ① main 을 올려야 워크플로가 산다 — **제일 급하다**

워크플로는 **main 에서 돈다.** 지금 main 이 94커밋 낡아서 둘 다 죽어 있다.

| 워크플로 | 증상 | 원인 |
|---|---|---|
| 정제시트 갱신(30분) | 아이카·이안카 **정책** 미러 실패 | main 의 `sync-mirror-policies.mts` 가 `hdr[0] !== '정책코드'` |
| 시트 동기화·발행(2시간) | `Error: 상품마스터 A:AZ 헤더 불일치` | 「상품마스터 연동 안 함」이 main 에 없음 |

**오늘 판매시트가 한 번도 새로 발행되지 않았다.** 재고 미러 4곳은 살아 있다
(아이카 103 · 오토플러스 85 · 이안카 82 · 아이언 26).

### ② 차급이 시트와 어긋난 5대 — 정제칸을 고친다

시트가 정본이다. 다섯 대 다 **시트 쪽이 맞다.**

| 공급사 | 차량번호 | 차 | 정제칸 | 시트(맞는 값) |
|---|---|---|---|---|
| 빌린카 | 161호1272 · 161호1273 | 팰리세이드 LX3 | 차종구분 MPV | **SUV** |
| 빌린카 | 23누8273 | C-클래스 W205 | 차종크기 준중형 | **중형** |
| 아이카 | 182허5109 | G80 RG3 | 차종크기 중형 | **준대형** |
| 손오공 | 68로3201 | 볼트 EUV | 차종구분 해치백 | **SUV** |

### ③ 시트에 하이브리드 세부모델이 빠졌다 — 37대

연료 어긋남 37건이 **전부 「하이브리드」**다. 정제칸은 하이브리드인데 그 세부모델에
하이브리드 원자(U)가 시트에 없다.

```
17대  하이브리드 ↔ 시트엔 가솔린만
 9대  하이브리드 ↔ 가솔린/LPG
 7대  하이브리드 ↔ 디젤/가솔린
 4대  그 외
```

안내 탭이 이미 규칙을 적고 있다 —
「**엔카가 하이브리드를 세부모델로 안 가르면 우리가 가른다**(싼타페 하이브리드 MX5)」.
**시트에 하이브리드 줄을 넣어야 한다.** 정제칸이 틀린 게 아니다.

### ④ 「차종분류」 칸이 SUV 를 MPV 라고 한다 — 42대

정제칸에는 「차종분류」(합친 값)와 「차종크기+차종구분」(두 칸)이 **둘 다** 있다.
**차종분류 쪽이 틀렸다.**

```
21대  그랑 콜레오스 · 토레스 J100 · 더 뉴 토레스 J116/J140    차종분류 MPV → SUV
14대  아르카나 · 트레일블레이저 9BYC · 더 뉴 티볼리 X100        차종분류 MPV → SUV
 7대  트랙스 크로스오버 9BQC                              차종분류 MPV → SUV
12대  「준중형」·「준대형」·「경형」처럼 크기만 적고 차체가 빠짐
```

판매시트 「차종구분」은 **차종크기+차종구분**을 쓰므로([publish-origin-tab.mts:552](../scripts/publish-origin-tab.mts#L552))
지금 영업자 화면은 맞게 나간다. 급하진 않다.
다만 **같은 뜻의 칸을 둘 두면 언젠가 반드시 갈린다** — 하나로 줄이는 게 맞다.

### ⑤ 시트에 없는 세부모델 249대 — 대부분 「엔카 중고차 밖」이다

시트가 428종뿐이라 나오는 수다. **먼저 JSON 기준으로 걸러라** — JSON 에는 394대가 붙는다.
JSON 에도 없는 것이 진짜 채울 대상이고, 1차 감사에서 그건 59건이었다:

**시트/JSON 둘 다에 줄을 넣어야 하는 것**(페이스리프트가 통째로 없음)

```
9대 모델 Y FL   5대 G80 RG3 FL   4대 GV80 JX1 FL   2대 GV70 JK1 FL
11대 쏘나타 DN8 디 엣지   5대 디 올 뉴 니로 EV SG2   2대 디 올 뉴 셀토스 SP3
1대씩 모델 3 FL · 캐스퍼 일렉트릭 AX1e · G90 1세대 부분변경 HI · 더 뉴 스타리아 투어러 US4
```

**정제칸 표기를 사전에 맞춰야 하는 것**

```
13대 「더 뉴 기아 레이 TAM」 → 「더 뉴 레이 TAM」   (제조사가 이름에 끼었다)
 1대 「SM7 1세대」        → 「SM7」
 1대 「쿠퍼 컨트리맨 F60」   → 「쿠퍼 컨트리맨 R60/F60」
 1대 「G80 부분변경 RG3」   → 「G80 RG3」
 1대 「더 뉴 모닝 JA」      → 사전엔 「더 뉴 모닝 TA」뿐 — 어느 쪽이 맞는지 확인 필요
```

세부모델 정본 = **모델+개발코드**. 풀체인지 `아반떼 CN8` · 페리 `더 뉴 아반떼 CN8`.
`디 올 뉴` 는 세부모델이 아니라 `aliases` 에 넣는다(안 그러면 「더 뉴 디 올 뉴 …」가 된다).

### ⑥ 안 채운 29대

```
15대 차종크기만 빔    9대 차종크기·차종구분 둘 다 빔    2대 차종구분만 빔    3대 그 외
```

### ⑦ 손대지 말 것

- **제조사 「르노」·「KGM」** — 안내대로 맞는 값이다. 시트 표기(르노코리아·KG모빌리티)로 바꾸지 마라.
- **배기량 어긋남 33건** — 시트가 엔카 실매물 기준이라 좁다. ③ 하이브리드와 같은 뿌리일 수 있으니
  ③ 을 먼저 닫고 다시 세라.

## 2. 크로스체크 — 코덱스

사장님 2026-08-21 「크로스체크를 해야겠네」. **위 0장이 전부 자기검증이라 늦게 잡혔다.**
만든 사람과 검증하는 사람을 나눈다. **내 감사 도구를 믿지 말고 원본을 직접 열어라.**

1. `scripts/audit-refine-vs-master.mts` 가 **정말 시트를 읽는가.** 사전이 뭔지 첫 줄에 찍는다.
2. **②의 5대**를 시트에서 직접 열어 세 칸(차종크기·차종구분·차종분류)을 눈으로 본다.
3. ③ 하이브리드 37대가 **정말 시트에 하이브리드 줄이 없는 것인지**, 아니면 세부모델 이름이 어긋난 것인지.
4. 정책 탭을 읽는 곳이 **정말 다 이름으로 찾는가** — `grep -rn "hdr\[0\]" scripts/ lib/`.
5. 판매시트 「차종구분」이 **어느 칸에서 나오는가.** 두 경로가 남아 있으면 그 자체가 사고다.
6. 대수: 공급사 시트 → 정제시트 → 판매시트 → ERP 가 같은 수인가.
   형식은 「우리 시트 N · 아닌 시트 N · 총 N」.

어긋나면 **고치지 말고 보고한다.** 내가 틀렸으면 틀렸다고 적어라 — 그러라고 나누는 것이다.
