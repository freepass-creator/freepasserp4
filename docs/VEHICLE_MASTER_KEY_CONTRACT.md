# 차종마스터 트림행키 영구계약

기준일: 2026-08-15  
대상: `ERP4 차종마스터 원천대장` → `차종마스터`

## 운영 규칙

`트림행키`는 차번에 저장되는 영구 식별자다. 행 번호나 정렬 순서가 아니라 코드 자체가 차량을 가리킨다.

- 기존 코드를 삭제하지 않는다. 안 쓰는 차는 행을 남기고 `관리상태=제외`로 바꾼다.
- 기존 코드의 `마스터ID·파워트레인순번·트림순번`을 바꾸지 않는다.
- 기존 코드의 차량 의미(`원산지`, 제조사~세부트림, 세대/개발코드, 생산·연식, 연료·배기량·터보·구동·인승·배터리)를 바꾸지 않는다.
- `파워트레인` **합침 표시열**은 양식에서 뺄 수 있다(2026-08-18). `파워트레인순번`(`::v##`)과 연료·배기·터보·구동·배터리 원자축은 유지한다. 라벨 문자열은 artifact가 prior·파생으로 보존한다. 키 기준판 schemaVersion 3 = 의미 열에서 파워트레인 라벨 제외.
- 오기 수정으로 차량 의미가 달라지면 기존 코드를 `제외`로 보존하고 새 코드를 추가한다.
- 새 파워트레인·트림은 이미 쓴 순번을 재사용하지 않고 다음 미사용 순번으로 추가한다. 중간 빈 순번을 당겨 채우지 않는다.
- 행 이동·정렬, 검증상태, 관리상태, 신차/중고차, 별칭, 근거와 기준일 변경은 허용된다.

## 강제 장치

- 시트 `J:M`은 편집 경고 보호 범위다.
- `data/vehicle-trim-key-registry.json`은 현재 코드와 차량 의미의 기준판이다.
- `npm run audit:vehicle-trim-keys`는 다음을 발견하면 실패한다.
  - 코드 삭제·중복·재사용
  - 코드와 마스터ID/순번 불일치
  - 등록된 코드의 차량 의미 변경
  - 검토하지 않은 새 코드
- 검토가 끝난 새 코드만 `npm run audit:vehicle-trim-keys -- --register-new`로 추가한다. 이 명령은 기존 계약 위반이 하나라도 있으면 기준판을 갱신하지 않는다.
- `npx tsx scripts/sim-vehicle-trim-key-contract.mts`는 동일 입력의 멱등성과 삭제·의미변경·순번변경 차단을 검증한다.

라이브 감사 자격증명에는 `spreadsheets.readonly`만 허용한다. 현재 운영 서비스계정처럼 이 읽기 전용 스코프가 위임되지 않은 환경에서는 연결 도구로 `차종마스터!A:AD` 값을 추출한 뒤 아래처럼 감사한다. 감사 때문에 전체 Sheets 쓰기 스코프를 추가하지 않는다.

```powershell
npm run audit:vehicle-trim-keys -- --snapshot=C:\\path\\to\\master-values.json
```

스냅샷은 `[[헤더...], [행...]]` 또는 `{ "values": [[헤더...], [행...]] }` 형식이다.

이 장치는 행 순서로 키를 다시 만들지 않는다. 따라서 중간 행을 삽입하거나 정렬해도 기존 코드가 움직이지 않으며, 기존 코드의 의미를 바꾸는 편집은 기준판 감사에서 실패한다.

## ERP JSON 생성

`scripts/generate-vehicle-trim-master.mts`는 시트 한 행을 JSON 한 레코드로 내보낸다. 기존 그룹형 `vehicle-master.json`과 달리 `trim_row_key`, 정확배기량, 구동, 인승, 배터리와 상태를 잃지 않는다.

- `automatic`: 관리상태와 검증상태가 모두 `확정` — 자동 매칭에 사용 가능
- `manual`: `검증중`이면서 `1차확인` 또는 `교차확인` — 사람이 선택해 코드를 박는 용도
- `blocked`: `제외`, `보강대기`, `미검증` 또는 상태 조합 불일치 — 후보에서 제외하되 기존 코드 조회를 위해 레코드는 보존

생성 전에 영구키 기준판 감사를 강제하며, 행 순서를 바꿔도 결과가 동일하도록 코드순으로 정렬한다. 출력은 `public/data/vehicle-trim-master.json`이다.
