# 엔카 매물 전수 학습 → 차종마스터 결손 찾기 (2026-08-09)

작성: Claude Code(설계·엔드포인트 검증) → 구현: Cursor → 검증: Codex

## ★대전제 — 엔카에서 가져오되 **표기는 우리 규격으로**

엔카는 **「그 트림이 실재하는가」를 확인하는 근거**로만 쓴다. 표기법은 가져오지 않는다.

| | 엔카 표기 | 우리 마스터에 넣을 것 |
|---|---|---|
| 파워트레인 | `Badge = "터보 인스퍼레이션"` (트림이 섞여 있다) | 파워트레인은 「1.6 터보」, 트림은 「인스퍼레이션」으로 **쪼갠다** |
| 파워트레인 | `Badge = "2.5"` | 우리 규격대로 「가솔린 2.5」 |
| 세부트림 | `BadgeDetail = "르블랑"` | 「르블랑」 (그대로 맞으면 그대로) |
| 오탈자 | 엔카에 「비지니스」로 올라온 매물 | 우리 정본 「비즈니스」 |

**판단 기준: 우리 마스터에 이미 있는 이웃 트림의 표기를 따른다.**
같은 세대에 「노블레스 라이트」가 있으면 새로 넣는 것도 그 어투로 맞춘다.
엔카가 「Noblesse Light」라고 써도 우리는 한글이다.

기존에 마스터가 쓰던 표기는 **한 글자도 바꾸지 않는다.** 엔카가 더 그럴듯해 보여도 그렇다 —
표기를 갈아치우면 지금 잘 붙어 있는 405대가 통째로 어긋난다.

---

## 왜 하나

지금 마스터 결손을 **우리 매물 762대에서 역산**하고 있다. 그건 표본이 우리 재고뿐이라
「트랙스 크로스오버에 RS가 있는가」를 확인할 방법이 추측밖에 없다.
시중 매물 21만 대를 보면 **실재하는 조합만** 남는다 — 지어낼 여지가 사라진다.

## 1. 검증된 사실 (2026-08-09 직접 확인)

전부 실제로 호출해서 확인한 값이다. 추측 아님.

```
GET https://api.encar.com/search/car/list/general
    ?count=true
    &q=(And.Hidden.N._.CarType.A.)          ← A=전체 · Y=국산(150,598) · N=수입(65,025)
    &sr=|ModifiedDate|<offset>|<limit>      ← URL 인코딩 필요: %7CModifiedDate%7C0%7C100

헤더:  User-Agent: Mozilla/5.0   Accept: application/json
```

| 확인 항목 | 결과 |
|---|---|
| 전체 매물 | **215,622대** (국산 150,598 · 수입 65,025) |
| `limit` | **100 동작** |
| `offset` 상한 | **없음** — 0 / 9,900 / 20,000 / 100,000 전부 100건 정상 반환 |
| 필요 요청 수 | **약 2,157회** (215,622 ÷ 100) |
| 인증 | 불필요 |

> ⚠ 응답은 UTF-8이다. PowerShell 5.1의 `Invoke-WebRequest`로 받으면 한글이 깨진다
> (「더 뉴 그랜저 IG」→「ë ë´ ê·¸ëì  IG」). **Node(tsx) `fetch`로 받으면 정상.**
> 크롤러는 `.mts`로 짤 것.

### 응답 필드

```
Id, Separation, Trust, ServiceMark, Condition, Photo, Photos,
Manufacturer, Model, Badge, BadgeDetail, GreenType, FuelType,
Year, FormYear, Mileage, ..., Price, SellType, BuyType, OfficeCityState
```

## 2. ★핵심 — 엔카 4단이 우리 4단과 그대로 맞는다

이게 이 작업의 근거다. 실제 응답 두 건:

```
Manufacturer=현대  Model=더 뉴 그랜저 IG  Badge=2.5            BadgeDetail=르블랑
Manufacturer=현대  Model=캐스퍼          Badge=터보 인스퍼레이션  BadgeDetail=(없음)
```

| 엔카 | 우리 마스터 | 확인 |
|---|---|---|
| `Manufacturer` | 제조사 | 현대 = 현대 |
| `Model` | **세부모델(세대)** | 「더 뉴 그랜저 IG」 ← 우리 `sub_model`과 표기까지 같다 |
| `Badge` | **파워트레인** | 「2.5」·「터보 인스퍼레이션」 |
| `BadgeDetail` | **세부트림** | 「르블랑」 |

「더 뉴 그랜저 IG」가 우리 마스터 표기와 **글자까지 일치**한다.
우리 마스터가 애초에 이 계통 표기를 따라 만들어졌다는 뜻이고, 대조 비용이 거의 없다.

⚠ 다만 `Badge`가 항상 파워트레인은 아니다 — 「터보 인스퍼레이션」처럼 트림이 섞여 온다.
**기계적으로 1:1 대응시키지 말 것.** 아래 4의 판정 규칙을 따른다.

## 3. 수집 설계

### 무엇을 저장하나 — **분류 튜플만**

```ts
type Tuple = {
  maker: string;        // Manufacturer
  sub_model: string;    // Model
  badge: string;        // Badge
  badge_detail: string; // BadgeDetail
  fuel: string;         // FuelType
  green: string;        // GreenType (전기·하이브리드 구분)
  year_min: number;     // Year 최소 (FormYear 아님)
  year_max: number;
  n: number;            // 이 조합의 매물 수 ← 신뢰도 지표
};
```

**`Id`·`Price`·`Mileage`·`Photo`·판매점 정보는 저장하지 않는다.** 우리가 필요한 건 분류뿐이고,
남의 매물 정보를 쌓아둘 이유가 없다. 21만 행이 아니라 **중복 제거한 수천 행**이 산출물이다.

### 예의 — 남의 서버다

- **요청 사이 1초 이상** 간격. 병렬 금지. 2,157회 × 1초 ≈ 36분이면 충분하다
- 실패 시 지수 백오프(2s → 4s → 8s), 3회 실패하면 그 offset 기록하고 **다음으로 진행**
- 100건마다 중간 저장 — 중간에 끊겨도 처음부터 다시 돌리지 않게
- `User-Agent`에 연락 가능한 표기를 넣는 것을 권장

### 산출물

```
tmp/encar/raw-<offset>.json        중간 저장(재개용)
tmp/encar/catalog.json             중복 제거한 Tuple 목록  ← 이게 결과물
tmp/encar/master-diff.csv          마스터와 대조한 리포트  ← 사람이 볼 것
```

## 4. 마스터 대조 — 판정 규칙

`tmp/encar/master-diff.csv` 열:

```
구분 · 제조사 · 세대(sub_model) · 트림 · 엔카매물수 · 우리마스터 · 우리재고대수 · 판정
```

`구분`은 넷 중 하나:

| 구분 | 뜻 | 조치 |
|---|---|---|
| **결손** | 엔카에 있고 마스터에 없음 | ★보강 대상 |
| **표기차** | 뜻은 같은데 글자가 다름 (「비지니스」/「비즈니스」) | 오탈자 사전에 넣을 것. 마스터 표기는 **그대로 둔다** |
| **일치** | 양쪽 다 있음 | 볼 것 없음 |
| **우리만** | 마스터에 있고 엔카에 없음 | **지우지 말 것** — 신차·법인 전용 등 중고시장에 안 도는 차가 있다 |

### 정렬 우선순위

`우리재고대수` 내림차순 → `엔카매물수` 내림차순.
**우리가 실제로 파는 차의 결손이 먼저다.** 21만 대 전수라도 우리와 무관한 결손은 뒤로 민다.

### 신뢰도 문턱

엔카 매물 **3대 미만인 조합은 「결손」으로 올리지 않는다.**
오타로 등록된 매물 하나 때문에 마스터에 없는 트림이 생긴다.

## 5. 하지 말 것

> **마스터가 정본이다. 엔카는 참고 자료다.**

- ❌ **자동 반영 금지.** `catalog.json`이 마스터를 직접 고치는 경로는 만들지 않는다
- ❌ **표기 갈아치우기 금지.** 엔카가 「가솔린 2.0」이라 해도 우리 파워트레인 규격을 따른다
- ❌ **삭제 금지.** 「우리만」에 뜬 항목을 지우지 않는다
- ✅ 넣는 건 **빈 곳 채우기만.** 기존 트림 목록은 건드리지 않는다
- ✅ 반영 전 사장님이 `master-diff.csv`를 보고 승인

이유는 하나다 — 실측에서 재매칭이 기존 값을 지우는 차가 12대 나왔다.
원문에 「스탠다드」가 또렷한데 마스터에 없어서 지워지는 것이었다.
**못 잡는 것보다 틀리게 잡는 게 나쁘다.**

## 6. 받아들일 조건

1. `catalog.json`에 **국산·수입 모두** 들어 있을 것 (`CarType.A`)
2. 한글이 깨지지 않을 것 — 「더 뉴 그랜저 IG」가 그대로 읽힐 것
3. 중간에 끊고 다시 돌려도 **처음부터 다시 받지 않을 것**
4. `master-diff.csv` 상위 30행에 아래가 **결손으로 잡힐 것** (이미 실측으로 아는 답)

```
트랙스 크로스오버 9BQC   RS              우리재고 18대
더 2026 셀토스 SP3     베스트 셀렉션      우리재고 12대
```

이 넷이 안 나오면 대조 로직이 틀린 것이다. **정답지로 쓸 것.**

