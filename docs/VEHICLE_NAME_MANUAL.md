# 차명 매뉴얼 — 어떻게 갖고 와서 어디에 어떻게 놓나

> 사장님 2026-08-28 「차명을 어떻게 갖고 와서 어떤 위치에 어떻게 놓는지 · 어디는 모델명만 ·
> 어디는 세부모델로 · 어디는 세부트림까지 조합해서 · 이걸 학습해서 제안해 보라고」.
>
> 실측: `scripts/audit-vehicle-name-tiers.mts` (매물 816대, 2026-08-28)

---

## 1. 이름은 조립한다 — 원문을 그대로 쓰지 않는다

공급사가 시트에 적은 글자는 이렇게 생겼다:

```
싼타페 MX5 26MY 하이브리드 2WD 7인승 익스클루시브
기아_쏘렌토_쏘렌토 하이브리드(4세대) / 프레스티지
베뉴25MY 자가용 가솔린1.6IVT PREMIUM(원톤)
```

연식·연료·구동·인승·판매문구가 이름에 섞여 있다. 그대로 쓰면 **차마다 이름 길이가 제각각**이고,
연식·연료는 아래 스펙 줄에서 또 나와 **같은 값이 두 번** 나온다.

그래서 **정제칸에서 원자를 꺼내 우리가 조립한다.** 공급사 원문은 버리지 않고
상세 「기타사항 › 공급사 차명」에 따로 세운다(2중 보관 — 우리가 어떻게 바꿔 읽었나를 대조하는 자리).

```
원문   싼타페 MX5 26MY 하이브리드 2WD 7인승 익스클루시브
       ↓ 정제칸에서 꺼낸다
조각   제조사=현대 · 세부모델=싼타페 MX5 · 세부트림=익스클루시브
       ↓ 조립
이름   현대 싼타페 MX5 익스클루시브
```

## 2. 이름을 이루는 원자 — 실제로 얼마나 차 있나

| 칸 | 채워짐 | 이름에 쓰나 |
|---|---:|---|
| `maker` 제조사 | 100% | ○ 맨 앞 (좁은 화면에서만 뺀다) |
| `sub_model` 세부모델 | 98% | ○ **이름의 몸통** |
| `model` 모델명 | 100% | △ 세부모델이 없을 때만 대신 선다 |
| `trim_name` 세부트림 | 84% | ○ 몸통 뒤 |
| `variant` 파워트레인 | **0%** | (비어 있다 — 아래 §5) |
| `trim_extra` 추가표기 | **0%** | (비어 있다) |
| `vehicle_name` 완성명 | 0% | 레거시. 정제칸이 통째로 빌 때 최후 수단 |
| `supplier_vehicle_name` 원문 | 100% | ✕ **이름으로 쓰지 않는다.** 기타사항에만 |

실측: 몸통이 **세부모델로 선 차 781대 · 모델명으로 선 차 32대 · 둘 다 없는 차 3대.**

## 3. 어디에 무엇을 놓나

**규격은 하나다 — 「제조사 + 세부모델 + 세부트림」.** 자리마다 다른 이름을 만들지 않고,
**어디를 잘라 쓰는지**만 다르다. 자리마다 조립을 새로 하면 화면끼리 글자가 어긋난다.

| 자리 | 무엇을 | 왜 |
|---|---|---|
| **모바일 목록 카드** | 세부모델 + 세부트림 (**제조사 뺌**) | 폭이 좁다. 제조사는 사진과 모델 이름으로 이미 안다 |
| **웹 목록 · 카드 제목** | 제조사 + 세부모델 + 세부트림 | 폭이 있다. 제조사가 정렬·검색의 첫 단서다 |
| **상세 맨 위 제목** | 제조사 + 세부모델 + 세부트림 (전문) | **여기가 이름의 정본 자리.** 본문에서 다시 적지 않는다 |
| **상세 본문** | — | 「차명」 줄 없음(2026-08-28 제거). 제목과 같은 값을 두 번 읽게 했다 |
| **계약서 · 서명 · 공유 · 문서** | 전문 + 차량번호 | 어느 차인지 특정해야 한다. 계약은 **계약 당시 스냅샷**이 정본 |
| **채팅방 · 알림 제목** | 짧게 (세부모델까지) | 한 줄에 다른 정보와 같이 선다 |
| **검수 · 감사 로그** | **원문 그대로** | 증거다. 정규화·중복 제거를 하지 않는다 |

### 조립은 한 곳에서만
`lib/domain/vehicle-name.ts` 의 `vehicleNameOf` / `vehicleNameParts` 가 유일한 조립기다.
**화면에서 손으로 이어 붙이지 않는다** — 붙이는 순간 제목과 공유 문구의 글자가 갈린다.

```ts
vehicleNameOf({ kind: 'product', product: p }, { tier: 'full' })                    // 웹 제목
vehicleNameOf({ kind: 'product', product: p }, { tier: 'full', omitMaker: true })   // 모바일 목록
vehicleNameOf({ kind: 'contract', contract: c, product: p }, { tier: 'full' })      // 계약 (스냅샷 우선)
vehicleNameOf({ kind: 'raw', raw: p }, { tier: 'raw' })                             // 감사 전용
```

## 4. 이름에 넣지 않는 것

- **연식 · 주행 · 연료 · 배기량 · 구동 · 인승** — 원자로 따로 갖고 있다가 스펙 줄에서 쓴다
- **색** — 차의 이름이 아니다
- **판매문구**(런칭·자가용·원톤·MY 표기) — 공급사 영업 글이다
- **제조사 중복** — 트림 원문에 제조사가 또 들어 있으면 걷어낸다

## 5. ★지금 어긋나 있는 것 (실측 2026-08-28)

### ① 등급 T1·T2 가 실제로는 같다 — 816대 전부 0% 차이
설계상 `short`(T1) = 제조사+몸통+트림, `full`(T2) = T1 + 파워트레인 + 추가표기 인데,
**`variant`·`trim_extra` 가 816대 전부 비어 있어** 두 등급이 늘 같은 글자를 낸다.

> **제안** — 둘 중 하나를 고른다.
> (가) 파워트레인(`variant`)을 정제칸에서 채운다. 「2.5 가솔린 터보」가 이름에 서야 하는지
>      사장님 판단이 필요하다 — 서면 이름이 길어지고, 안 서면 등급을 둘 둘 이유가 없다.
> (나) **등급을 하나로 줄인다.** 지금 화면들이 실제로 가르는 축은 등급이 아니라
>      «제조사를 넣나 빼나»(`omitMaker`) 하나뿐이다.
>
> 지금 상태는 «둘인 척하는 하나»라, 다음 사람이 T1/T2 를 다른 뜻으로 알고 고친다.

### ② 색이 세부트림 칸에 들어와 이름에 선다 — 25대
제네시스 **기본형** 차들이다. 공급사 원문에 트림명이 없고 색만 있어 정제 때 색이 트림 자리에 앉았다.

```
원문  제네시스_GV80_3.0 디젤 AWD_기본형     → 이름 「제네시스 GV80 블랙」
원문  G90 RS4 가솔린 3.5T AWD 블랙          → 이름 「제네시스 G90 블랙」
```

색은 §4 대로 이름에 넣지 않는다. **트림이 「기본형」이면 「기본형」으로 두거나 비운다.**
고치는 자리는 화면이 아니라 **정제칸(AI 정제 사전)** 이다.

### ③ 제원이 세부트림 칸에 들어온 차 — 3대
`45 TFSI` · `45 TFSI S line`(아우디). 수입차 트림 표기가 원래 제원을 품는 형태라
색과 달리 «틀린 값»은 아니다. 다만 국산 규격과 모양이 다르다는 것은 알아 둔다.

## 6. 길이 — 잘림은 이름을 줄여서 풀지 않는다

전문(제조사 포함) 글자 수: 최소 5 · 중앙 **16** · 95% **23** · 최대 42.

목록에서 이름이 잘리는 것은 **정상**이다(사장님 2026-08-22 「목록에 나오는 거는 세부모델
세부트림, 짤리는 건 어쩔 수 없고」). 잘림은
- 제목에 `title` 속성을 붙여 마우스로 전문을 보이고
- 상세 제목에서 전문을 편다

로 푼다. **같은 이름을 한 화면에 두 번 찍어서 풀지 않는다.**

## 고칠 때 지킬 것

1. 조립은 `vehicle-name.ts` 한 곳에서만. 화면에서 손으로 잇지 않는다
2. 공급사 원문을 이름으로 쓰지 않는다 (기타사항에만)
3. 이름에 연식·연료·구동·인승·색·판매문구를 넣지 않는다
4. 정제 결과가 이상하면 화면이 아니라 **정제칸**을 고친다
5. 바꾸면 이 문서를 같이 고친다
