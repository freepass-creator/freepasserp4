>

> 왜 이 문서가 필요한가 — 2026-09-08 하루에 판매시트가 **21회차 연속 발행 실패**했고, 그 원인이 전부

## 0. 한 줄

```
원천(공급사 시트·홈피·API)
   │  ① 직접수집 — 차번 하나에 «값 한 벌»을 완성해 원자에 박는다
   ▼
원자 products  (차번 = 문서키, 구조적 유일)
   │  ② 문지기가 검사한다 — 통과해야 아래로 내려간다
   ├──▶ 상품리스트 공용 [F01]      4탭 (상품리스트·손오공구독·픽업구독·오플구독)
   ├──▶ 상품리스트 하허호 [F86]    F01 을 «회사별로만» 쪼갠 것
```

★**넷은 «같은 원자»를 읽는다.** 어느 하나가 따로 세거나 시트를 다시 읽으면 그 순간 갈린다.
  실제로 그래서 「1초 만에 582 → 694」가 났었다(`CLAUDE.md` 「화면이 시트를 직접 읽어 상태를 덮지 않는다」).

## 1. ★★칸마다 주인은 하나다

**오늘 사고의 뿌리.** 한 문서를 넷이 쓰면서 서로의 칸을 덮었다 —
`_direct_ingest_at` · `_mirror_at` · `_refined_at` · `_var_synced_at` 가 한 문서에 같이 찍혀 있고,
상태가 `status`(출고가능)와 `vehicle_status`(출고불가)로 **두 벌**이 되어 있었다(실측 161허1334).

| 칸 묶음 | 주인 | 그 밖은 |
|---|---|---|
| **정체·제원** 차명(원문)·제조사·모델·세부모델·세부트림·색·연식·배기량·구동·인승·원산지 | **직접수집**(원천 → 원자) | 읽기만. 빈 칸 채움도 «원천이 없을 때»만 |
| **상태** 배차상태·listable | **상태 연동**(매시간) + **정산원장**(⑤′ 계약중/출고불가) | 아무도 안 덮는다 |
| **요금** 대여료·보증금 | **가격블록** | 덮지 않는다 |
| **정책·계좌** 보험·연령·해지·전용계좌 | **정책 조인**(공급사 「운영정책」) | 덮지 않는다 |
| **상품구분** | **원천 「분류」** → `canonProductType` | 라이프사이클로 바뀐다 — write-once 로 굳히지 마라 |

⚠ **상태 칸을 두 벌로 두지 않는다.** `vehicle_status` 하나만 쓴다.
  `status`·`status_kind`·`listable` 은 그 하나에서 «파생»되는 값이지 따로 적는 값이 아니다.

⚠ **빈 칸을 지어내지 않는다.** 원천에 없으면 「없다」가 아니라 «모른다»다 — 비운 채로 내리고 목록으로 받는다.
  ★단 하나 예외: 세부트림은 그 세부모델 마스터 풀에 없으면 **「기본형」**(`차종명명-정제-매뉴얼` §3).

## 2. ★★출고불가여도 원자는 온전하다

> 사장님 2026-09-08 「출고불가여도 일단 **데이터는 다 갖고 와서 맞춰 놓자**」
> `CLAUDE.md` — 「차량 스펙·조건·대여료·정책 = **상태값과 무관하게** 무조건 노출한다」(2026-09-04)

```
출고불가 = 「목록에 안 세운다」          ← 발행이 상태를 보고 정한다
        ≠ 「그 차를 모른다」            ← 원자는 온전해야 한다
```

⚠ 실측 2026-09-08 — 웰릭스 여섯 대가 시트엔 41~44칸이 차 있는데 원자엔 12~14칸뿐이었다.
  상태 하나 때문에 차 이름·요금·정책이 통째로 사라져, 다시 팔 때마다 처음부터 채워야 했다.

## 3. 내려가는 네 곳 — 무엇이 같고 무엇이 다른가

| | 상품리스트 공용 [F01] | 하허호 [F86] | ERP | 화이트라벨 |
|---|---|---|---|---|
| 무엇 | 우리 영업자가 보는 표 | 채널이 보는 표 | 파인더·상세 | 채널 이름으로 나가는 손님 면 |
| 가르는 축 | **갈래**(구독·픽업·오플·나머지) | **회사** | 필터 | 채널 |
| 열 | @매핑 정본 | **F01 열 그대로** — 여기서 새로 정하지 않는다 | — | — |
| 정렬 | 아래 §4 | 같음 | 같음 | 같음 |
| 나가면 안 되는 것 | — | **원가·수수료** | — | **원가·수수료 · 우리 상호** |

★**하허호 시트는 F01 을 «회사별로만» 쪼갠 것**이다(사장님 2026-09-08 「F01 을 토대로 그냥 회사별로만
  쪼개 놓으면 되는 건데」). 열·요금 규격을 여기서 다시 정하지 않는다 —
  ⚠ 실제로 규격을 새로 짜다가 오플 탭 열을 «두 벌»로 만들어 시트를 깨뜨렸다(2026-09-08).

★**화이트라벨 = 우리 이름이 서면 안 된다**(`CLAUDE.md` — 「노브랜드로 아무것도 안 보여야 되는 거니까」).
  공급사·영업자가 같이 쓰는 판이라 브랜드 표식을 세우지 않는다. 채널 시트도 같은 규율이다.

## 4. 기본 정렬 — 어떤 리스트도 같다

정본은 `docs/영업자시트-매뉴얼.md` 「★기본 정렬」. 여기 요약만 둔다.

```
① 신차가 맨 위
② 모델별로 «묶는다»   인기순(계약 실적) → 상품 많은 순 → 모델명
③ 묶음 «안»에서       신차 = 싼 대여료 · 중고 = 최신 연식 먼저, 그다음 값
④ 공급사 · 차번
```
★**「인기순」과 「상품 많은 순」은 다른 축**이다 — 인기는 «팔린 것», 상품 많은 순은 «들고 있는 것».
  ERP 가 `popular` 한 칸에 뭉쳐 둔 것은 고쳐야 할 자리다(사장님 2026-09-08 「ERP 정본이 잘못된 거야」).

## 6. 하면 안 되는 것

1. **원자를 안 거치고 시트→시트로 나르지 마라.** 대수가 두 군데서 세어져 어느 숫자도 못 믿게 된다.
2. **발행기가 규칙을 들고 있지 마라.** 오플 보증금 문구·손오공 반납형 키·단기/장기 범위가
   발행기 안에 흩어져 있었고, 그게 오플 보증금 0/84 의 원인이었다. **차번에 딸린 값을 칸에 박기만 한다.**
3. **한 탭을 두 발행기가 쓰지 마라.** ⑥ 과 ⑯ 이 같은 탭을 덮어 21회차 발행이 죽었다.
   가드는 반드시 **제가 찍은 대수**와 견준다(`tmp/판매탭-직전대수.json`).
4. **코드를 공급사로 취급하지 마라**(사장님 2026-09-08). 표시는 이름, 그것도 **한글**
   (에스에이·케이에이치·제이앤제이 — 제공시트 이름이 정본). 못 찾으면 «비운다», 코드로 때우지 않는다.
5. **채널·공급사 시트에 우리 몫을 싣지 마라.** 원가·수수료·마진은 한 칸도 안 나간다.

## 7. ★★값을 재기 «전»에 «어디서 읽는지»를 잰다

> 2026-09-08 — 이 문서를 쓰다가 「틀린 차 이름」의 진짜 원인을 찾았다. 매칭기가 아니라 **주소**였다.

```
웰릭스 원천 = partner.sheet_url = 1hfXngq… = 2026-08-15 «폐기된» 옛 제공시트
   그 시트의 차명 열 이름은 「차명(트림)」 — 별칭 목록에 없다        → 차명 빈 칸
   차명이 비면 「제조사+모델+트림」으로 합성하는데 그것도 다 비었다    → 남은 건 「기아」 한 마디
   매칭기가 「기아」를 보고 아무 모델이나 붙였다                    → K8이 «모닝», 카니발이 «스포티지»
```

**24일 동안 아무도 몰랐다.** 시트는 «읽혔고», 행도 «있었고», 게이트도 통과했기 때문이다.
실측하니 **11개 공급사**가 같은 식으로 폐기 주소에 멈춰 있었다.

★**문패(공급사시트정리)가 원천 주소의 정본**이다. `partner.sheet_url` 은 화면용 사본이라 늦는다.
  규칙 SSOT = `lib/domain/supplier-source.ts` — 폐기 명단에 있는 주소면 **던진다**(조용히 읽지 않는다).

```
검사   npx tsx … scripts/audit-supplier-source.mts     문패 ↔ 사본 ↔ 폐기 명단
고침   npx tsx … scripts/align-partner-sheet-url.mts --apply   사본을 문패에 맞춘다
```
⚠ **읽는 주소와 보는 주소가 다르면 사고가 안 보인다** — 화면은 죽은 시트를 열어 주고 코드는 딴 데서
  읽으니, 어느 쪽이 진짜인지 아무도 못 짚는다. 그래서 둘을 «같게» 둔다.

⚠ **제조사 한 마디는 차명이 아니다** — 비운다. 「모른다」로 남겨야 검수 목록에 오른다.
  지어낸 이름은 조용히 팔려 나가지만, 빈 칸은 누군가 채우게 된다.
