## 2. 필수값 — 「비어 있음」과 「없음」은 다르다

빈칸은 «직원이 안 채웠다»로 읽히고, `0원`은 «그렇게 합의했다»로 읽힙니다.
그래서 **보증금 0원 계약도 `0` 을 명시로 받습니다.**

### 없으면 못 보냄

| 값 | 비고 |
|---|---|
| 차명 | |
| 차량번호 | **신차라 아직 없으면 「미정」** 이라고 적으면 통과 |
| 대여기간 | 1~120개월 |
| 월 대여료 | 없으면 `0` |
| 보증금 | 없으면 `0` |
| 운전자 연령 · 약정주행거리 · 특약 확인(있음/없음) | |
| 렌터카사 · 고객명 · 연락처 · 계약 정책 · 납부 조건 | |

### 없어도 보냄

```
차대번호 · 연식 · 주행거리 · 연료 · 배기량 · 구동방식 · 승차정원
색상 · 선택 옵션 · 차량가액 · 비고
```
→ **안 적으면 ERP 값이 그대로 나갑니다.** 발송 화면 자리표시에 `ERP: 가솔린` 처럼 보입니다.

## 3. 규격 규칙 — 깨면 안 되는 것

전부 실측으로 잡은 것들입니다. 되돌리면 같은 증상이 다시 납니다.

1. **글자 크기는 `:root` 의 `--fs-*` 9개만.** ERP `tokens.ts FS` 에서 인쇄용으로 한 단(−1px) 내린 값
2. **라운드는 `--radius`(4)·`--radius-card`(8) 둘뿐.** 칩 전용 3px 같은 걸 새로 만들지 않는다
3. **표는 전부 「머리띠 + 카드」.** 장별 override 금지 (칸 여백이 6/5/3.5px 세 갈래였던 적 있음)
4. **`.rhead` 여백을 장마다 바꾸지 않는다** — 문서의 시작선이다
5. **인라인 색으로 글자 크기를 바꾸지 않는다.** 부연은 `.dim` 클래스로
6. **`data-accent` 는 속성 맨 뒤에** — `class="section" data-contract-option="…"` 이 붙어 있어야 sim 통과
7. **약관 조문 참조는 「제17조 및 제18조」.** 축약(`제17조·제18조`)은 sim 이 막고, **주석에 써도 걸린다**
8. **새 `data-field` 는 `FIELD_MAP` 에 등록**
9. **발송 화면에서 받는 값은 `ISSUE_INPUT_FIELDS` 에 등록** — 빠지면 입력해도 말없이 버려진다
10. **세로 간격은 하나의 사다리** — 머리띠→표 0 · 표→그 표의 ※ 1.2mm · 블록→블록 5mm · 섹션→섹션 8mm
11. **한 줄짜리를 표로 세우지 않는다.** 표 밑 부가 설명(※)으로
12. **파란 안내 박스를 잇달아 쌓지 않는다.** 단계 안내는 «가이드»지 알림이 아니다

## 4. 함정 — 겪은 것

| 증상 | 진짜 원인 |
|---|---|
| 보증금 있는 계약이 「계약서 만들기」가 영원히 비활성 | `draftInputRecord` 가 `contract_draft` 를 안 실어 회차 선택이 검증기에 안 닿았다 |
| 발송 화면에서 입력했는데 계약서에 안 찍힘 | `ISSUE_INPUT_FIELDS` 허용목록에 없으면 **말없이 버려진다** |
| 표 칸 「없음」만 이웃보다 작게 인쇄됨 | `[style*="color:var(--mute)"]` 규칙이 **인라인 색을 근거로 크기까지** 줄였다 |
| 약관 하단이 매 장 15~24mm 씩 빔 | 되돌림 판정이 «바닥에 닿음»을 «넘침»으로 오인해 잘 채운 배치를 매번 폐기 |
| 폰트가 이상해 보임 | 파일(`file://`)로 열면 `/fonts/…` 절대경로라 **Pretendard 가 안 붙는다.** 반드시 서버로 |
| 「넘침 0」인데 실제로 글이 잘림 | `.pbody` 가 `overflow:hidden` 이라 `scrollHeight` 로는 못 잡는다 |
| 계약서 서식을 레지스트리로 옮겼더니 경계 가드가 FAIL | 가드가 «파일명 문자열»을 보고 있었는데 파일명이 `CONTRACT_DOCUMENT_TEMPLATES` 로 옮겨 갔다. **가드를 푸는 게 아니라** 같은 성질을 다시 세운다 — ① 빌더가 허용목록을 거치는가 ② 기본값이 표준 계약서인가 ③ 등록된 서식 파일이 실제로 있는가 ④ **아무 값이나 넣어도 허용목록 밖으로 안 나가는가(실제로 돌려서)**. 정규식 부정 검사는 안전한 코드까지 잡아 못 쓴다 |
| **손님이 어느 화면에서 400 으로 갇힘** | 화면이 새 단계를 만들면 그 키로 진행을 기록하는데, 서버 `PROGRESS_KEYS` 에 없으면 「기록할 전자계약 단계가 올바르지 않습니다」로 막힌다. 실제로 **개인 계약이 「매출증빙」에서 통째로 막혀 있었다**(2026-08-28). 화면·서버를 각자 만지면 서로 「상대가 했겠지」로 지나간다 — `sim-esign-progress-keys` 가 맞춘다 |
| 계약조건 낱장을 체크했는데 서버에 기록이 없음 | 낱장 확인도 같은 길(`markProgress`)로 가는데 **`.catch(() => {})` 로 조용히 삼킨다.** 허용목록에서 빠지면 화면은 멀쩡한데 기록만 사라져 **눈으로는 못 잡는다** |
| 손님이 입력한 값이 계약서에 자리표시자로 찍힘 | `FIELD_MAP` 등록 + 제출 API 저장까지 했는데 **봉인 스냅샷(`esign-signed-snapshot`)이 그 칸을 안 실었다.** 세 곳을 다 지나야 계약서에 닿는다 — ① FIELD_MAP ② 제출 저장 ③ **봉인 스냅샷 `confirmedFields`**. `from:` 메타는 배선의 증거가 아니다 |
| 차량가액에 엉뚱한 값 | 재고 `vehicle_price` 는 **관리자 전용 원가**, 전자계약 쪽 같은 이름 필드는 **기간별 대여료 표**였다 |
| 신차 계약을 아예 못 보냄 | `erp_product` BLOCK 이 항상 걸렸다 — 신차는 ERP 재고에 없는 차다 |
| ERP 차량 고르면 차량번호를 못 고침 | 고르는 순간 입력칸이 사라져, 재고부터 바꾸러 가야 했다 |

## 8. 법인 계약 — 임차인과 «서명하는 사람»은 다르다

2026-08-28 · 사장님 「법인계약도 대표자가 서명하고 처리할 수 있게끔」

### 무엇이 문제였나

법인으로 발행하면 계약자 칸이 통째로 법인 값으로 바뀐다.

| 칸 | 개인 | 법인 |
|---|---|---|
| `customer_name` | 성명 | **법인명** |
| `customer_id` | 주민등록번호 | **법인등록번호** |
| `driver_license_no` | 운전면허번호 | **사업자등록번호** |

즉 **대표자 개인을 적을 자리가 없었다.** 그런데도 「본인 신분증을 촬영해 주세요」·「본인 얼굴을
촬영해 주세요」를 시켰다 — **누구의 얼굴인지 대조할 기준이 없는 사진**을 받고 있었다.

### 바로잡을 것 하나 — 대표이사의 서명은 「위임」이 아니다

**대표이사가 법인 계약에 서명하는 것은 «대표권 행사»다. 위임장이 필요 없다**(법인등기부등본이
대표권을 증명한다). 위임장이 필요한 건 **대표이사가 아닌 임직원**이 서명할 때뿐이다.

한 벌로 묶으면 정상 계약에서 없어도 되는 서류를 요구하게 된다. 그래서 관계를 **값으로** 받는다.

### 칸 — `FIELD_MAP` 등록 완료

| 필드 | 라벨 | 필수 | 비고 |
|---|---|---|---|
| `signer_name` | 서명자 성명 | ✅ | |
| `signer_role` | 법인과의 관계 | ✅ | **「대표이사」 / 「위임받은 임직원」 둘 중 하나** |
| `signer_id` | 서명자 주민등록번호 | ✅ | 13자리 · **암호화 저장**(`rrn-crypto`) |
| `signer_license_no` | 서명자 운전면허번호 | ❌ | 서명자가 곧 운전자는 아니다. 필수로 걸면 면허 없는 대표이사가 막힌다. 비면 계약서에서 그 줄이 접힌다 |

> ⚠ 셋 중 하나라도 없거나 관계가 저 두 값이 아니면 **서버가 제출을 막는다**
> (`app/api/freepass-esign/public/[token]/route.ts`). 화면에서 안 받으면 법인 계약이 아예 안 나간다.

### 서류 — 손님이 관계를 고르는 «그 자리»에서 승격된다

법인 프리셋(`corporate`)은 **하나**다. 위임 서류는 「해당 시」로 항상 목록에 있다.

```
발행 시점        필수  사업자등록증 · 법인등기부등본 · 법인인감증명서
                해당 시 위임장 · 재직증명서

서명자 = 대표이사        그대로 (위임 서류 안 내도 됨)
서명자 = 위임받은 임직원   위임장 · 재직증명서가 필수로 승격
```

**왜 프리셋을 둘로 안 나눴나** — 발행 시점에는 누가 서명할지 모른다. 프리셋은
`contract.customer_type` 에서 **자동으로** 정해지고, 영업이 고르는 자리가 없다.
둘로 나눠 두고 영업이 잘못 고르면 **계약서에 「대표이사」라고 거짓이 찍힌다.**

승격 규칙은 한 곳에만 있다 — `applySignerRoleToDocuments()`.
**손님 화면과 서버가 이 함수 하나를 같이 쓴다.** 각자 판정하면
「화면엔 선택인데 서버가 막는」 상태가 되고, 손님은 이유를 모른 채 갇힌다.

> ⚠ 발행 가드(`lib/server/freepass-esign.ts`)는 **필수인 party 서류만** 동결을 확인한다.
> 「해당 시」까지 요구하도록 되돌리면 **법인 계약이 아예 발행되지 않는다.**

### 계약서에서 어디에 찍히나

**01 이 아니라 서명란 바로 위**다. 이유 둘:
1. 01 의 남는 자리는 **12mm** 인데 이 표는 **34.7mm** 다(실측 2026-08-28). 애초에 안 들어간다
2. 뜻으로도 여기가 맞다 — 서명하는 손의 신원은 서명란에 붙어 있어야 읽힌다
   (임대인 쪽 「대표이사 조규진」과 같은 자리)

넣고 잰 값: **개인 17장 · 법인 17장, 둘 다 넘침 없음.**

### 되돌아가지 못하게 박은 것

```bash
npx tsx scripts/sim-esign-corporate-signer.mts
```

일곱 가지를 본다 — 서식 칸·법인 전용 접힘 · FIELD_MAP 등록 · **제출값이 봉인 스냅샷까지 흘러가는지**
· 개인 계약에선 안 채워지는지 · 위임 서류 승격 · 발행 가드 · 관계 목록이 한 곳인지.

> **왜 만들었나**: 실제로 «받기만 하고 버리는» 사고를 냈다(2026-08-28).
> FIELD_MAP 에 등록하고 제출 API 에서 저장까지 했는데, **봉인 스냅샷이 그 칸을 안 실어서**
> 계약서에는 자리표시자가 그대로 찍힐 뻔했다.
> `FIELD_MAP` 의 `from:` 은 **메타데이터라 실제 배선을 증명하지 못한다** —
> 같은 이유로 `tax_ceo`·`tax_email`·`tax_biz_type_item` 은 배선돼 있는데 「미정」으로 적혀 있어
> 감사가 3개를 헛경보하고 있었다. **배선은 흘려봐야 안다.**

### 아직 안 된 것 — 손님 화면

`app/sign/[token]/page.tsx` 에 **「서명자 정보」 화면**이 없다. 법인일 때만 서는 단계다.
`corporate === true` 이면 `identity` 다음에 세운다.

## 9. 주민등록번호 키 — `FREEPASS_RRN_KEY`

### 상태 — **등록 완료 (2026-08-28)**

```
Production   ✓ Sensitive
Preview      ✓ Sensitive
Development  ✓ Non-sensitive   ← 일부러다. env:pull 이 .env.local 로 받아야 로컬이 돈다
.env.local   ✓
```
세 환경 모두 **같은 값**(32바이트 hex). 값은 어디에도 찍지 않았다 —
필요하면 `npx vercel env pull` 로 꺼낸다(민감 표시된 Production·Preview 는 되읽을 수 없다).

붙는 두 지점도 다 돼 있다.
```
저장  app/api/freepass-esign/public/[token]/route.ts            encryptRrn()
해제  app/api/freepass-esign/contracts/[contractCode]/route.ts  decryptRrn()
```

**동작 확인** — `enc.v1.` 표식 · 되돌리기 · 매번 다른 암호문(IV) · 원문 비노출 · 옛 평문 통과 ✓

**가장 안전한 순간에 넣었다** — 등록 전에는 암호화된 기록이 하나도 없었다.
나중에 정했다면 그 사이 쌓인 것을 못 풀었을 것이다.

### 키 규격

**32바이트.** hex 64자 또는 base64. 만드는 법:
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### ★깨면 되돌릴 수 없는 것 셋

1. **키를 바꾸면 옛 계약의 주민번호를 영영 못 푼다.**
   `decryptRrn` 은 실패해도 던지지 않고 **빈 값**을 돌려준다 — 계약서 전체가 안 나오는 것보다
   그 칸만 비는 편이 낫기 때문이다. 즉 **조용히 사라진다.** 로테이션은 «옛 키로 풀고 새 키로 다시 감싸는»
   이관 스크립트가 먼저다.
2. **세 환경에 같은 키를 넣는다.** 다르면 Preview 에서 만든 계약을 Production 에서 못 푼다.
3. **키를 코드·문서·커밋에 남기지 않는다.** Vercel 환경변수와 사장님 보관처에만 둔다.

### 남은 것 — 평문으로 저장된 옛 계약 (담당 **Codex**)

암호화를 붙이기 «전»에 제출된 계약은 RTDB 에 **평문 13자리**로 남아 있다.
`isEncryptedRrn()` 이 `enc.v1.` 표식으로 가려내므로, 표식 없는 것만 골라 감싸는 이관이 필요하다.
**얼마나 있는지부터 세는 것이 먼저다.**

### 함정 — `env:diff` 의 「≠prod」

민감으로 표시된 값은 **되읽을 수 없다**. `vercel env pull` 하면 `"[SENSITIVE]"` 가 대신 온다.
`env:diff` 가 그걸 모르고 **18개 키를 계속 「≠prod」로 헛경보**하고 있었다(2026-08-28 고침).
이제 `?`(못 봄)로 나온다.

> 헛경보가 상시로 켜져 있으면 **진짜 어긋남이 났을 때 아무도 안 본다.**
