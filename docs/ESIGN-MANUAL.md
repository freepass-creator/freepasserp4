## 2. 필수값 — 「비어 있음」과 「없음」은 다르다

빈칸은 «직원이 안 채웠다»로 읽히고, `0원`은 «그렇게 합의했다»로 읽힙니다.
그래서 **보증금 0원 계약도 `0` 을 명시로 받습니다.**

### 없으면 못 보냄

| 값 | 비고 |
|---|---|
| 차명 | |
| 차량번호 | **신차라 아직 없으면 「미정」** 이라고 적으면 통과 |
| 대여기간 | 1~120개월 |
| 월 대여료 | 없으면 `0` |
| 보증금 | 없으면 `0` |
| 운전자 연령 · 약정주행거리 · 특약 확인(있음/없음) | |
| 렌터카사 · 고객명 · 연락처 · 계약 정책 · 납부 조건 | |

### 없어도 보냄

```
차대번호 · 연식 · 주행거리 · 연료 · 배기량 · 구동방식 · 승차정원
색상 · 선택 옵션 · 차량가액 · 비고
```
→ **안 적으면 ERP 값이 그대로 나갑니다.** 발송 화면 자리표시에 `ERP: 가솔린` 처럼 보입니다.

## 3. 규격 규칙 — 깨면 안 되는 것

전부 실측으로 잡은 것들입니다. 되돌리면 같은 증상이 다시 납니다.

1. **글자 크기는 `:root` 의 `--fs-*` 9개만.** ERP `tokens.ts FS` 에서 인쇄용으로 한 단(−1px) 내린 값
2. **라운드는 `--radius`(4)·`--radius-card`(8) 둘뿐.** 칩 전용 3px 같은 걸 새로 만들지 않는다
3. **표는 전부 「머리띠 + 카드」.** 장별 override 금지 (칸 여백이 6/5/3.5px 세 갈래였던 적 있음)
4. **`.rhead` 여백을 장마다 바꾸지 않는다** — 문서의 시작선이다
5. **인라인 색으로 글자 크기를 바꾸지 않는다.** 부연은 `.dim` 클래스로
6. **`data-accent` 는 속성 맨 뒤에** — `class="section" data-contract-option="…"` 이 붙어 있어야 sim 통과
7. **약관 조문 참조는 「제17조 및 제18조」.** 축약(`제17조·제18조`)은 sim 이 막고, **주석에 써도 걸린다**
8. **새 `data-field` 는 `FIELD_MAP` 에 등록**
9. **발송 화면에서 받는 값은 `ISSUE_INPUT_FIELDS` 에 등록** — 빠지면 입력해도 말없이 버려진다
10. **세로 간격은 하나의 사다리** — 머리띠→표 0 · 표→그 표의 ※ 1.2mm · 블록→블록 5mm · 섹션→섹션 8mm
11. **한 줄짜리를 표로 세우지 않는다.** 표 밑 부가 설명(※)으로
12. **파란 안내 박스를 잇달아 쌓지 않는다.** 단계 안내는 «가이드»지 알림이 아니다

## 4. 함정 — 겪은 것

| 증상 | 진짜 원인 |
|---|---|
| 보증금 있는 계약이 「계약서 만들기」가 영원히 비활성 | `draftInputRecord` 가 `contract_draft` 를 안 실어 회차 선택이 검증기에 안 닿았다 |
| 발송 화면에서 입력했는데 계약서에 안 찍힘 | `ISSUE_INPUT_FIELDS` 허용목록에 없으면 **말없이 버려진다** |
| 표 칸 「없음」만 이웃보다 작게 인쇄됨 | `[style*="color:var(--mute)"]` 규칙이 **인라인 색을 근거로 크기까지** 줄였다 |
| 약관 하단이 매 장 15~24mm 씩 빔 | 되돌림 판정이 «바닥에 닿음»을 «넘침»으로 오인해 잘 채운 배치를 매번 폐기 |
| 폰트가 이상해 보임 | 파일(`file://`)로 열면 `/fonts/…` 절대경로라 **Pretendard 가 안 붙는다.** 반드시 서버로 |
| 「넘침 0」인데 실제로 글이 잘림 | `.pbody` 가 `overflow:hidden` 이라 `scrollHeight` 로는 못 잡는다 |
| 차량가액에 엉뚱한 값 | 재고 `vehicle_price` 는 **관리자 전용 원가**, 전자계약 쪽 같은 이름 필드는 **기간별 대여료 표**였다 |
| 신차 계약을 아예 못 보냄 | `erp_product` BLOCK 이 항상 걸렸다 — 신차는 ERP 재고에 없는 차다 |
| ERP 차량 고르면 차량번호를 못 고침 | 고르는 순간 입력칸이 사라져, 재고부터 바꾸러 가야 했다 |

## 5. 열린 질문 — 아직 못 정한 것

| # | 질문 | 걸린 사람 |
|---|---|---|
| Q1 | **부속서류 빈칸을 어떻게 채우나** — 인수증 12칸·연대보증 8칸·개인사업자 세금계산서 7칸. 인도 시점 정보라 계약 발송 시점엔 존재할 수 없는 것이 섞여 있다. 손으로 쓰는 서식으로 둘지 / ERP 입력을 붙일지 | 사장님 |
| Q2 | **보증금 빈칸을 저장 시점에도 구분할까** — 지금은 발송 화면에서만 막힌다. `N()` 이 빈 문자열을 0 으로 바꿔 저장하므로, RTDB 에 굳고 나면 「안 적음」과 「0원」을 구분할 수 없다 | Claude·Codex |
| Q3 | **약관 「정비공장」 ↔ 계약서 「정비점」** — 뜻은 같고 글자가 다르다. 약관을 「정비점(정비공장 등)」으로 넓힐지 | 사장님 |
| Q4 | **배포** — `main` 이 162+ 커밋 뒤라 밀면 다른 세션 작업까지 통째로 나간다 | 사장님 |
