# 가지·병합 매뉴얼 — 충돌은 «사고»가 아니라 «묵힌 값»이다

> 2026-09-08. 열린 PR 여섯 중 **넷이 충돌**이었다. 하나(#15)는 나흘 묵혀 **충돌 파일 30여 개**가 됐고,
> 그건 풀 수가 없어서 **병합을 포기하고 「없는 것만 옮겨 심었다」.** 그 하루의 값을 여기 적어 둔다.

기계 검사 = **`npm run check:branches`** — 열린 가지의 충돌·묵음을 미리 잰다.
어긴 채로 두면 그 가지는 언젠가 「통째로 못 쓰는 가지」가 된다.

---

## 0. 한 줄 요약

**충돌의 크기 = 갈라진 날수 × 겹친 주제.** 둘 다 우리가 정하는 값이다.

```
#20  1커밋 · 하루 묵음 · 겹친 주제 1개  →  충돌 파일 1개  →  15분
#23  1커밋 · 사흘 묵음 · 겹친 주제 1개  →  충돌 파일 1개  →  20분
#15  193커밋 · 나흘 묵음 · 손님화면 통째  →  충돌 파일 30여 개  →  «병합 불가»
```

---

## 1. 가지를 따기 «전»에

### ① 주제로 나눈다 — 같은 화면을 두 가지가 동시에 짜지 않는다

#15 와 main 은 나흘 동안 **손님화면·화이트라벨·견적을 각자 다시 짰다.**
커밋 제목 겹침은 **0건**인데 충돌은 30여 파일이다 — 「다른 일을 했는데 같은 파일을 만졌다」가 아니라
**같은 일을 두 번 했다.** 이건 병합으로 못 푼다. 어느 쪽이 최신인지는 파일마다 다르고,
잘못 고르면 **새 판이 옛 판으로 되돌아간다**(「왜 또 얼레벌레 자꾸 바뀌냐」의 정체).

⇒ 가지 하나 = 주제 하나. 손님화면을 건드리는 가지는 **한 번에 하나만** 연다.

### ② 며칠 걸릴 일이면 «작게 여러 번» 판다

main 은 9/4~9/8 에 PR **25개**를 작게 머지했다. 그중 충돌 난 것은 없다.
같은 기간 #15 는 커밋 193개를 한 가지에 쌓았다. 차이는 실력이 아니라 **묶음 크기**다.

## 2. 가지를 딴 «뒤»에

### ③ 하루에 한 번 main 을 받는다

```bash
git fetch origin && git merge origin/main
```

받는 쪽이 **가지**다(main 에 밀어 넣고 푸는 게 아니라). 매일 받으면 충돌은 매번 한두 줄이다.
사흘 안 받으면 그 사흘이 통째로 한 번에 온다.

### ④ 밀기 전에 «건드리지 않고» 재 본다

```bash
git merge-tree --write-tree --name-only origin/main origin/<가지>
```

작업본을 전혀 안 건드리고 충돌 파일 목록이 나온다. `npm run check:branches` 가 이걸 전 가지에 대고 돈다.

### ⑤ PR 이 CONFLICTING 이 되면 «그날» 푼다

```bash
gh pr list --state open --json number,headRefName,mergeable
```

내일로 미루면 내일은 더 크다. 이 표에 CONFLICTING 이 하나라도 있으면 그날 일과에 넣는다.

---

### ⑥ `MERGEABLE/CLEAN` 은 「지금 main 에서 초록」이라는 뜻이 «아니다»

> 2026-09-08 실제. #22 는 `mergeable=MERGEABLE` · `verify=SUCCESS` 였는데
> **머지되자 main 이 `check:ui`·`check:building` 둘에서 깨졌다.** 그 체크는 **옛 base** 로 돌았고
> 그 사이 도면 눈금이 조여졌기 때문이다(`borderRadius: 2` · 하드코딩 높이 0→1).
> 게이트를 통과한 게 아니라 **옛 게이트를 통과한 것**이다.

**충돌(`mergeable`)과 초록(`statusCheckRollup`)은 다른 것이다.** 충돌이 없어도 «규격»은 어긋날 수 있다.

- 가지가 며칠 뒤처졌으면 **머지 «전»에 `git merge origin/main` 을 받아** 체크를 다시 돌린다.
  그게 「지금 main 에서 초록」의 유일한 증거다.
- 머지 «뒤»에도 main 에서 한 번 돌린다 — 여기서 빨간불이면 **그 자리에서** 고친다:

```bash
npm run typecheck && npm run check:tokens && npm run check:ui && npm run check:design && npm run check:building
```

## 3. 충돌을 «푸는» 법 — 파일 종류마다 다르다

### ㉠ 코드 — 상위집합이 이긴다

한쪽이 다른 쪽을 **포함**하면 포함하는 쪽을 통째로 취한다. 줄 단위로 섞지 않는다.

> #20 실제. `lib/server/firestore-ref-shim.ts` 를 양쪽이 각자 만들어 add/add 충돌.
> main 판에는 9/5 운영사고(16 UNAUTHENTICATED)를 겪고 넣은 **제한시간**과
> **「한 번 막히면 더 안 두드린다」**가 있었고 가지 판에는 없었다.
> ⇒ `git checkout --theirs` 로 main 판을 그대로. 가지가 진짜 가져오는 것(라우트 3개)만 남겼다.

**판정법** — `git diff <가지판> <main판>` 을 «양방향»으로 세어 본다. 한쪽 방향이 0 이면 그쪽이 부분집합이다.

### ㉡ 생성 데이터 — 글자로 병합하지 말고 «다시 돌린다»

```bash
git checkout --theirs public/data/vehicle-master.json   # 정본(main) 을 받고
npx tsx scripts/<그-스크립트>.mts --apply                # 스크립트를 다시 돌린다
```

> #23 실제. 차종마스터 JSON 을 양쪽이 각자 다시 만들었다(main = `market_class`·`newcar_priced`,
> 가지 = 연료축 분리). 글자로 병합하면 **어느 쪽 값이 살아남는지 아무도 모른다.**
> main 판을 받아 스크립트를 다시 돌리니 `market_class` 1,816건 그대로 · 의도한 6건만 바뀌었다.

### ㉢ 묵어서 «주제가 통째로 겹친» 가지 — 병합하지 말고 «옮겨 심는다»

**증상 셋이 같이 나오면 병합을 포기한다.**

```bash
# ㉠ 커밋 제목 겹침이 0 인데 충돌 파일이 열 개가 넘는다 = 같은 일을 두 번 했다
# ㉡ 겹친 파일에서 main 쪽이 «더 크다» = main 이 더 나아갔다
git cat-file -s origin/main:lib/whitelabel.ts        # 32,852
git cat-file -s origin/<가지>:lib/whitelabel.ts      # 15,345
# ㉢ 그런데 가지에만 있는 «새 파일»이 많다 = 그게 진짜 유실 위험이다
comm -23 <(git ls-tree -r --name-only origin/<가지> | sort) \
         <(git ls-tree -r --name-only origin/main   | sort)
```

⇒ **main 에서 새 가지를 뜨고, 위 `comm` 목록만 옮긴다.** 겹치는 파일은 손대지 않는다.
   옮길 때 **묶음별로 작은 PR** 로 나눈다(관제탑 한 벌 / 도구·기록 한 벌 …).
   원래 가지는 **닫는다** — 열어 두면 다음 사람이 또 병합을 시도한다.

⚠ 옮겨 심을 때 **딸린 것을 같이 본다.** 화면만 옮기면 빈 화면이다 —
  `/hub` 를 옮기면서 «상태를 쓰는» `hourly-sync` 의 발행 훅을 같이 옮겨야 했다.
  참조가 끊긴 곳은 이렇게 찾는다:

```bash
node node_modules/esbuild/bin/esbuild <옮긴 .mts 들> --loader:.mts=ts --outdir=/tmp/x
```

★**`.mts` 는 `npm run typecheck` 가 «안» 본다**(tsconfig `include` 의 `**/*.ts` 에 `.mts` 는 안 걸린다).
  스크립트를 옮겼으면 위 esbuild 파싱을 따로 돌린다.

### ㉣ 옮기면 «지금 규격»에 맞춰야 한다

묵은 가지의 코드는 그 사이 조여진 게이트를 모른다. 옮긴 뒤 **반드시** 돌린다:

```bash
npm run typecheck && npm run check:tokens && npm run check:ui && npm run check:design && npm run check:building
```

> 실제로 `/hub` 는 `fontSize: 20`(FS 여섯 값 밖) · `borderRadius: 999`(숫자 금지) ·
> 도면 미등록 셋에 걸렸다. 셋 다 옮기면서 고쳤다.

## 4. 충돌을 «안 나게» 만드는 법 — 파일 쪽 규칙

### ⑦ 생성 파일의 서식은 «하나»다

```
JSON.stringify(raw, null, 2)   ← 차종마스터 정본 서식. 1 로 쓰지 마라.
```

> 2026-09-08 실제. `retire-hybrid-master-models.mts` 만 들여쓰기를 **1칸**으로 썼다
> (`apply-market-class`·`apply-newcar-priced` 는 2칸). 한 항목만 바꿔도 **7만 줄이 통째로 다시 쓰여**
> 파일 전체가 충돌했다. 2칸으로 맞추니 **22줄** 바뀜으로 줄었다.

⇒ 같은 파일을 쓰는 스크립트가 둘 이상이면 **서식을 맞춘다.** 안 맞추면 그 파일은 영원히 충돌한다.

### ⑧ 「전부 다시 쓰기」를 하지 않는다

정렬·포맷·개행을 바꾸는 커밋은 **그것만** 담아 따로 올린다. 내용 변경과 섞으면
그 파일은 그 뒤로 어떤 가지와도 충돌한다.

| 재는 것 | 왜 |
|---|---|
| **충돌 파일 수** | `git merge-tree` 로 작업본 안 건드리고 미리 |

| **커밋 제목 겹침** | 0 인데 충돌이 크면 «같은 일을 두 번» — 병합 말고 옮겨심기 |
