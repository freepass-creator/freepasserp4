## 피드 API — `GET /api/newcar`
| 쿼리 | 뜻 |
|---|---|
| `?maker=현대` | 그 제조사만 (현대·기아·제네시스·르노) |
| `?model=그랜저` | sub_model 부분일치 (현대 「디 올 뉴 아반떼」·기아 「sorento」 슬러그) |
| `?group=model` | 모델별로 묶어서 — 견적기 「모델 고르고 → 트림·옵션」 흐름용 |

**응답(기본):**
```json
{ "count": 423, "makers": ["현대","기아","제네시스","르노"], "updatedAt": "2026-09-05",
  "trims": [ { "maker":"현대", "sub_model":"디 올 뉴 아반떼", "carType":"디 올 뉴 아반떼",
    "fuel":"가솔린", "trim":"모던", "priceBefore":23980000, "priceAfter":23980000,
    "options":[{"name":"컴포트 I","price":900000},…], "rules":[…] } ] }
```
`?group=model` 이면 `{ modelCount, models:[{maker, sub_model, fuels[], trimCount, trims[]}] }`.

## 필드 뜻 (확정 규격)
- **priceBefore / priceAfter** — 세제혜택 «전 / 후». 가솔린 등 감면 없으면 전=후. 전기·하이브리드는 다르다(개소세·교육세·취득세 감면). ★후>전 역전은 버그(택시·영업용 taxIncentive 음수 처리 완료).
- **options** — `[{name, price}]`. `price:0` = 기본 포함, 없으면(−) 해당 트림에 제외. 기아는 좌표추출이라 이름 일부 조각(`옵션N`) 가능, **가격은 정확**. 현대는 선형 파싱이라 이름 깨끗.
- **basePrices** (제네시스만) — 기본모델 엔진×구동 «변형 가격» 배열. 제네시스는 트림계층이 아니라 «기본모델+필수/선택 옵션»이라 priceBefore=최저 변형, basePrices=전 변형.
- **rules** — 조합규칙(배타·종속) 문자열. 기아 PDF에서 뽑음.
- **carType** — 제조사 원문 모델명(현대=한글·기아=영문슬러그). sub_model 과 매칭 다리로 씀.

## 견적기용만 고르기 (신차/중고 구분)
`new_car_trim` 은 **전부 크롤 실가**라 그대로 견적에 쓸 수 있다. 차종마스터 쪽에서 «현행/실가»를 나눈다:
- `market_class` = `신차`(year_end=「현재」·현행생산) / `중고`(생산종료).
- `newcar_priced` = new_car_trim 에 실가 있는지. **`market_class=신차 && newcar_priced=true` = 견적기가 바로 쓰는 51개**(나머지 신차는 수입·미크롤).

## ★★★차량가 «기준» — 세제혜택 «전»(개별소비세 5% = 제조사 표시가) 하나다

> 사장님 2026-09-09 「견적만 제대로 나오게 해 **기준만 있으면** 됩니다」

**값을 꺼내는 문은 하나다 — `lib/domain/estimate/car-index.ts` `trimPrice()`.**
견적기·캐스케이드·차 고르기 시트·잔가 짚기·손님 견적서가 전부 이 문으로 꺼낸다.
기준을 바꾸려면 **여기 한 줄**을 바꾼다. 문 밖에서 꺼내는 것은 `npm run check:estimate` 가 막는다.

왜 「전」인가 — 셋이 한 방향이다:

1. **세제혜택은 «원가 엔진»이 제 줄에서 뺀다.** `calc.js:248` 이 전기차 취득세를
   `max(0, costEx × 세율 − acqTaxCredit 140만)`(지방세특례제한법 §66③)으로 **직접** 감면하고,
   구매보조금도 취득가에서 «먼저» 뺀다.
   그런데 `priceAfter` 는 **개소세·교육세·취득세 감면을 «섞어» 뺀 값**이다
   (`scripts/crawl-newcar-hyundai.mts:40` — `taxIncentive = 개소세·교육세·취득세 감면액`).
   ⇒ 그대로 쓰면 **취득세 감면을 두 번** 뺀다.
2. **옵션값이 「전」 기준이다** — 제조사 공식 가격표(개소세 5%)에서 그대로 딴 값이라,
   차값만 「후」로 쓰면 한 견적서 안에서 **기준이 섞인다**.
3. 이 문서가 위에서 그렇게 정했다 — 「모든 가격 = 개별소비세 5% 기준 … 감면은 **받는 쪽에서 적용**」.

⚠ **여섯 군데가 따로 꺼내고 있었다**(2026-09-09 화면 실측) — 손님이 캐스케이드에서
  「EV9 GT-Line **7,917만**」을 고르는데 견적서에는 「**8,329만**」이 찍혔다. **412만원** 차이다.
⚠ 「전」이 비면 «지어내지 않는다» — 「후」로 물러서되 `trimBasis` 가 말하고, 손님 견적서가
  「가격기준 · 세제혜택 후」로 **적는다**.

### ⚠ 아직 안 한 것 — 개소세·교육세 감면이 원가에 «안» 들어간다

엔진이 제 줄에서 빼는 것은 **취득세 감면(전기 140만)과 구매보조금**뿐이다.
`priceBefore` 는 표시가라 **개소세·교육세 감면**(하이브리드·전기)이 아직 안 빠져 있다 —
그만큼 원가를 **높게** 잡아 대여료가 비싸게 나온다(EV9 GT-Line 기준 전−후 412만 중 취득세 몫을 뺀 나머지).

★고치는 법은 «법정값을 짐작»하는 게 아니라 **제조사가 준 숫자에서 뽑는 것**이다 —
  `개소세·교육세 감면 = (priceBefore − priceAfter) − 엔진이 이미 적용한 취득세 감면`.
  피드가 두 값을 다 싣고 있으므로 계산할 수 있다. **사장님 확인 뒤** 엔진 줄로 붙인다
  (돈이 움직이는 일이라 조용히 넣지 않는다).

## ★★옵션 «조합 규칙» 피드 (2026-09-09 추가)

`/api/newcar` 가 트림마다 **다섯 칸**을 더 싣는다. 견적기는 이걸로 «있을 수 없는 차»를 막는다
(로직 정본 = `lib/domain/estimate/option-rules.ts` · 원본 = 웰릭스 `mobile/StepVehicle.vue`).

| 칸 | 뜻 |
|---|---|
| `optionsMaster` | `{id: {name, sub, price, requires[]}}` — 그 트림의 옵션 사전. `sub` 는 이름에서 «뗀 규칙 문장» |
| `exclusiveGroups` | `[{id,label,members[]}]` — 그 안에서 **택1** |
| `optionExcludes` | `{부모: [막히는 것]}` — 부모를 고르면 그것들을 못 고른다 |
| `availableOptions` | 그 트림에서 «고를 수 있는» id 들. ⚠ **빈 배열 = 「고를 것이 없다」**, 칸이 «없는» 것 = 「못 받았다」. 둘을 같게 읽으면 못 고르는 것을 판다 |
| `impliedOptions` | ★★**「이미 산 것」** — 값에 이미 들어 있어 **다시 팔면 안 되는** 엔진·구동. 선행 조건으로는 «충족»으로 본다 |

★★`impliedOptions` 판정은 **한 곳**이다 — `lib/domain/estimate/implied-options.ts` (`impliedOf`).
인제스터도 기아·현대 크롤러도 제네시스 펴기도 **여기를 부른다.** 예전에는 인제스터에만 있어

또 받고 있었다(2026-09-09 검수).

★규칙은 옵션 «이름 안»에 문장으로 온다 — 「블랙 루프스킨(선루프와 동시 적용 불가)」·「A ※ B 적용 시 가능」·

  이 자리에도 같은 병이 있었다(`/\s\*/` 죽은 정규식 · 주석에 있는 `※`). 지금은 주석을 걷은 코드만 보고,
  파서는 실제 문자열로 시험한다.

## 알려진 한계 (코덱스 검토 2026-09-05 반영 — 견적 확정 전 알고 쓴다)
- **옵션은 «연료-정확한 것만»** — PDF 연료 감지가 약해, 다연료 모델에서 연료가 안 잡히면 «틀린 연료 옵션을 붙이느니 안 붙인다»(현대 51트림·232셀만). 파서 연료 감지를 넓히면 커버리지 오른다. `newcar_priced`·옵션 유무는 «있으면 정확, 없으면 미수집»이지 «없으면 옵션 없음»이 아니다.
- **현대 재크롤은 옵션을 지우지 않는다(merge)** — 하지만 트림이 바뀌면 옵션도 갱신돼야 하니, **매 크롤 뒤 `attach-hyundai-options.mjs` 재실행이 정석**. 파이프라인 순서 = 크롤 → attach → audit.
- **기아·제네시스는 재적재 시 먼저 지운다** — 가격 바뀌면 옛 문서가 남던 것 방지(delete-first). 제네시스는 8모델 전부 추출 검증 뒤에만 삭제.
- **세제혜택 후(현대)** = API `taxIncentive` 로 계산(양수 감면만). **공식 견적서와 원단위 대조는 아직 안 함** — 택시·영업용 음수 의미 포함해 표본 대조 필요.
- **market_class/newcar_priced 는 휴리스틱** — `year_end`=「현재」→신차, new_car_trim 모델명 부분일치→실가있음. 「현행이며 실가 확인」의 «확정»이 아니라 «후보 표시»로 쓴다.
- **매일 모니터 감시 범위** = 현대 트림 추가·삭제·차량가만. 옵션·색상 변동, 기아·제네시스·르노는 아직 미감시.
- **audit-newcar 는 배포 게이트** — 이상 있으면 exit 1. 근사중복(스타리아 9/11인승 등 실구성)은 경고만.
