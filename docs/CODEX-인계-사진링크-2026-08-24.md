# 코덱스 인계 — 차량번호 셀 사진 링크(2026-08-24)

## 무엇이 문제였나

사장님: 「손오공하고 오플은 들어가 있는데 상품리스트에는 링크가 없다고 사진링크가」
「사진링크를 좀 동일하게 처리해줘야지」

**«사진링크» = 「사진」 칸의 주소 글자가 아니라 «차량번호 셀의 파란 링크»다.**
원본 오토플러스 시트가 「★★★ 차량번호 클릭 후 차량이미지 다운로드 가능합니다 ★★★」라고
가르쳐 놓았고, 우리 표도 그 손버릇을 그대로 잇는다. 영업자는 차번을 누른다.

「사진」 칸 값은 세 탭 다 들어 있었다(192·30·67). **차번 셀 링크만 상품리스트에 없었다.**

## 왜 갈렸나 — 발행기 두 곳이 각자 걸고 있었다

| | 링크 소스 | 결과 |
|---|---|---|
| `publish-sonogong-tab` | 원본 차번 셀 링크 **∪ 「사진」 칸 값** | 걸림(30·67) |
| `publish-origin-tab` | 원본 차번 셀 링크 **만** | 원본에 링크가 없으니 **늘 0대** |

같은 일을 두 곳이 따로 하니 한쪽만 고쳐졌다. 사장님이 앞서 뱃지 때도 지적한 그 모양이다 —
「같은 건데 왜 몇 개만 저러냐」.

## 어떻게 고쳤나 — 한 곳으로 모았다

**정본: `lib/domain/sales-sheet-format.ts` → `buildSalesFormatRequests()` 맨 끝**

- 발행기는 `body: rows` 만 넘긴다. 링크 코드는 발행기에 **없다**(둘 다 걷어냄).
- 소스는 그 탭의 **「사진」 칸 값** 하나다. 줄마다 그대로 차번 셀에 건다.
- 사진이 빠진 차는 **옛 링크를 먼저 걷어낸다**(안 지우면 지난번 주소가 남아 남의 차로 간다).
- 서식(`textFormatRuns`: 링크색·밑줄·글꼴·크기)은 손오공이 쓰던 모양 그대로.

### 손대면 안 되는 것 셋

1. **맨 끝이어야 한다.** 뒤에 `repeatCell` 이 한 번이라도 오면 링크가 통째로 지워진다.
2. **판단하지 않는다.** 「사진」 칸에 있는 주소를 그대로 건다. 그 주소가 그 차 것인지는
   **공급사 시트에 넣을 때** 문지기(`lib/domain/photo-link-guard.ts`)가 이미 봤다.
   나르는 길에서 또 고르면 빠지는 차가 생긴다 — 사장님 「니가 빼면 안 되고 있는 걸 그대로 갖고 오는 거잖아」.
3. **발행기에서 따로 걸지 마라.** 그게 이 사달의 원인이다.

## 검사

```
npm run check:photo-link
```

두 가지를 본다 —
① 발행기가 링크를 따로 걸고 있지 않은가(또 갈리는 씨앗) ② 세 탭에서 「사진」 값 = 차번 셀 링크인가

읽을 때는 링크가 **세 자리**에 숨는다는 것을 잊지 마라 —
`hyperlink` · `userEnteredFormat.textFormat.link` · `textFormatRuns[].format.link`.
그리고 `values` API 로는 **안 보인다**. `includeGridData=true` 여야 한다.
(이걸 몰라서 「원본에 사진이 없다」고 잘못 본 적이 있다.)
