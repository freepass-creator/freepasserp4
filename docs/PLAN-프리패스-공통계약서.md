# 설계 — 프리패스 공통 계약서 1벌 (2026-08-10)

사장님 지시: **「일단 프리패스 공통계약서부터 하나 만들자」**

공급사마다 계약서를 따로 만들지 않는다. **한 벌로 시작한다.**
공급사가 다른 것은 계약서가 아니라 «값과 정책»이다 — 그건 이미 정책관리에 있다.

---

## 0. 규격은 이미 있다 — 그것을 쓴다

사장님 지시: **「계약서 규격은 그걸 쓸거야」**

```
규격 = public/contract-template/rental-contract.html  (data-field 140개)
매핑 = lib/domain/esign-field-map.ts                  (필드 ↔ 원자)
```

**이 서식은 프리패스가 만든 것이고, 착한거래가 사본을 가져간 것이다.**
원본은 여기다. 두 리포가 갈리면 `check:template-drift` 가 잡는다 — 끄지 마라.

그러므로 아래 실물 학습은 «새 규격을 만들기 위한 것»이 아니다.
**우리 규격이 실물에 견주어 무엇을 빠뜨렸는지 세기 위한 것**이다.

### 대조 결과 — 규격은 이미 실물을 덮는다

140필드를 세어 보니 「정비/서비스가 없다」는 첫 판단은 틀렸다.
`esign-display-fields` 의 9섹션만 보고 말한 것이었고, 규격에는 다 있다.

| 실물 12부가 가진 것 | 규격의 필드 | 값 출처 |
|---|---|---|
| 정비상품 | `maintenance_product` | 정책 `maintenance_service` |
| 긴급출동 | `emergency_dispatch_limit` | 정책 `annual_roadside_assistance` |
| 대차서비스 | `replacement_car_policy` | 고정문구 |
| 지정 정비점 | `designated_garage` | 고정문구 |
| 인수옵션·만기 인수금 | `buyback_option` · `buyback_price` | 입력 |
| 약정주행·초과요금 | `annual_mileage` · `over_mileage_rate` | 정책 |
| 자차 면책 최소·최대 | `self_damage_deductible_min/max` | 파생 |
| 보증금 분납 1~5회차 | `deposit_round_1~5` | 입력 |
| CMS 출금계좌·자동이체일 | `cms_account_no` · `auto_debit_date` | 입력 |

**빠진 것은 필드가 아니라 «값을 어디서 받을지»다.** 140개 중 32개가 `미정` —
담을 칸이 아직 없다는 뜻이다. 그게 진짜 할 일이다.

## 1. 무엇을 근거로 만들었나

카톡으로 받은 **계약서 실물 12부**를 기계로 읽어 항목 이름만 뽑았다
(`scripts/learn-contract-labels.mts`). 값은 읽지 않았다 — 고객 성명·주민번호가 들어 있다.

```
손오공 개인 · 손오공 법인 · 손오공 구독 · 아이언 · 스타스카이 · 빌린카
센트로 · KH · 리더스 · 렌트존 · 에스에이 · 우리캐피탈
```

서로 다른 라벨 447개 중 **11~12부에 공통으로 나온 것**이 아래 골격이다.
지어내지 않았다. 열두 회사가 실제로 같은 것을 적고 있다.

전체 24개 공급사 폴더가 있고 지금 쓰는 곳은 그중 일부다. 12부는 «운영 중인 곳» 위주로 골랐다.

## 2. 실물이 말하는 골격

12부가 공통으로 가진 문서 구조는 넷이다. **한 파일 안에 네 문서가 들어 있다.**

```
① 본계약    자동차 렌탈(대여) 계약서
② 동의서    개인정보 수집·이용 / 제3자 제공 / 차량회수 동의
③ 부속서류  효성CMS 자동이체 신청서
④ 인수증    차량 인수증 · 운전자격 검증 확인서
```

**이것을 한 장으로 붙이지 않는다.** 계약서 하나에 CMS 신청과 인수증까지 묶여 있어서
지금 직원이 엑셀 한 파일을 통째로 돌리고 있는 것이다. 서명 시점이 다르다 —
본계약은 계약할 때, 인수증은 차를 받을 때 서명한다. §7 참고.

## 4. 지금 있는 것과의 차이

기존 `esign-display-fields` 는 9섹션이다.

```
임차인정보 · 사업자정보 · 차량정보 · 대여조건 · 운전자 · 보험 · 사고·면책 · 출금계좌 · 연대보증인
```

규격(140필드)에는 원자가 다 있는데 **화면 9섹션에는 정비/서비스가 안 보인다.**
규격에 있는 것을 화면이 안 보여 주면 직원은 «없는 줄» 안다. 섹션을 열어 주면 된다.

### 해야 할 일

1. **`미정` 32필드에 수집 경로를 준다** — 이게 진짜 남은 일이다(§4-1)
2. **화면 섹션(`esign-display-fields`)에 정비/서비스를 노출** — 규격엔 있는데 화면에 없다
3. 고정문구를 `esign-standard-terms` 에 채움 — 중도해지·연체·자차처리·보증금반환·사고다발
4. 섹션 순서는 **규격을 따른다.** 실물 절 번호에 맞추려고 규격을 흔들지 않는다

---

### 4-1. `미정` 32필드 — 담을 칸이 없는 것들

| 무리 | 필드 | 어떻게 받을까 |
|---|---|---|
| 반납 정산 | `return_datetime` · `odometer_return` · `fuel_gauge_return` · `damage_return` | **반납 때** 받는 값이다. 계약 시점에 물으면 안 된다 |
| 추가운전자 2·3 | `drv2_*` · `drv3_*` (6개) | 입력 칸 추가 |
| 세금계산서 | `tax_ceo` · `tax_email` · `tax_biz_type_item` | 사업자 계약에서만 |
| 기타 | `contract_place` · `customer_email` | 계약 장소는 고정문구로 가능 |

반납 관련 4개는 **본계약이 아니라 반납 정산 문서**의 값이다 —
차량 인수증을 분리하듯(§7) 반납도 분리해야 한다. 계약서에 빈칸으로 남기지 마라.

## 5. 공급사 차이는 계약서가 아니라 «값»이다

12부를 훑으면 문서 구조는 같고 **숫자와 문구만 다르다.**

```
자차 면책금     50만원 / 100만원 / 200~400만원      ← 정책값
중도해지수수료   잔여기간 대여료 총합 × 해지수수료율     ← 산식은 같고 요율만 다름
운전자 연령     만 26세 이상 (12부 중 11부가 같은 값)  ← 정책값
정비상품        정비제외 / 포함                      ← 정책값
```

그러므로 **공급사별 계약서를 만들지 않는다.** 한 벌에 정책값을 부어 넣는다.
이미 정책 34칸이 시트로 나가고 있고, 계약서도 같은 원천을 본다.

예외로 보이는 것 둘:
- **손오공 구독 약정서** — 렌트가 아니라 구독이라 조건 축이 다르다. 이미 표준 3벌에 구독 2벌이 있다.
- **우리캐피탈** — 캐피탈 상품이라 12부 중 라벨이 가장 이질적이다. 나중에 본다.

## 6. 「1번만 입력하면 되는 것」 — 회사 고정값

사장님 지시: *엑셀에 입력되는 정보를 미리 입력해놔야 하는 거, 즉 1번만 입력하면 되는 거.*

계약마다 바뀌지 않는 값이 있다. 이건 **계약서에 묻지 않는다.** 회사 설정에서 한 번 받는다.

| 값 | 실물 예 | 어디에 |
|---|---|---|
| 렌트회사명 | ㈜손오공렌터카 | 파트너 |
| 사업자번호 | 882-87-00650 | 파트너 (이미 있음) |
| 회사 주소 | 서울특별시 강서구 양천로53길 30 | 파트너 |
| 대표자 | 12부 전부 | 파트너 ⚠ 없음 |
| 대여료 입금계좌 | 신한 100-032-471576 | 파트너 ⚠ 없음 |
| 자동이체일 규칙 | 출고일 기점 고정 | 정책 |
| 보험 담보·면책 | 대인 무한 / 자차 50만 | 정책 (있음) |
| 정비·대차·긴급출동 | 연 1회 / 연 5회 | 정책 (있음) |
| 약관 본문 | 자동차대여약관 | 표준 (있음) |

**계약마다 묻는 것은 열 몇 개뿐이다** — 계약자 4·차량 3·조건 6 정도.
나머지는 이미 시스템이 안다. 이것이 「엑셀 → 넣기 → 확인 → 보내기」가 성립하는 이유다.

파트너에 없는 것 둘(**대표자 · 입금계좌**)을 먼저 채워야 계약서가 완성된다.

## 7. 한 파일에 든 네 문서를 넷으로 가른다

| 문서 | 서명 시점 | 어디로 |
|---|---|---|
| 본계약 | 계약할 때 | 전자계약 |
| 개인정보 동의 3종 | 계약할 때 (본계약과 함께) | 전자계약 동의 단계 |
| CMS 자동이체 신청 | 계약 직후 | **별도** — 계좌정보는 저장 영역을 분리 |
| 차량 인수증 + 운전자격 검증 | **차를 받을 때** | **별도** — 출고관리와 연결 |

인수증을 본계약에 붙이면 **아직 받지도 않은 차를 받았다고 서명**하게 된다.
지금 엑셀이 그렇게 돼 있어서 직원이 출고 때 종이를 다시 돌리고 있다.

## 9. 손대면 안 되는 것

- **실물 계약서를 리포에 넣지 않는다.** 고객 성명·주민번호·연락처가 들어 있다.
  `tmp/contract-samples/` 는 git 무시 확인함. 검사에는 값을 지운 구조 샘플만 쓴다.
- **공급사별 계약서를 새로 만들지 않는다.** 다른 것은 값이지 문서가 아니다.
- **인수증·CMS 를 본계약에 붙이지 않는다.** 서명 시점이 다르다.
- **계약서 서식 원본은 프리패스다.** 착한거래가 사본을 가져갔다.
