## 한 줄

**도구마다 v3 를 같이 보느냐 v4 만 보느냐가 달라서** 같은 재고가 다른 수로 나온다.

## 무슨 일이 있었나

영업자 시트에 **458건**이 올라갔는데 실제 차는 **409대**였다. 49대가 두 번씩 올라간 것이다.

파보니 이런 짝이었다:

```
109호3398   EXT_4d757134e233   |   RP004_109호3398      둘 다 [출고가능]
```

`EXT_…` 는 v3 이관 사본이고 `RP004_…` 는 시트가 앞으로 갱신할 정본이다.

## ★핵심 — 삭제가 v4 로 안 넘어왔다

```
EXT_4d757134e233
   v3   _deleted = true        ← 예전에 「이 차 뺀다」고 지운 것
   v4   _deleted = undefined   ← 그 삭제가 v4 에는 없다
```

그래서 보는 곳마다 답이 다르다:

| 보는 곳 | 기준 | 결과 |
|---|---|---|
| 화면 · 영업자 시트 · 카탈로그 | **v4 만** | 살아 있음 → 목록에 뜬다 |
| `scripts/fold-sync-twins.mts` | v3 + v4 **합침** | 이미 지워진 것으로 보고 건너뛴다 |

`fold-sync-twins` 는 `mergeNodes(p3.val(), p4.val())` 로 두 노드를 합쳐 읽는다(80행 근처).
합치면 v3 의 `_deleted=true` 가 이겨 `live` 에서 빠지고, **접을 그룹 0** 이 된다.
정작 v4 에서는 멀쩡히 살아 목록에 뜬다.

⚠ 오늘 커밋 `ee93842` 「v3 운영 노드는 관리자만 쓴다 — erp4 는 애초에 v3 에 쓰지 않는다」
로 v4 단독을 못 박았다. **이 도구만 아직 v3 를 같이 본다.**

## 목록 기준 — 건드리지 말 것

`lib/domain/product.ts` `isHiddenFromCatalog` 에 박아 뒀다.

```
활성 783대 − 출고불가 305대 = 458건   ← 「재고에서 출고불가 빼고 다 올린다」
```

- **출고협의**는 일정 조율만 하면 되는 «가능한 차»다. 이름만 보고 빼면 75대가 사라진다.
- **계약중**은 숨기지 않고 마크로 알린다.
- 상태값이 **빈 차**도 안 거른다 — 데이터가 덜 채워진 것이지 못 파는 게 아니다.

거르는 상태를 **늘리지 마라.**
